# start-to-do — запуск задачи исполнителем

Аргумент: номер/название задачи из плана модуля (например `AM-07б`).

## 1. Задача и контракты
- Найти задачу в плане модуля (`docs/plan/<модуль>.md`): скоуп, ключевые файлы, условия приёмки, оценка, зависимости.
- Стыки задачи: по `docs/<модуль>_contracts.md` — какие контракты задача использует или поставляет, их версии. Нет контракта для нового стыка — **сначала описать** (владелец, потребители, интерфейс, единицы, инварианты, версия) и добавить контрактный тест; расхождения с кодом — записать и раздать.
- Зависимости готовы? Если нет — может ли задача работать против контракта на подставных данных (поля из файлов, заглушки)? Иначе — не запускать.

## 2. Рабочая копия
```
git -C <копия модуля> worktree add ~/deltaplan-<модуль>-<задача> -b <модуль>/<задача> feature/<модуль>
```
(от актуальной ветки модуля, после вливания уже принятого). Первый запуск Godot в новой копии — `godot --headless --path . --import`.

## 3. Тип исполнителя
| Работа | Тип |
|---|---|
| код игры, физика, GPU, UI, сеть | `dp-engineer` |
| прототип, эталон, замеры, литература/данные | `dp-researcher` |
| документы, страницы сайта, тексты | `dp-writer` |
| замены по шаблону, прогоны, скриншоты готовыми инструментами | `dp-mechanic` |
Модель можно переопределить (`model` в Agent), если задача явно проще или сложнее типа. Повтор неудачной задачи — новый исполнитель с более чёткой спецификацией (можно `fable`).

## 4. Задание (шаблон)
1. **Задача** и её место в плане (1–2 фразы, зачем).
2. **Где работать**: копия и ветка; чужие копии не трогать; свежая работа соседей — `git merge feature/<модуль>`.
3. **Контракты**: стыки задачи — документ, раздел, версия; менять интерфейс — только через координатора.
4. **Скоуп и ключевые файлы**; чего не трогать (файлы других задач по плану).
5. **Условия приёмки** — дословно из плана + как проверить (тесты, замеры, скриншоты — в `build/screenshots/<задача>/`).
6. **Правила** — ссылкой: `/home/greg/deltaplan/.claude/workflow.md`, «Общие правила»; особенности задачи (GPU-замок, большие данные — где лежат).
7. **Отчёт**: что сделано (коммиты), числа приёмки, что не вышло, открытые вопросы, как проверить, пути к картинкам.

## 5. Журнал
Строка в журнал модуля (`docs/plan/<модуль>_progress.md`): задача → «в работе», тип исполнителя, копия/ветка, дата; коммит журнала (`git commit -- <журнал>`).

## 6. Приёмка (после отчёта)
Перепроверить приёмку самому (тесты/числа), влить `<модуль>/<задача>` в `feature/<модуль>`, прогнать затронутые тесты, `git worktree remove` и удалить ветку, отметить в журнале «принята» с коммитами и ключевыми числами.
