# start-to-do — запуск задачи

Аргумент: задача из плана модуля (`<ID>` или раздел).

1. **Контракты.** `.dpcli/dpcli plan <м> <раздел>` — скоуп, файлы, приёмка, зависимости. Стыки — `.dpcli/dpcli plan <м> --contracts <имя>`: нет контракта для нового стыка — сначала описать (версия, контрактный тест). Зависимость не готова и подставных данных нет — не запускать.
2. **Карточка** (создаёт копию и ветку `<м>/<ID>` от `feature/<модуль>`):
   ```
   .dpcli/dpcli task new <м> [ID] --type <тип> --title "…" --goal "1–2 фразы" --plan-ref "<раздел>" \
     --scope <путь> --dont-touch <путь> --contract <имя>@<версия> \
     --test <фильтр> --check <имя> "<cmd>" "<exit=0|re:…|num:(…) <=X>"
   ```
   Как делать, если неочевидно (файлы, функции, формат, замок GPU/CPU, где данные), — `.dpcli/dpcli task note <ID> "…"`. Исполнителю не должно понадобиться ничего искать.
3. **Задание.** `.dpcli/dpcli task brief <ID>` — отказ значит, что карточка неполна: дописать (`task set`/`task note`).
4. **Запуск.** Агент типа карточки (`--type`), сообщение — вывод `brief` как есть, без добавлений. Модель — sonnet (`dp-mechanic` — haiku); opus — только если проектирование нельзя вынести в карточку/контракт.
5. **Журнал.** `.dpcli/dpcli event <ID> started`.

| Работа | Тип |
|---|---|
| код и тесты | `dp-engineer` |
| прототип, замеры, литература | `dp-researcher` |
| документы | `dp-writer` |
| замены по шаблону, прогоны | `dp-mechanic` |

Свои типы — `.dpcli/dpcli agents`. Приёмка — .claude/workflow.md, «Приёмка».
