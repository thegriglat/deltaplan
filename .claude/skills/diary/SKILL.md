# diary — запись в дневник разработки

Дневник — markdown-файлы в `diary/` репозитория (`/home/greg/deltaplan`); на сайт не попадает, читается на GitHub. Одна запись — один день: `diary/ГГГГ-ММ-ДД.ru.md` (есть и старые `.en.md` — новые не нужны). Это дневник, а не статья: коротко, по делу, по-русски. Репозиторий открытый — текст публичный.

Аргумент (необязательный): что записать (тема/событие). Без аргумента — собрать итоги дня самому.

## 1. Какой файл
- Дата — сегодняшняя по местному времени (`date +%F`). **Дата записи берётся из имени файла** (`2026-09-30.md` или `2026-09-30-что-угодно.md`); поле `date` в шапке, если есть, — та же дата.
- Файл дня уже есть → дописать в него новый раздел (не создавать второй файл за день) и обновить вступление-итог.
- Нет → создать:
  ```
  ---
  title: "Короткий заголовок о главном за день"
  date: 2026-09-30
  description: "Итог дня одной фразой"
  ---

  Вступление-итог дня: 1–3 предложения.

  <!--more-->

  ## Первая тема
  ```
- Разделы — `##` (при необходимости `###`).

## 2. Что писать
Источники: разговор в сессии, `.dpcli/dpcli digest --since today` (решения, принятые задачи, правки плана, коммиты главной ветки), `git log --since=<дата> --format="%h %ad %s" --date=format:%H:%M` (через `rtk proxy git log`, чтобы не обрезало), CHANGELOG.md, docs/plan/, docs/research/.

Разделы по темам дня, внутри — факты:
- **что сделали** — функционально, с коммитами коротким хешем `abc1234` (проверить `git cat-file -t`), версии — номером;
- **решения и почему** — кто предложил (пользователь — глобальный координатор: идеи, решения, границы модели; Claude и агенты — код, источники, расчёты), какие варианты отклонены и почему;
- **отзывы пилотов** — дословные цитаты в кавычках «…»; автор — «пилот» / «пилот-консультант». **Слова «мама», «папа», «родители» не использовать** (публичный текст), личные и семейные детали не выносить;
- **находки и уроки** — что оказалось не так, как думали (ложные тревоги, регрессии, числа замеров);
- **ссылки** — относительные от `diary/`: `[air-model](../docs/archive/plan/air-model.md)`, `[итог](../tools/research/heat_ca/out/summary.md)`, картинки — `![Подпись](../tools/research/…/flow.png)`; путь проверить, что файл есть.
Не пересказывать каждый коммит; не лить воду; цифры — из замеров, не на глаз. Тексты для родителей, questions.md, личные пути, токены — не в дневник.

## 3. Проверка и коммит
- `grep -niE "мам|папа|пап[уые]|родител" diary/<файл>` — пусто.
- Коммит только файла дня: `git commit -m "Дневник: <дата> — <тема>" -- diary/<файл>` (перед этим `git add` для нового файла). Пушить — только по просьбе.
- Коротко сказать пользователю, что записано (2–4 пункта) и путь к файлу.
