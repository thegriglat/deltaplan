# diary — запись в дневник разработки

Дневник — раздел «Дневник» сайта проекта (Hugo, тема Hugo Book, `site/`), публикуется на GitHub Pages: https://thegriglat.github.io/deltaplan/diary/ . Одна запись — один день: `site/content/diary/ГГГГ-ММ-ДД.md` (в `/home/greg/deltaplan`). Это дневник, а не статья: коротко, по делу, по-русски. Публичный текст.

Аргумент (необязательный): что записать (тема/событие). Без аргумента — собрать итоги дня самому.

## 1. Какой файл
- Дата — сегодняшняя по местному времени (`date +%F`). **Дата записи берётся из имени файла** (`2026-09-30.md` или `2026-09-30-что-угодно.md`); поле `date` в шапке, если есть, — та же дата.
- Файл дня уже есть → дописать в него новый раздел (не создавать второй файл за день) и обновить вступление-итог.
- Нет → создать:
  ```
  ---
  title: "Короткий заголовок о главном за день"
  date: 2026-09-30
  description: "Итог дня одной фразой"
  ---

  Вступление-итог дня: 1–3 предложения.

  <!--more-->

  ## Первая тема
  ```
- `# Заголовок` в теле НЕ писать — тема печатает title сама. Разделы — `##` (при необходимости `###`).

## 2. Что писать
Источники: разговор в сессии, `git log --since=<дата> --format="%h %ad %s" --date=format:%H:%M` (через `rtk proxy git log`, чтобы не обрезало), CHANGELOG.md, docs/plan/, docs/research/.

Разделы по темам дня, внутри — факты:
- **что сделали** — функционально, с коммитами шорткодом `{{< commit abc1234 >}}` (хеш проверить `git cat-file -t`), версии — ссылкой на страницу версии `/releases/X.Y.Z/`;
- **решения и почему** — кто предложил (пользователь — глобальный координатор: идеи, решения, границы модели; Claude и агенты — код, источники, расчёты), какие варианты отклонены и почему;
- **отзывы пилотов** — дословные цитаты в кавычках «…»; автор — «пилот» / «пилот-консультант». **Слова «мама», «папа», «родители» не использовать** (публичный текст), личные и семейные детали не выносить;
- **находки и уроки** — что оказалось не так, как думали (ложные тревоги, регрессии, числа замеров);
- **ссылки** — на планы и исследования от корня репозитория: `[docs/plan/air_model.md](/docs/plan/air_model.md)`, `[итог](/tools/research/heat_ca/out/summary.md)`; картинки — `![Подпись](/tools/research/heat_ca/out/s1_sun_one_slope/flow.png)`, скриншоты версий — `/releases/X.Y.Z/screenshots/<файл>.jpg`. Ссылки проверяются при сборке (битая — ошибка). Файлы > 10 МБ — только ссылкой (уйдёт на GitHub).
Не пересказывать каждый коммит; не лить воду; цифры — из замеров, не на глаз. Тексты для родителей, questions.md, личные пути, токены — не в дневник.

## 3. Проверка и коммит
- Сборка без ошибок: `cd site && ~/.local/bin/hugo --renderToMemory 2>&1 | grep -E "WARN|ERROR"` — пусто (записи «из будущего» включены, `buildFuture`).
- `grep -niE "мам|папа|пап[уые]|родител" site/content/diary/<файл>` — пусто.
- Коммит только файла дня: `git commit -m "Дневник: <дата> — <тема>" -- site/content/diary/<файл>` (перед этим `git add` для нового файла). Пушить — только по просьбе (после пуша в main сайт пересобирается сам, `.github/workflows/pages.yml`).
- Коротко сказать пользователю, что записано (2–4 пункта) и путь к файлу; посмотреть — `cd site && hugo server` → http://localhost:1313/deltaplan/diary/ .
