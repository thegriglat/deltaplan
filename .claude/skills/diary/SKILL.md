# diary — запись в дневник разработки

Дневник — Hugo-блог в `/home/greg/deltaplan/diary/`. Одна запись — один день: `diary/content/posts/ГГГГ-ММ-ДД.md`. Это дневник, а не статья: коротко, по делу, по-русски.

Аргумент (необязательный): что записать (тема/событие). Без аргумента — собрать итоги дня самому.

## 1. Какой файл
- Дата — сегодняшняя по местному времени (`date +%F`).
- Файл дня уже есть → дописать в него новый раздел (не создавать второй файл за день).
- Нет → создать. Шапка (TOML) — только с заголовком; дату Hugo берёт из имени файла:
  ```
  +++
  title = 'Короткий заголовок о главном за день'
  +++
  ```
  Без шапки запись тоже рендерится («Запись ДД.ММ.ГГГГ»), но заголовок лучше дать.

## 2. Что писать
Источники: разговор в сессии, `git log --since=<дата> --format="%h %ad %s" --date=format:%H:%M` (через `rtk proxy git log`, чтобы не обрезало), CHANGELOG.md, docs/plan/, docs/research/, questions.md.

Разделы — жирный заголовок абзаца (`**Тема.**`), внутри — факты:
- **что сделали** — функционально, с хешами коммитов (`abc1234`), версии/теги;
- **решения и почему** — кто предложил (пользователь — глобальный координатор: идеи, решения, границы модели; Claude и агенты — код, источники, расчёты), какие варианты отклонены и почему;
- **отзывы пилотов** — дословные цитаты в кавычках «…» (мама/папа — как «пилот», «мама»);
- **находки и уроки** — что оказалось не так, как думали (ложные тревоги, регрессии, числа замеров);
- **ссылки** — на планы и исследования (`docs/plan/…`, `docs/research/…`, `tools/research/…`), картинки прототипов — путями в репозитории.
Не пересказывать каждый коммит; не лить воду; цифры — из замеров, не на глаз. Личные тексты для родителей (инструкции, сообщения) — не в дневник.

## 3. Проверка и коммит
- Сборка без ошибок: `cd diary && hugo --quiet && rm -rf public` (Hugo — `~/.local/bin/hugo`; записи «из будущего» включены, `buildFuture`).
- Коммит только файла дня: `git commit -m "Дневник: <дата> — <тема>" -- diary/content/posts/<файл>` (перед этим `git add` для нового файла). Пушить — только по просьбе.
- Коротко сказать пользователю, что записано (2–4 пункта) и путь к файлу; посмотреть — `cd diary && hugo server` → http://localhost:1313.
