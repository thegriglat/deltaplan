# PR-9: профиль и пачка 2

Замер: Онгудай 400 м, release, 8 потоков, под замком cpu (18 слотов), `run.sh before|after` в одной серии
(before — бинарь родительского коммита). Тождественность: `compare_r2.py` -> identical=4/4 (итерации, невязки, u_rel те же).

## Профиль до пачки (`profile/`, u3_heat, 8 потоков, perf record -F 499)
- `solve_group` (прогонки) 64,5 % циклов и 83 % L1-промахов; `build_all_mom` 7,8 %, `build_heat` 6,2 %, `kloc` 5,0 %,
  `resid` 2,1 %, `prolong` 1,8 %, rayon+crossbeam ~7 %, ядро ~2 %.
- perf stat: IPC 1,75, L1-промахов 9,56 млрд, LLC-промахов 0,40 млрд.
- harness (`harness_before`, `harness_after`; на клетку-прогонку, 3 компоненты): x / y / z — тактов 47,7 / 74,1 / 81,4, L1-промахов
  0,96 / 2,54 / 2,38, инструкций 93 / 76 / 74. y и z — IPC < 1: упор в память (30 % тактов с ожиданием L2-промаха), не в инструкции.
- Внутри потока: 8 потоков дают ускорение 5,7 против 1 потока; 89 % занятости внутри параллельных областей.

## Правки пачки (по приоритетам: L1/обход, rayon, копии)
1. Ширина блока линий: BLOCK `[16,128,128]`, MAXL 64 — по y/z задача берёт всю строку (до 49 линий своего цвета), шаги идут
   подряд по памяти, аппаратная предвыборка работает; прежде 16 линий.
2. Граничные линии блока решаются одной группой (флаги соседей на линию), а не по одной (было nl=1 на линию) — самый крупный выигрыш.
3. Направление прогонки — константный параметр (`DIR`): слоты, смещения без проверок границ; указатель на x в регистре (`Cells`);
   предыдущие c', d' читаются из буфера, а не из отдельных массивов; буферы прямого хода — thread_local, не выделяются на задачу.
4. Строки шаблонов выровнены по 64 Б (`RowBuf`): у большого `Vec<Row>` адрес = страница+16, каждая вторая строка пересекала линию кэша (L1-промахи −2,7 %).
5. Копии и проходы: restrict+resid в один проход (массив `r` уровня убран); rhs = div − mean·fluid сразу в строки MG вместе с обнулением phi;
   phi − pm·fluid сразу в pfull; эффективный источник theta' (`q − thd/τ`) считается в ядре, массив `qeff` убран.
6. Индексная арифметика: целочисленные деления на клетку в kloc/mom/heat/restrict/prolong заменены счётчиками.

Арифметика и порядок операций не менялись.

## Испытано и отброшено (замер в серии, без выигрыша или хуже)
чтение строк заранее (touch) на 2–8 шагов; выбор вместо ветвления по `c != 0` (медленнее, цепочка зависимостей); обратный ход на месте
в `dp` (+6 %); разбиение прямого хода на сбор и векторную рекуррентность (+8 %); конвейер двух цветов по плоскостям z (лучше в harness,
хуже в реальной итерации); последовательные грубые уровни; `with_max_len`.

## Что осталось (оценки)
Прогонки ~60 % времени; z и y — по-прежнему упор в задержки памяти (нет software prefetch в stable без `core::arch`). Построители
mom/heat/kloc ~20 % — арифметика и ветвления. Хвост задач в областях (занятость 86–93 %): дробление последних плоскостей — оценка 1–2 %.
SIMD по линиям требует транспонирования строк (AoS 32 Б) — оценка до 10 %, большая правка.
