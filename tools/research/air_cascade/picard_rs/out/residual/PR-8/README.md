# PR-8 — невязка → отклонение поля, порог «годно для игры»

Задача 4 плана picard-rs (решение пользователя 2026-10-24). Сводка — `summary.json` (контракт R7 v1, проверка
`contract/check_residual.py` → `ok series=5 points=43`). Решение о пороге принимает пользователь на шлюзе; здесь — данные и предложение.

## Как воспроизвести
```
# из корня копии, фоном (около 15 мин, всё под .dpcli/dpcli lock cpu PR-8, 8 потоков)
bash tools/research/air_cascade/picard_rs/out/residual/PR-8/run.sh
python3 tools/research/air_cascade/picard_rs/residual/md_tables.py tools/research/air_cascade/picard_rs/out/residual/PR-8/summary.json
```
`run.sh` гонит `picard solve` (R6 v2: `--tol-scale`, `--snap-at`, `--snap-dir`, `--save-state`, `--init`), потом
`residual/summarize.py` (читает R4 `.json/.bin` и вход R1, считает отклонения по регионам) и проверку R7. Результаты R2 v3 всех
прогонов — `r2/`. Снимки и состояния (десятки МБ) — `~/data/air_cascade/picard_rs/residual/PR-8/` (вне git). Входы — `~/data/air_cascade/ongudai/`
(R1/R5, только чтение; происхождение и лицензия данных — как в `tools/research/air_cascade/export/README.md`). Код: `residual/fields.py`
(чтение, регионы, отклонения), `residual/summarize.py`, `residual/md_tables.py`, `residual/table.py`, порог — `residual/threshold.json`.

## Что измерено
- Эталон серии — прогон с `tol_scale 1` (критерий эталона, холодный старт). Точки: `by: iter` — поле после N итераций того же пути (снимок R4,
  N = 30/50/100/150; тёплый: 10/20/30/50), `by: tol_scale` — отдельный прогон с множителем 3/10/30 (холодный ещё 5 и 7 — между точками контракта).
- Отклонение: `du` = |Δ(u,v)| (модуль разности горизонтального ветра в узле), `dw` = |Δw|, max и rms по клеткам региона, против эталона. `dwt` — то же для
  вертикальной скорости вдоль рельефа wt = w + u·hx + v·hy (hx, hy — градиент рельефа): у самой земли w ≡ 0 (нижняя жидкая клетка, шахматка), поток идёт
  вдоль склона (turbulence.md:255), поэтому на склонах чувствуется wt, а не w. Невязки точки — `mom_rms`, `div_rms`, `th_rms` как у критерия случая.
- Время до точки (8 потоков, код ветки после PR-6/PR-7, ~58 мс/итер u3_heat): по N — время `history[t_s]` чистого прогона без снимков (`*_time`), линейно между
  проверками; по tol_scale — время итераций прогона (`residuals.t_s`). Время итоговой оптимизации пересчитает PR-o; N и невязки от кода не зависят.
- Невязки снимка по N — записи `history` на ближайшей проверке не раньше N (проверки у холодного на итерациях 11, 21, …, у тёплого — 10, 20, …; поле `res_it` в точке): для
  холодного N=30 невязки взяты на итерации 31 (смещение на одну итерацию, ≈ 1 %), поля и время — точно на N.
- Тёплый ряд (R5): холодный сошедшийся h1200 → `--init` для h1215; эталон — холодный сошедшийся h1215. Тёплый сходится за 20 итераций, поэтому для N = 30 и 50 прогон
  с `tol_scale 0,001`, `max_iters 50` (путь решения тот же). Пара mech h1200/h1215 вырождена (PR-3) — не мерилась.

## Что видно
1. **Отклонение падает быстро.** u3_heat, u3_mech, u6_heat: к 100 итерациям у старта Δw ≤ 0,023, Δ(u,v) ≤ 0,13 м/с; к 150 — Δw ≤ 0,004, Δ(u,v) ≤ 0,02. До 50 итераций
   поле заметно другое: u3_mech Δw у старта 0,22, Δ(u,v) 0,98 м/с (механический случай сходится медленнее тепловых). Отклонение по области (в основном выше 400 м и в губках)
   в 3–13 раз больше, чем у старта.
2. **tol_scale ↔ невязка ↔ отклонение (холодный).** tol 3 — Δ ≤ 0,004 / 0,016 у старта (быстрее эталона всего в 1,3–1,5 раза); tol 5 — ≤ 0,008 / 0,034;
   tol 7 — ≤ 0,014 / 0,06; tol 10 — ≤ 0,022 / 0,129 (склон u3_mech Δwt 0,143); tol 30 — 0,06–0,40 / 0,3–2,0: заметно.
   Ускорение мало: tol 5 — ×1,6–1,7 (u3_heat 6,53 с из 11,21), tol 10 — ×2,1–2,7, tol 30 — ×4,2–10,8 (но поле негодно).
3. **Поток.** Ошибка пика w в термиках и среднего w в термиках/на склонах при tol ≤ 10 не больше ±0,003 м/с (склоны ±0,001, по Δwt ±0,001); при tol 30 — пик −0,018 и среднее −0,017 (u3_heat), среднее +0,013 (u3_mech).
4. **Пол точности пренебрежимо мал.** Сошедшийся f32 против f64-решения случая (`sol_*`): у старта Δw ≤ 5e-6, Δ(u,v) ≤ 1.6e-5 м/с, θ' ≤ 2e-5 К — на 4 порядка ниже любого порога; порог не ограничен точностью f32.
5. **Эталон по критерию ≠ неподвижная точка.** Сравнение с «глубоким» полем (tol_scale 0,1): у u3_heat, u3_mech, u6_heat, h1215 различие ≤ 0,004 м/с у старта и ≤ 0,03 по области — критерий эталона достаточен.
   **У u0_heat (штиль, только нагрев) — нет:** различие 0,38 м/с по w и 0,73 по (u,v) у старта, до 1,8 м/с по области (знак w на 1–1,5 км над рельефом меняется); сама глубокая точка за 1500 итераций (91 с) тоже не сошлась
   (mom_rms 3,5e-6 стоит на месте). Отклонения от эталона у u0_heat при любом tol_scale (0,3 м/с у старта уже при 30 и 150 итерациях) — это дрейф медленной моды, а не недосчёт; порог по нему не измерить.
6. **Тёплый старт.** Исходное h1200 против h1215 — Δw 0,010 м/с у старта: за 15 минут поле меняется мало. После первых итераций тёплый старт на 0,03 м/с хуже исходного (4 V-цикла): старт 0,033 → 0,038 (N=2–4) → 0,025 (N=10) → 0,009 (20) → 0,003 (30) → 0,001 (50).
   tol_scale 3, 10, 30 останавливают тёплый на первой проверке (10 итераций, 0,63 с), поэтому эти три точки совпадают; тёплый сошёлся (tol 1) за 20 итераций, 1,22 с против холодного h1215 16,9 с (×14), 10 итераций — ×27.

## Порог (предложение; решение — шлюз пользователя)
Подробно — `summary.json → threshold`; кратко:
- **Критерий поля:** у старта (crop, до 400 м над рельефом) Δw ≤ 0,05 и Δ(u,v) ≤ 0,2 м/с (max по клеткам); на склонах (10–400 м) Δw (и Δwt) ≤ 0,1 м/с.
- **Откуда:** 0,1 м/с — порог звука подъёма вариометра (`configs/audio.json:17`), гистерезис 0,05 м/с (`:21`); ошибка ниже порога не включает писк, у старта берётся половина.
  Среднее вариометра (25 с, `configs/instruments.json:7`) и фильтр 0,7 с (`:5`) сглаживают шум, но не постоянное смещение поля, поэтому порог — на максимум, не на rms.
  Шум игры поверх поля у старта (turbulence.md:121, AS-2): σ_w 0,33–1,2, σ_u 1,4–2,5 м/с, значит 0,05 / 0,2 м/с — не более 15 % σ_w / σ_u.

## Допущения и границы
- Сравнение — внутри одного решателя (Rust, f32) с эталоном по его же критерию; «сошедшееся» = остановка по `tol_scale 1`, что по п. 5 для u0_heat не неподвижная точка.
- Регион `launch` — окно crop (16×16 клеток, 6,4 км), не точка старта; сетка 400 м, шаг по вертикали 105 м: нижний слой агл < 105 м одна клетка, поэтому «10–50» и «50–100» —
  это одна и та же нижняя клетка столбца (различаются только положением центра над ступенькой рельефа).
- Склоны и термики — определения мои (пороги — по распределению Онгудая и паре u3 mech/heat, не по коду игры; в игре аналогов регионов нет). Термики в mech — механические восходящие ≥ 0,75 м/с.
- Перцептивный порог пилота по ветру и w (кроме порога звука) в проекте не измерен; 0,05/0,2 м/с — доли шума игры (≤ 15 %), не измеренный предел восприятия.
- Цепочка тёплых стартов (T → T+15 → T+30) не мерилась: ошибка может копиться. Один Онгудай 400 м; mech h1200/h1215 не мерилась.
- Вертикальная скорость в узлах сетки, как в состоянии (скорости не интерполировались в точки между узлами).
