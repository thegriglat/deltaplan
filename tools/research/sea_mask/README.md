# Признак «море»: проверка на данных мест (SEA-1)

## Вывод

Признак работает на 16 проверенных местах (`works = true`, контракт S1 v2). Внутренняя вода: 0 клеток far помечено морем (Бухтарма, Катунь, Ладога, Байкал,
Верхнее, Мелларен, Мёртвое море в двух квадратах, Солтон-Си). Морские места: помечено 100 % воды дальше 2 км от берега (Флорианополис, Рапа-Нуи, учебный остров).
Каспий и Эйсселмер (`edge`) помечаются морем — решение за шлюзом. Озёра — никогда: признак держится на **трёх условиях**, все должны выполниться; озеро, нарушающее хотя бы одно, морем не помечается.

## Признак словами

Вход: `far.webp` (высоты, 1601×1601, 100 м) и `far_surface.webp` (классы 0..8) готового места.

1. Вода far: класс 6, либо класс 0 (нет данных WorldCover — так записан открытый океан) при высоте ≤ 0,5 м.
2. Компоненты воды, 8-связность (края far-квадрата берегом не считаются).
3. Компонента размером ≥ 100 клеток (1 км²) — **море**, если одновременно
   - (уровень) медиана высот far по компоненте ≤ 0,25 м;
   - (край) компонента касается края far-квадрата 160 км;
   - (берег) 99-й процентиль высот компоненты ≥ −1 м: у моря есть вода на уровне берега (Copernicus 0 м; Рапа-Нуи и учебный остров — ровно 0,0, Флорианополис 8,5 м),
     у озера ниже моря всё глубоко (Мёртвое море −366…−350 м, Солтон-Си −70 м). Односторонность «≤ 0,25 м» этим закрыта.
   Помечаются все клетки такой компоненты (устья рек и лагуны, соединённые с морем, тоже; во Флорианополисе 14–16 тыс. клеток воды выше 5 м).

Почему так: озеро выше порога (Ладога 1,0, Мелларен 3,0, Бухтарма 388, Байкал 449, Верхнее 179 м) отвергается уровнем; озеро с любым
уровнем, целиком лежащее внутри квадрата (Мёртвое море −415 м, малые водоёмы у моря с уровнем ~0 — у Мелларена их бухты с h = 0,0 не касаются края), — краем; озеро ниже моря, режущееся краем far (Мёртвое море 31,4/36,35, Солтон-Си), — условием берега.
Ошибка возможна, только если озеро одновременно на уровне ≤ 0,25 м, больше квадрата 160 км и имеет воду на уровне ≥ −1 м (Каспий у Баку: q99 = 0,0, поэтому помечен) — такого в проверенных местах нет.
Высоты как улика: Copernicus над морем ровно 0 м; Terrarium даёт в океане отрицательную батиметрию, которая **доживает до `far.webp`**
(Рапа-Нуи медиана −3042 м, Флорианополис −59 м); у озёр Terrarium почти ничего не даёт (Верхнее ровно 179 м, Байкал 449 м; у Ладоги и Мелларена
есть клетки h < 0 — потому решение по компоненте, а не по клетке).

## Запас по уровню

`level_margin_m` = 1,00 (Ладога: уровень в слое 1,00 м, реально 5 м; порог 0,25 м, то есть до порога 0,75 м). Поле берётся по контракту как наименьший
`level_m` внутренних водоёмов, которые отвергаются только уровнем (касаются края, но выше порога): Ладога 1,0, Мелларен 3,0 (слой даёт 3,0 м, а не 0,7). Озёр между 0,25 и 1 м
в проверенных местах нет. Даже если бы такое озеро лежало в квадрате целиком, его отвергло бы касание края.

## Размыкание проток

Эрозия водной маски на 5 клеток (≈ 1 км) перед разметкой, чтобы озеро, соединённое с морем каналом, не склеивалось с ним, реализована (`OPEN_CELLS` в `sea_mask.py`),
но выключена: на 16 местах результат тот же (в Мелларене озеро и Балтика и без неё разные компоненты), а канал уже ≈ 1 км, цели «море — озеро» не меняет. Включить, если появится склеенный случай.

## Где считать и цена

`build`: новая стадия после `smooth` (нужны итоговые `far.webp` и `far_surface.webp`), результат — файл в папке места (напр. `sea_mask.webp`, L8, 1601×1601, значения 0/255;
сжимается в десятки КБ). При загрузке пришлось бы повторять разметку компонент каждый старт. Замер на Python (numpy, разметка серий в чистом Python): **314 мс**
в среднем на место (по прогонам 110–310 мс, шум от загрузки машины); в GDScript оценка 5–10× больше, то есть ~1–2 с в фоновом потоке стадии (оценка, не замер).

## Границы и допущения

- Истинная вода в морских местах определена тем же шагом 1 (класс 6 или класс 0 при h ≤ 0,5), поэтому «100 %» не ловит сушу, записанную классом «не вода»; берег — расстоянием 2 км до ближайшей не-воды.
- Класс 0 считается океаном: WorldCover не покрывает открытый океан (Рапа-Нуи 2,19 млн клеток класса 0, h от −3485 до 0). Нет покрова вообще (отказ слоя) — `far_surface.webp` не сформируется, признак не посчитать: нужен резерв только по высотам.
- Условие берега требует, чтобы в квадрате видна была вода с уровнем ≥ −1 м: кусок открытого океана без берега (только глубокая вода у края) не помечается. Полоска Средиземного моря на западном краю квадрата 31,5/35,5 помечается: её компонента содержит клетки берега.
- Море целиком внутри квадрата (остров-карлик, закрытая бухта без выхода к краю) не помечается: условие края требует, чтобы вода уходила за край 160 км. Учебный остров и Рапа-Нуи проходят (вода у края).
- Прибрежные реки и лагуны, соединённые с морем, помечаются морем целиком.
- Верхнее: у Terrarium батиметрии Великих озёр в этом месте нет (ровно 179 м).

Данные мест не хранятся (≈90 МБ, в кеше профиля).

## Дальность far против горизонта

far тянется на ±80 км от центра места. Горизонт с 300 м ≈ 62 км (внутри far), с 1500 м ≈ 138 км (far не хватает: за 80 км данных нет).
