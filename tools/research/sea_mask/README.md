# Признак «море»: проверка на данных мест (SEA-1)

## Вывод

Признак работает на 10 проверенных местах (`works = true`), но запас по одному месту тонкий (Ладога, см. «Границы»).
Внутренняя вода: 0 клеток far помечено морем (Бухтарма, Катунь, Ладога, Байкал). Морские места: помечено 100 % воды дальше 2 км
от берега (Флорианополис, Рапа-Нуи, учебный остров). Решение по `edge` (Каспий, Эйсселмер, Мёртвое море) — за шлюзом: признак
помечает морем все три (высоты ≤ 0 по слою), по таблице ниже.

## Признак словами

Вход: `far.webp` (высоты, 1601×1601, 100 м) и `far_surface.webp` (классы 0..8) готового места. Шаги:

1. Вода far: класс 6, либо класс 0 (нет данных WorldCover — так записан открытый океан) при высоте ≤ 0,5 м.
2. Компоненты воды, 8-связность (края far-квадрата не считаются берегом).
3. Компонента размером ≥ 100 клеток (1 км²) с медианой высот far ≤ 0,25 м — море; помечаются все её клетки (включая устья рек и лагуны,
   соединённые с морем; во Флорианополисе 16 341 клетка помеченной воды выше 5 м — это такие рукава/лагуны).

Почему работает: Copernicus над морем ровно 0 м; Terrarium в океане даёт отрицательную батиметрию, и она **доживает до `far.webp`**
(Рапа-Нуи медиана −3042 м, Флорианополис −59 м, Каспий −39 м); озёра и водохранилища лежат выше (Бухтарма 388, Байкал 449 м,
Катунь 947 м). Покомпонентная медиана нужна, чтобы не размечать разрозненные клетки с h ≤ 0,5 внутри озера (у Ладоги
есть участки h < 0 из озёрной батиметрии Terrarium).

## Где считать и цена

`build`: новая стадия после `smooth` (нужны итоговые `far.webp` и `far_surface.webp`), результат — файл в папке места (напр.
`sea_mask.webp`, L8, 1601×1601, 1 бит значения; сжимается в десятки КБ). При загрузке пришлось бы повторять разметку компонент при
каждом старте. Замер на этом Python (numpy, разметка компонент серий в чистом Python): **117 мс** в среднем (80–254 мс) на место;
в GDScript ожидаем порядка 5–10× дольше (оценка, не замер), то есть до ~1–2 с в фоновом потоке стадии.

## Границы и допущения

- **Тонкий запас у Ладоги**: слой даёт ей 1,00 м (в реальности 5 м), порог 0,25 м. Озеро с уровнем слоя ≤ 0,25 м (низкие озёра у моря,
  Эйсселмер, дельты) будет помечено морем. На `edge` это ожидаемо.
- Истинная вода в морских местах определена тем же шагом 1 (класс 6 или класс 0 при h ≤ 0,5), поэтому «100 %» не ловит сушу, записанную классом «не вода»;
  берег проверен только расстоянием 2 км до ближайшей не-воды.
- Класс 0 считается океаном по тому, что WorldCover не покрывает открытый океан (Рапа-Нуи 2,19 млн клеток класса 0, h от −3485 до 0). Нет покрова
  вообще (отказ слоя) — `far_surface.webp` не сформируется, признак не посчитать: нужен резерв (только высоты).
- Учебный остров — синтетика (море 0 м); Рапа-Нуи в слое — одна компонента, не касающаяся края.
- Прибрежные реки и лагуны, соединённые с морем, помечаются морем целиком (в Флорианополисе 16 341 клетка выше 5 м, в Рапа-Нуи 99).

## Воспроизведение

Данные мест собраны из копии (первый запуск — `godot --headless --path . --import`):

    XDG_DATA_HOME=~/.cache/dp-xdg/deltaplan-sea-ships-SEA-1 godot --headless --path . -- \
      "--prefetch=-27.7176,-48.7799;-27.12,-109.35;49.6,83.9;50.79,86.13;60.8,31.5;51.85,104.9;40.35,49.9;52.75,5.35;31.5,35.5"
    git archive feature/training-island data/locations/training_island | tar -x -C <tmp>   # учебный остров, ветку не вливать
    python3 -I tools/research/sea_mask/sea_mask.py --cache <профиль>/Deltaplan/locations --ti <tmp>/data/locations/training_island

Нужны numpy и Pillow (проверено с venv `tools/research/heat_ca/.venv`). Файлы: `sea_mask.py` (признак, проверка, summary), `sealib.py` (компоненты,
расстояние до берега, чистый numpy), `loadplace.py` (чтение слоёв места). Данные мест не хранятся (≈45 МБ, в кеше профиля).

## Дальность far против горизонта

far тянется на ±80 км от центра места (160 км). Горизонт с 300 м ≈ 62 км (внутри far), с 1500 м ≈ 138 км (far не хватает: за 80 км нет данных).
