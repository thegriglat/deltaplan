# cascade-2d: эталоны Пикара (CSD-1)

Случаи F0 для C0–C3 (и C4 — разрез Аскарово) в формате R1 на пяти вложенных сетках и решения `picard_rs`
(`rust/`, без правок) на них. Поля (F1) и случаи — вне git, в `$CASCADE2D_DATA` (по умолчанию `~/data/cascade_2d`,
около 1 ГБ); в git — этот README, скрипты, записи прогонов F2 (`../out/runs/<C>/picard_none_d<dx>.run.json`) и
`convergence.{json,md}`.

## Воспроизведение (≈ 15 мин при пяти параллельных слотах замка; последовательно ≈ 50 мин)
```
cargo build --release --manifest-path rust/Cargo.toml -p picard_rs          # rust/target/release/picard
tools/research/cascade_2d/py tools/research/cascade_2d/cases/build_cases.py        # случаи R1 (CuPy, GPU без замка, ~25 с)
tools/research/cascade_2d/py tools/research/cascade_2d/cases/run_refs.py all       # solve (под замком cpu) + F1/F2 + таблица
```
`run_refs.py solve|convert|table --cases C1,C2 --dx 100,50` — по частям. Венв `py` ставит `cupy-cuda12x[ctk]` (нужен
только сборщику случаев). Для C4 нужна собранная игрой локация `~/.local/share/Deltaplan/locations/askarovo`
(`detail.webp`, Copernicus GLO-30; нет — `build_cases.py --cases C0,C1,C2,C3`).

## Случаи
- Сетка (F0): x ∈ [−6400, 6400] м, dx = 400/2^k, dz = dx/4, `z0 = −dz` (`air3d/synth.py: grid2d`), nz подобрано под
  верх ≥ 2500 м (2500 м при dx 400…, 2506 м при 25 м), nx = 32·2^k, **ny = 4** на всех уровнях (ширина по y = 4·dx).
  Гребень по y постоянен, ветер вдоль +x (`wdir` 270°), стенки по y — `sponge_axes="x"`.
- Параметры физики — `params` случая игры `~/data/air_cascade/ongudai/ongudai_d400_u3_mech_h1200.json` (все ключи
  `Params`), кроме: `sponge_axes="x"`; `max_profile=None` (по правилу z_sat при `alpha=0,112` и U10 случая:
  1,487 / 1,568 / 1,242 для U10 5 / 8 / 1 м/с); `dtau_u=None` → 0,3·dx с (зависит от уровня); `cd` решатель считает
  из `dz` и `z0=0,1` м (зависит от уровня). `taper=True` (как в игре; нагрев C3 гаснет в 2 км у края).
  Фон: C0, C1, C4 — нейтраль (`gam = 0`), C2 — N = 0,01 с⁻¹, C3 — `cbl_gam(1500, 5,8 К/км)`, `z_i = 1500`, солнце
  `sun_flux(az 100°, el 45°)` как `heated_slope`. `sol_*` — нули (эталона, кроме самого Пикара, нет; в случаях нет
  ключа `solution`, поэтому `picard` не считает невязку против «эталона»).
- C4: профиль высот по линии с запада на восток через старт `biyagoda_west` (X = 0 — точка старта), шаг 25 м
  билинейно из `detail.webp`, на грубых уровнях — среднее по блокам 25 м (вложенность); высоты сдвинуты так, что
  минимум разреза = 0 (база 417,7 м н. у. м.). Гребень на X = 62,5 м (646,4 м н. у. м., старт 634,9 м ≈ «~630 м» конфига),
  H = 207,8 м (над минимумом в 3 км против ветра), L = 275 м (наветренная полуширина по H/2); `x_c`, `L`, `H` — в
  `case_params` JSON случая (для M1). Рельеф постоянен по y — это не 3D-рельеф Аскарово.
- M1: C0, C1, C3 — x_c = 0, L = 500; C2 — L = 300; C4 — из `case_params`.

## Метод
`picard solve <случай> --threads 1 --max-iters 3000 --time-budget 7200 --save-state … --out …` под
`dpcli lock cpu cascade-ref` (по одному запуску на случай одновременно, пять случаев параллельно, каждый — один слот
замка). State (R4 v2, MAC-сетка с ореолом) переводится в F1 среднего ряда j = ny/2 = 2 (нулевая нумерация интерьера):
`u[k,f] = U[k+1, j+1, f+1]`, `w[kf,i] = W[kf+1, j+1, i+1]`; решатель разнесённый, нормальные скорости на гранях —
пересчёта не требуют. `tu`, `tw`, `cell` (1 — воздух), `h` — из случая; скорость на стенках (`t = 0`) — 0.
U_ref — |u| P25 в клетке на ~100 м над землёй при x = −4800 м, она же и для остальных уровней того же случая.

### Что важно знать о замках и потоках
Замок `cpu` ставит cgroup `CPUQuota=100%` на один слот. Замер C1 d100: `--threads 8` — 55 с (процесс 53 с CPU, но с
троттлингом), `--threads 1` — 15 с. Поэтому все прогоны — **1 поток** (в задании было 8): время и «один ряд»
сопоставимы с каскадом на одном ядре; результат (итерации, поле) от числа потоков не зависит. Пять прогонов шли
параллельно (разные слоты, 20 ядер, параллельно шёл чужой счёт): два одиночных контрольных прогона C1 d100 дали
59,0 и 62,3 мс/итер против 61,1 в пачке — разброс в пределах 5 %.
Пик памяти — `ru_maxrss` процесса `lock+picard` (`wait4`); у уровней ≤ 200 м это ≈ 31 МБ обёртки `lock`, а не решателя.
`arrays_mb` — размер `.bin` случая + state. `per_row_s` = `work_s/ny`, `work_s = total_s − setup_s`.

## Допущения, границы, находки
1. **Дивергенция среднего ряда ≠ нулю.** Решатель трёхмерный, стенки по y трут (профиль u(j) у стенок меньше фона на 1–10 %), и
   в клетках возникает вторичное течение v ≠ 0 (до 0,13 м/с у C1 d100). Поэтому 2D-дивергенция F1 среднего ряда по
   формуле F1 **не** совпадает с `div_rms` решателя (≈ 1e-6…1e-7 с⁻¹ по 3D): `max rel_div` P-эталона по F1 —
   1e-3…7e-2 (при пороге K1 для каскада 1e-5). F1 среднего ряда — как велит контракт (строка `picard_none_d<dx>.json`).
   Сверка: СКО 3D-дивергенции из state по клеткам воздуха совпадает с `div_rms` решателя (C1 d25: 9,8e-7 против 9,9e-7;
   на крупных уровнях — в разы, пороги критерия 1e-6; в `notes` каждой записи F2 числа `div_rms` решателя, 3D из state, F1 2D, max|div|).
   **Дополнительно** `fields/<C>/ymean/picard_none_d<dx>.{json,bin}` — F1 из среднего u, w, θ′ по всем рядам: для него
   2D-дивергенция равна средней 3D (v = 0 на стенках), `max rel_div` ≈ 3e-7…8e-5 (C0–C4); отличается от среднего ряда на
   `max|Δu|/U_ref` 0,2–10 %, `max|Δw|/U_ref` 0,0–7 % (C3 d400: 26 %, слабый ветер) — числа в `notes` F2. Пользоваться им
   там, где нужна дивергенция-согласованная база (баланс K1), средним рядом — там, где контракт.
2. **Однородность по y** (`y_uniform`, max |f(j) − f(ny/2)|/U_ref по u, w): 0,4–2 % на C0 и растёт с мелкостью сетки и
   с рельефом до 12–20 % (C1/C2/C4 при 25 м, C3 400 м — 0,5 при U_ref = 1,2 м/с). Растёт потому, что ширина по y =
   4·dx сужается, а пристенный слой по y — физический масштаб. Влияние на сам средний ряд оценено на C1/C2 d100
   прогонами с ny = 8 и 16 (ширина ×2, ×4): СКО(u_ny − u_4)/U_ref = 0,8–0,9 % (C1), 1,2–2,2 % (C2), max 4,5–5 % (C1) и 7–15 % (C2). Значит средний ряд ny = 4 грубее оценкой, чем «чистое 2D» на 1–2 % СКО; решение
   `ny = 4` — по заданию (наименьшее, при котором решатель работает; ny < 4 контракт не допускает, ny = 2 не пробовалось).
3. **Время и потоки**: см. выше; цифры — для 1 потока на слот замка, на Xeon E5-2666 v3 (2,9 ГГц, `host.cpu`).
   `per_row_s = work_s/4` — делим на ny, как в F2; реально решатель считает 4 ряда сразу (стенки по y), 1 ряд не считается.
4. **C3 (слабый ветер 1 м/с, нагрев)**: на 400 м `y_uniform` 0,5 и `max rel_div` 0,28 — относительно U_ref = 1,2 м/с
   (его вертикальный масштаб термика сравним с U). Использовать осторожно; 100 м и мельче — 0,03–0,06 и 0,06–0,13.
5. **C4**: профиль из ЦМР 25 м, постоянный по y, без шероховатости леса; P25 сошёлся (560 итераций).
6. **dz = dx/4 на всех уровнях и верх 2500…2506 м** — не одинаковый верх, различие 6 м (грани вложены по x и z).
7. Не проверялось: дальние изменения `Params` (`closure`, `local_k`), число проверок критерия — как в игре.
