# cascade_rs — каскад по граням без состояния (CSD-3)

Исследовательский крейт модуля cascade-2d. Берёт поле родителя (`picard`, P400 или P200, F1) и
спускает его до 25 м, не решая никакой задачи: каждая грань родителя делится на две подграни
(сумма — ровно поток родителя), внутренние грани четырёх детей находятся из баланса массы
каждого ребёнка. Нет шагов по времени и нет состояния: значение в любой точке уровня 25 м
считается по цепочке клеток-предков, а не по всему полю. Варианты V0–V3 и V3h — по карточке плана
(`docs/plan/cascade-2d.md`, «Опыт»). Решатель игры (`picard_rs`) используется только для чтения
файлов случаев R1 (`Case::load`), эталон мельче родителя крейт не читает.

## Схема простыми словами

Сетки вложены (F0): x-грани уровня n — чётные x-грани уровня n+1; z-грани уровня n — нечётные
z-грани уровня n+1 (у всех уровней низ `z0 = −dz`, поэтому нижняя грань родителя у детей
отсутствует; нижняя строка (z < 0) — земля на всех уровнях, её неполное покрытие ничего не меняет;
по F0 ребёнок имеет `2·nz−1` строк, геометрия случая обрезается до этого числа). Дети клетки `(K, I)`: строки `2K−1`, `2K`, столбцы
`2I`, `2I+1`.

1. **Деление грани.** x-грань родителя `u` (скорость, м/с) даёт подграни `u_lo = u − d`,
   `u_hi = u + d`: средняя скорость сохраняется, значит поток через грань — тоже (подграни вдвое
   короче). Для z-грани — `w_l = w − d`, `w_r = w + d`. Если одна подгрань закрыта (стенка на
   мелком уровне), вся скорость `2u` идёт в открытую. `d` зависит только от самой грани, её соседей
   вдоль неё и геометрии — у обеих клеток-соседей результат один и тот же.
2. **Баланс детей.** Четыре ребёнка образуют цикл из четырёх внутренних граней
   (`ub, ut` — x-грани нижней/верхней пары, `wl, wr` — z-грани левой/правой пары). Четыре уравнения
   «сумма потоков ребёнка = дивергенция × площадь» на три независимых (сумма — баланс самого
   родителя) и одну свободу — циркуляцию Γ вокруг центра. Если часть детей в земле или внутренние
   грани закрыты, цикл распадается на дерево или несколько кусков: решение находится
   последовательным снятием листьев, циркуляции нет. В каждом куске у всех детей одинаковая
   дивергенция — средняя по внешнему потоку куска (для целой клетки это дивергенция самого
   родителя; у бездивергентного родителя — ноль), поэтому баланс точен всегда, пока внешний поток
   вообще может пройти (см. «потерянный поток»).
3. **Циркуляция Γ** (одна свободная степень): минимальное по методу наименьших квадратов (в
   скоростях) отклонение внутренних скоростей от целевых `t_e`. V0: `t = 0` (минимальная норма
   внутренних потоков). V1+: `t` — среднее из скоростей двух внешних подграней по разные стороны от
   внутренней грани (билинейная реконструкция внутри клетки), в V3 вертикальные цели умножены на
   множитель Фруда клетки.
4. **θ′ детей.** V0–V2: как у родителя. V3, V3h: `θ′_c = θ′_p + τ_cool·(Q_c − mean(Q детей в воздухе))`
   (мелкий поток тепла Q из случая; среднее родителя не меняется).

## Варианты и формулы

Обозначения: `u`, `w` — скорости на грани родителя, `d` — сдвиг подграни (выше), `s_u`, `s_w` —
наклон вдоль грани по соседним граням родителя (на шаг клетки), `minmod(a,b) = 0` при `ab ≤ 0`,
иначе меньшее по модулю.

| вариант | геометрия детей | деление `d` | Γ |
|---|---|---|---|
| V0 | как у родителя (повтор, земля 400 м) | 0 (0,5/0,5) | мин. норма |
| V1 | как у родителя | `s/4`, `s = minmod(u_k − u_{k−1}, u_{k+1} − u_k)` по открытым граням родителя; нет соседа — 0 | к билинейной реконструкции |
| V2 | **мелкая из случая** (cell, tu, tw) | как V1; закрытая подгрань — поток в другую; обе закрыты — потерян | как V1 |
| V3 | как V2 | V2 + Фруд на x-гранях + тепло на z-гранях | как V1, w×множитель Фруда |
| V3h | как V2 | V3 + хеш грани | как V3 |

V0 и V1 «ничего не знают о земле мельче родителя»: их дети повторяют клетки и типы граней родителя
(`Geo::inherit`), поэтому стенки остаются нулевыми и баланс точен без знания рельефа. Рельеф
мелких уровней появляется с V2 (и тогда выход F1 содержит геометрию мелкого уровня из случая).

**Рельеф (V2+).** Подграни, закрытые на мелком уровне (земля по геометрии уровня), получают 0, вся
скорость грани родителя идёт в открытую подгрань. Скорость у земли `w ≈ U∇h` получается не из
формулы, а из баланса детей: ступень рельефа внутри клетки заставляет поток подняться через
внутренние грани.

**Стенка родителя, подграни открыты (минимальное правило).** Поток родителя через стенку — 0,
значит обе подграни получают 0, даже если на мелком уровне одна из них открыта. Это слабость
метода у земли (предмет исследования): воздух, который на 400 м «в земле», а на 25 м есть,
остаётся стоячим карманом; приток в него и обратный возврат каскад создать не может. Счётчик
таких граней — `wall_parent_open_sub` в `notes` F2 (на синтетическом C1 — 176 из 137 819 граней).
Обратный случай (родитель открыт, обе подграни закрыты) — «потерянный поток» `lost_flux_faces`: масса
пропадает, дивергенция детей остаётся ненулевой, она видна в `balance`. Для синтетической геометрии крейта (грубый
уровень — верхняя огибающая мелких столбцов) счётчик равен 0: верхний ряд детей воздушной клетки всегда воздух.
Для реальных случаев CSD-1 он возможен — проверить по `notes` первого же реального прогона.

**Устойчивость (V3), число Фруда.** `Fr = |u| / (N·dz_n)`, `dz_n` — шаг родителя, `N² = (g/θ₀)·(gam + ∂θ′/∂z)`, θ₀ = 300 К (как `air3d/air.py`), `gam` — фоновый градиент θ̄, К/м, из статического входа случая R1 того же уровня (по строке; ключ `--n-bg` — только переопределение для тестов: `gam = N²θ₀/g`), клетка — среднее по двум клеткам грани. Множитель `g = min(1, Fr/Fr_c)`,
`Fr_c = 1,0` — середина блокирования Fr ≈ 0,8–1,1 (`docs/research/air_phase_results.md`: резкая
ступенька или узкая сигмоида; здесь линейный подъём 0 → 1 — самое простое, не подгонялось). На
x-грани сдвиг `d > 0` (избыток вверх) умножается на `g`, сдвиг вниз не меняется — избыток уходит
в нижнюю подгрань. В циркуляции Γ вертикальные цели умножаются на `g` клетки. Замечание: при
`Fr = U/(N·dz)` и N = 0,01 с⁻¹ правило срабатывает только при |U| < N·dz ≈ 1 м/с (400 м) или
0,25 м/с (25 м) — то есть редко, в основном в застое.

**Тепло (V3), z-грань.** Контраст `T = clamp((θ_R − θ_L)/θ_s, −1, 1)`, θ_L, θ_R — средние θ′ детей по
обе стороны подграни, `d += c_h·|w|·T`, `c_h = 0,5`, `θ_s = 0,5 К`. Для `w > 0` (подъём) больше потока
через тёплую подгрань; для `w < 0` (опускание) — через холодную; сумма не меняется. Правило автомата
(`tools/research/heat_ca/README.md`): тёплое поднимается, плавучесть относительно фона. `c_h` и
`θ_s` — **не измерены**, выбраны так, чтобы предельное деление было 0,25/0,75; чувствительность — в
CSD-4. Без Q (синтетика без нагрева, C0–C2) правило не действует. Единицы Q — К/с (R1: источник
`Q − θ′_d/τ`), равновесие без переноса `θ′ = τ_cool·Q`; грубая верхняя оценка (без переноса).

**Хеш (V3h).** `d += 2·δ_n·σ·ξ`, `ξ ∈ [−1, 1)` — равномерное число из хеша (seed, уровень, тип
грани, положение, splitmix64), `δ_n = δ₀·2^(−n/3)`, `δ₀ = 0,1`, n — индекс мелкого уровня (1 для
400→200). Множитель 2 — перевод «±δσA в потоке» в скорость на подграни вдвое короче. Закон 2^(−n/3):
приращение скорости на масштабе r ∝ r^(1/3) (Колмогоров), масштаб уменьшается вдвое за уровень.
σ — из сдвига родителя по замыканию игры (`docs/guide/air-model/turbulence.md`): `u*_m = l·|∂U/∂z| /
(1 + 5·Ri)`, `l = 1/(1/κz + 1/λ)`, λ = 40 м (для слоя перемешивания до 2,5 км), `σ_w = 1,25·u*_m`,
`σ_u = σ_w·(0,177 + 0,000823·h_ft)^(−0,4)`. На x-гранях σ_u, на z-гранях σ_w. Хеш применяется только
когда обе подграни открыты: сумма сохраняется. Сохраняет ли V3h среднее поле — вопрос для CSD-4;
по построению хеш симметричен (среднее ξ = 0).

## Режимы и побитное совпадение

- **Всё поле** (`descend`): строки родителя считаются параллельно (rayon), результат собирается по
  порядку — результат не зависит от числа потоков (тест 1 и 8 потоков).
- **Опрос точки** (`query`): те же функции правил, но значения грани мелкого уровня запрашиваются
  у ленивого уровня с памятью: грань → клетка-родитель → её грани, соседи вдоль грани и клетки для N, σ
  → родитель родителя … до F1. Один поток. Значения совпадают с полем побитно (`max_abs_diff_vs_full = 0`):
  внутри все вычисления в f64 из значений f32, результат уровня округляется в f32 и дальше читается
  именно таким. Время точки в F2 — **холодное** (цепочка с нуля на точку), тёплое (общая память
  точек) — в `notes`.

## Запуск

```
cargo build --release --manifest-path tools/research/cascade_2d/cascade_rs/Cargo.toml   # под .dpcli/dpcli lock cpu
B=tools/research/cascade_2d/cascade_rs/target/release/cascade
$B selftest                                    # max_rel_div=…, path_vs_full=…
$B descend --parent $CASCADE2D_DATA/fields/C1/picard_none_d400.json --case C1 --to 25 \
    --variant V3 --threads 8 --out-dir $CASCADE2D_DATA/fields/C1
$B query   --parent … --case C1 --to 25 --variant V3h --seed 5 --points 5000 --out-dir …
$B synth-parent --case C1 --dx 400 --u0 5 --noise 1 --out /tmp/p/fields/C1/picard_none_d400.json
$B descend --parent /tmp/p/fields/C1/picard_none_d400.json --case C1 --variant V2 --geom synth-heated \
    --out-dir /tmp/p/fields/C1 --runs-dir /tmp/p/runs        # синтетика, без реальных случаев
tools/research/cascade_2d/py tools/research/cascade_2d/contract/check_contract.py /tmp/p/fields
```
`--geom case` (по умолчанию): мелкие уровни из `$CASCADE2D_DATA/cases/<C>_d<dx>.json` (R1, средний
ряд `j = ny/2`; `hc` — 2D без ореола); `--geom synth|synth-heated`: встроенный холм Агнеси
(`synth.rs`). Ключи: `--n-bg` — фоновая N (1/с), `--seed` — хеш V3h и точки опроса, `--runs-dir`
— куда класть копию F2 (по умолчанию `tools/research/cascade_2d/out/runs` репозитория).
Тесты: `cargo test --release` (8 тестов: баланс всех уровней/вариантов, сумма подграней, общая
грань, локальность деления, 1 и 8 потоков, query == descend, стенки 0, V0 и хеш). Время —
`bench.sh` под замком cpu.

## Выход
F1 каждого уровня `cascade_<V>_d<dx>_from<pdx>.{json,bin}` и F2 `cascade_<V>_d25_from<pdx>.run.json`
(для опроса — `….query.run.json`, `time.work_s` = полное время всех точек). `balance.max_rel_div` —
максимум по уровням; `U_ref` берётся **из родителя** (|u| на грани x = −4800 м, на 100 м над
землёй), эталон P25 крейт не читает; M1 пересчитает по P25. `ny = 1`.

## Результаты самопроверки (синтетика, не реальные случаи)
`cascade selftest`: холм Агнеси C1/C2, родители P400 и P200, бездивергентные (функция тока в узлах:
дивергенция нулевая точно), гладкий и со случайной добавкой, все 5 вариантов, все уровни до 25 м:
`max_rel_div = 3,2·10⁻⁷` (порог 10⁻⁵; остаток — округление в f32), `path_vs_full = 0`.
Время (`results/bench.txt`, 20-ядерный Xeon E5-2666 v3, под замком cpu; поле 25 м ≈ 245 тыс. клеток):
весь спуск 400 → 25 м — 0,03–0,25 с (V0 0,05, V3h 0,13 при 1 потоке; многопоточность на таком
объёме не окупается), одна точка по пути, холодная: V0 4,6 мкс, V1 23, V2 28, V3 25, V3h 36 мкс
(тёплая: 3–15 мкс). Память пика (VmHWM) ≈ 24 МБ. Это синтетика; цифры по реальным случаям — в CSD-4.

## Допущения, границы применимости
- Квази-2D срез: средний ряд случая, y-производных нет.
- Баланс точен только для куска детей, у которого внешний поток проходит; «потерянный поток» и
  нестыковка геометрий уровней дают ненулевую дивергенцию (видно в `balance`).
- Нет инерции и давления: отрыв за гребнем, ротор, волны — только от родителя.
- Коэффициенты правил V3/V3h (`Fr_c`, `c_h`, `θ_s`, `δ₀`, λ) взяты из литературы и игры, не
  подгонялись под эталон; `c_h`, `θ_s` не измерены.
- Не проверено на реальных случаях R1 (CSD-1 ещё не выдал `cases/`): загрузчик `--geom case`
  написан по контракту R1 и `picard_rs::case`, индексация проверена только чтением кода.
- В F1 нет фонового θ̄: `gam` берётся из случая R1 (для родителя — из случая его уровня).
- `Fr` по определению карточки (`U/(N·dz_n)`) срабатывает только при очень слабом ветре.
