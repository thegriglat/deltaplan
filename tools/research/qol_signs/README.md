# QL-5: почему не видно птиц, сколько признаков термика (Q-20, Q-28)

Замер без правок кода игры. Весь путь — настоящий: `main._fly(FlightSettings.defaults())` (место, час 13/15, 15 июля,
26 °C, ветер по умолчанию меню) → поле «фазы + Пикар» на GPU (`air_src != null`, термики `AirThermals`)
или, для сравнения, headless-аналитика. Дальше шагается только `Atmosphere.step(0,2 с)` и свои `BirdFlock`/`DustDevils`
(те же классы игры) из неподвижной точки наблюдения 600 с.

Точки наблюдения: **A** — старт + 300 м над ним; **B** — самая низкая точка рельефа в 4 км от старта (сетка 250 м) + 1000 м.

## Команды воспроизведения

```
# из корня копии; GPU-часть под замком, ~25 мин
tools/dp job --lock gpu start ql5 3300 tools/research/qol_signs/run.sh
tools/dp job wait ql5 3300
python3 tools/research/qol_signs/summarize.py   # (run.sh вызывает сам) -> table_*.csv, summary_numbers.json
```

Файлы: `signs_probe.gd/.tscn` — замер одного места/часа → `out/{gpu,ana}_<место>_<час>.json` (сырые расстояния до птиц
по секундам, ряды фильтра); `summarize.py` — сводка; `table_places.csv` — **таблица 4 места × 2 часа × 2 точки × 2 движка**;
`table_px.csv` — размер птицы в пикселях; `summary_numbers.json` — всё вместе + агрегаты.
Данные (2,8 МБ) — в `out/`, лицензий внешних данных нет (только конфиги и модели репозитория).

## 1. Размер птицы в пикселях

`assets/models/bird.glb`: AABB меша **1,60 × 0,11 × 0,75 м** (размах 1,6 м), масштаб узла и корня 1,0; в `BirdFlock`
MultiMesh-экземпляры без масштаба (`span_m` в конфиге влияет только на запасную сетку) → в мире размах ровно 1,6 м.
Камеры кабины и сопровождения берут один `camera.json fov_deg = 60°` (по вертикали; слайдер 45…100°), кадр 1920×1080:
px = размах / дальность · 540 / tan(fov/2).

| дальность | fov 45° | fov 60° | fov 100° |
|---|---|---|---|
| 300 м | 5,2 px | 4,7 px | 2,4 px |
| 800 м | 2,0 px | 1,8 px | 0,9 px |
| 1500 м | 1,1 px | 0,94 px | 0,5 px |

Дальность, где птица = 2 px: 1043 м (45°), **748 м (60°)**, 362 м (100°); = 5 px: 417 / 299 / 145 м; = 10 px: 209 / 150 / 72 м.
Птица не уменьшается меньше пикселя (LOD/мин. размера нет) — но тёмная точка 1–2 px на фоне гор/неба мерцает и тонет.

радиусу (круг 2,5 км — малая часть круга генерации):

| ongudai 13 / 15 | 1684 / 1505 | 1681 / 1505 | 1021 / 908 | 31 / 29 | 10 / 11 |
| altai 13 / 15 | 1933 / 1811 | 1924 / 1801 | 1148 / 1075 | 28 / 23 | 17 / 17 |

(Для B «всего/сила/огибающая» те же порядки, см. `table_places.csv`.) Прошли фильтр: A ≈ 20, B ≈ 13 (поле GPU), в аналитике 7–9.

Слабое место фильтра — не пороги: сила ≥ 1 м/с проходит 99 %; все термики глубже 210 м (`pass_depth_ok` ≈ `pass_all`).

## 4. Почему пилот не видит птиц

**Главная причина — размер/дальность, а не отсутствие птиц.** Птицы появляются (3 стаи, ~10 птиц), термиков хватает ×3–10, но
стая выбирается по близости к пилоту в круге 2,5 км, и половина птиц дальше ~1,1 км: модель 1,6 м без масштаба и LOD даёт там
1,3–1,4 px. Не меньше 2 px — 11–24 % птице-секунд, ≥ 5 px (хоть что-то различимое) — ≤ 1,5 %. Пилот, летящий в термике, чаще всего
не ближе 150 м (≥ 10 px) к стае: таких птице-секунд 0,2 %.

Вторые причины (числами/по коду):
1. **Лимит `max_flocks = 3`**, 2–5 птиц: всего ~10 точек на круг 2,5 км (~20 км²) — плотность мала; стаи выбираются по горизонтали
   от фокуса, не по тому, где они были бы видны из кадра (направление взгляда не учитывается).
2. **Ширина кадра**: в поле зрения 60° по вертикали (≈ 91° по горизонтали, fov слайдер 45–100°) попадает ≈ четверть птиц; при fov 100°
   дальность 2 px — всего 362 м.
3. **Пугливость**: `flee_radius_m = 40` — ближе 40 м птица уходит (кроме 15 % «компаньонов»), т. е. ближний крупный план редок.
4. **Цвет**: силуэт `(0,16; 0,11; 0,07)` на фоне тёмных склонов; контраст с небом высокий, но 1–2 px мигает (не антиалиасится) — не измерялось.

## 5. Предложения для правок (QL-8/QL-9, не применялись)

Измерено «≥ 2 px» при множителе размаха (пересчёт расстояний из `out/*.json`, fov 60°):

| размах × | дальность 2 px | секунд с ≥ 1 птицей ≥ 2 px (GPU, A / B) |
|---|---|---|
| 1 (1,6 м) | 748 м | 0,51 / 0,47 |
| 2 (3,2 м) | 1496 м | 0,86 / 1,00 |
| 3 (4,8 м) | 2244 м | 0,99 / 1,00 |

1. **Масштаб птицы ×2–3** (орёл 2–2,3 м, гриф до 2,8 м; ×2 — размах ≈ 3 м условно «крупная стая»/запас на контраст) — главный рычаг: ×2 даёт 1,3 → 2,7 px
   при 1,1 км. Физически честнее — стая крупных птиц; но это ценой «неверного размера». Альтернатива ниже.
2. **Мин. размер в пикселях** (шейдер: растить меш так, чтобы размах ≥ 3–4 px, т. е. ×2–3 на 1–1,5 км, на ближних — без роста). Честнее масштаба:
   вблизи размер реален, вдали сохраняется «точка».
3. **Число стай/птиц**: `max_flocks` 3 → 5–6 и радиус выбора 2,5 км → 1,5–2 км с приоритетом термиков перед пилотом/в кадре;
   термиков с запасом хватает (≥ 9 прошли везде).
4. **Порог силы/огибающая** менять незачем: сила ≥ 1 м/с проходит 99 %, огибающая ≥ 0,5 оставляет ~60 %; слотов не хватает, а не термиков.
5. Для Q-28 (признаки термика): в 10 минутах у пилота — 3 стаи, ~5 пылевых вихрей (3 км; по умолчанию лимит 3 одновр.), 60–80 кучевых
   одновременно в 5 км (это самый богатый признак: поле «фазы + Пикар» даёт в 2,6 раза больше облаков, чем аналитика). Пыль и птицы редки.

## Ограничения и неуверенность

- Точка наблюдения неподвижна; пилот движется (≈ 10–15 м/с, за 10 мин — 6–9 км), направление взгляда не учтено → «≥ N px» — верхняя оценка по дальности.
- «Типичный июльский день» = `FlightSettings.defaults()` (15 июля, 26 °C, ветер по умолчанию, `sky = clear`); день с 3 м/с на 10 м. Один сид мира (из конфига),
  без разброса по сидам.
- `field.thermals` включает весь круг генерации (много больше окна 2,5 км), поэтому «всего» — не «видимых».
- Поле заменяет в 600 с только ходом `Atmosphere.step`, без пересчёта GPU-поля в полёте (его делает `Game`, у нас отключён).
- Видимость 1–2 px (мерцание, контраст) — оценка по пикселям, картинки не открывались.

## 6. Повтор после правок QL-8 (мин. размер птицы, 6 стай, хищные птицы)

Что изменено: `bird.gdshader` растит птицу вдали до размаха `birds.min_span_px` = 3 px (размер в px — как в замере:
размах/дальность · (H/2) · P[1][1]; вблизи реальный); `max_flocks` 3 → 6, `radius_m` 2500 → 2000, предпочтение термикам впереди по курсу
(`ahead_bias` 1); до 3 одиночных хищных птиц (`max_raptors`, размах 1,8–2,2 м) в термиках `near_thermals` глубже 760 м,
кружат выше 700 м над источником. Порог силы и огибающая не менялись.

Повтор: `tools/dp job --lock gpu start ql8 3600 tools/research/qol_signs/run.sh` → данные в `out_ql8/` (QL-5 остался в `out/`),
сводка — раздел `qol8` в `summary_numbers.json` (QL-5-числа не тронуты). `summarize.py` считает размер птицы с минимумом

для любой птицы, так что метрика с минимумом сводится к «есть хоть одна птица в 2 км» (доля 1,0 = птицы были каждую секунду);
без направления взгляда, как и в QL-5. Мин. высота хищной птицы над источником в замере 575 м (GPU) — это снижение при уходе
из термика/испуге (планируют вниз), в круге они выше 700 м (тест `test_raptors_high_in_deep_thermals_only`).
Скриншоты (500 и 800 м, птицы — тёмные точки 2–3 px, смазаны дымкой) — `build/screenshots/QL-8/`, `tools/shots/birds_shot.gd`.

Замер сделан при min_span_px 5, итог пересчитан для 3 (`QL8_MIN_PX=3 python3 summarize.py`; симуляция от размера не зависит).

Сырые данные повтора QL-8 (`out_ql8/*.json`, 16 файлов, ~16 МБ) в git не хранятся (в `.gitignore`); лежат локально в `tools/research/qol_signs/out_ql8/`
рабочей копии задачи. Воспроизвести: `tools/dp job --lock gpu start ql8 3600 tools/research/qol_signs/run.sh`, затем `summarize.py`
(сводка — `summary_numbers.json`, раздел `qol8`).

## QL-9: ласточки и пух над молодыми термиками (повтор после ревью)

Замер: `tools/dp job --lock gpu start ql9 3300 tools/research/qol_signs/run9.sh` → `out/s9_gpu_<место>_<час>.json` (~1 МБ, в git), итог — раздел `qol9` в summary_numbers.json.
После ревью: пух поднимается со скоростью воздуха (сила·огибающая − оседание 0,3 м/с), раздувание на экране ≤ 3,5 раза (разрешение глаза ~0,3 мрад), дальность видимости = размер / 0,3 мрад (ласточка ~1,1 км, пух 0,4 км). Результат: признаков за 10 мин в 3 км (минимум по местам) 0,8 (до 6,2; среднее 1,2: altai 1,5, askarovo 0,8, aushkul 1,0, ongudai 1,5). Порог ≥ 3 не достигнут — числа записаны как есть. Проверка «off_thermal» = 0 — это проверка наличия живого термика с силой ≥ порога; геометрическая часть (у оси, до 0,85 радиуса) тривиальна по построению.
