# OBC-5: критерий остановки (г) по истории невязок

Вариант (г) п. 9 плана outflow-bc (Этап 2): по истории невязки (проверка раз в 10 итераций) подгонять
`log r(k) ≈ log(r_∞ + A·ρ^k)` в скользящем окне последних W итераций; стоп «сошлось» — `r_∞` ниже порога игры;
стоп «плато» — `(r(k) − r_∞)/r_∞ < ε`. Данные — `res_hist` 720 записей OB2 (`tools/research/outflow_bc/out/cases.jsonl.gz`,
OBC-3). Новых прогонов нет. Историй SY-12 в репозитории нет (план: проверка на них — в этапе 2), поэтому только корпус OBC-3.

## Воспроизведение

```
mkdir -p build/obc
uv run --no-project --with numpy --with scipy python tools/research/outflow_bc/stopfit/stopfit.py \
  --cases tools/research/outflow_bc/out/cases.jsonl.gz --out build/obc/OBC-5_stop.csv   # ~10 мин на 16 процессах
cmp build/obc/OBC-5_stop.csv tools/research/outflow_bc/stopfit/stop.csv
python3 tools/research/outflow_bc/stopfit/analyze.py --cases tools/research/outflow_bc/out/cases.jsonl.gz \
  --stop build/obc/OBC-5_stop.csv --aux build/obc/OBC-5_stop_aux.csv --outdir build/obc [--W 100 --eps 0.1]
```

Файлы: `stop.csv` — mom_rms, строка на запись × (W, ε) (6480 строк; поля `case_id,variant,u10_in,fr,heat,status,iters,W,eps,k_stop,reason,r_inf,rho,r_at_stop`;
`reason` conv|plateau|none, `k_stop` пусто при none); `stop_aux.csv` — то же для div_rms и th_rms (колонка `res`; th — только если не нулевая во всей истории);
`analysis.json` (все числа ниже), `tables.md`, `max_stopped.csv` (список остановленных max-записей с уровнем невязок и блужданием).
Данные — собственные расчёты проекта (лицензий сторонних нет); код: numpy, scipy (BSD).

## Метод и допущения

- **Порог игры** (в записях не лежит; прочитан из кода, только чтение): `tol_mom_rms 2e-5`, `tol_th_rms 5e-7`, `tol_div_rms 1e-6`
  (`rust/dp-air/src/field/case_build.rs` ~стр. 99–101) × `tol_scale 5` (`rust/picard_rs/src/api.rs` ~252: `crit.tol_* *= opts.tol_scale`;
  dp-air `air/tol_scale = 5`) → **mom 1e-4, th 2,5e-6, div 5e-6**; стоп игры — все три ниже (`solver.rs` ~1314). Сверка по корпусу:
  на последней проверке 461 ok-записей max mom = 9,9995e-5, th = 2,50e-6, div = 1,4e-6 (< порогов) — согласуется.
- Подгонка `scipy.optimize.least_squares` по `log r`, окно = W/10+1 проверок (W=50 → 6 точек, 100 → 11, 200 → 21), `0 ≤ r_∞ ≤ min(окно)`,
  `A ≥ 0`, `0.01 ≤ ρ ≤ 0.999` (ρ — на шаг 10 итераций), 2 старта, аналитический якобиан. Первая проверка с полным окном —
  итерация W+10: **записи, закончившиеся раньше, этим критерием не остановить вовсе** (у ok таких 399 из 461; медиана ok — 10 итераций).
- Правило на каждой проверке: `r_∞ < порог` → conv; иначе `(r−r_∞)/r_∞ < ε` → plateau; первый срабатывший k.
  Для ok остановка раньше `iters` — «ранняя»; при отсутствии срабатывания игра стоит на своём `iters`.
- Основная невязка mom_rms; «все три» (stop_aux) — k = max по трём невязкам.
- Ограничения: поля по итерациям нет — отклонение поля в момент остановки (ложная остановка по полю) **здесь не измерить**; U10 корпуса 0,5–9, штиля нет.

### ok (сошлись по критерию игры, 461)

- Применим только к 62 записям с `iters ≥ 110` (их итераций всего 17130 из 29390); остальные 399 (медиана 10–40 итераций) не затрагиваются.
- Из 62: **58 остановились раньше фактической** — 40 conv, 18 plateau; экономия 9540 итераций (57 % итераций этих 58; 32 % всех итераций ok).
- conv-ранние: `r_at_stop` / порог — медиана 4.4 (0,94–52); k=110 — 3-й квартиль (срабатывание на первой же проверке с полным окном; макс 210), экономия медиана 110 итераций.
  Это прогноз «дойдёт до порога» по ρ окна, а не факт; без поля нельзя сказать, насколько поле на k отличается от сошедшегося.
  Защита `r(k) ≤ 3·порога` оставила бы 12 из 40.
- **plateau-ранние (18) — ложные остановки по критерию игры**: невязка встала (до ε от плато), но игра потом дошла до порога, потеряв 10–790 итераций
  (медиана 95); `r_at_stop` / порог 1,0–13 (медиана 2,9). То есть плато на 1–13 порогах — не обязательно предел, невязка бывает ступенчатой.
- Вывод по ok: (г) на сошедшихся даёт экономию только на медленных (>110 итераций), с ценой ложных остановок у трети остановленных plateau.

### max (не сошлись за 1000, 259)

- Остановлено **258 из 259** (одна — mom и th не вышли на плато), медиана k_stop = 290, экономия против 1000: 179 700 из 259 000 итераций (**69 %**);
  conv — 99, plateau — 159.
- Уровень невязки в момент остановки: mom / порог — медиана 74 (квартили 25–104, макс 201), т.е. невязка стоит на 25–100 порогах, не рядом с ними.
- **Подозрительный класс (блуждание > 0,1·U10): 239 из 258 (92 %)**; `late_spread60_p90 / U10` медиана 0,44 (0,007–11). Только 19 остановленных — с малым блужданием.
  Плато невязки почти всегда = поле блуждает (физика Пикара в слабый ветер), а не поле «тихо дошло». Ранговая корреляция `r_at_stop` и `spread/U10` лишь 0.36 —
  по уровню невязки отличить блуждание в 0,1·U10 от 0,5·U10 нельзя.
- **conv-остановки у max — ложные**: 99 штук при том, что игра за 1000 итераций до порога не дошла (mom ни разу не ниже 0,82 порога, только у 5 записей и ненадолго).
  `r_at_stop` > 3·порога у 97, > 10·порога у 79; ρ упирается в границу 0,99+ у 47 — это экстраполяция плоской/шумной истории (r_∞ ≈ 0 при ρ→1 и A мало).
  Правило «r_∞ < порог» без условия «и сама невязка уже около порога» применять нельзя; нужно `r(k) ≤ c·порог` (c ~ 3) или оценка с доверительным интервалом.
- По всем трём невязкам (stop_aux): max останавливается так же (258/259; conv по всем трём — 73; медиана k 300); держит остановку th вместе с mom, div не мешает.
  Для ok «по всем трём» ранних 58 из 62 — как по mom.

### Класс PR-8 (плато невязки при далёком поле)

В корпусе похожих историй **нет**: у всех max-записей `mom_rms` на последних 100 итерациях — ≥ 1,37 порога (мин. за всю историю 0,82 порога), т.е. плато ВЫШЕ порога
(7e-3 медиана), а не 3,5e-6 ≪ порога как в PR-8 (штиль u0). Минимальный U10 корпуса 0,5 м/с — штиля нет. Следовательно, на этом корпусе (г) не может
«зациклиться на низком плато» — риск PR-8 здесь не проверяется; он проверяется только на штилевых случаях (u0 / U10 < 0,5) этапа 2. В остальном (г) по построению
не отличает «сошлось на низком уровне» от «стоит на низком уровне, но дрейфует» — для обоих r_∞ ниже порога → conv. Условие против этого — сверка с изменением поля
между снимками (п. 9 (а)–(б)), записи OB4 `err_hist`.

## Предварительный вывод (до данных этапа 2)

1. **Что (г) решает по невязке.** Определяет момент, когда невязка перестала падать (plateau): на max это 258 из 259 записей на k≈290 вместо 1000 (−69 %).
   Это надёжный сигнал «Пикар вышел на плато/блуждание», но не «поле сошлось»: 92 % таких остановок — блуждание > 0,1·U10, т.е. после plateau нужен переход (в) на усреднение снимков.
2. **Что (г) не решает.** (i) conv по экстраполяции r_∞ ненадёжен: у max даёт 99 ложных «сошлось»; (ii) на сошедшихся даёт экономию только у ~13 % записей (>110 итераций)
   и 18 из 62 раннее plateau ложны; (iii) окно W=100 не работает на первых 110 итераций; (iv) не отличает размах блуждания.
3. **Нельзя проверить без полей** (этап 2, `err_hist` OB4): отклонение поля в момент остановки от среднего поздних / от сошедшегося; ложные остановки по полю (невязка встала, поле далеко —
   PR-8) — в корпусе нет такого класса при U10 ≥ 0,5; штиль надо добавить; связь `r_at_stop` и ошибки поля.
4. Рекомендация для этапа 2: сравнивать (г) с (а)–(в) на тех же снимках; в (г) использовать только plateau + условие `r(k) ≤ c·порог` для conv, W = 100, ε = 0,1; при plateau ставить признак блуждания и усреднять снимки.
