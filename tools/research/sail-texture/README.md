# SLT-1 — развёртка UV паруса у моделей крыльев

Данные — только наши glb (`assets/models/glider_<id>.glb`, список — `configs/wings/*.json → visual.visual_model`, 49 шт.), внешних данных и лицензий нет.
Воспроизведение из корня репозитория (python3 + numpy, Godot не нужен): `python3 tools/research/sail-texture/uv_measure.py` → `uv_table.json`.
Система координат — как в Godot: Y вверх, нос −Z, правая законцовка +X. UV читаются из glb как есть; Godot при импорте UV **не** переворачивает (проверено `GLTFDocument` на aeros_discus: UV и UV2 совпали с файлом до 1e-5).

## Сводка

Все 49 моделей — одна схема (сборщик `tools/blender/build_gliders.py` + экспорт с `v_gltf = 1 − v_blender`); исключений по раскладке нет, у каждой по одному узлу Sail, одному примитиву, одному материалу (albedo 1024×1024, `texCoord` 0), других мешей с материалом паруса нет.

| Регион | u | v (как в Godot, v=0 — верх картинки) | Направление |
|---|---|---|---|
| верх (2 185 вершин у discus) | 0…1 | **0,5…1** | u=0 у левой законцовки (−X), u растёт к правой; v=1 у передней кромки, v=0,5 у задней |
| низ | 0…1 | **0…0,5** | u=0 у левой (−X); v=0,5 у передней кромки, v=0 у задней |
| карман киля (8 моделей) | 0,52 (константа) | 0,5…1, как у верха | плоскость x=0, v как у верха вдоль корневой хорды |

Модели с карманом киля: apogee, atlas, magic, slavutich_ut, ww_cross_country, ww_eagle, ww_super_sport, ww_ultra_sport. UV2: верх `y∈[0,1]` (=1−t), низ `y∈[−1−cov…−1]` (cov — доля нижнего покрытия, у моделей −1,12…−1,96).

u линейна по x (корреляция 1,000 у всех, u = (x/полуразмах_станции+1)/2), v — доля **местной** хорды, а не глобальный z: линии v=const идут вдоль хорды-сетки с учётом стреловидности, поэтому афинная подгонка (u,v)=A(x,z) даёт невязку до 0,37 — это не ошибка, картинка «повторяет» форму крыла.

Зеркальность при взгляде снаружи, нос вверху экрана (определитель якобиана UV по экрану): **верх — зеркально** (картинка вверх ногами по хорде: нос — нижний край картинки), **низ — не зеркально, но повёрнута на 180°** (взгляд снизу: правая сторона экрана = −X). То есть родная текстура с обеих сторон «лежит» не читаемо; читаемое наложение требует пересчёта UV в шейдере.

Родная область: на каждую поверхность приходится половина картинки 1024×512 px (2:1). Реальная поверхность: размах/средняя хорда (площадь проекции верха / размах) — минимум 4,48, медиана 7,04, максимум 8,45; размах/корневая хорда 2,94…4,88 (медиана 4,24).

## Формула для шейдера (рекомендация, решение — за координатором)

Свою картинку `C` (UV картинки (a,b), b вниз) накладывать по UV1 вершины, без UV2 и без пересборки glb. Нормированные координаты поверхности: `s = u` (0 — левая законцовка), `q ∈ [0,1]` (0 — передняя кромка, 1 — задняя):
- верх (`UV.y > 0.5`, к нему же карман киля): `q = 2·(1 − v)`; из верха и из кармана читать одинаково;
- низ (`UV.y < 0.5`): `q = 2·(0,5 − v)` (v=0,5 → q=0 передняя, v=0 → q=1 задняя).

Варианты:
1. **Одна картинка на обе стороны, читаемая снаружи.** Верх (взгляд сверху, нос вверху): `C(a,b) = (s, q)`. Низ (взгляд снизу, нос вверху, право экрана = −X): `C(a,b) = (1 − s, q)`. Текст на нижней стороне читается слева направо снизу, на верхней — сверху; с кабины (изнутри, снизу вверх сквозь парус) пилот видит низ без зеркала. Нужен выбор по `UV.y` (в шейдере `UV.y > 0.5`) — два ветвления без текстурных выборок лишних.
2. **Только верх** (камера сзади/сбоку-сверху видит верх; пилот под крылом верх не видит) — `q` и `s` по формуле верха, низ — родная текстура. **Только низ** — то, что видит пилот из кабины и камера «сверху вниз» не видит; низ — по формуле низа, верх родной. Выбор: если вид с кабины важнее — низ; камера сзади/снаружи — верх (по умолчанию вариант 1).
3. **Пропорции.** Поверхность вытянута 4,5…8,5 : 1 (медиана 7), квадратная картинка при `(s,q)` на весь парус растянется по размаху в ≈7 раз. Либо (а) растянуть как есть (просто, но искажает), либо (б) **вписать по центру с полями** — взять `a = (s − 0,5)·K + 0,5`, где `K = (размах/ср.хорда)/(w/h картинки)`; при `K>1` вне `a∈[0,1]` поле (родная текстура / цвет паруса). Для картинки 1:1 и медианы 7,04 ширина картинки на парусе ≈ 14 % размаха (≈1,4 м); для 2:1 ≈ 28 %. K зависит от модели — передавать в шейдер uniform'ом из размаха и площади (числа есть в таблице; площадь проекции ≈ площадь паруса `planform_area_top_m2`: 12,5…17,6 м²). Центр симметричен: u=0,5 лежит на оси x=0.
Учесть: v — доля местной хорды, поэтому линии картинки идут по хорде со стреловидностью (не по глобальному z): картинка «обтягивает» крыло, а не лежит плоским листом.

## Допущения и границы применимости

- Классификация вершин по связным компонентам индексной сетки (верх / низ / карман), не по меткам имён; невыявленных вершин 0 у всех 49.
- Взгляд «снаружи» и знак определителя — для модели в нулевой позе; анимация шейдера (смещение по Y) раскладку не меняет.
- Площадь — проекция верха на xz (без учёта кривизны), средняя хорда = площадь / размах.
- Для `cov` и диапазона UV2 использован один glb через Godot; по остальным — чтением файла (все собраны одним сборщиком, диапазоны UV2 совпадают с формулой).

## Побочная находка: UV2 в шейдере паруса

`assets/shaders/sail/sail.gdshader` ждёт `UV2.y`: верх `0…1` (0 — передняя), низ `+2`, `low = step(1.5, UV2.y)`. В Godot (проверено на aeros_discus) приходит `UV2.y = 1 − y_сборщика`: верх `0…1` (**1 − t**: 1 — передняя, 0 — задняя), низ `−1…−1,96`. Следствия: `low` всегда 0 (нижняя обшивка колышется как верхняя, `lower_surface_factor` не действует); `t` в `body`/`te` перевёрнут — вес «тела» максимален у передней кромки, а «задняя кромка» (`te`) — у передней; у низа `t<0` — вес 0. Не проверялось визуально; чинить — отдельным решением (не в SLT).
