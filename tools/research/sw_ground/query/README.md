# SWG-6 — рычаги опроса поля панелей на окнах игры

**Прервано решением пользователя (2026-11-09):** замеры остановлены; не сняты `vert_interp` отдельно (элементное FP64-ядро) и
`panels_rotor` с лучшим сочетанием. `above_ground` отдельно снят (3 повторения), но под чужой загрузкой GPU (99 % util) — его
время (стадия смены ветра 128 с против 94 с у SWG-3) не сопоставимо с SWG-3; доля сэкономленных точек — 18 % (100 м) / 18 % (50 м).

## Что сделано
`fastq.py`: слитое ядро CUDA (поток = точка, FP32 или FP64, координаты сдвинуты в центр окна) для `panel_velocity`;
подмена на время `velocity_jh` (JH и решение остаются как в SWG-3). Дальнее поле — октодерево по центроидам панелей, узел =
монополь + диполь (Барнс–Хат по блокам точек 6·dx; критерий R_узла ≤ θ(d − R_блока)), θ = 0,5 выбран до замера, 0,3 и 0,7 — для зависимости.
Тесты (`test_query.py`): fp64-ядро = `influence.panel_velocity` (1e-9), fp32 ≤ 1e-4, θ→0 = прямой счёт, ошибка монотонна по θ.

## Результат (медианы 3 повторений; полная таблица — `../out/swg-6/tables.md`)
| Окно | Стадия | fp64 (SWG-3) | fp32 | fp32+надземные | fp32+надз.+узлы θ 0,5 | + интерп. по вертикали | Пикар 8 пот. tol 5 |
|---|---|---|---|---|---|---|---|
| 100 м | холодный | 121,8 | 19,2 | 13,6 | 13,9 | 13,4 | 3,1 |
| 100 м | смена ветра | 93,8 | 5,4 | 4,5 | 4,2 | 3,6 | 3,4 |
| 50 м | холодный | 192,7 | 25,6 | 16,4 | 17,6 | 16,5 | 6,2 |
| 50 м | смена ветра | 190,8 | 7,6 | 6,0 | 5,9 | 4,6 | 13,8 |

- Опрос поля (без сборки и LU): 108 → 2,6 с (100 м), 179 → 5,1 с (50 м); холодный старт теперь определяют сборка и LU (10–19 с, под загрузкой GPU).
- **Ошибка** против fp64 на надземных точках: FP32 — rms 2e-7, max_abs 3e-5 м/с, 100 % точек в допуске игры (|Δ| ≤ 0,05 + 2 %|v|).
  Узлы θ 0,7 / 0,5 / 0,3: max_abs 0,36 / 0,15 / 0,03 м/с, rms_rel 2,1e-3 / 8,8e-4 / 2,5e-4; доля вне допуска 2e-3 % / 1e-3 % / 0 (превышение ≤ 0,007 м/с при θ 0,5).
  Интерполяция по вертикали (каждый 2-й уровень выше 300 м): max_abs 0,25–0,36 м/с, в допуске 100 % (округлено).
- Слияние ядра само даёт ×2–3 (fused64: 56 с против 122 с); FP32 — ещё ×3–5. Дальние узлы у fp32 ничего не добавляют: после FP32 опрос быстрее хвоста хоста (JH, `bg`, выбор точек) и LU.
- **Вывод:** годны в игре FP32 и надземные точки (точность не страдает). Узлы θ ≤ 0,3 в допуске, θ 0,5 — в допуске почти везде. **Против Пикара после рычагов:**
  холодный 100 м — 4,5×, 50 м — 2,6×; смена ветра — 1,3× (100 м) и 0,4× (50 м, быстрее Пикара). Для холодного старта остаётся LU плотной матрицы (≈ 10–19 с).

## Границы
GPU общий (чужие задачи до 99 % util и 8–11 ГБ): время с этой загрузкой, разброс в `note` строк. LU сделан на месте (`fastq.lu_inplace`, память GPU) —
невязка `solve` в этих прогонах недостоверна; блок опроса элементного ядра 1·10⁶ вместо 3·10⁶ (числа те же). Ошибка — против fp64 того же окна и стадии; панели
сами по точности против Пикара не сверялись. Сетка панелей ds_min = dx, как SWG-3. Строки fp64/нить/Пикар — копия SWG-3 (variant null → fp64, err null).
