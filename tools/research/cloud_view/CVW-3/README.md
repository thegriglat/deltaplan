# CVW-3: мгла не протекает в небо ступенькой и в дымку облаков

## Что сделано (К2 v3)
- `scripts/game/cloud_whiteout.gd::apply`: при `amount = 0` — исходные параметры (включая режим тумана и параметры глубины) побитно, метаданных нет.
  При `amount > 0` (v = amount — линейно, непрерывна, `v(0)=0`, `v(1)=1`; amount уже сглажен экспонентой `rise_time_s`):
  - небо: `fog_sky_affect = lerp(s0, 1, v)`, `s0` — исходный, если исходный туман включён, иначе 0;
  - **рельеф**: `fog_mode = FOG_MODE_DEPTH`, `fog_density = v` (максимум), `fog_depth_begin = 0`, `fog_depth_end = L`, `fog_depth_curve = p`.
    Доля тумана на расстоянии d: `F(d) = v · smoothstep(0, L, d)^p ≤ v`, насыщения дальнего рельефа при малом amount нет;
  - `L` — `configs/game.json → cloud_whiteout.visibility_m` = 65 м (Кошмидер 3,9/σ, σ ≈ 0,06 1/м — то, что давал v1); `p` = 0,365 — не подбор на глаз, а наименьшие квадраты
    формы `smoothstep^p` к закону Бера–Ламберта `1 − exp(−3d/L)` на (0, L] (`CloudWhiteout.depth_curve()`). Отклонение формы: `F(L) = v` против 0,95·v у экспоненты; у `smoothstep` в нуле нулевой наклон, поэтому
    при d ≪ L доля чуть меньше (глубинный туман Godot другой формы не даёт);
  - цвет тумана — lerp к цвету мглы по amount; метаданные `fog_base`, `whiteout_veil` (К2).
- `cloud_layer.gd`: дымка облаков из `fog_base`; вуаль `_update_veil` каждый кадр, цвет — с множителем света того же кадра (`_light_factors()`, общий с `_update_light`); параметры `veil_color`/`veil_v` — в материале (обе ветки).
- `cloud_raymarch_cs.gdshaderinc` (компоновщик, пара в UBO `VEC_PARAMS`) и `cloud_volume.gdshader` (запасной путь): `col = col·(1−v) + veil_color·alpha·v` после дымки.
- Линейная плотность v1 и геометрическая (промежуточный вариант, отклонён ревью как подобранная) убраны.

## Как мерили
Стенд `tools/shots/cloud_view_edge_shot.gd` (в него добавлена колонка `x_terr_luma` — средняя яркость нижней трети кадра без пикселей облаков), ongudai, часы 13 и 18, режим `game`, вертикальный проход
через основание, `--paths=v --speed=60 --step=6 --vmax=300`, на коде после `task sync` (CVW-4 влит; мгла по рисуемым облакам). `analyze.py`: окно — кадры с `|cam_y − base| ≤ 50 м`
(16 и 8 кадров); `sky_g_step_max` — max |Δ`x_bg_g`|, `other_rgb_step_max` — max по каналам |Δ`x_other_*`|, `terrain_step_max` — max |Δ`x_terr_luma`| между соседними кадрами;
`fog_frac_at_L_amount1` — `amount1.gd` (настоящий конфиг, amount = 1, формула режима DEPTH); `code_commit` — `git log -1 --format=%h -- scripts configs`.

**Исключение в `other_rgb_step_max`.** Опорный «кадр без облаков» (второй SubViewport) в нескольких кадрах выпадает из гладкого хода (`x_nc_luma_mean` 0,2391 → 0,2344 → 0,2404 на первом кадре с amount > 0),
из-за чего маска облаков (`x_mask_frac` 0,656 → 0,753 → 0,658) и `x_other_*` дают одиночный выброс (сырой 0,044). Весь кадр при этом гладок (`luma_mean` 0,33497 → 0,33573 → 0,33682), на PNG
кадры 014/015 не отличаются. Шаги с такими кадрами (отклонение `x_nc_luma_mean` от среднего соседей > 0,003 при штатном ≈ 0,0003) в метрике пропущены; сырое число — `other_rgb_step_max_raw` в `after.json`.
Причина выброса опорного кадра не выяснена (подозрение — первый кадр второго SubViewport после переключения режима тумана).

## Границы модели
- Исходный туман окружения включён (world.json `fog.density > 0`, в игре сейчас 0): при amount → 0+ режим переключается с экспоненциального на глубинный — исходная доля тумана на рельефе теряется скачком
  (в игре туман выключен, не проверялось на стенде).
- `smoothstep^p` аппроксимирует Бера–Ламберта в среднем (ошибка до нескольких процентов доли), не точно.
- `terrain_step_max` 0,0123 при 13 ч — тот же выброс опорного кадра (яркость рельефа считается по пикселям вне маски облаков); без него шаг ≈ 0,003.
