# AN-2: сеть «2,5D-оператор» — реализация (контракты A1–A3)

Код: `model.py` (сеть), `phys.py` (профили, условия, обратное преобразование — единственная `to_physical`), `data.py`
(загрузчик вырезок), `losses.py`, `train.py`, `evaluate.py`, `tests/test_contract.py`. Образцы, повороты, карты и деление —
импорт из `../air_nn_pilot/` (кеш подготовки П2 `prep_dirs` прогона `runs/2026-10-03_p2b`, `split.json`, `config.json`; пилот
не правится). Прогоны — `$AIR_NN_DATA/ann2/runs/<имя>/` (вне репозитория). Результаты проб (малые) — `out/an2/`.
Python — venv пилота (`V=/home/greg/deltaplan-air-nn/tools/research/air_nn_pilot/.venv/bin/python`, symlink `../air_nn_pilot/.venv`).

## Вход сети (A2)
Карты 2D (7, float32, повёрнутая система П2 v4, из карт П2 v3 `prep.maps` — формулы и нормировки там, фиксированные):
`terrain` (hc′ − mean)/1000 м; `heat_flux` d400_H/800 Вт/м² (у решения без нагрева — 0); `slope_along`, `slope_cross` /0,3;
`tpi_2k` /300 м; `tpi_8k` /1000 м; `shelter` Sx /0,3 рад. Карты `x`, `y` П2 **не берутся** (абсолютных координат нет, сеть
свёрточная; признака края области нет — граница видна лишь через нулевое дополнение свёрток). Карты считаются на полной
области 96² и режутся (контекст tpi_8k и Sx — из всей области, а не вырезки). Воды и z0 в данных П1 нет (решатель — z0 = 0,1 м
везде, воды нет) — карт воды/z0 пока нет; когда у решателя появятся, добавятся каналами (версия A2 +1).
Профиль притока (вход 1D энкодера, `phys.profile_input`, 13 уровней П1, (3, 13)): U(η)/10 с U = U10·mp·min((η/z_sat)^α, 1),
z_sat = 10·mp^(1/α) (как решатель); θ̄(η)/5 К — фон решателя: dθ̄/dz = 3 К/км ниже 3500 м над морем, 6 К/км выше, от
среднего рельефа случая; log(η/25)/log(80). Фон решателя один для всех случаев (Cond.gam_*) — отсюда «стратификации почти нет».
Скаляры (21, `phys.scalars`): 18 чисел FiLM П2 (U10/10, cos r, sin r, α, mp, z_i, z_lcl, sun_el, sun_x, sun_y, heat, t_max,
stab, cap_flag, cap_agl, hour, brk, t_air — нормировки `prep.film`), dx/400 − 1, признак «нагрев» (heated), Fr⁻¹ = N·σ_h/max(U10, 1)
(N² = g/θ0·3 К/км; σ_h — СКО рельефа окна, считает сеть из карты — работает на любом окне). Решение без нагрева `m` — образец
с нулевой картой потока тепла, heated = 0, числами нагрева (z_i, z_lcl, солнце, heat, cap, hour, brk, t_max, t_air) = 0 и
маской на θ′ (в данных у `m` нет θ′: 3 канала; метаданные это подтверждают).
Высота η: непрерывная, м над рельефом клетки; обучение — лог-равномерно в [25, 2000] м по колонке (K = 4 высоты на колонку за
шаг), цель — линейно между уровнями П1.

## Выход (A2), порядок каналов `phys.OUT_NAMES`
`du_par`, `du_perp`, `w` — в долях max(U(η), 1 м/с) (U(η) — приток на этой высоте; du — отклонение от профиля притока; компоненты
по осям x′, y′ повёрнутой системы), `theta` — θ′, К (без масштаба), `logsig_*` — log σ по каждому из четырёх. σ² = σ_floor² +
exp(2·raw), пол 0,005 доли U (≈ шум решателя 0,01 м/с) и 0,02 К. Обратное преобразование — `phys.to_physical` (м/с, К, исходная
система); тест сверяет с `prep.to_physical` П2 (разность 4·10⁻¹⁵).

## Сеть
ConvNeXt-энкодер-декодер (каналы 32/64/128/192 на масштабах 1, ½, ¼, ⅛; блоки dw7×7 + LN + FiLM + MLP), узкое место — 2 слоя
внимания по грубым токенам (карта ⅛, не больше 12×12: 64² → 8², 96² → 12², шире — усреднение до 12², поправка билинейно
обратно; позиции — depthwise 3×3 по сетке токенов), карта признаков F = 64 канала; 1D энкодер профиля (2 свёртки + MLP) +
скаляры → вектор условий 128 (FiLM каждого блока и смещение головы); голова колонки — MLP 128 из (F(x,y), условия, Fourier(η),
U(η), θ̄(η), η) → 8 выходов. 3,05 М параметров (`python model.py --count` → `params_M 3.045`). Карта любого размера (кратного 8
или с реплицирующим дополнением).

## Потеря и обучение
NLL Гаусса по каналам с масками (веса каналов 1, 1, 1, 0,5), записанная как ½z² + log(σ/σ_floor) ≥ 0 (константа — для осмысленного
отношения потерь; градиент тот же) + `div_w`·штраф дивергенции массового потока: анельастика ρ ∝ exp(−z/8,5 км),
D = ∂x′u + ∂y′v + ∂ηw − w/H по паре высот (η, 1,15η) на вырезку, нормировка D·dx/max(U, 1) (члены наклона рельефа опущены —
малый вес 0,02 по умолчанию). AdamW (lr 1·10⁻³, wd 0,05), разогрев 3 %, косинус до 2 %, bf16 autocast, EMA 0,999, обрезка
градиента 1. Аугментации: вырезка 64² случайного положения из 96², отражение поперёк ветра (`prep.reflect`, правила П2 v4,
вероятность ½), решение h/m с вероятностью ½.

# AN-3: пилотный прогон на всём наборе П2 и оценка против P2

**Поправка подачи θ̄(η).** В AN-2 θ̄ бралось как «3 К/км ниже 3500 м, 6 К/км выше» (по умолчанию `air3d` Cond). Проверка: решатель в
данных П1 берёт профиль из `weather.Day.gamma` случая (`film_bg.py` П2), он разный у каждого случая — нейтральный слой перемешивания
(0 К/км) до z_i, ночная инверсия до 14 К/км, 5,8 К/км выше. Фон 3/6 К/км не совпал ни у одного случая (по 6210 случаям кеша П2:
θ̄(2000 м) − θ̄(0): медиана 1,2 К, максимум 11,6 К). Исправлено: `bg_theta.py` восстанавливает `Day` (как P3E6, сверка с `day` метаданных —
0 расхождений) и интегрирует γ от среднего рельефа на 13 уровнях П1 → `$AIR_NN_DATA/ann2/bg_theta.npz` (не в git); `phys.bg_theta_of(meta)`
→ канал θ̄ 1D энкодера; голова колонки берёт θ̄(η) линейной интерполяцией этого же канала (`phys.theta_interp`, `model.decode(…, prof)`).
Формы тензоров не менялись, контрактный тест зелёный. Не исправлено: Fr⁻¹ в скалярах считается по N фона 3 К/км (`phys.N2_BG`), а не по
N случая (в `film_bg.npz` P3E6 есть N_bl и Fr).
