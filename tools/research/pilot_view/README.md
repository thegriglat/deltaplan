# PV-1: геометрия лёжа и вид из кабины

Задача PV-1 модуля pilot-view. Повод — отзыв пилота-тестировщика (08.10): пилот висит слишком высоко (нужно 2-3 дюйма = 5-7 см над базовой штангой), штанга и носовые тросы не видны из кабины. Выход — предложение для A3 v8 (`proposal.json`) и скрипт без Godot (`cockpit_view.py`).

## Вывод

1. **Причина «трапеция за камерой» — не один параметр, а три.** (а) База под плечами (A3.1), плечи на 0,35 м впереди подвески, глаза на 0,27 м впереди плеч: штанга на 0,29 м позади плоскости глаз. (б) Смещение камеры `cockpit.offset_m` (0; 0,12; −0,15) выносит камеру ещё на 0,15 м вперёд и на 0,12 м вверх относительно глаз модели. (в) Зазор 0,34-0,43 м вместо 0,06. Итог сейчас: штанга 112-120 градусов от оси взгляда, носовые тросы видны только при FOV 78-164 (медиана 135).
2. **Один лишь зазор 0,06 м не помогает**: штанга по-прежнему за плоскостью глаз (118 градусов у apogee); видна 0 крыльев из 48 при любом FOV.
3. **Физика руки при зазоре 0,06 м требует штангу впереди плеч.** Плечевой сустав тогда на 0,244 м выше оси штанги; сегменты руки 0,26 + 0,38 м. Штанга под плечом = локоть ~40 градусов (A3.2 допускает от 55). При локте 90-150 градусов штанга на 0,40-0,57 м впереди плеч (рекомендую 0,50, локоть ~120 градусов). Согласуется с общим описанием («arms out holding the control bar Superman style»), но прямого измерения в источниках нет (см. «Где источники расходятся»).
4. **Это означает наклон стоек 27,7-32,6 градуса** (сейчас 5,9-13,0; допустимо 4-13) - **A1 меняется**, и сдвигать пилота назад нельзя (центр масс 85 кг на 0,5 м позади подвески ломает трим). Следствия: центр масс крыла по трубам уходит вперёд на 0,046-0,059 м (aframe_cg.py) - у cg-крыльев подвеска едет с ним, у passport-крыльев ЦМ оказывается на ~5 см впереди подвески (проверка поляр/тримов - шлюз A3.4). Решение A3.1 («база под плечами», решение пользователя 05.10 по фото points.png) этим пересматривается; ранний вариант проекта (до AF-1) имел базу на 0,55 м впереди плеч и наклон 24 градуса.
5. **Параметры пилота**: только опустить пилота на 0,275-0,374 м (медиана 0,325): `pilot_eye[2]` -0,937 → -1,262, `hang_length_m` 1,211 → 1,536, `body_below_hang_m` 1,137 → 1,462. Положение пилота берётся из `pilot.glb` (пересборка `build_pilot.py`); в физике полёта эти ключи не читаются. Глубина оси штанги под подвеской разная у крыльев (1,56-1,66 м), поэтому общее число даёт зазор 0,011-0,110 вместо 0,06 - решение координатора (длина подвески по крылу или подгонка длины стоек).
6. **Камера и FOV**: смещение камеры [0; 0; 0] (в глазах модели), взгляд на 10 градусов вниз, `fov_deg` по вертикали 90 (16:9 = 121 градус по горизонтали, около binocular поля человека; слайдер 45-100 это покрывает). Тогда центр штанги и носовые тросы видны при FOV 72-96 по всем 48 крыльям, 44 из 48 - при FOV <= 90.

Что требует какого шлюза: зазор и положение пилота по вертикали - физика маятника/визуал (`pilot.json`, `pilot_eye`); вынос штанги вперёд - A1 (наклон стоек), шлюз; камера и FOV - `camera.json`, не физика.

## Скрипт cockpit_view.py

Те же данные, что у игры: `glider_params.json` + `aframe_geom.py` (точки трапеции), `aframe_trim.json` (тангаж киля на триме), `pilot_eye`, `configs/pilot.json`, `configs/camera.json`. Камера = `pilot_eye` + `cockpit.offset_m` в осях крыла; голова держит горизонт мира по тангажу (как `_level_head`), взгляд на `-look_down_deg`. Носовой трос - от угла штанги к носовому узлу (на 0,05 м позади носа, как в `build_gliders.py`). Видимость - модель точечной камеры: точка в кадре, если `max(|y/z|, |x/z|/аспект) <= tan(vfov/2)`; `min_vfov_deg` = max(для центра штанги, для ближайшей к кадру точки носового троса). Центр штанги за плоскостью глаз (z <= 0) - не виден при любом FOV (`visible_at_any_fov: false`, `min_vfov_deg: 180`).

Сверка с игрой (`tests/game/test_cockpit.gd`, текущая ветка, взгляд вперёд, FOV 75; файл `game_test_cockpit_current.txt`): угол от оси до ближайшей точки хорды штанги - игра / скрипт: apogee 110,8 / 112,6; training 111,5 / 112,1; sport 111,0 / 111,9; laminar 110,9 / 111,7. Взгляд вниз 90 градусов, угол до центра штанги: 29,8 / 27,8; 29,3 / 27,7; 25,3 / 23,9; 27,1 / 25,9. **Расхождение 0,6-1,8 градуса, скрипт систематически даёт штангу чуть дальше/ближе на ~1-2 градуса**: в игре через 12 с полёта пилот и крыло не в точном трим-положении (сглаживание позы, тангаж не равен таблице), поэтому скрипт даёт геометрию трима. Для решения (штанга на 45-65 градусов ниже оси) этого достаточно.

Прежний ручной расчёт AF-2 (114-115 градусов) совпадает по порядку с 112 в тесте (тогда ещё другое смещение).

### Воспроизведение (из корня репозитория, python3 + stdlib, без Godot)

```
python3 tools/research/pilot_view/cockpit_view.py --wing apogee --json        # текущая игра
python3 tools/research/pilot_view/cockpit_view.py --all                       # таблица по крыльям (текст)
python3 tools/research/pilot_view/cockpit_view.py --all --json > all_wings_now.json
python3 tools/research/pilot_view/cockpit_view.py --all --json --gap 0.06 --bar-fwd 0.50 --cam 0 0 0 --look-down 10 > all_wings_proposed.json
python3 tools/research/pilot_view/cockpit_view.py --all --json --gap 0.06 --cam 0 0 0 --look-down 10 > all_wings_gap_only.json
python3 tools/research/pilot_view/cockpit_view.py --wing apogee --gap 0.06 --bar-fwd 0.50 --cam 0 0 0 --solve   # подбор наклона взгляда
```
Параметры: `--gap` (зазор низ тела - верх штанги, пилот сдвигается по вертикали), `--bar-fwd` (вынос штанги вперёд от плеч; пилот сдвигается по y, а `upright_tilt_needed_deg` показывает, какой наклон стоек дал бы то же без сдвига пилота), `--cam X Y Z`, `--look-down`, `--aspect`, `--solve`, `--max-look-down`. Сверка с игрой: `godot --headless --path . res://tests/run_tests.tscn -- --filter=test_cockpit` (после `godot --headless --path . --import`, с временным `XDG_DATA_HOME`).

- Wikipedia «Hang gliding»; hghistory.to1.uk (ход штанги ~48 дюймов, «Superman style»); Finsterwalder; US10604250; Wikipedia «Visual field» (70 вверх, 80 вниз); калькулятор vFOV.

## Где источники расходятся / не уверен

- **Явного источника «штанга на X см впереди плеч» нет.** Вынос 0,40-0,57 м - расчёт кинематики руки при зазоре 0,06 (длины сегментов из кости pilot.glb, не из антропометрии первоисточника: коэффициенты Drillis-Contini по памяти, не проверены). Фото-подтверждение (POV, форум «basebar is in my face») недоступно: форум hanggliding.org отдаёт 403, POV-поиск ничего не дал. Нужен независимый взгляд пилотов (мама/папа): где штанга относительно подбородка на триме.
- **Зазор.** Руководство CG-1000: 5-10 дюймов; Wills Wing: «как можно ближе»; тестировщик: 2-3 дюйма. Нижняя граница руководства 12,7 см > 5-7 см тестировщика. Принято 0,06 как решение пользователя; измерять «верх штанги - низ подвесной системы» или «до груди» - у производителей по-разному.
- **Глаза.** `eye_from_shoulder` [0,27; 0,105] - число модели; стоя глаз выше сустава плеча на ~0,21 м; для лёжа независимого источника нет.
- Применимость: геометрия сагиттальная, трапеция в нейтрали (pilot_shift = 0), горизонтальный взгляд головы без крена; без перспективной дисторсии и без экранных элементов; носовой трос - прямой отрезок от угла штанги к носу.
