# Опыт 5. Чередующиеся прогонки по линиям (ADI) до установившегося поля автомата

Вопрос: можно ли получить установившееся поле клеточного автомата тепла и массы (`../model.py`) не
тысячами шагов по времени, а раундами неявных прогонок по линиям: в 2D 4 прохода на раунд (вверх/вниз
по столбцу, вправо/влево по слою), в 3D — 6; каждый проход — прогонка Томаса вдоль всех линий сразу
(на GPU — поток на линию), и для тепла, и для импульса, и для массы/давления.

Итог коротко: **да, и к точно той же неподвижной точке, что у автомата**; 100–190 раундов до 1 % на
клетках 200–25 м (сценарии 1 и 4), в 9–23 раза быстрее шагов по времени на GPU. Главный ускоритель —
не сами прогонки, а крупный псевдошаг тепла: медленная мода задачи — выхолаживание τ = 2 ч.
Подробно — `summary.md` (если нет — текст в отчёте координатору), таблицы — `out/tables.md`.

## Что решаем (та же дискретизация, что у автомата)

Невязки считаются **кодом самого автомата** (`adi5.ADI5.heat_residual`, `mom_force`): полулагранжев
перенос импульса с тем же dt, вязкость с теми же краями, губка, перенос тепла «откуда дует»,
теплопроводность по отклонению от фона, выхолаживание τ. Неподвижная точка шага автомата:

- тепло: −∇·F(u, θ) + нагрев − θ′/τ = 0, F = u·θ(«откуда дует») − κ∇θ′;
- импульс: G(u, θ′) − ∇p = 0, G = [(SL_dt(u) − u)/dt + ν∇²u + b(θ′) − губка·u]/(1 + dt·губка);
- масса: ∇·u = 0 на каждой клетке.

Проверка: невязки на эталоне «8 ч шагов» ~10⁻⁷ (т. е. код невязок = автомат); автомат, запущенный с
найденной прогонками неподвижной точки, за 2 ч модели уходит от неё на ≤ 4·10⁻⁴ (`out/fixed/fixed.json`).

## Схема раунда (`adi5.py`, `line_poisson.py`)

Коррекция по невязке (defect correction) + неполная проекция, «SIMPLEC в псевдовремени»:

1. тепло: δθ = (1/Δτ_θ + A_h)⁻¹R_h — прогонки по столбцам, затем по слоям (3–10 раз);
2. импульс: δu = (1/Δτ + A_u + S)⁻¹(G − ∇p) для u и w, плавучесть — из нового θ; S — неявная
   плавучесть (дополнение Шура связи w ↔ θ: подъём на δw приносит воздух холоднее на Γ·δw/P_h);
3. масса: ∇·(d_f∇φ) = ∇·u*, d_f = 1/(1/Δτ + S), u = u* − d_f∇φ, p += φ — тоже прогонками:
   - `adi`: Писмен–Рэчфорд на одном уровне, 8 пар прогонок со сдвигами (геометрический цикл) на раунд;
   - `lmg`: «зебра»-прогонки (столбцы, затем слои; линии одной чётности независимы) как сглаживатель
     на уровнях d, 2d, 4d, …, билинейная интерполяция поправки (V-цикл, 2 на раунд);
   - `mg`: многосеточный решатель автомата (точечный Гаусс–Зейдель) — только для сравнения.

A_h, A_u — «против течения» + диффузия (+1/τ, губка), только предобусловливатель: точность задаёт
невязка, поэтому их неточность (upwind вместо полулагранжева, отброшенные связи) неподвижную точку не
сдвигает. Прогонка — одно ядро CUDA (`adi5._thomas_kernel`: поток на линию, прямой ход и обратный
внутри), раунд — один CUDA Graph.

Выбранные варианты (`exp5.config`):

| Вариант | Δτ импульса | Δτ_θ тепла | прогонок тепла на раунд | давление |
|---|---|---|---|---|
| `implicit_steps` — «неявные шаги» | 100 с | 100 с | 3 (200/100 м), 6 (50 м), 10 (25 м) | `lmg`, 2 V-цикла |
| `lines_mg` | 20 с | 4000 с | то же | `lmg`, 2 V-цикла, неявная плавучесть |
| `lines_adi` | 20 с | 4000 с | то же | `adi`, 8 пар прогонок, неявная плавучесть |

## Как воспроизвести (из `tools/research/heat_ca/exp5_adi`)

```bash
PY=../.venv/bin/python
$PY ref8h.py                  # эталон: 8 ч без досрочной остановки (+ до 10 ч, снимки каждые 10 мин) → out/ref8h/, out/ref8h.log
$PY fixedpoint.py             # точная неподвижная точка прогонками + проверка автоматом → out/fixed/, out/fixed.log
$PY exp5.py sweep             # подбор, стадия 1 (один Δτ на всё) → out/sweep.json, out/sweep.log
$PY exp5.py sweep2            # подбор, стадия 2 (Δτ_θ ≫ Δτ, неявная плавучесть) → out/sweep2.json, out/sweep2.log
$PY exp5.py main              # s1, s4 × 200/100/50/25 м × 3 варианта (истории ошибок) → out/main.json, out/main.log
flock /tmp/heat_ca_gpu.lock $PY exp5.py timing       # мс/раунд и мс/шаг (200…6,25 м) → out/timing.json
flock /tmp/heat_ca_gpu.lock $PY bench_thomas.py      # прогонок на раунд, нс/точку ядра → out/thomas_bench.json
$PY figs5.py                  # все картинки + out/tables.md, out/tables.json, out/automaton_curves.json
```

Стадия 1 подбора (`sweep`) считалась кодом до перестановки порядка в раунде; её конфигурации без
`schur` воспроизводятся текущим кодом тем же порядком (`order="heat_first"`, по умолчанию); с
`schur=True` — это нынешний вариант `schur="ph"`. Эталон `out/refs` базы только читается (в таблице
«старый эталон»).

- `rounds_lines_adi.png`, `rounds_lines_mg.png`, `rounds_implicit_steps.png` — **ошибка против числа
  раундов по размерам клетки** (сплошные — к неподвижной точке, пунктир — к эталону «8 ч»);
- `time_50.png`, `time_25.png` — ошибка против времени GPU: шаги по времени и три варианта прогонок;
- `sweep.png` — подбор: при общем Δτ раунды·Δτ ≈ 30 000 с (итерации идут «физическим временем»),
  инверсия не терпит Δτ > 100 с; с Δτ_θ ≫ Δτ и неявной плавучестью — 60–190 раундов;
- `fields_s1_sun_one_slope.png`, `fields_s4_inversion.png` — поле прогонок (w, θ′) и разность «эталон 8 ч
  минус неподвижная точка»: эталон всюду в долине холоднее на ~0,008 К —
  не досчитанный медленный прогрев (мода выхолаживания τ = 2 ч).

Самые показательные для статьи: `rounds_lines_adi.png`, `time_25.png`, `sweep.png`, `fields_s4_inversion.png`.

- `adi5.py` — невязки автомата, предобусловливатели, прогонка (ядро CUDA, «зебра»), раунд, CUDA Graph;
- `line_poisson.py` — уравнение массы прогонками: Писмен–Рэчфорд и многоуровневые прогонки;
- `ref8h.py`, `fixedpoint.py` — эталоны; `exp5.py` — прогоны и замеры; `figs5.py` — картинки/таблицы;
  `bench_thomas.py` — пропускная способность прогонки (для оценки 3D);
