# Опыт 4: установившееся поле проходами по слоям (матрицы перехода)

Идея пользователя: считать установившееся поле автомата тепла и массы не тысячами шагов по времени,
а проходами слой за слоем: «состояние слоя k+1 = M_k · состояние слоя k (+ нагрев у земли)», проход
вверх и проход вниз. Итоги, таблицы, вердикт — `summary.md`. База прототипа — `../README.md`,
`../out/summary.md`; эталонные поля — `../out/refs/` (только чтение).

## Файлы

| Файл | Что это |
|---|---|
| `model.py`, `plots.py` | копии базы (геометрия, маски, фон, нагрев, эталонный автомат, метрики) — без изменений |
| `steady4.py` | стационарная невязка автомата F(x) (те же операторы, что `HeatCA._step_impl`, без времени) и двухпроходный решатель: гармоники по x + блочная прогонка 4×4 по слоям (матрицы перехода); ускорение Андерсона (CPU/CuPy, для отладки); опыты с прогонками тепла; последовательность сеток |
| `gpu.py` | тот же повтор целиком на GPU: ядро двух проходов (поток на гармонику, цикл по слоям), переходы в гармоники своими ядрами умножения, Андерсон на устройстве, CUDA Graph (по графу на ячейку кольца истории) |
| `run4.py` | прогоны: длинный эталон, точность/сходимость, время (под замком), тёплый старт, картинки, таблицы |
| `figs4.py` | картинки и таблицы |
| `out/` | всё, что посчитано (см. ниже) |

## Как воспроизвести (все команды — из этой папки)

```bash
cd tools/research/heat_ca/exp4_transfer_sweeps
PY=../.venv/bin/python                     # общий venv прототипа (numpy, matplotlib, cupy-cuda12x)

$PY run4.py refs_long      # автомат базы до 12 ч модельного времени, 4 сценария × 200/100/50/25 м
                           #   → out/refs_long/<сценарий>_<клетка>.npz (≈ 10 мин на RTX 4070 SUPER)
$PY run4.py accuracy       # проходы: до 600 повторов, снимок раз в 5 → out/results/*.json, out/fields/*.npz
flock /tmp/heat_ca_gpu.lock $PY run4.py timing     # время на GPU под общим замком → out/timing.json
$PY run4.py warm --cells 50,25                     # тёплый старт → out/warm.json
$PY run4.py figs           # out/flow_*.png, out/err_*.png, out/convergence.png, out/time.png,
                           #   out/transfer_matrices.png, out/iterations_s1_sun_one_slope.mp4
$PY run4.py tables         # out/tables.md (вставлены в summary.md)
```

Параметры по умолчанию (все картинки и таблицы — с ними): `--mem 64` (память Андерсона),
`--iters 600`, `--stop 3e-7` (остановка по ‖f‖ₛₖ — пол float32), float32 на GPU, регуляризация
малой системы Андерсона 1e-8 (после масштабирования столбцов), «якорь» давления гармоники m = 0
`1e-4/ν`. «Сошлось» — w, u, θ′ отличаются от окончательного решения меньше 2 % (L2 по воздушным
клеткам) и дальше не выходят. Физика и параметры — ровно как у эталона (`Params()` базы: ν = κ = 30 м²/с,
τ = 2 ч, губки, нагрев), подгоночных множителей нет.

Отладочный путь на CPU (numpy, float64):
```python
from model import SCENARIOS, Params
from steady4 import SteadyOp, anderson
op = SteadyOp(SCENARIOS["s1_sun_one_slope"], Params(cell=100, device="cpu"))
x, hist = anderson(op, op.x0(), 150, mem=40)
uc, wc, th = op.centers(x)
```

## Что в out/

- `results/<сценарий>_<клетка>.json` — история сходимости (ошибки против окончательного решения и
  эталона на каждом снимке), число повторов до 1/2/5 %, метрики (`plots.metrics`) проходов и эталона;
- `fields/<сценарий>_<клетка>.npz` — поля проходов (uc, wc, th на момент «сошлось» и окончательные),
  снимки по повторам (для анимации);
- `refs_long/` — автомат, досчитанный до 12 ч (эталоны `../out/refs` остановлены на ~3,5 ч и ещё
  дрейфуют: 4–6 % по w, 10–17 % по θ′);
- `timing.json`, `warm.json`, `tables.md`, картинки `*.png`, анимация `iterations_*.mp4`.
