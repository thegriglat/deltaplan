# Паспорта дельтапланов: сводный набор данных

Из страниц/PDF производителей и карточек DHV (разбор LLM Haiku, JSON с цитатами) собран единый набор по моделям и размерам. Список моделей для людей — `docs/research/glider_models.md` (генерируется этим же скриптом).

## Воспроизведение

```
cd tools/research/data/wing_passports
python3 consolidate.py        # только стандартная библиотека; ~1 с
```
Вход: `out/haiku/*.json` (68 файлов: страницы и PDF производителей; `ww__placard.json` — плакаты Wills Wing, `ww__polar_data.json` — точки поляр), `out/haiku_dhv/*.json` (15 пачек карточек DHV Geräteportal; парапланы пропущены при разборе). Для признака «Wölbklappe» и списка кандидатов читаются, если есть локально, `out/text/*` и `raw/dhv/index.json` (в git не лежат; PDF и тексты не храним — см. `sources.md`, `fetch_*.py`).
Выход: `wings_merged.json`, `wings_merged.csv`, `wings_geometry.json`, `polars_points.json`, `consolidate_stats.json`, `../../../../docs/research/glider_models.md`.

Схема сырья: `parse.py` (строки 15–35), источники: `sources.md`, промпт разбора DHV: `haiku_prompt.md`.

## Что делает consolidate.py

- Производители нормализуются (`norm_mfr`: Wills Wing / Wills Wing Inc. / «Inc. (Alt)», Moyes / … Pty Ltd, AEROS Ltd. / Aeros, Icaro / ICARO / Icaro 2000 s.r.l. / Laminar, A.I.R. (Rühle, исправлена двойная кодировка UTF-8), Bautek, Airborne / AIRBORNE WINDSPORTS, Seedwings, Ellipse, Flugsport Skypoint, Delta Flugschule Condor, DesignProducts).
- Модели (`norm_model`) приводятся к (семейство, версия, размер): «Litespeed RX TECHNORA-5» = «Litespeed RX 5» → семейство Litespeed RX, размер 5; «Combat L12 07 LW», «Combat-L 12 07» → семейство Combat L, размер 12, год модели 2007, вариант LW; «Laminar Zero 9 14.1» → семейство Laminar, версия Zero 9, размер 14.1. Ключ записи: `производитель|семейство|версия|размер` (версия нужна, только если поколения различаются, как у Laminar Z8/Zero 7/Zero 9 и Malibu/Malibu 2; вариант — C у Discus, XC/Race у Sting 3, Plus/Light у Atos — в ключ не входит). Записи без размера (30 ключей) остаются отдельными, не приклеиваются к размерам.
- Единицы → SI (ft², ft, in, lb, mph, ft/min), у каждого значения хранятся сырое значение, единица, цитата, файл-источник. Выбор значения: приоритет источников DHV > PDF производителя > страница производителя/плакат > архив, медиана внутри класса; значения вне физ. диапазона не участвуют в выборе, пока есть годные.
- `conflict: true` — значения из разных источников расходятся > 3 % (диапазон в `range`). Это нормально для DHV vs производитель: DHV Vne (испытанная, часто 90 км/ч) ниже заявленной производителем (100 км/ч); у DHV «Startgewicht» — другой смысл, чем «pilot hook-in weight».
- Физическая проверка (`flags`, не правится): площадь 8–22 м², размах 8–12,5, масса крыла 18–45 кг, Vne 50–120 км/ч, Va 40–110, Vms 25–50, Vd 40–130, удлинение 3,5–9,5, лат 8–40, стартовая масса 40–250 кг и др. (`FIELDS` в скрипте). Дополнительно: `vd_below_vne`, `ar_inconsistent` (размах²/площадь ≠ заявленному удлинению > 5 %), `unit_problem`, `reclassified_or_suspect_unit`, `placard_metric_reinterpreted`.
- Переклассификации с пометкой (не молча): Vms в ft/min → `min_sink_ms` (это скорость снижения); best_glide с единицей скорости и значением > 25 → `best_glide_speed`; площадь с единицей «m» = м²; доля двойной поверхности ≤ 1 → ×100; **плакаты Wills Wing**: часть записей на странице метрическая (км/ч, кг), но разобрана как mph/lb — если Vne > 65 или Va > 60 «mph», единицы переинтерпретированы как км/ч и кг (67 записей, флаг `placard_metric_reinterpreted` с сырым значением).
- DHV: у карточек, где в тексте отчёта есть «Wölbklappe(n)», в `features.vg_camber_flap_dhv` лежит цитата (Atos VQ/VR/VRS/VRQ и Aeros Phantom).
- Статус `current` = сертификация DHV ≥ 2015 или страница/PDF (не архивная) на сайте производителя; плакат, точки поляр и архив Wills Wing за признак актуальности не считаются.

## Геометрия для 3D (`wings_geometry.json`)

Отдельно от паспорта: `items[]` с каноническим именем, исходным именем, `value_mm` (или `value_deg`, `value_g`, `text`), цитатой и файлом. Где что есть: диаметр передней кромки — Discus, F2, Sting 3, Fizz, T2/T2C; хорда на 3 ft от кончика — F2, T2/T2C; высоты латов/кончиков (карбон/алюминий) и длина троса траверсы — Icaro Laminar (Alto — трос); ЦТ от носа киля — Moyes Litespeed RX/S, Litesport, Malibu; диаметр киля — Fizz, Litespeed S; длина в сложенном виде (в т. ч. короткая) — Icaro, Airborne, Moyes. Угол носа — 55 записей, 23 семейства (из DHV не приходит, только от производителей), число латов — в `items` как `battens`. Единицы «64ths in»/«32nds in» (диаметры тросов) переведены в мм.

## Чего не хватает

- Vms/Va/Vd есть в основном у Wills Wing (страницы и плакаты); у Moyes, Aeros, Icaro, Airborne — Vne и Vmin/Vmax при VG 0/100 % у части моделей (см. покрытие).
- Поляр мало: 8 моделей WW (две точки V1/V2 — минимальное снижение и 530 fpm). Для остальных поляр нет.
- Геометрия каркаса (диаметры труб, длина киля, траверсы) есть у 14 семейств; нет профиля, закрутки, хорд по размаху.
- DHV: разобраны 107 карточек из 524 (все сертификаты ≥ 2015 — в наборе; старые 1979–2013 не скачивались).
- Аппараты вне набора: Airborne Edge/Fun/Streak/Clip (в текстах страниц упоминаются), Moyes Xtralite/Mars/Sonic, Icaro Mini, La Mouette и отечественные (Атлас, Апогей, Славутич — есть только в `configs/wings/`).
- Часть записей с пустым размером (DHV не указывает размер в имени: Bautek, Seedwings, Ellipse и др.).

## Лицензии и источники

Данные — факты из открытых страниц и документов производителей и DHV Geräteportal (dhv.de), используются для исследования и калибровки физической модели; PDF/тексты в репозиторий не кладутся. Ссылки на источники — `sources.md`, для каждого значения — файл и цитата в `wings_merged.json`. Запись о лицензии — в `ASSETS.md` (строка про `out/haiku`); `out/haiku_dhv` — тот же источник (DHV).

## ТЗ на 3D-модели и правки конфигов (2026-10-01)

- `make_3d_tz.py` + `tz_curated.py` (ручная часть: модели, базы, заметки, вопросы) + `tz_head.md` (вводная часть) → `docs/research/glider_3d_tz.md` (по разделу на существующую/новую модель). Запуск: `python3 make_3d_tz.py`.
- `wings3d_geometry.py` — геометрия паруса 3D-моделей без Blender (площадь в плане, подбор хорды на конце); без аргументов печатает сверку `glider_params.json` с конфигами.
- `out/construction/batch_{a,b,c}.json` — выборка Haiku по открытым страницам: мачтовое/безмачтовое, VG, годы, преемственность, заметки по виду (цитата + URL). Тип принимается в ТЗ только при цитате, прямо называющей мачту/безмачтовость.
- Что изменено в `configs/wings/*.json` и какие данные противоречат конфигам — `docs/research/wings_config_sources.md`.

## Новые крылья по ТЗ: спецификация и применяющий скрипт (W3-02)

- `make_3d_tz.py` пишет вместе с ТЗ `out/wings3d_spec.json` — машиночитаемую спецификацию 39 новых крыльев (форма — `docs/contracts/wings-models3d.md`, К3): `params` — значения таблицы «Что задать» (поля `glider_params.json`), `config` — паспорт опорного размера (размах, площадь, масса крыла, hook-in пилота, доля двойной обшивки, тип конструкции, группа, годы, прототип, блок DHV: Vmin/Vmax при VG 0, «Startgewicht», Vne, номер сертификата — только из карточек DHV), `sources` — ключи `wings_merged.json`; `manual` — строки «Что задать» без числа (текстом). Нет в паспорте — `null`. Генератор сам сверяет таблицы ТЗ со спецификацией (расхождение — ошибка); `python3 make_3d_tz.py --check` — только сверка, без записи.
- `make_new_wings.py <id…>` (`--existing` — все уже добавленные, `--all` — все 39) пишет для каждого крыла запись `tools/blender/glider_params.json → wings.<id>` (копия базы + `params` + раскраска по номеру раздела), `configs/wings/<id>.json` (копия конфига базы + паспорт + поляра и скорости подобием по нагрузке, К4; `_doc` с источниками, проверкой DHV Vmin и списком полей «как у базы») и строку `locale/ui.csv`. Идемпотентен; новые записи — после существующих, в порядке разделов ТЗ. Печатает таблицу К4. Ручные правки вида крыла — `wings3d_overrides/<id>.json` (`params`/`design`/`config`), накладываются последними.
- Дальше: `blender --background --python tools/blender/build_gliders.py -- <id…>`, `XDG_DATA_HOME=$(mktemp -d) godot --headless --path . --import`, `tests/game/test_wing_models_contract.gd`, `scenes/models_preview/check_models.gd`.
