# HH-1c: точка росы дня против облачности и жары дня (ERA5)

Вопрос: насколько Td дня (в долях σ климата месяца и в К) сдвигается в ясный / переменный / пасмурный день и в день жарче обычного. Нужно для Td дня в HH-4 вместо `td_follow_heat` и множителя дымки overcast.

## Данные и источники
- ERA5, ARCO-ERA5 (Google Cloud Public Datasets, `gs://gcp-public-data-arco-era5/ar/1959-2022-1h-360x181_equiangular_with_poles_conservative.zarr`): `total_cloud_cover`, `2m_temperature`, ячейка 1° (среднее четырёх узлов). Лицензия: Copernicus (CC-BY 4.0), Hersbach et al. 2020, QJRMS 146, 1999-2049, doi:10.1002/qj.3803.
- Td дня и климат (среднее, σ ячейка-месяц, маска суши) — из HH-1 (`~/data/haze_humidity/daily/`, `climatology.npz`, ERA5 1991-2020; не в git, большие).
- Облачность дня = средняя `tcc` за местные 10-16 ч (6 ч), местные сутки = UTC-сутки со сдвигом round(lon/15) ч. Классы: clear tcc < 0.2, partly 0.2-0.6, overcast > 0.6. `dtmax_k` — отклонение суточного максимума T2m от среднего по (ячейка, месяц).
- Сырьё: `~/data/haze_humidity/td_sky/<год>.npz` (по 270 МБ, локально).

## Воспроизведение
```
~/data/haze_humidity/venv/bin/python fetch_tcc.py 2011 2013     # или run_fetch.sh (2011-2020)
~/data/haze_humidity/venv/bin/python analyze.py                  # td_sky.json, td_sky.csv, acc_cache.npy (~7 с)
```

## Метод
Суша (lsm > 0.5) 0-75° |lat|, 4 пояса (0-20, 20-40, 40-60, 60-75), физические сезоны (юг сдвинут на полгода, полушария сливаются), вес cos(lat). Для каждого (пояс, сезон, класс): доля дней `frac`; средняя аномалия Td `mu_sigma` (в σ) и `mu_k` (К) к среднему выборки ячейка-месяц; `beta` (К/К) — регрессия аномалии Td на аномалию Tmax внутри классов (общая на пояс/сезон; `beta_cat` — по классам); `mu_sigma_uncentered` — сдвиг класса при климатической Tmax, т.е. после вычитания beta·dTmax; `res_ratio` — σ остатка (после класса и beta) к σ климата. `se_mu_sigma` — джекнайф по годам (3 года: грубая оценка, нижняя). В `sites` и строках `site` csv — те же величины для ячеек Алтай, Аскарово, Крым, Дараб, Кэрнс.

## Как использовать в HH-4
`Td = Td_clim + σ·(mu_sigma_uncentered[sky] + e·res_ratio[sky]) + beta·(Tmax − Tmax_clim)`, e ~ N(0,1) (единичная σ остатка внутри класса — приближение); либо без beta и с `mu_sigma` (там связь с жарой уже внутри). Класс неба — по выбранной облачности игры.

## Результат (3 года 2011-2013, суша мира, pooled)
| | clear | partly | overcast |
|---|---|---|---|
| доля дней | 0,246 | 0,258 | 0,496 |
| mu_sigma, σ | -0,275 | +0,011 | +0,130 |
| mu_sigma_uncentered, σ | -0,456 | -0,134 | +0,641 |
| mu_k, К | -1,19 | +0,02 | +0,58 |
| dTmax, К | +0,51 | +0,45 | -0,48 |
| res_ratio | 0,96 | 1,00 | 1,11 |

beta pooled = 0,59 К/К (beta_cat 0,43 / 0,51 / 0,67).

## Критерий единого значения и вывод
Единое значение допустимо, если разброс по поясам/сезонам < ~0,1 σ (mu) и < ~0,2 К/К (beta). Не выполняется: beta от -0,28 (тропики JJA) до 1,0 (60-75°, DJF/SON); res_ratio в 60-75° в 2-3 раза ниже (0,3-0,5 против ~1 в тропиках: климатическая σ там сильно больше σ остатка, т.е. Td привязана к воздушной массе/Tmax); пасмурный день +1,3 К зимой/весной в 20-40° (SE ~0,03 σ). Поэтому в HH-4 брать таблицы по поясам и сезонам из `td_sky.json`; одно значение (pooled) — только запасной вариант: beta = 0,6.
Практически: `td_follow_heat` (beta) — ~1 в высоких широтах вне лета, ~0,3 летом и ≤0 в тропиках (там жара дня не повышает Td: сухой воздух / ясно). Эффект облачности на Td дня небольшой (|mu_sigma| ≤ 0,3 σ в среднем), ясный день суше на 0,2-0,6 σ.

## Длина ряда: 3 года вместо 10 (решение пользователя 2026-10-22)
Пользователь подтвердил: 3 года (2011-2013) достаточно, докачка 2014-2020 не делается. `fetch_cds_daily.py` и `build_cds_daily.py` (CDS daily-statistics, 2014-2020) оставлены как конвейер на будущее: **не запускались**, результатов от них в таблицах нет.
Погрешность от короткого ряда:
- Джекнайф по годам (`se_mu_sigma` в json/csv, по ячейкам пояс x сезон): медиана 0,033-0,036 σ, максимум 0,11-0,14 σ (класс ясно/переменно/пасмурно). Оценка из трёх блоков грубая и, вероятно, занижена; для pooled-значений SE заметно меньше.
- Сверка с неполными 2014-2020 (смесь: 2011-13 полностью + 2014-20 частично): pooled mu_sigma -0,29/0,00/+0,14 против -0,28/+0,01/+0,13, beta 0,60 против 0,59 — различия ≤ 0,02 σ и 0,01 К/К.
- Определение облачности (окно 10-16 ч против суток): pooled -0,28/+0,13/0,59 против -0,30/+0,17/0,58 (`td_sky_day3y.json`); 16,1 % дней меняют класс (`class_shift_window_vs_day.json`).
Вывод: pooled-коэффициенты устойчивы на уровне ~0,02-0,04 σ; отдельные клетки пояс x сезон надёжны до ~±0,1 σ (1 σ джекнайфа максимум), различия внутри этого уровня не интерпретировать. `td_sky.json` (основной) = окно 10-16 ч, 3 года.

## Ограничения
- Только 3 года (2011-2013) вместо плановых 10: ARCO отдавал NaN-блоки, остальные годы не докачались (в `~/data/haze_humidity/td_sky_bad/` и `parts/` — неполные); по решению пользователя не докачивалось (см. выше). SE в json — по 3 годам, занижены.
- Td дня = среднее 00 и 12 UTC (HH-1), не местный полдень; tcc ERA5 — реанализ, не наблюдения. Сезоны полушарий слиты. Муссоны/берег внутри пояса усреднены; в 1° ячейке Крыма (море, lsm<0,5) сайт-строки справочные. Границы применимости: суша 0-75° |lat|; высота места не учитывается.
