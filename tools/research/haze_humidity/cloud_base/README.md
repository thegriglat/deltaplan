# HH-3 — проверка яркости основания облаков

Правок игры нет. Вопрос: корректна ли яркость основания кучевых и Cb относительно неба и освещённой вершины
(`clouds.extinction_per_m`, `base_darkness`, `ambient_bottom`, `sky_occlusion_m`, `configs/atmosphere.json`).

## Метод

1. **Кадры игры** (окно, `run_frames.sh`; копии `tools/shots/cloud_field_shot` и `storm_shot` с тремя отличиями:
   линейный тонмаппер с экспозицией 0,4 (яркость = пиксель/0,4, без тонмаппера AgX); тени облаков на земле
   выключены; каждый вид снимается дважды — с облаками и с выключенным `CloudCompositorEffect`). Маска
   облака — разность кадров (|ΔY| > 8 % от Y без облаков), Y = 0,2126R+0,7152G+0,0722B в линейном sRGB.
2. **`analyze.py`**: L_base — среднее по нижним 20 % каждой вертикальной серии облачных пикселей (≥ 24 px);
   L_sky — небо (B/R > 1,8 в кадре без облаков) на 12–70 px ниже той же серии; L_top — 95-й перцентиль Y
   облачных пикселей вида; L_base_p10 — 10-й перцентиль пикселей основания («ядро», тёмная часть).
   Для видов с глазом ниже основания — срезы по дальности до плоскости основания (6 и 12 км).
3. **`model.py`**: аналитический порт `cloud_light` для плоского слоя мощности D (сколько света получает
   основание при данных `sky_occlusion_m`, `base_darkness`, `ambient_*`) — `model.json`.
4. **Физический эталон** `lit_ratio_lo/hi`: двухпотоковое пропускание T = 1/(1 + 0,75(1−g)τ), g = 0,85
   (Lacis, Hansen 1974; Bohren 1987, Am. J. Phys. 55, 524 — формула дана координатором, по первоисточникам
   не сверена); R = 1−T; L_base/L_top = (T + R·A·f)/R, A — альбедо земли 0,1–0,3, f — доля освещённой
   земли вокруг 0,7–1. Вилка: lo = (τ_max, A 0,1, f 0,7), hi = (τ_min, A 0,3, f 1). τ: тонкое Cu 10–25,
   среднее Cu 25–60, Cb 100–300 (диапазоны координатора; Cb ≥ 100 — типично для ливневых).
   В игре τ по вертикали ≈ 0,09·ρ·D: D = 400 м, ρ 0,7 → 25; D = 1,25 км → 79 (в вилке).


## Вердикт

**В целом корректно.** Среднее base/top в кадрах (0,33–0,41 ближе 12 км) попадает в физическую вилку для
средних Cu (0,22–0,66), Cb (верхний край 0,39) и тонких Cu (нижний край 0,43). Основание ≈ яркость
соседнего неба (base/sky 1,0–1,1 вблизи): для Cu правдоподобно, для Cb наблюдения качественно говорят «темнее
неба» — числами не подтверждено (источника яркости основания Cb в cd/м² не нашлось).

Что на границе:
- Тёмное ядро толстого основания (D ≥ 1,5 км, в т.ч. Cb) в модели = 0,10 от вершины — на нижней границе вилки Cb
  (0,10): пол задан только `ambient_bottom·base_darkness·ambient_energy` (Y ≈ 0,14), от толщины не зависит.
  Темнее Cb не бывает при любых параметрах, кроме снижения `base_darkness`/`ambient_bottom`.
- `sky_occlusion_m` действует только пока D ≲ 3·sky_occlusion_m (≈ 1 км при 350): толще облако даёт тот же пол.
  В кадрах разброс 150–700 в пределах ±0,02 по L_base (шум ≈ тот же порядок), эффект «выкл.» — +35 %.
  Для тонких Cu (300–500 м) порт даёт 0,14–0,18 — в 2,5–3 раза ниже вилки 0,43–1,19, но кадры тонких Cu
  (0,40–0,41) лежат у нижней границы: пиксели в основном края и тонкие части.
- Перебелённость Cb «под основанием»: L_base 0,47 при небе 0,43 — включает ливневую завесу (virga) и
  боковую подсветку; чистое ядро 0,30 (p10).

Предложений по правке параметров нет; если Cb нужно заметно темнее неба (визуальное решение), рычаг —
`ambient_bottom`/`base_darkness` (пол), а не `sky_occlusion_m`.

## uncertain

- Сегментация основания по нижним 20 % серий в кадре — эвристика: примешивает бока и тонкие края (завышает
  L_base против «плоского» основания); p10 — оценка снизу. Глубину пикселя из кадра не снять.
- `depth_m` в ratios.csv — максимальная мощность по полю/Cb, а не облака в кадре.
- Эталон — двухпотоковый (изотропное основание, R = 1−T, без фазы и угла солнца); вилка широкая (×3).
  Формула и диапазоны τ взяты из карточки, по первоисточникам не проверены; наблюдательных яркостей основания
  (cd/м²) найти не удалось.
- L_sky — небо в кадре с дымкой игры (зависит от задач haze); дальние виды («far» Cb, «level») ослаблены дымкой.
- Тонкие Cu: один кадр с 1 % облачных пикселей (n 226–501), статистика слабая.
- Облака в кадре эволюционируют на секунды между снимками sky_occlusion — флуктуации ±0,02 внутри ряда не значимы.
