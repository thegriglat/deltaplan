# Окружение, запуск пилота П-2 и config.yaml

Часть пилота air-nn; вход и границы — [README](../README.md). Сеть заменена в игре фазовой сборкой (AP-21).

## Окружение

```bash
cd tools/research/air_nn_pilot
./setup_env.sh            # .venv (Python 3.12, uv), версии — requirements.lock; проверяет CUDA, cupy, ORT
```
Только `.venv/bin/python`. Новые пакеты — в `requirements.in` + `./setup_env.sh --relock`.

## Запуск пилота П-2 (одна команда, в tmux)

```bash
cd /home/greg/deltaplan-air-nn/tools/research/air_nn_pilot          # копия модуля air-nn (после слияния air-nn/assemble)
./setup_env.sh                                                      # сначала: окружение (.venv)
tmux new -s p2 './run_pilot.sh; exec bash'
# отцепиться: Ctrl-b d;   вернуться: tmux attach -t p2;   где прогон: ./run_pilot.sh status
```
Этапы (NN-P7): **1** рельеф П6 (`terrain_cut.py run`, пропуск, если `tiles/v3/manifest.json` complete) → **2** досчёт наборов
(`terrain` — 360 мест × 12 условий, П1 v3, 2 воркера на GPU; `main` — готовый, под версией `main_version` s0-3acd749, не
пересчитывается) → **3** подготовка тензоров (кеш, контракт П2) → **4** обучение основной сети → **5** кривая (в):
25/50/100/200 мест пула (300 = основная сеть) → **6** оценка, экспорт ONNX, ORT ↔ PyTorch → **7** картинки и `report.md`
(вердикт ШП-2 — правилом П3 v3). Время и диск полного прогона (оценка по пробе на `tiles/v3`, `figures/estimate_p2_full.json`):
**≈ 10 ч GPU (набор) + ≤ 4,7 ч обучения + ≈ 0,3 ч CPU ≈ 15 ч**, диск **≈ 18 ГБ** (набор 5,8 + кеш подготовки 8,4 + кеш main 3,7 +
прогоны 0,5); подробности — «Оценка полного прогона П-2» ниже. Проверенная команда мини-прогона на тех же настоящих местах —
`./run_pilot.sh --smoke` (~2 мин после досчёта 27 случаев; профиль `smoke_mock` — прежний smoke на подставном П6, для тестов).

В терминале — только строка этапа и одна обновляемая строка прогресса (единицы этапа, %, сколько осталось):

### Продолжить, начать с нуля, статус
- **Продолжить** после Ctrl-C, обрыва, перезагрузки — **та же команда** (`./run_pilot.sh`). Готовые шаги пропускаются
  (`manifest.json` с `complete` и тем же хешем входов), обучение продолжается с `ckpt/last.pt` (результат — как у
  непрерванного, см. «Тесты»), без дублей каталогов и ручной чистки (остатки `*.tmp*` удаляются сами).
- **С нуля** — новое имя: `./run_pilot.sh --name pilot2` (набор и кеш подготовки не пересчитываются).
- Если входы шага изменились (правка `config.yaml` или кода обучения, набор вырос) — шаг откажется продолжать старый
  прогон (код 1, «входы изменились») — запускать под новым `--name`.
- **Статус**: `./run_pilot.sh status [--smoke] [--name ИМЯ]` — идёт ли, что готово по шагам, путь к отчёту и вывод.
- **Мини-прогон**: `./run_pilot.sh --smoke` — профиль `smoke` (smoke П-2, NN-P7): набор `smoke` NN-P1 v1 (15 случаев: ongudai × 3 — (б);
  s_hill, p_000…p_002 × 3; один p_* — (б′)) + набор `terrain_smoke` (П1 v3, **настоящие места tiles/v3**: t_0050, t_0125, t_0200,
  t_0275 — пул, уклон p50 0,08…0,41; t_0318, t_0327 — Кавказ, (г); × 2 условия = 12 случаев, около половины — max); кривая (в)
  2 и 4 места П6 (4 = основная сеть), десятки эпох, свои каталоги `pilot/smoke_p2`; проходит до `report.md` со всеми разделами
  П3 v3 (проверка конвейера, не качества): `tests/check_report_v3.py --latest-smoke`. Профиль `smoke_mock` — прежний smoke
  на подставных П6 и terrain (`tests/make_mock_p6.py`, П1 v3 с подставными метаданными решений) — для тестов.

### Коды выхода
| код | значение |
|---|---|
| 0 | отчёт готов |
| 1 | ошибка шага (хвост — в `pilot.log`), или прогон уже идёт в другом процессе, или входы шага изменились |
| 2 | неверные аргументы |
| 3 | нет места на диске (проверка перед шагом) |
| 4 | набора нет или в нём мало пригодных случаев |
| 130 / 143 | прерван SIGINT (Ctrl-C) / SIGTERM — шаг дописал чекпойнт; повтор той же команды продолжает |

Сигналы: первый SIGINT/SIGTERM передаётся шагу — он дописывает чекпойнт и выходит; второй — немедленный выход.
`kill -9` управляющего процесса убивает и шаг (PR_SET_PDEATHSIG), замок GPU и замок прогона снимает ОС.

## Конфиг (`config.yaml`)
Один файл: зёрна (`split.seed`, `train.seed`), размеры сети, эпохи, деление v3 (`split`), оценка и правило ШП-2
(`eval`, `eval.shp2`), кривая (`curve`), оценка полного обучения (`estimate`), наборы — список `datasets`
(`{name, gen, root}`: `name` — набор для `dataset.py path/run --dataset`, `gen` — досчитывать ли, `root` — явный каталог)
и индекс мест П6 `terrain_index`. Путь данных — `AIR_NN_DATA` из окружения.
Раздел `profiles.<имя>` накладывается при `--smoke` (= `--profile smoke`). Снимок конфига прогона —
`runs/<…>/config.json`.
