# П3-Б: формы профиля по высоте (POD) целей П-2 (NN-P10)

Готово: v4 и v5.

## Метод и границы
- POD по высоте отдельно по каждой величине (v4: u∥,u⊥,w без нагрева; u∥,u⊥,w,θ′ с нагревом — 7 величин; v5 — 9),
  ковариация 13×13 по всем клеткам 96² обучающих случаев `split.json` прогона 2026-10-03_p2b (3897 случаев, 35,9 млн
  профилей), центрирование по среднему профилю μ(z). Базис — собственные векторы, без весов по высотам (13 уровней
  неравномерны по z, каждая высота равноправна — как в потере сети).
- Ошибка — физическая: цель с K формами → `prep.to_physical` → вектор ветра (u, v) против поля решателя, интерполяция
  50–75 м как `evaluate.level_weights`; медиана и p90 по клеткам (каждая 3-я по обоим осям), все случаи без отбора по
  сходимости: (г) `holdout_sys_ids` — 720 случаев, обучение — 600 случайных `train_ids`. Ветер без нагрева (m) и с (h).
- Правило: «да», если при K ≤ 6 p90 ошибки восстановления ветра на 60 м на (г) ≤ 0,1 м/с для v5 (для v4 — справочно).
  Берётся худшее из m и h.
- Применимость: линейная проекция на общие формы; в ошибку не входит ошибка самой сети (она сложится с ней), цель
  в кеше — float16 (K = 13 даёт p90 ≤ 0,001 м/с — это потолок точности кеша).
- Воспроизведение: `cd tools/research/air_nn_pilot && dp lock cpu nnp10 --timeout 1800 -- .venv/bin/python p3/pod.py --enc v4`
  (≈ 1,5 мин, 4 процесса, ОЗУ < 2 ГБ); числа — `p3/out/pod_v4.json`, формы — `$AIR_NN_DATA/pilot/p3/NN-P10/pod_v4.npz`
  (`mean [7,13]`, `phi [7,8,13]`).

## Решение
- v5, (г), K = 6: p90 ветра на 60 м = 0,137 (без нагрева) / 0,206 (с нагревом) м/с > 0,1; при K = 8 — 0,099 / 0,109.
  Порог не достигнут ни при каком K ≤ 8 (нагрев 0,109). Узкое место — разгон и поворот (a, sin δ, cos δ), а не w_rel.
- v4 (справочно): K = 6 — 0,232 / 0,246.
- Для координатора, не для приёмки: при пороге p90 ≤ 0,3 м/с («ок») упаковка была бы «да» — v5 с K = 3 (0,260 / 0,272),
  v4 с K = 4 (0,259 / 0,267); K = 6 даёт запас (v5 ≤ 0,21).

упаковка: нет
