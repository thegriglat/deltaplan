## SR-К1. Сценарий штопора и метрики выхода (v2)
v2 (2026-10-21, по SR-2): режим `pull_release` обязателен (кроме SR-1, начатой по v1): `standard` у sport отсекает пилот-модель теста (удержание −1 на скорости), а не штопор.

Владелец — SR-2 (стенд модели `tools/research/spin_recovery/spin_run.gd`); потребители — SR-1 (тот же сценарий через
путь ввода игры), SR-3 и последующие.

**Условия.** Модель — как `tests/flight/pendulum/pendulum_sim.gd` (`S.make(крыло)`, эталонная масса пилота,
ρ = 1,225 постоянная, штиль, `S.reset` — 1000 м, курс север). Шаг основной 1/120 с; проверка устойчивости к шагу —
ещё 1/60 и 1/30 (`dt` в строке). Крылья: `sport` (предмет), `laminar`, `training` (контроль).

**Вход** (как `test_pendulum_spin.gd`, PD-22):
1. 14 с вираж 30° вправо: `S.BankHold.new(deg_to_rad(30), 6.0, 2.5, 1.0)`, pitch 0.
2. Фаза 0: pitch 0 → 1 линейно за 10 с, крен держит `BankHold`.
3. Первый срыв (любая полоса `strips.blend[j] > 0.01`) → фаза 1: крен ввода замирает на последнем значении, pitch
   продолжает рампу до 1; фиксируются `h_stall` (высота), `first` (внутренняя/внешняя/обе — правая консоль
   `[0, n/2)` внутренняя).
4. Через 6 с после первого срыва — начало выхода `t_rec0`; в этот момент пишутся параметры штопора
   (`spin_*`: средняя скорость рыскания за фазу 1, макс. крен и снижение за фазу 1).

**Режимы выхода** (`mode`):
- `release` — (а) отдать управление: с `t_rec0` ввод pitch = 0, roll = 0 до конца прогона. В пути ввода игры (SR-1) —
  мышь больше не двигается (смещение ведёт себя по конфигу игры: возврат к центру, мёртвая зона).
- `standard` — (б) по Жеглову (с. 122), как `test_pendulum_spin.gd`: pitch −1 и roll = −sign(скорость рыскания),
  пока не выполнено `tr ≥ 1 с и (tr ≥ 10 с или (срыва нет и |dψ/dt| < 45°/с))` (`tr` — от `t_rec0`); затем pitch =
  clamp(−2·(V − Vтрим)/Vтрим, −1, 0) (V, Vтрим — км/ч, Vтрим — воздушная скорость после `S.reset` до входа), крен —
  `BankHold` с целью 0.
- `pull_release` — «на себя» и смещение против вращения ровно как в `standard` до того же условия конца, затем pitch = 0,
  крен — как в `standard` (`BankHold` с целью 0); реализация — `tools/research/spin_recovery/spin_run.gd` (SR-2). Пилот,
  отдавший ручку в нейтраль после «на себя»; при pitch = 0 после «на себя» срабатывает отпускание рук VM-12.
- Другие режимы — новым значением `mode` с описанием в отчёте задачи; `release`, `standard`, `pull_release` обязательны.

**Выход** (`recovered`): |крен| < 15°, |dψ/dt| < 20°/с и ни одной сорванной полосы — 3 с подряд. `recover_s` —
начало этого окна минус `t_rec0`; `loss_m` — `h_stall` минус высота в начале окна. Нет выхода за 60 с от `t_rec0` —
`recovered = false`, `recover_s`/`loss_m` = null. После выхода 20 с: `after_bank_max_deg` (макс. |крен|),
`after_stall_s` (время, когда сорвано больше половины полос). Нечисловое состояние модели — `finite = false`, прогон
кончается.

**Балансировка вариантов.** Вариант, меняющий геометрию или аэродинамику (крутка, хорда, стреловидность, V-образность,
C_L max полос), — перед входом: заново `strips.match_polar_cl_max()` (если `strip_cl_max_match_polar`), затем `dcm0`
секущими под паспортный трим ±0,01 км/ч (как генератор игры, `tools/research/pullin_speed/pullin_speed.gd`). Иначе
разница в штопоре может быть разницей трима. `trim_kmh` пишется всегда.

## SR-К2. Данные прогонов (v1)
Владелец — координатор; пишут все задачи волны, читает SR-К3 и шлюз итога.

Каталог задачи — `tools/research/spin_recovery/out/<id>/` (`<id>` — ID задачи строчными: `sr-1`, `sr-2`, …).
Крупного нет; всё коммитится. Запись — во временный файл и переименование.

**`runs.jsonl`** — строка на прогон, ключи (единицы — СИ, углы — градусы, Vтрим — км/ч; нет значения — null, не NaN):

| ключ | тип | что |
|---|---|---|
| `contract` | str | `"SR-К2 v1"` |
| `task` | str | `"SR-1"` … |
| `wing` | str | имя конфига крыла |
| `variant` | str | `game` — игра как есть; прочие — по задаче (описаны в `variants` сводки) |
| `mode` | str | `release`, `standard`, … (SR-К1) |
| `dt` | float | шаг, с |
| `trim_kmh` | float | трим варианта до входа |
| `first` | str | `внутренняя` / `внешняя` / `обе` / `""` (срыва не было) |
| `spin_yaw_dps`, `spin_bank_max_deg`, `spin_sink_max_ms` | float | штопор за фазу 1 |
| `recovered` | bool | SR-К1 |
| `recover_s`, `loss_m` | float/null | SR-К1 |
| `after_bank_max_deg`, `after_stall_s` | float/null | SR-К1, null без выхода |
| `finite` | bool | |
| `extra` | object | диагностика задачи (свободно; SR-1 — путь ввода) |

**`summary.json`**: `{"contract": "SR-К2 v1", "task": "SR-n", "commit": "<git hash стенда>", "cmd": ["…"],
"variants": {"<variant>": "<что меняет, одна строка>"}, "rows": [<строки runs.jsonl без extra>]}`. Обязательно в
`rows`: `variant = game`, режимы `release` и `standard`, крылья `sport`, `laminar`, `training`, шаг 1/120.
Таблица для документа — `tables.md` там же.
