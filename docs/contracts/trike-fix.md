# Контракты trike-fix (код задач TKF)

## TKF-К1 v3. Углы тележки к крылу: определения, сценарии, `summary.json`, пороги
Владелец — TKF-1 (инструмент, данные, `check_summary.py`); потребители — TKF-4 (тест с порогами — v2 этого раздела),
TKF-7 (кадры и таблица «после» тем же инструментом). Контрактный тест — `tools/research/trike-fix/check_summary.py
<summary.json>` (пишет TKF-1): exit 0 — схема и единицы верны.

**Тела и базисы** (мир Godot; дельталёт игрока через `Glider.setup_trike(Config "tow_tug", 0, Config "trike_pilot")`):
- `W` — `TrikeRig.wing_basis` (крыло: −Z по килю вперёд, +Y — нормаль вверх).
- `C_vis` — `TrikeRig.cart_basis` (то, что рисуется, с ограничением поворота `CART_TURN_DEG_S`).
- `C_phys` — тот же базис без ограничения поворота (`_cart_model_basis(pilot_pos, hang_pos, wing_basis, on_wheels)`),
  то есть ориентация по физике «Маятника».
- Начало обеих моделей — `HangPoint` (`hang_pos`); оси `trike.glb` — TT-К6 (в Godot: +Y вверх, −Z вперёд, +X вправо).

**Величины** (каждая — для `C_vis` и `C_phys`, суффиксы `_vis`/`_phys`; градусы):
- `bar_deg` — положение середины базовой штанги трапеции (точка из модели/параметров крыла `trike_ixess15`, источник —
  в `README.md` инструмента), переведённой в оси тележки, на дуге TT-К6 вокруг `HangPoint`: угол от `trike_params.json
  bar.trim` в плоскости симметрии тележки, «+» — к `full_push`. Допустимо `−pull_deg ≤ bar_deg ≤ push_deg`
  (`bar.pull_deg`, `bar.push_deg`). За `push_deg` — штанга за передним подкосом (п. 1).
- `roll_rel_deg` — поворот крыла относительно тележки вокруг продольной оси тележки (−Z), «+» — правое крыло вниз.
- `yaw_rel_deg` — угол между проекцией киля крыла на плоскость ⟂ мачте тележки и продольной осью тележки, «+» — нос
  крыла вправо.
- `mast_normal_deg` — угол между мачтой (направление ЦМ тележки → `HangPoint` в данном базисе: −`C·CART_CM_MODEL`) и
  нормалью крыла `W.y`; > 90° — тележка выше плоскости крыла (п. 2, «сквозь крыло»).
- `vis_lag_deg` — угол между `C_vis` и `C_phys` (кватернионы).

**Сценарии** (штиль, ветер выключен; старт в воздухе 300 м над ровной землёй, 80 км/ч, горизонтально, штанга 0, шаг
игры 1/60 с; ввод `ControlInput`: `pitch` +1 — «от себя», −1 — «на себя»; `roll` +1 — вправо; `throttle_axis` через
`TrikeEngine` или прямым заданием `thrust_n` — способ в `README.md`):
- `trim_full` — газ полный, штанга 0, 30 с.
- `push_full` — газ полный, `pitch` +1 10 с, затем 0 10 с. `pull_full` — то же с `pitch` −1.
- `throttle_step` — штанга 0; газ 0 → полный на 5 с → 0 на 20 с; 35 с.
- `turn30`, `turn45` — газ половина и 0 (два прогона, суффиксы `_half`/`_idle`), вход в крен 30°/45° простым
  регулятором крена и удержание 20 с. `reversal45` — перекладка 45° → −45° → 45°, газ половина.
- `roll_pump` — газ полный, `roll` ±1 сменой каждые 2 с, 20 с.
- `pitch_pump` — газ полный, `pitch` ±1 с периодом, близким к собственному периоду качания тележки (подбор — в `README.md`),
  20 с.
Можно добавлять свои сценарии, эти — обязательны.

- v2 (2026-11-02, по TKF-1, `docs/research/trike-fix/coupling.md`): шаг — шаг физики игры (`physics_ticks_per_second`
  120, 1/120 с), а не 1/60 (отличие < 1°). Причина пп. 1, 2, 4 и скрутки по рысканию — вид: `cart_basis` ограничен
  20 °/с всегда. **Правка (TKF-4, вариант V1):** в воздухе `cart_basis` = `C_phys` без ограничения; ограничение поворота —
  только для сглаживания скачка колёса ↔ воздух (≈ 8,5°, не дольше ≈ 0,5 с). Рыскание тележки к крылу = 0 (узел подвеса —
  шарнир тангажа и крена, Gratton; AAIB G-CEVW). Физику `PendulumModel` правка не меняет.
  **Тест** `tests/flight/test_trike_coupling.gd` (пишет TKF-4; сценарии и величины — как выше, тем же способом расчёта, что
  `tools/research/trike-fix/coupling_run.gd`; без 1 с после старта и 0,5 с после отрыва):
  (1) `yaw_rel_deg_vis` ≤ 1,0° во всех сценариях; (2) `vis_lag_deg_max` ≤ 1,0° в `turn30_*`, `turn45_*`, `reversal45`,
  ≤ 3° в `push_full`, `pitch_pump`, `roll_pump`; (3) `mast_normal_deg_max_vis` ≤ 20°; (4) `bar_deg_vis` ∈ [−`pull_deg`;
  `push_deg` + 0,5°] в `trim_full`, `throttle_step`, `turn*`, `reversal45`, `roll_pump` (`push_full`, `pitch_pump` —
  не проверяются: выход за упор «от себя» в физике, вариант V2 — решение отдельно); (5) |`roll_rel_deg_vis`| ≤ 15°;
  (6) переход колёса → воздух: `cart_basis` непрерывен (≤ предел °/с · dt за шаг) и через ≤ 0,6 с совпадает с `C_phys`
  (≤ 0,5°). Тесты `tow`, `tow_trike`, `trike` — зелёные.
  Уточнение (2026-11-02, вопрос TKF-4): TT-К4 v2 требует «не быстрее 20°/с» только для перехода колёса → воздух после
  отрыва; `tests/contracts/test_tow_k9.gd` проверяет предел 20°/с весь полёт — проверку сузить до перехода (до
  отрыва + время гашения скачка, ≤ 0,6 с), дальше `cart_basis` = `C_phys` (≤ 0,5°). Правит TKF-4.

- v3 (2026-11-02, TKF-5 после исправления знака `CART_CM_MODEL`, TKF-К4 v2): скачок ориентации колёса → воздух
  ≈ 16° (было ≈ 8,5° при ошибочном знаке) гасится тем же пределом 20 °/с за ≈ 0,8 с: в (6) и в `test_tow_k9` окно
  перехода — ≤ 0,9 с, скачок — ≤ 20°; (4) — `bar_deg_vis` ∈ [−10,7°; `push_deg` + 0,5°] во всех сценариях, включая
  `push_full`, `pitch_pump` (нижний предел — касание груди при ходе 0,178 м, Q4 (б)).

<control_summary.json>` (пишет TKF-2): exit 0 — схема верна.

- Аппараты: дельталёт игрока (как TKF-К1) при газе 0 / 0,5 / 1; дельтапланы `sport` и учебный (крыло и пилот по

## TKF-К3 v1. Струя винта по траве: `Terrain.set_wash`
Владелец — TKF-6; потребитель — `Game` (дельталёт игрока). Основание — п. 5 решения 2026-11-02 и вердикт «несложно»
`docs/research/trike-fix/grass-wash.md` (TKF-3). Контрактный тест — `tests/vegetation/test_grass_wash_gpu.gd` (пишет TKF-6).

- `Terrain.set_wash(pos: Vector3, dir: Vector3, thrust_n: float) -> void` → `GrassField.set_wash(...)` (тот же путь, что
  `press_pos`: uniform-ы материала ближней травы раз в кадр, без новых проходов, текстур, буферов). `pos` — центр диска
  винта (мир, та же система, что `press_pos`), `dir` — единичное направление струи (назад по оси тяги), `thrust_n` ≥ 0 —
  тяга `TrikeEngine`/`TrikeRig.thrust_n`. Скорость струи — идеальный диск `v = sqrt(2T/(ρ·A))`, Ø винта 1,80 м, ρ ISA;
  затухание и ширина — по записке TKF-3 (оценка, помечено в `_doc`).
- Выключено (uniform `w` = 0, трава как раньше), если `thrust_n` < порога или ось выше порога над землёй; один источник —
  дельталёт игрока; у дельтаплана `set_wash` не вызывается или с `thrust_n` 0.
- Числа (порог тяги, высота, коэффициенты затухания/ширины, предел дальности) — `configs/vegetation.json → grass.wash` с `_doc`.
- Средняя трава (shell/cards) — по выбору TKF-6, если на ближней (≤ 35 м) струя видна целиком — не трогать.
- **Инварианты** (GPU-тест): (1) `thrust_n` 0 — кадр совпадает с кадром без вызова `set_wash` (пиксели равны);
  (2) полная тяга, ось 1 м над землёй — средний наклон/сдвиг травы в конусе за винтом (2–10 м по оси) заметно отличается от
  кадра без струи, вне конуса (сбоку > 6 м, дальше 25 м) — не отличается; (3) цена по протоколу G3
  (`docs/contracts/grass-rocks.md`, `tools/bench/frame_profile.sh`, замок gpu) — разница в пределах шума ±0,1 мс.

## TKF-К4 v2. Упор переднего подкоса и ход штанги «на себя» дельталёта
Владелец — TKF-5; потребители — `TrikeRig`/`Glider` (игрок), `TowTug` (тот же `cart`), TKF-7. Основание — ответ Q2 (а)
(2026-11-02), `docs/research/trike-fix/coupling.md` §3 V2, `docs/research/trike-fix/control.md` §4–6. Контрактный тест —
`tests/flight/test_trike_bar_stop.gd` (пишет TKF-5).

- **Величина штанги** — `bar_deg` TKF-К1 (геометрия: середина базовой штанги крыла в осях тележки по физике `C_phys`,
  угол на дуге TT-К6 от `bar.trim`, «+» к подкосу; расчёт — как `tools/research/trike-fix/coupling_run.gd`). Нули
  `trapeze.json` (`neutral_input0` и т. п.) — оценка TT-8; где они расходятся с замером `bar_deg` в игре, верен замер.
  TKF-5 сначала сверяет: `bar_deg_phys` при вводе `pitch` −1 / 0 / +1 на газу 0 и 1 (установившееся) — таблица в отчёт.
- **Упор подкоса (физика).** `PendulumModel.setup(..., apparatus_cfg)`: новый необязательный ключ аппарата (имена — за
  TKF-5, с `_doc` в `configs/tow_tug.json → cart`): предел относительного тангажа крыла к тележке в сторону «от себя»,
  эквивалентный `bar_deg` = `bar.push_deg` (4,95°, `tools/blender/trike_params.json`), и параметры упора (жёсткость и
  демпфирование момента-упора или ограничение в решателе — способ за TKF-5, обоснование в отчёте). Нет ключа — модель
  **бит в бит** прежняя (дельтапланы, `tests/flight`, `tests/contracts` — равенство как TT-К3 (1)). Ключ в `cart` действует
  и на `TowTug` (подкос у буксировщика тот же).
- **Ход «на себя» игрока.** `configs/trike_pilot.json` (новый блок с `_doc`) — ход штанги «на себя» дельталёта игрока
  0,20–0,25 м вместо `cart.arms_shift_pull_m` 0,111; применяет `Glider.setup_trike` после `TrikeRig.apply_arms`.
  `TowTug` и `cart.arms_shift_pull_m` — без изменений. Значение — наибольшее в 0,20–0,25, при котором на полном «на себя»
  `bar_deg_phys` ≥ −`bar.pull_deg` (штанга не входит в грудь пилота) на газу 0, 0,5, 1.
- **Инварианты теста:** (1) без нового ключа — траектория дельтаплана и тележки как прежде (равенство за 10 с);
  (2) дельталёт игрока, сценарии TKF-К1 `push_full`, `pitch_pump`, `trim_full`, `throttle_step`: `bar_deg_phys` ≤
  `push_deg` + 0,5° (без 1 с после старта); (3) полный «на себя» на газу 0 / 0,5 / 1: `bar_deg_phys` ≥ −`pull_deg`,
