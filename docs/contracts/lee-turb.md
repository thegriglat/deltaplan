# Контракты модуля lee-turb

Общее для всех стыков.
- Данные и скрипты исследований — `tools/research/lee_turb/`; выводы — `docs/research/lee_turb.md`.
- Единицы — СИ (м, м/с, м²/с², с). Пустая ячейка csv — «нет данных»; `NaN`, `-`, `?` не писать.
- csv — UTF-8, разделитель `,`, первая строка — заголовок ровно из перечисленных столбцов в этом порядке;
  текстовые поля с запятой — в кавычках. Запись — во временный файл и переименование.
- Контрактный тест: `python3 tools/research/lee_turb/contract/check_contract.py <файл>` (тип — по имени файла:
  `lit_numbers.csv` → LTL, `lee_obs.csv` → LTO, `*.lts.csv` → LTS); `--selftest` — проверка самого теста.
  Выход 0 — формат верен, 1 — нарушения (печатаются), 2 — ошибка чтения.
- Надёжность `reliability`: `A` — число из текста/таблицы источника или из сырых данных измерений;
  `B` — оцифровано с графика; `C` — выведено, пересчитано или оценка автора задачи (как — в `note`).

## LTL v1 — числа литературы
Владелец — LT-1; потребители — координатор (LTM), LT-модель, сверка.
- Путь — `tools/research/lee_turb/lit/lit_numbers.csv`.
- Столбцы: `id,quantity,value,low,high,unit,flow,definition,source,where,reliability,note`
  - `id` — уникальный, `[a-z0-9_]+`;
  - `quantity` — имя величины, `[a-z0-9_]+` (напр. `ddelta_omega_dx`, `sigma_u_peak_over_du`, `x_tke_max_over_xr`);
  - `value` — число; `low`, `high` — разброс источника или между источниками (пусто — не указан); если заданы,
    `low ≤ value ≤ high`;
  - `unit` — `1` для безразмерных, иначе СИ;
  - `flow` — одно из `mixing_layer_single`, `mixing_layer_two`, `step`, `fence`, `hill2d`, `hill3d`, `ridge_field`,
    `escarpment`, `general`;
  - `definition` — непустое: как определена и нормирована величина (какая толщина, какой ΔU, от какой точки x);
  - `source` — непустое: автор(ы), год, журнал/книга, doi если есть; `where` — рисунок/таблица/формула/страница;
  - `reliability` — `A|B|C`.

## LTO v1 — измерения за гребнем
Владелец — LT-3; потребители — сверка (LT-5 и далее), координатор.
- Путь — `tools/research/lee_turb/obs/lee_obs.csv`; рядом `tools/research/lee_turb/obs/README.md` — источники,
  лицензии/цитирование, отбор периодов, команды воспроизведения.
- Одна строка — одна станция (мачта/уровень/зонд) в одном случае (осреднение по периодам случая).
- Столбцы: `site,case,station,x_m,z_m,H_m,xr_m,x_game,z_game,u_ref_ms,u_ref_def,sigma_u_ms,sigma_v_ms,sigma_w_ms,tke_m2s2,uw_m2s2,L_u_m,n,stab,source,reliability,note`
  - `site` — `[a-z0-9_]+` (`perdigao`, `askervein`, `bolund`, …); `case` — `[A-Za-z0-9_]+` (`NE`, `SW`, `TU03B`, …);
    `station` — имя мачты и высота, напр. `tse09_20m`;
  - `x_m` — расстояние по среднему ветру случая от гребня (точки отрыва) гряды/холма, за которой стоит станция,
    м, «+» — по ветру (наветренные станции допустимы, «−»); `z_m` — высота над местной землёй, м (> 0);
  - `H_m` — превышение гребня над подветренным подножием/дном долины (как в Menke 2019 для Perdigão), м (> 0);
  - `xr_m` — длина пузыря отрыва в этом случае по измерениям, м (пусто — неизвестна);
  - `x_game`, `z_game` — положение станции в кадре места игры (горизонталь, м), если место есть в игре; иначе пусто
    (оба пусты или оба заданы);
  - `u_ref_ms` > 0 и `u_ref_def` — опорная скорость и её определение (напр. `U100 наветренной мачты tse04`);
  - `sigma_u_ms`, `sigma_v_ms`, `sigma_w_ms` — в осях среднего ветра станции (u — вдоль, v — поперёк, w —
    вертикаль), м/с, ≥ 0; `tke_m2s2` ≥ 0; `uw_m2s2` — ковариация; `L_u_m` — интегральный масштаб, > 0;
    хотя бы одно из `sigma_*`/`tke_m2s2` задано;
  - `n` — число осреднённых периодов (≥ 1), длина периода — в `note`;
  - `stab` — `neutral` или число z/L;
  - `source`, `reliability` — как в LTL.

## LTS v1 — разрез болтанки стендом
Владелец — LT-2; потребители — сверка (LT-5), модель (LTM, сравнение «прежняя/новая»).
- Команда: `cargo run -q --release --manifest-path rust/Cargo.toml -p dp-stand -- lee --case <cases/x.json> --from x,z --to x,z --ys y0,y1 --step <м> [--dy <м>] [--time <с>] [--configs <каталог>]` —
  csv в stdout; точки — по линии `from → to` с шагом `--step` (горизонталь игры) × высоты MSL `y0..y1` с шагом
  `--dy` (по умолчанию `--step`); точки под рельефом пропускаются.
- Первая строка — комментарий `# lts v1 case=<имя> time=<с> git=<хеш> model=<модель>`, затем заголовок:
  `s,x,y,z,agl,u_par,u_perp,w,lee_f,du,u_h,shear,sigma_u,sigma_v,sigma_w,l_u,l_w,src`
  - `s` — расстояние вдоль линии от `from`, м; `x,y,z` — кадр игры (y — высота MSL); `agl` — над рельефом;
  - `u_par`, `u_perp`, `w` — средний ветер (MEAN) вдоль линии, поперёк (влево +), вертикаль, м/с;
  - `lee_f` — признак отрыва [0, 1]; `du` — скачок слоя смешения ΔU, м/с; `u_h` — U_H на уровне гребня, м/с;
    `shear` — |∂U_h/∂z|, 1/с (величины модели, как они есть в `terms/turb`);
  - `sigma_u`, `sigma_v`, `sigma_w` — итоговые σ болтанки поля в точке (после выбора большего ветви), м/с;
  - `l_u`, `l_w` — масштабы вихрей, которые получает спектр (после растяжений и ограничений), м;
  - `src` — какая ветвь дала σ_w: `mech` (механическая), `conv` (конвективная), `mix` (слой смешения), `none`.
- Вне поля (аналитика) — строка с `src` = `none` и пустыми величинами поля; поведение модели стенд не меняет.
- Добавление столбцов — новая версия контракта (решает координатор).

## LTM — модель слоя смешения
Будет задана координатором после LT-1 (LTL) и LT-2 (LTS, что поле даёт за гребнем), до кода в `dp-air`.
