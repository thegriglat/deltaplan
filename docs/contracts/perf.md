# Контракты модуля perf

Контрактные тесты — `tests/test_perf_contracts.gd` (фильтр `perf_contract`), каждый тест пишет
задача-владелец; меняются только вместе с контрактом (версия +1, через координатора).

## PF-К1. Итог короткого замера `perf_check` — версия 1

- Владелец: PF-2. Потребители: приёмка PF-4…PF-9 (проверки `num:`), PF-10.
- Запуск: `tools/bench/perf_check.sh <out_dir> <пресет> [<место>=ongudai]` — под
  `dp lock gpu` (сам скрипт замок не берёт); дисплей `DISPLAY=:0`, профиль Godot — временный в
  `<out_dir>`; окно 1920×1080 во весь экран, VSync и предел кадров сняты (как PF-1).
  Код выхода 0 — замер годен; ≠ 0 — нет (Godot упал, автопилот сел до отметки и т. п.).
- Итог: `<out_dir>/summary_<пресет>_<место>.json`, один объект:

| ключ | тип | единицы | смысл |
|---|---|---|---|
| `schema` | str | — | `"perf_check/1"` |
| `preset`, `loc`, `commit`, `adapter`, `size` | str | — | пресет, место, `git rev-parse --short HEAD`, видеокарта, размер окна `"WxH"` |
| `gpu_ms_cockpit`, `gpu_ms_60` | float | мс | GPU окна на паузе, отметки 2 с (кабина) и 60 с (сзади), опыт base |
| `clouds_ms_cockpit`, `clouds_ms_60` | float | мс | проход «Post Transparent Compositor Effects» там же |
| `grass_ms` | float | мс | цена травы: base − nograss на фоне выключенного облачного эффекта, кабина (0 на low) |
| `frame_ms_fly`, `gpu_ms_fly` | float | мс | средний кадр по стене / GPU в полёте без паузы |
| `frame_ms_1pct_fly` | float | мс | среднее 1 % худших кадров полёта по стене |
| `max_hitch_ms`, `max_hitch_ms_after2s` | float | мс | самый долгий кадр полёта; то же без первых 2 с сим.времени полёта |
| `air_recompute_frame_ms` | float \| null | мс | средний кадр во время пересчёта поля в полёте (null — пересчёт не застали) |

- Отсутствующее значение — `null`, ключ всё равно есть. Числа — из замера, не оценки.
- `tools/bench/perf_check.py <out_dir> --key <ключ> [--preset P] [--loc L]` печатает одно число
  (или `nan` для null, код 1) — для проверок `num:` в карточках.

## PF-К2. Буфер облаков и параметры качества — версия 1

- Владелец: PF-4. Потребители: PF-7 (марш по четвертям), PF-6 (масштаб 3D), PF-10.
- Где: `configs/atmosphere.json → clouds.quality_presets.<low|medium|high>`; применяет
  `CloudLayer.set_quality(q)` → свойства `CloudCompositorEffect`.
- Поля качества (как в коде сейчас, плюс новое): `shadow_map_px`, `shadow_steps`, `coarse_steps`,
  `max_iterations`, `fine_step_per_m`, `fine_step_min_m`, `light_steps`, `detail`, `lowres_scale`
  (доля внутреннего размера 3D по каждой оси, 0 < x ≤ 1), **`max_buffer_px`** (int, пикселей;
  предел площади буфера облаков; 0 — без предела).
- Размер буфера (единственная функция, `CloudCompositorEffect.buffer_size(full: Vector2i) -> Vector2i`,
  статическая, без RD): `full = RenderSceneBuffersRD.get_internal_size()` (после `scale_3d`);
  `s = lowres_scale`; если `max_buffer_px > 0` и `full.x·full.y·s² > max_buffer_px` —
  `s = √(max_buffer_px / (full.x·full.y))`; размер = (max(1, ceil(full.x·s)), max(1, ceil(full.y·s))).
  Пропорции сохраняются; площадь ≤ `max_buffer_px` с точностью до округления вверх (≤ +1 строка/столбец).
- Инварианты: при `full` ≤ 1920×1080 и значениях пресетов предел не срабатывает для low/medium
  (картинка у нас та же, что от одного `lowres_scale`); смена качества на лету пересоздаёт цели.
- Контрактный тест: поля всех трёх качеств есть и нужных типов; `buffer_size` для 1920×1080 и
  3024×1964 по формуле; площадь ≤ `max_buffer_px`.

## PF-К3. Предел пикселей 3D-рендера — версия 1

- Владелец: PF-6. Потребители: `GraphicsPresets.apply_viewport` (игра, меню), `settings_panel.gd`,
  PF-К2 (буфер облаков считается от внутреннего размера — предел PF-К3 уменьшает и его), PF-10.
- Конфиг: `configs/game.json → render_budget_mpx` (float, мегапикселей внутреннего 3D-разрешения;
  0 — без предела; по умолчанию 2,1 ≈ 1920×1080).
- Функция: `GraphicsPresets.budget_scale(size_px: Vector2i, budget_mpx: float) -> float` (статическая)
  = 1,0, если `budget_mpx <= 0` или `size.x·size.y <= budget_mpx·10⁶`; иначе
  `√(budget_mpx·10⁶ / (size.x·size.y))`, не ниже 0,25. `size_px` — размер вьюпорта в физических
  пикселях (на Retina — с учётом масштаба экрана).
- Итоговый масштаб окна: `min(масштаб пресета, budget_scale)`; режим — FSR 1, если итог < 1;
  ручной «Масштаб рендера» пилота (`render_scale_auto=false`) — главнее и предел не применяется.
  Пересчёт при смене размера окна/полноэкранного режима.
- Контрактный тест: 1920×1080, 2,1 → 1,0; 3024×1964, 2,1 → 0,5946 ± 0,001; 3840×2160, 2,1 → 0,5032 ± 0,001;
  budget 0 → 1,0; ключ в `game.json` есть.

## PF-К4. Источники термиков поля воздуха (сборка в рабочем потоке) — версия 1

- Владелец: PF-5. Потребители: `ThermalField` (выбор термиков), `Atmosphere.refresh_now` и PF-8,
  сеть (`air_sources_mask()` ведущего → `set_air_forced()` клиентов).
- Сейчас (код): `ThermalField._update_air()` при смене ключа (уровень поля, подпись маски ведущего)
  синхронно `AirThermals.new().build(f, cfg, forced)` → `air_src`; на время сборки `air_src = null`.
- Становится: сборка — в `WorkerThreadPool` по снимку входов (уровень `WindField` не меняется после
  подачи; `cfg`, `forced`, высоты рельефа — копии или только чтение потокобезопасных данных);
  **`air_src` на главном потоке меняется только целиком и только по готовности**; до готовности —
  прежний `air_src` (или null, если его не было). Устаревшая сборка (ключ сменился, пока считалась) —
  отбрасывается. `_clear_dynamic_caches()` — в момент подмены, не в момент запуска.
- Инварианты: результат сборки в потоке совпадает с синхронной для тех же входов (`mask_bytes()`
  байт в байт, `grid_sig` тот же) — детерминизм сети; поток не трогает дерево сцены и не пишет
  общих данных; выход из места/игры — ждать или бросать задачу без утечки.
- Контрактный тест: сборка в потоке и синхронная на одном поле → одинаковые `mask_bytes()` и
  `grid_sig`; пока сборка идёт, `air_src` — прежний объект.
