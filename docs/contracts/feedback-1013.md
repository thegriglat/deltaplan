## FBW-К2 v2
Изменено в v2 (13.10, одобрено главной сессией): вода — исключение из «H ≤ 0»: поток по water_flux (T воды − T воздуха), без солнца; суша — как в v1; рождений термиков нет нигде, включая воду.

Время суток и высота солнца для притока тепла и термиков.
- Владелец: FBW-1. Потребители: `WeatherModel.derive(…, час)` (ход дня), `SurfaceHeat` (K↓, H), `SurfaceHeating`/`Terrain.set_class_sun` (запаздывание прогрева), `AirRuntime` (вход решателя при пересчёте), термики масштаба 2 (`AirThermals`) и аналитические (`thermal_field.gd`).
- Часы игры (`settings.start_hour`, `sky.clock`) — **поясное время места**: `utc_offset_h` локации, нет — `round(lon/15)`, `world.json → time.utc_offset_h` как сейчас (`SunClock`). Единственный источник высоты солнца — `SunClock.solar_position(lat, lon, день_года, часы)` (или та же функция с тем же соглашением); ни один потребитель не трактует час как солнечное время, UTC или «типичный день» без даты и широты.
- Высота солнца ψ ≤ 0 → K↓ = 0; на всех классах суши H ≤ 0 (включая запаздывание прогрева); вода — по water_flux (T воды − T воздуха), без солнца (тёплое озеро вечером даёт H > 0 — это физика, не обрезать); новые термики (пузыри, источники) не рождаются нигде, включая воду; живущие дожимают свой цикл распада, не дольше своей обычной жизни.
- Облачность (`sky` погоды) уменьшает K↓ на всех путях (поле и аналитика) один раз, без двойного учёта.
- Единицы: часы — float, 0…24, поясное время; ψ — градусы; H — Вт/м²; w — м/с.
- Инвариант для теста: 15.10, 20:00 поясного, широты 40–60° (долготы мест игры) — ψ < 0, H ≤ 0 по всем классам суши (вода — по water_flux), рождений термиков 0 за 10 мин игрового времени после старта; 15.07, 13:00, ясно — H > 0 и термики есть.
