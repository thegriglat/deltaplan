# Контракты модуля crash-reports

## CR-К1 Документ диагноза (версия 1)
Владелец — координатор; авторы — исполнители CR-1…CR-3; потребитель — координатор (карточки правок).

Файл `docs/research/crash-reports/cr-<n>.md`, frontmatter по правилам `docs/` (`type: research`, `status: active`, `module: crash-reports`, `area: release`). Обязательные разделы (заголовки второго уровня, ровно так):
- `## Отчёты` — номера issues, версия (хеш коммита и тег), GPU, API рендера, стадия; общие признаки группы.
- `## Механизм отчёта` — что значат «стадия», «хвост лога», когда отчёт создаётся (по коду сборщика отчётов) — коротко, со ссылкой `файл:строка`.
- `## Причина` — место в коде (`файл:строка` на коммите версии), цепочка событий до обрыва, доказательство: воспроизведение, лог или логический вывод; степень уверенности (`подтверждено` | `вероятно` | `гипотеза`) и что её ограничивает. Если в группе несколько причин — подраздел на каждую.
- `## Исправлено ли в main` — `да` (коммит) | `нет` | `частично`, с доказательством по истории git.
- `## Воспроизведение` — команда/сценарий на Linux (RTX 4070 SUPER, Vulkan; D3D12 недоступен) или почему нельзя; что воспроизвелось.
- `## Предложение правки` — что менять (файлы, функции), тест на воспроизведение, риск; без кода правки.

Скрипты воспроизведения — `tools/research/crash-reports/cr-<n>/`, команда запуска — в документе.

### Приватность (инвариант)
Репозиторий публичный. В репозиторий (документы, скрипты, отчёт задачи) — только: номера issues, версия/хеш, модель GPU, ОС, API, стадия, настройка graphics, текст ошибок движка/игры и `файл:строка`, числа (время стадии, VRAM). Нельзя: координаты, названия/идентификаторы мест (`pt_…`), IP/пути пользователя, дословные куски лога длиннее строки ошибки, данные о процессоре/RAM конкретного пилота. Сырые отчёты — только вне репозитория: `~/.cache/dp-crash-reports/` (не коммитить).

### Контрактный тест
Проверки карточек CR-1…CR-3: наличие всех разделов (`grep -c`), отсутствие координат и `pt_` (`grep -E`), `.dpcli/dpcli docs check`.

## CR-К2 GpuHealth — признак отказа видеокарты (версия 2)
Владелец — CR-5; потребители — CR-6 (AirRuntime), CR-8 (сообщение игроку). Основание — решение пользователя 2026-10-23: при потере видеокарты не отключать расчёт молча, а сообщить игроку.

Файл `scripts/core/gpu_health.gd` (+ `.uid`), `class_name GpuHealth`, только статические члены, без автозагрузки:
- `static func report_failure(source: String, detail: String) -> void` — первый вызов: запоминает `source` (напр. `"AirGpu.buffer"`), `detail` (текст ошибки/размер), время `Time.get_ticks_msec()`; одна строка `printerr("GPU: отказ ресурса: <source>: <detail>")`; последующие — только счётчик (в лог не пишут).
- `static func is_failed() -> bool`, `static func source() -> String`, `static func detail() -> String`, `static func count() -> int`.
- `static func reset() -> void` — только для тестов.
- Инвариант: сам ничего не отключает и UI не показывает; потоко-безопасен для вызова из потока задачи (запись — под `Mutex`).
- Когда вызывать: пустой RID из `RenderingDevice` (буфер, текстура, набор uniform, конвейер, шейдер) или отказ `sync`/`submit` в коде расчёта ветра; не вызывать на штатном отсутствии GPU (headless, `RenderingServer.get_rendering_device() == null`) — это не отказ.

- (v2, отчёт #18 2026-10-23: потеря устройства D3D12 без GPU-ветра) Второй источник — журнал движка: узел/логгер `scripts/core/gpu_loss_logger.gd` (владелец CR-8) через `OS.add_logger` (класс `Logger` Godot 4.5+) ловит сообщения движка с признаками потери устройства — `0x887a0005`, `0x887a0006`, `0x887a0007`, `DEVICE_REMOVED`, `DEVICE_HUNG`, `DEVICE_RESET`, `VK_ERROR_DEVICE_LOST` — и вызывает `GpuHealth.report_failure("engine", <первая строка>)`. Логгер вызывается из любых потоков: только запись под `Mutex`, без UI.

Контрактный тест — `tests/atmosphere/test_air_gpu_invalid.gd` (CR-5): буфер заведомо невозможного размера → `GpuHealth.is_failed()`, `count() >= 1`, одна строка в логе.

## CR-К3 Выбор драйвера рендера и выбор после обрыва (версия 3)
Владелец — CR-8; потребитель — CR-9 (манифест itch), CR-7 (отчёт показывает драйвер). Основание — решение пользователя 2026-10-23.

- Хранение: `game.json` → `display.rendering_driver`: `"auto"` (по умолчанию, ничего не задаёт) | `"vulkan"` | `"d3d12"` | `"metal"`. Применение до старта движка — файл переопределения настроек проекта в `user://` (механизм Godot `application/config/project_settings_override`), строка `rendering/rendering_device/driver.<os>=…`; для `"auto"` файл удаляется. Если механизм не работает в 4.7.2 — исполнитель CR-8 сообщает `contract:` с замером, не обходит молча.
- Приоритет: `--rendering-driver` в командной строке перекрывает сохранённый выбор (поведение Godot); действия itch с явным драйвером — разовые.
- Альтернатива для предложения: Windows `vulkan` ↔ `d3d12`; macOS `metal` ↔ `vulkan`; Linux — альтернативы нет (сообщение без переключения).
- Перезапуск: `OS.set_restart_on_exit(true, <аргументы запуска без --rendering-driver>)` + выход из дерева.
- Текущий драйвер — `RenderingServer.get_current_rendering_driver_name()`.
- (v2, ответ Q1 2026-10-23) Окно после обрыва: если прошлый сеанс оборвался на стадии `wind` (ожидающий отчёт `CrashReport`) или в этом сеансе `GpuHealth.is_failed()` — окно с выбором, по порядку: 1) «Сменить драйвер на Y и перезапустить» — первым, рекомендуемым (нет альтернативы, Linux — пункта нет); 2) «Упрощённый ветер (без GPU)» — `UserSettings.save_patch("atmosphere", {"air_model": {"enabled": "off", "off_reason": "crash"}})`; 3) «Попробовать снова» — ничего не меняет. Выбор сохраняется (драйвер — п. выше; ветер — `atmosphere.air_model`). Окно — один раз на обрыв, не на каждый запуск.
- Пометка: пока `atmosphere.air_model.off_reason == "crash"` и `enabled == "off"`, в стартовом меню видна строка «Ветер упрощён: прошлый расчёт оборвался» с кнопкой «Вернуть расчёт» (пишет `enabled: "auto"`, удаляет `off_reason`). Ручной выбор «упрощённый» в настройках `off_reason` не ставит.
- (v3, отчёт #18) Окно после обрыва показывается и при любой стадии, если в хвосте лога прошлого сеанса (ожидающий отчёт `CrashReport`) есть признак потери устройства из CR-К2 v2; в текущем сеансе — по `GpuHealth.is_failed()` от любого источника (AirGpu или журнал движка). Окно — один раз за сеанс.
