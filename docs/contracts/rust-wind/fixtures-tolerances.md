# W8. Фикстуры T1 и допуски (v3)

Часть `docs/contracts/rust-wind.md` (версия — там, заголовок W8). Менять — только координатор.
Владелец — RW-1 (снимает на текущем коде до правок атмосферы), RW-2 (второй набор — по слагаемым W7). Потребители — `cargo test` (RW-6…12), GDScript-тесты T7.
**Опорная ревизия GD-ветра** (решение пользователя 2026-10-29, без смены версии): `feature/rust-wind` `c591b1026` — последняя ревизия с полем Пикара на GPU и всеми слагаемыми на GDScript до выноса в крейт (RW-7b отключает GPU-путь). Недостающие эталоны (новые случаи, дампы внутренних величин) снимаются по мере нужды из рабочей копии на этой ревизии (`git worktree add <путь> c591b1026`), генератором `tools/wind_fixtures/` той же ревизии или скриптом задачи; заранее не добираются. Ревизия — в `generator`/`manifest` эталона.
**Генераторы удалены** (решение пользователя 2026-10-30, RW-13 `a5d9387c3`, RW-14e; без смены версии): GD-код ветра и погоды, снимавший эталоны, удалён; эталоны остаются файлами (`rust/dp-air/tests/data/*`, `tests/fixtures/wind/`), в `manifest.json` — `generator_removed_at`. Новые эталоны с GD-стороны — только из рабочей копии на опорной ревизии (выше); правка эталона под изменённую физику крейта — задачей с обоснованием в отчёте, не молча.

**Формат** (`tests/fixtures/wind/`, json + двоичный f32 LE, как R1 picard-rs: GDScript пишет, Rust читает без зависимостей; запись — во временный файл и переименование):
- `places/<имя>.json` + `.bin` — `AirPlaceData` (W5): заголовок; в `.bin` подряд `heights` (int16 со смещением `h_offset` и шагом `h_scale` из заголовка, ≤ 0,1 м), `water` u8, `cls` u8, `moist` u8 (×1/255). Мест — 2: синтетическое (аналитический мир `atmo_fingerprint.gd`) и одно реальное с полем (предложение — Онгудай, как в air-cascade). Всё в git ≤ 20 МБ; больше — локально, путь и команда пересъёмки в `tests/fixtures/wind/README.md`.
- `cases/<имя>.json` — `{version: 1, place, conditions (W5), seed, static_thermals, configs_sha1: {имя: sha1}, times_s: [..], focuses: [[x,y,z,w]..], points: [[x,y,z]..], point_tags: [..], terms: [..] | null, generator: "<коммит>"}`; `point_tags` из набора `ground, lee, thermal, field_edge, above_base, storm, wave, far`.
- `cases/<имя>.bin` — f32 LE `[time][point][k][4]`: `k = 0` — итог `(vx, vy, vz, σ)` `SAMPLE_FULL`, `k = 1` — `SAMPLE_MEAN`, `k ≥ 2` — слагаемые по `terms` (второй набор).
- `cases/<имя>.desc.json` — описания W6 на каждый `t`: `cores`, `clouds`, `crests`, `cloudbase_msl`.
- Случаев — не меньше 6: слабый/средний/сильный ветер, термики днём, гроза, волна; каждый на 3 момента (старт, +15 мин после пересчёта, +60 мин).
- RW-1 идёт до RW-2 (`AirPlaceData` ещё нет): генератор пишет поля W5 сам — из `AirRuntime.place_of` (`air_runtime.gd:270`: `detail` `HeightLayer`, `water`, `surface`, `loc`, `start_sites`) для реального места и из аналитического мира для синтетического.
- Генератор — `tools/wind_fixtures/gen_fixtures.gd` (headless, под `lock cpu`); повторный запуск на той же ревизии даёт побитно те же файлы.

**Допуски T1** (решение вопроса 3 плана; Rust против фикстуры GDScript, по точке и моменту):
| Величина | Допуск |
|---|---|
| итог `SAMPLE_MEAN` и детерминированные слагаемые (аналитика, гребень, термики, гроза, волна, облака) | `|Δv| ≤ 0,05 м/с + 2 % |v_ref|` по каждой компоненте |
| слагаемое поля Пикара | поле — допуски air-cascade («Допуски сверки»: `u_rel ≤ 1e-3`, `th_abs ≤ 0,05 К`) после одинакового числа итераций; в точке — `|Δv| ≤ 0,1 м/с + 3 %` (другой решатель и критерий, `tol_scale = 5`) |
| σ | `|Δσ| ≤ 0,02 м/с + 5 %` |
| итог `SAMPLE_FULL` | при воспроизведённом шуме — как `SAMPLE_MEAN`; при заменённом шуме (вопрос 5 плана) — поточечно не сравнивается, только T3 (статистика) и `SAMPLE_MEAN` |
| ядра | тот же набор (по id или ближайшему): число равно; место `≤ max(25 м, 2 % radius)`; `w`, `radius` `≤ 3 %`; `top` `≤ 10 м`; `stage` `≤ 0,05` |
| облака | число равно; центр `≤ 50 м`; база/верх `≤ 10 м`; `growth/decay` `≤ 0,05` |
| база облаков | `≤ 5 м` |
| доля точек вне допуска | 0 (поточечно); исключение — точка, где расхождение объяснено высотой рельефа (W5: билинейно по 25 м против `terrain.height_at`), отмечается в отчёте с числом |

Допуск, который не сходится по честной причине (другой решатель, растр вместо `terrain.height_at`), — `contract:` с замером, W8 v2. Подгонять реализацию под фикстуру вне физики нельзя.

**v2 (2026-10-29: ответ пользователя на Q1; итоги RW-6z, RW-U1, RW-U2; предложения RW-8a).** Дополняет таблицу выше; где расходится — действует v2.

*Поле Пикара против запечённого поля (T1 полей, `rust/dp-air/tests/acceptance.rs` `t1_*`) — по классам клеток уровня.* Числа в отчёте — абсолютные: max |Δ| и rms в м/с (θ′ — К), доля клеток вне допуска по классу; «× допуска» — только рядом.
| класс клетки | что это | допуск u, v, w_mech, w_conv |
|---|---|---|
| `mech` | клетка замороженной колонны (маска заморозки своего решения: с нагревом — для u, v, w_conv, θ′; без нагрева — для w_mech) | `|Δ| ≤ 1 % |U_loc| + 0,01 м/с` |
| `conv` | незамороженная клетка решения, сошедшегося у крейта и у эталона; статус эталона неизвестен — считается «сошёлся» | `|Δ| ≤ 1e-3·u0 + полкванта f16` (как v1) |
| `nonconv` | незамороженная клетка решения, не сошедшегося у крейта или у эталона (статус эталона записан) | `|Δ| ≤ 15 % |U_loc|` |

`|U_loc|` — горизонтальная скорость эталона в клетке, `u0` — max |(u, v)| уровня эталона; полкванта f16 — от максимума канала уровня. θ′ во всех классах — `0,05 К + полкванта` (v1). Сошлось — `Converged` (у крейта — `Solved`, у эталона — ключ `solver` уровня, ниже). Расхождение `mech` 0,6–0,7 % |U| над рельефом (thermal_slope, RW-U2 № 6) не разбирается (решение пользователя 2026-10-29).

*Статус решателя эталона.* Перепечатанные поля пишут в `meta` уровня необязательный ключ `solver: {heat: {stop, iters, div_rms}, mech: {stop, iters, div_rms}}`; нет ключа — статус неизвестен. Поля игры печатались без него.

*Эталоны с известной ошибкой GPU* как есть не сверяются: `training_island/landing_hill` — насыщение веса F в f32 (RW-U1); эталон — перепечатка CPU-путём фаз (`air_phase_cpu.gd`, f64) на опорной ревизии со статусом решателя (решение координатора 2026-10-29). `volcano_island/thermal_slope` — каналы заморозки решения с нагревом (RW-U2; крейт по W11 v11 сознательно иной): сверяются `mech` и решение без нагрева (`w_mech`); `conv`/`nonconv` решения с нагревом — только в отчёте числами, не FAIL.

*Предложения RW-8a (этап 3):*
- **ядра:** число может отличаться на ≤ 2 на момент и ≤ 3 % суммарно по случаю (дискретные решения порогов); каждое несовпавшее ядро — в отчёте (id, место, w, какое решение разошлось). Допуски совпавших — таблица v1.
- **точки `above_base` и до 250 м под базой облаков** сверяются только после RW-11 (облака в крейте); до того — пропуск, число пропущенных — в отчёте.
- **режим `off`** (`air_model.enabled = off`, поле не считается) — отдельный случай фикстур (RW-2c) в формате v1; допуски — как `SAMPLE_MEAN`.
- **эталон погоды** — `cases/<имя>.weather.json` рядом со случаем: `{version: 1, generator, derive: {<поле WeatherModel.derive>: число | массив}, day: {<час>: {<поле AtmoDay>: число | массив}}}`, имена полей — как в GDScript; допуск `|Δ| ≤ 1e-6 + 1e-5·|ref|` (детерминированные формулы, f64 у обеих сторон). Снимает задача, которой эталон нужен (опорная ревизия, выше); другое имя поля или единица — `contract:`.

**Скорость** (бенч `cargo bench`, release-профиль W9; игровой замер — под `lock gpu`): `sample_many` 18 точек ≤ 50 мкс, 1000 точек ≤ 2 мс (один вызов, главный поток); `advance_to` ≤ 0,5 мс; базовая линия — `rust/dp-air/benches/baseline.json` (снимает RW-4 на `Calm`, RW-6…12 обновляют на `Formula`); регрессия > 20 % от базовой — FAIL.

**v3 (2026-10-29, решение пользователя: упрощённый режим ветра убрать).** Случай режима `off` (`synth_off`, RW-2c) удаляется из эталонов вместе с тестами, которые его сверяют; пункт v2 «режим `off`» не действует.
