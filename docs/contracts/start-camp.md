# Контракты модуля start-camp

Общее: мир Godot — метры, +Y вверх, вперёд модели −Z; координаты мира (x, z) на земле — `Vector2(x, z)`.
Всё у старта — **детерминированно** от сида конфига, места (округление 0,5 м) и курса старта (округление 1°);
не зависит от погоды, часа, игрока, числа ботов (кроме числа палаток = 1 + боты, как было). Менять интерфейс —
только через координатора (версия +1, потребители правятся в том же шаге). Контрактный тест — владелец,
отдельный файл `tests/contracts/test_start_camp_contracts_k<n>.gd` (headless, ломается при смене формы).

## SC-K1 v1 — зона старта
Владелец: координатор (правила), реализация — SC-1 (палатки), SC-2 (вещи). Потребители: SC-1, SC-2, SC-3,
`BotPilots.find_spots`, `NetQueue.spots_for`.
- Оси старта (как `BotPilots.find_spots`): `h = deg_to_rad(heading_deg)`, `fwd = Vector2(sin h, −cos h)`
  (курс разбега, ветер — в лицо), `right = Vector2(cos h, sin h)`; для точки `p`: `rel = p − s`,
  `along = rel·fwd`, `lat = rel·right`.
- **Коридор разбега**: `along > −8` и `|lat| < corridor_half_width_m + 2` (`bots.json → launch`, 9 м) —
  ничего статичного (палатки, вещи, крылья). Впереди линии старта (`along > 0`) — тоже ничего.
- **Точка готовности** `s − fwd·ready_behind_m` (2 м): свободный круг 5 м.
- **Пятачок вещей** (SC-2): центры вещей в 6–28 м от старта, `along ≤ −3`, вне коридора; уклон под вещью
  ≤ `start_gear.max_slope_deg`, не на бровке, не в лесу/воде/застройке/тропе/камнях (те же запреты, что у
  палаток: `WorldObjects._camp_env`).
- **Кольцо лагеря** (SC-1): центр лагеря 30–50 м от старта (`tents.distance_m`, `prefer_distance_m` 40), край
  пятна любой палатки ≥ `tents.camp_min_edge_m` (32 м) от старта — пятачок вещей и лагерь не пересекаются
  по построению; `along ≤ −5` (позади или сбоку, не впереди), вне коридора; центр палатки не ниже старта
  более чем на `tents.max_drop_m` (5 м) — не вниз по склону; ровно, не у обрыва (как было). Мест нет —
  кольцо расширяется ступенями `tents.distance_steps_m` ([60, 80, 150]); прямоугольник мест ожидания
  ботов **больше не запрет** для палаток.
- **Боты** ждут вне палаток и вещей: `place_camp` вызывается до `BotPilots.setup_in_world`; `find_spots`
  получает `obstacles` = камни/кусты/деревья + `ObstacleIndex.points_near(c, r, ["tent", "gear"])` (SC-K2);
  в сети `NetQueue.spots_for` — тот же набор (одинаковые места у всех).

## SC-K2 v1 — снаряжение у старта (`StartGear`) и препятствия
Владелец: SC-2 (`StartGear`), SC-1 (`ObstacleIndex.points_near`). Потребители: SC-1, SC-3, боты, столкновения.
- `scripts/world_objects/start_gear.gd`, `class_name StartGear extends RefCounted`:
  - `static func plan(start: Vector3, heading_deg: float, cfg: Dictionary, env: Dictionary) -> Array[Dictionary]`
    — чистая функция; `cfg` = `configs/world_objects.json → start_gear`; `env` — как у `TentCamp.plan`
    (`height_fn` обязателен; `blocked_fn`, `lines`, `points`, `points_fn` — по возможности).
  - элемент: `{kind: String, variant: String, position: Vector3, basis: Basis, yaw: float, color: int,
    radius_m: float, box: Vector3}`:
    - `kind` ∈ `wing` (собранное крыло), `kit_bundle` (трубы с парусом в рулоне на чехле), `kit_frame`
      (трапеция на земле), `bag` (чехол крыла), `harness` (рюкзак/подвеска), `helmet`, `bottle`;
    - `variant` — для `wing` id конфига крыла (`configs/wings/<id>.json`, модель — его поле `model`), иначе
      префикс ноды в glb (SC-K3: `wing_bag_long`, `harness_pack`, …);
    - `position` — начало модели в мире (у вещей — на земле, у крыла — `HangPoint`); `basis` — поворот в мире
      (курс + наклон по рельефу; у крыла — поза «на штанге носом в землю»), без масштаба; `yaw` — рад вокруг
      +Y (−Z модели → направление); `color` — индекс палитры `start_gear.colors` (−1 — без тона);
    - `radius_m` — круг пятна (зазоры, трава SC-K6); `box` — `Vector3(полуширина x, полудлина z, высота)`
      коробки препятствия в осях вещи, `Vector3.ZERO` — не препятствие (шлем, бутылка).
  - Постоянный набор на старт (числа — `start_gear.counts`, выбор внутри — от сида): крыльев 2–4, `kit_bundle` +
    `kit_frame` — 1 пара (рядом, ≤ 4 м), чехлов 3–6 (кучкой, часть — у крыльев), рюкзаков/подвесок 2–4, шлемов
    1–3, бутылок 2–5. Места нет — меньше, без ошибки. Правила места — SC-K1 (пятачок вещей).
  - Крыло: нос (передний конец киля) и концы базовой штанги (колёса, если есть) на земле ±0,05 м; нос в
    сторону `fwd` ±12° (носом в ветер); крылья не пересекаются (круг `span/2`, зазор ≥ 0,5 м).
  - `static func build_node(items: Array, cfg: Dictionary) -> Node3D` — визуал: мелочь — MultiMesh на
    вариант × LOD (`visibility_range`), крылья — `glider_<id>.glb` (трапеция и каркас дальше
    `wing_detail_m` не рисуются, всё крыло — дальше `wing_visibility_m`); тени — как у палаток, без новых
    каскадов. Нет glb SC-K3 — временные меши тех же размеров (капсула, коробка, полусфера, цилиндр).
  - Бюджет на один старт (замер в отчёте SC-2): вблизи (< `wing_detail_m`) ≤ 70 тыс. треугольников
    (крылья 12,5–14 тыс.), вдали (> `wing_detail_m`) ≤ 40 тыс.; вызовов отрисовки мелочи ≤ 20.
- `WorldObjects`: `var start_gear: Array` — по старту локации (порядок `start_sites`) свой `Array[Dictionary]`;
  строится в `build()` для всех стартов; узел `StartGear_<i>`.
- Препятствия: крылья, `kit_*`, чехлы — `ObstacleIndex.add_box(..., "gear")` по `box` (столкновение —
  `crash_obstacle`, как у незнакомого вида).
- `ObstacleIndex.points_near(c: Vector2, r: float, kinds: PackedStringArray) -> Array[Vector3]` (владелец SC-1):
  описанные круги препятствий этих видов, пересекающие круг (c, r): `Vector3(x, z, радиус)` — формат
  `BotPilots.obstacles_near`.

## SC-K3 v1 — модели вещей у старта и полусобранного аппарата
Владельцы: SC-6 (`start_gear.glb`), SC-7 (`glider_kit.glb`). Потребитель: SC-2.
- Скрипты Blender 4.3 (`bl_util.py`, как `build_tents.py`): `tools/blender/build_start_gear.py` →
  `assets/models/world/start_gear.glb` (+ `assets/source/world/start_gear.blend`),
  `tools/blender/build_glider_kit.py` → `assets/models/world/glider_kit.glb` (+ `.blend`).
- Ноды: меши `<вариант>_LOD0` (ближний) и `<вариант>_LOD1` (дальний, грубый силуэт), на верхнем уровне.
- Оси: вперёд −Z (у длинных вещей длина вдоль Z, «перёд» — нос чехла/крыла, верх рюкзака), +Y вверх, начало —
  центр пятна на земле, нижняя точка y = 0 (до −0,02). Метры.
- `start_gear.glb`, варианты (размеры ±10 %; треугольники LOD0 / LOD1):
  - `wing_bag_long` — чехол крыла 5,6 м, сечение ~0,34 × 0,28 м (лежит, чуть приплюснут), неровный от труб
    внутри, торцы скруглены, молния по верху, 3–4 ручки-стропы; ≤ 700 / ≤ 60;
  - `wing_bag_short` — короткий пакет 4,2 м, то же сечение; ≤ 600 / ≤ 60;
  - `harness_pack` — рюкзак с подвеской, лежит на спине, 0,85 × 0,45 × 0,32 м, лямки сверху; ≤ 500 / ≤ 40;
  - `harness_open` — подвеска-кокон, вытряхнута и лежит плашмя, ~1,9 × 0,6 × 0,15 м, лямки, карабин; ≤ 700 / ≤ 40;
  - `helmet` — открытый шлем стоя, 0,29 × 0,23 × 0,20 м; ≤ 400 / ≤ 30;
  - `bottle` — бутылка 1,5 л на боку, Ø 0,09 × 0,33 м; ≤ 150 / ≤ 16.
- `glider_kit.glb`, варианты:
  - `kit_bundle` — сложенный каркас (передние кромки, киль, поперечина пучком ~5,5 м, торцы труб видны, кингпост
    рядом) с парусом в рулоне вокруг, на расстёгнутом раскрытом чехле (~5,6 × 0,9 м, края загнуты);
    ≤ 2500 / ≤ 150;
  - `kit_frame` — трапеция плашмя: стойки 1,65 м, базовая штанга 1,4 м, узел вершины, колёса на концах штанги
    (детали — `frame_parts.py`, `wheel_parts.py`), вершина к −Z; ≤ 2000 / ≤ 100.
- Материалы (имена — контракт; в glb — разумный `StandardMaterial3D`, игра заменяет по имени):
  `Fabric` — ткань с тоном экземпляра (SC-K5 `bag`), `FabricDark` — тёмная ткань без тона (SC-K5 `fabric_dark`),
  `Sail` — парус в рулоне с тоном (SC-K5 `sail`), `Webbing` — стропы, `Shell` — пластик шлема с тоном экземпляра,
  `Tube`, `Fitting`, `Steel`, `Tire` (общая текстура шины 256² — как у колёс крыльев), `Bottle`, `Cap`.
  Тон — `COLOR` экземпляра MultiMesh (SC-K5), поэтому в одном варианте с тоном — один тонируемый материал
  (кроме `Fabric` + `Webbing`/`FabricDark`). Цвета вершин в моделях — нет.
- UV для ткани не нужны (SC-K5 — проекция в осях объекта); текстуры — только `Tire`. Файл glb ≤ 250 КБ.
- Без логотипов и брендов. Контрактные тесты — у каждого владельца свой: `test_start_camp_contracts_k3_gear.gd`
  (SC-6), `test_start_camp_contracts_k3_kit.gd` (SC-7): ноды, оси/размеры по AABB, бюджеты, имена материалов.

## SC-K4 v1 — модель человечка у лагеря
Владелец: SC-8. Потребитель: SC-5 (`EggPeople`).
- `tools/blender/build_camp_person.py` → `assets/models/world/camp_person.glb` (+ `.blend`).
- Пять мешей на верхнем уровне, у каждого своё начало — шарнир (поза покоя, рост 1,75 м, лицом к −Z):
  `Legs` — начало (0, 0, 0) на земле между стоп, от подошв до таза 0,95 м, с обувью;
  `Torso` — начало (0, 0,95, 0) таз, до основания шеи 1,50 м (куртка/рубашка, воротник);
  `Head` — начало (0, 1,50, 0), шея, голова, волосы/кепка, макушка 1,75 м;
  `ArmR` — начало (+0,22, 1,42, 0) плечо, рука висит вдоль −Y, длина до кончиков пальцев 0,62 м, кисть;
  `ArmL` — зеркально, (−0,22, 1,42, 0). Поднимание руки — поворот вокруг оси Z шарнира (как `EggPeople`).
- Материалы: `Cloth` — одежда с тоном экземпляра (SC-K5 `cloth`: штаны на `Legs`, рубашка на `Torso`/`Arm*`),
  `SkinTint` — лицо/шея с тоном экземпляра (цвет кожи), `Skin` — кисти (фиксированный тон), `Hair`, `Shoes`.
  На меш — не больше одного тонируемого материала. Цвета вершин и UV — не нужны.
- Бюджет: всё ≤ 900 треугольников (`Head` ≤ 250, `Arm*` ≤ 100 каждая), один LOD. Формы — простые, но не
  капсулы: силуэт куртки и штанов, кисти, обувь, кепка/волосы. glb ≤ 80 КБ.
- Контрактный тест `test_start_camp_contracts_k4.gd`: ноды, начала шарниров ±0,02 м, рост, бюджет, материалы.

## SC-K5 v1 — ткань лагеря (шейдер)
Владелец: SC-4. Потребители: SC-2, SC-5, `TentCamp`, модели SC-K3/SC-K4 (имена материалов).
- `assets/shaders/camp/camp_fabric.gdshader` (spatial) + помощник `scripts/world_objects/camp_fabric.gd`,
  `class_name CampFabric`: `static func material(preset: String) -> ShaderMaterial` — один общий материал на
  пресет (кэш), пресеты: `tent`, `tent_door` (темнее), `bag`, `fabric_dark` (без тона), `sail`, `cloth`.
- Тон: итоговый цвет ткани (sRGB 0..1) = `base_color × COLOR.rgb × tint`, где `COLOR` — цвет экземпляра
  MultiMesh (`use_colors`; без них — белый), `instance uniform vec3 tint` (по умолчанию белый) — для
  отдельных `MeshInstance3D` (палатки). Пресет `fabric_dark` тон не берёт (`use_color = false`).
  Палитры в конфигах — sRGB 0..1; перевод в линейный — в шейдере.
- Узор и рельеф — в осях объекта (`VERTEX` до трансформации экземпляра; UV не нужны): рипстоп/плетение,
  складки и провис (нормаль), пыль снизу (`dirt_height_m` в осях объекта), матовая (`roughness` ~0,8–0,9,
  у `sail` глаже). Текстуры — ≤ 512², CC0 (строка в ASSETS.md), VRAM-сжатие + мипмапы, общие для всех
  пресетов. Без прозрачности (`alpha`), `cull_disabled` — по пресету.
- Контрактный тест `test_start_camp_contracts_k5.gd`: шейдер компилируется, пресеты есть, `tint` — instance
  uniform, `fabric_dark` без тона, повторный вызов возвращает тот же материал.

## SC-K6 v1 — примятая трава
Владелец: SC-3. Потребители: `WorldLink`/`Game` (подключение), PH-4 (`trample_at` — по желанию, для звука).
- `GrassField`:
  - `func set_trample_mask(img: Image, origin: Vector2, cell_m: float) -> void` — `img` формата `FORMAT_R8`
    (0 — нетронута, 255 — примята до земли), тексель (i, j) покрывает мир x ∈ [origin.x + i·cell, +cell),
    z ∈ [origin.y + j·cell, +cell); `null` — снять маску. Применяется ко всем материалам поля (`materials()`,
    включая дальний слой).
  - `func trample_at(x: float, z: float) -> float` — 0..1 (билинейно, вне маски 0) на CPU.
- `WorldObjects.trample_mask(start: Vector3, size_m: float = 256.0, cell_m: float = 0.5) -> Dictionary` —
  `{image, origin, cell_m}`: палатки (пятно — ~0,9, кольцо спада ~1,5 м), тропинки от палаток к старту
  (ширина ~0,8 м, ~0,6), пятна вещей SC-K2 (`radius_m` + 0,5 м, ~0,7), круг разбега/ожидания у старта
  (~6 м, ~0,5), тропа к старту `StartTracks` (ширина конфига, ~0,5; T-23). Пересчёт при `place_camp`.
- Шейдер (`grass.gdshader`): в маске трава ниже (до `trample_height_k`), наклонена в сторону, чуть желтее.
  Вне маски — без изменений (пиксель в пиксель с прежним). `grass_field.gd` — только добавления (PH-4).
- Контрактный тест `test_start_camp_contracts_k6.gd`: формат, привязка тексель ↔ мир, `trample_at` на
  краях и вне маски.
