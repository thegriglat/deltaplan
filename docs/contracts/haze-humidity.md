# Контракты haze-humidity

Контрактные тесты — `tests/contracts/test_haze_humidity_contracts.gd` (версии — константы в тесте, проверка заголовков
этого файла). Стыки волны 2 (чтение сетки в `WeatherModel`, эталоны погоды, дымка, пропускание) — дописываются сюда до
своих задач, после шлюза волны 1.

## HH1. Сетка климата точки росы (v1)

Владелец: HH-1 (запекание, `tools/research/haze_humidity/dew_point/`). Потребители: HH-4 (чтение в игре), контрактный тест.

**Файл:** `res://data/climate/dew_point_1deg.bin` (каталог `data/` входит в экспорт, `export_presets.cfg → include_filter`).
Пишется один раз: во временный файл рядом, затем переименование. Размер — ориентир ≤ 1 МБ (шлюз волны 1 — если больше).

**Порядок байтов** — little-endian. **Заголовок — 64 байта:**

| смещение | тип | поле | значение v1 |
|---|---|---|---|
| 0 | 4 × ASCII | `magic` | `HHTD` |
| 4 | u16 | `version` | 1 |
| 6 | u16 | `codec` | 1 = brotli (единственный в v1; Godot: `PackedByteArray.decompress(raw_size, FileAccess.COMPRESSION_BROTLI)`) |
| 8 | u16 | `nlon` | 360 |
| 10 | u16 | `nlat` | 180 |
| 12 | u16 | `nmonth` | 12 |
| 14 | u16 | `reserved` | 0 |
| 16 | f32 | `lon0_deg` | −179.5 — долгота центра столбца 0 |
| 20 | f32 | `lat0_deg` | −89.5 — широта центра строки 0 |
| 24 | f32 | `dlon_deg` | 1.0 |
| 28 | f32 | `dlat_deg` | 1.0 |
| 32 | f32 | `td_scale` | °C на единицу int16 (> 0; выбирает владелец, напр. 0.01) |
| 36 | f32 | `td_offset` | °C |
| 40 | f32 | `sd_scale` | К на единицу int16 (> 0) |
| 44 | f32 | `z_scale` | м на единицу int16 (> 0) |
| 48 | u32 | `raw_size` | байт после распаковки = 2·(2·nmonth·nlat·nlon + nlat·nlon) |
| 52 | u32 | `comp_size` | байт сжатых данных; размер файла **ровно** 64 + `comp_size` |
| 56 | u32 | `year0` | первый год климатологии источника |
| 60 | u32 | `year1` | последний год (включительно) |

**Данные** (байты 64…64+comp_size) — один поток brotli; после распаковки — три блока int16 подряд:
1. `TD` — nmonth·nlat·nlon: средняя за месяц точка росы на 2 м, °C, на средней высоте ячейки источника:
   `td_c = raw·td_scale + td_offset`.
2. `SD` — nmonth·nlat·nlon: σ среднесуточной точки росы вокруг средней месяца (дни этого месяца, все годы
   климатологии), К: `sd_k = raw·sd_scale`, `sd_k ≥ 0`.
3. `Z` — nlat·nlon: средняя высота ячейки по орографии источника (к ней отнесена `TD`), м над морем: `z_m = raw·z_scale`.

**Оси и индекс:** `i` — столбец, долгота центра `lon0 + i·dlon`, растёт на восток; `j` — строка, широта центра
`lat0 + j·dlat`, растёт на **север** (j = 0 — юг); `m` — месяц, 0 = январь. Индекс в блоках `TD`/`SD`:
`(m·nlat + j)·nlon + i`; в блоке `Z`: `j·nlon + i`. Значение ячейки — среднее по ячейке (не в узле), месяц — средняя за
календарный месяц (относится к середине месяца).

**Отсутствие данных:** raw = −32768 (только если в источнике у ячейки нет значения; суша мира должна быть покрыта
полностью). Читатель: пропуск → берёт ближайшую ячейку с данными той же строки, иначе — ошибка загрузки в лог и
поведение «без сетки» (решается контрактом чтения, волна 2).

**Инварианты:** все `td_c` ∈ [−80, 40] °C; `sd_k` ∈ [0, 20] К; `z_m` ∈ [−500, 7000] м; `raw_size` совпадает с
формулой; распаковка в Godot даёт ровно `raw_size` байт. Атрибуция и лицензия источника — в
`tools/research/haze_humidity/dew_point/README.md` (в игру — по шлюзу волны 1: `ASSETS.md`).

**Контрактный тест** (`tests/contracts/test_haze_humidity_contracts.gd`): версия HH1 в заголовке этого файла;
`Godot` распаковывает brotli (эталонный поток в тесте); если файл сетки есть — заголовок, размер файла, `raw_size`,
распаковка, диапазоны значений по всем ячейкам (нет файла — проверка формата пропускается: сетку кладёт HH-1).

## HH2. Сетка климата верхнего воздуха 700 гПа (v1)

Владелец: HH-1b (запекание, `tools/research/haze_humidity/upper_air/`). Потребители: HH-4 (замена
`configs/weather_model.json → upper_air.temp_c` и `upper_air.z_msl_m` климатом места), контрактный тест. Решение
пользователя 2026-10-21: верхний воздух — из ERA5 по месту и месяцу, в волне 2 вместе с точкой росы.
`upper_air.lapse_k_per_km` (градиент выше перемешанного слоя) остаётся в конфиге — в сетку не входит.

**Файл:** `res://data/climate/upper_air_1deg.bin`. Пишется один раз (временный файл + переименование). Размер ≤ 2 МБ.
Порядок байтов, оси, индекс, сжатие, значение ячейки и месяца — **как в HH1** (ячейка 1°, центр столбца 0 — −179.5°,
строка 0 — юг, индекс `(m·nlat + j)·nlon + i`, brotli). **Заголовок — 64 байта:**

| смещение | тип | поле | значение v1 |
|---|---|---|---|
| 0 | 4 × ASCII | `magic` | `HHUA` |
| 4 | u16 | `version` | 1 |
| 6 | u16 | `codec` | 1 = brotli |
| 8 | u16 | `nlon` | 360 |
| 10 | u16 | `nlat` | 180 |
| 12 | u16 | `nmonth` | 12 |
| 14 | u16 | `level_hpa` | 700 — уровень давления |
| 16 | f32 | `lon0_deg` | −179.5 |
| 20 | f32 | `lat0_deg` | −89.5 |
| 24 | f32 | `dlon_deg` | 1.0 |
| 28 | f32 | `dlat_deg` | 1.0 |
| 32 | f32 | `t_scale` | °C на единицу int16 (> 0) |
| 36 | f32 | `t_offset` | °C |
| 40 | f32 | `z_scale` | м на единицу int16 (> 0) |
| 44 | f32 | `z_offset` | м |
| 48 | u32 | `raw_size` | = 2·(2·nmonth·nlat·nlon) |
| 52 | u32 | `comp_size` | размер файла **ровно** 64 + `comp_size` |
| 56 | u32 | `year0` | первый год климатологии |
| 60 | u32 | `year1` | последний год (включительно) |

**Данные** — один поток brotli; после распаковки — два блока int16 подряд, каждый nmonth·nlat·nlon:
1. `T` — средняя за месяц температура воздуха на уровне `level_hpa`, °C: `t_c = raw·t_scale + t_offset`.
2. `Z` — средняя за месяц высота этого уровня над морем (геопотенциал / 9.80665), м: `z_m = raw·z_scale + z_offset`.

**Отсутствие данных:** не допускается (уровень давления есть над всей Землёй; под рельефом — экстраполяция источника,
как в ERA5). Значение −32768 — ошибка формата.

**Инварианты:** все `t_c` ∈ [−60, 30] °C; `z_m` ∈ [2000, 3500] м; `raw_size` по формуле; распаковка в Godot — ровно
`raw_size` байт. Атрибуция и лицензия — в `tools/research/haze_humidity/upper_air/README.md` (тот же источник, что HH1).

**Контрактный тест** (`tests/contracts/test_haze_humidity_contracts.gd`, `test_upper_air_format`): если файл есть —
заголовок, размер, `raw_size`, распаковка, диапазоны по всем ячейкам; нет файла — пропуск (сетку кладёт HH-1b).

## HH3. Густота дымки по влажности (v1)

Владелец: HH-6. Потребители: `Game._apply_haze` → `SkyEnvironment.set_haze_density` (как сейчас), HH-7 (аэрозоль в
пропускании — через материал дымки, см. HH4), HH-4 (меняет только источник Td, формулу не трогает). Основание — HH-2
(`tools/research/haze_humidity/haze/README.md` → «Предложение»), ответ пользователя на Q1 (2026-10-21).

**Конфиг** `configs/weather_model.json → haze_humidity`: `gamma` 0.6 (Zieger 2013), `rh_dry` 0.40, `rh_max` 0.95 (с
`_doc` и источником). Удаляются без остатка: `diurnal.evening_haze_k`, поле `haze_k` в `sky.*` (в т. ч. `overcast` ×1,3)
и `sky.fields_doc` про него; «к вечеру гуще» и «пасмурно мутнее» — только через RH (Td, разброс Td по облачности — HH-4).

**Функция** `WeatherModel.haze_k_rh(t_c: float, td_c: float, cfg: Dictionary = {}) -> float`:
`RH = e_s(Td)/e_s(T)`, `e_s(x) = 6.1094·exp(17.625·x/(x + 243.04))` (Магнус, Alduchov–Eskridge 1996, над водой при любой T);
`RH_c = clamp(RH, rh_dry, rh_max)`; `haze_k = ((1 − RH_c)/(1 − rh_dry))^(−gamma)`. Td > T → RH = 1 → `rh_max`.
Значения: RH ≤ 0,40 → 1,0; RH 0,85 → 2,30 (±0,01); RH ≥ 0,95 → 4,44 (±0,01).

**Выход** `WeatherModel.derive` (оба режима: `hour` = NAN и час): `w.haze_k = haze_k_rh(T, Td)`, где T — температура
этого часа (`_derived.temperature_c`), Td — `_derived.dew_point_c`; новое поле `_derived.rh` (0..1, до зажима).
Смысл `haze_k` прежний: множитель ослабления мутного слоя к `configs/world.json → haze.visibility_km` (60 км —
видимость сухого воздуха, RH ≤ 0,40); `SkyEnvironment` не меняется.

**Контрактный тест** — `tests/contracts/test_haze_humidity_hh3.gd` (пишет HH-6): три опорных значения `haze_k_rh`;
`derive` даёт `haze_k == haze_k_rh(_derived.temperature_c, _derived.dew_point_c)` и `_derived.rh`; в конфиге нет
`evening_haze_k` и `sky.*.haze_k`.

## HH4. Пропускание атмосферы для света облаков (v1)

Владелец: HH-7. Потребители: шейдеры облаков (`cloud_common.gdshaderinc` и оба хоста: `cloud_volume.gdshader`,
compute `cloud_raymarch_cs`), `CloudLayer`/`CloudCompositorEffect` (параметры). Рельеф, небо, `DirectionalLight3D`,
`configs/world.json → time.light` — не меняются.

**Таблица** — `Image.FORMAT_RGBF` (или RGBH), ширина `n_el` × высота `n_h` (по умолчанию 64 × 64), фильтр линейный,
края — clamp. Ось u (столбец) — высота солнца над математическим горизонтом точки от `el_min_deg` −8° до `el_max_deg`
+30° равномерно; ось v (строка) — высота точки от 0 до `h_max_m` 16000 м над морем равномерно. Значение — пропускание
T(λ) ∈ [0, 1] по каналам R, G, B (λ = 680, 550, 440 нм) вдоль луча от точки к солнцу в сферической атмосфере
(R⊕ = 6 371 000 м): Рэлей β_R(λ) ∝ λ⁻⁴ (β_R(550) = 1,16·10⁻⁵ м⁻¹ у моря, шкала высот 8 000 м) + аэрозоль мутного слоя —
ослабление `extinction` материала дымки (`SkyEnvironment.haze_material().get_shader_parameter("extinction")`, м⁻¹ на
550 нм, уже × `haze_k`) × `configs/world.json → haze.extinction_rgb`, постоянное от земли до
`SkyEnvironment.get_haze_top_msl()`, выше — 0. Луч, задевающий сферу уровня моря, — T = 0 (рельеф не учитывается).
Озон и многократное рассеяние не учитываются (граница модели — в отчёте и руководстве).

**Свет на облаке:** `sun_l(точка) = sun_toa · T(el_sun, y_точки) / T_ref`, где `sun_toa` — белый (цвет и энергия
солнца в зените без атмосферы, параметр), `T_ref = T(35°, долина места)` — нормировка: днём (солнце ≥ 35°) у основания
облака свет совпадает с нынешним `sun_color · sun_energy` (± 5 % по каналам). Солнце ниже горизонта земли (свет рельефа
погас) — облака выше точки касания ещё освещены; облака не освещаются, если T = 0.
Таблица пересчитывается при смене `extinction`/верха дымки больше чем на 5 % и при старте; не каждый кадр.

**Параметры** (`configs/world.json → clouds` или блок `sun_transmission` — выбирает владелец, с `_doc`): `n_el`, `n_h`,
`el_min_deg`, `el_max_deg`, `h_max_m`, β_R(550), шкала высот, длины волн.

**Контрактный тест** — `tests/contracts/test_haze_humidity_hh4.gd` (пишет HH-7): размер и формат таблицы; T ∈ [0, 1];
T(B) ≤ T(G) ≤ T(R) в каждой ячейке; T растёт с высотой точки и с высотой солнца; при el = 0°, у моря, без аэрозоля
−ln T(G) совпадает с аналитикой (функция Чепмена при 90°: β_R(550)·H·√(π·R⊕/(2H)) ≈ 3,29) ± 5 %; солнце в зените, у моря — −ln T(G) = β_R(550)·H ± 2 %; точка на 3 000 м при el = −2° — T > 0.

## HH5. Сетка климата температуры у земли: дневной максимум и суточная амплитуда (v1)

Владелец: HH-1e (запекание, `tools/research/haze_humidity/surface_t/`). Потребители: HH-4 (замена
`configs/weather_model.json → typical_max_c` и `diurnal.range_k` климатом места), контрактный тест. Ответ пользователя
на Q2 (2026-10-21): все климатические таблицы «одна на все места» — из ERA5, если данные есть.

**Файл:** `res://data/climate/surface_t_1deg.bin`, ≤ 2 МБ, запись — временный файл + переименование. Порядок байтов,
оси, индекс, сжатие, значение ячейки и месяца — **как в HH1**. Высота, к которой отнесены значения, — средняя высота
ячейки `Z` из HH1 (`dew_point_1deg.bin`; та же орография ERA5, в этот файл не дублируется). **Заголовок — 64 байта:**

| смещение | тип | поле | значение v1 |
|---|---|---|---|
| 0 | 4 × ASCII | `magic` | `HHST` |
| 4 | u16 | `version` | 1 |
| 6 | u16 | `codec` | 1 = brotli |
| 8 | u16 | `nlon` | 360 |
| 10 | u16 | `nlat` | 180 |
| 12 | u16 | `nmonth` | 12 |
| 14 | u16 | `steps_per_day` | сроков в сутках, по которым найден максимум/минимум (24 — по часам) |
| 16 | f32 | `lon0_deg` | −179.5 |
| 20 | f32 | `lat0_deg` | −89.5 |
| 24 | f32 | `dlon_deg` | 1.0 |
| 28 | f32 | `dlat_deg` | 1.0 |
| 32 | f32 | `tx_scale` | °C на единицу int16 (> 0) |
| 36 | f32 | `tx_offset` | °C |
| 40 | f32 | `dtr_scale` | К на единицу int16 (> 0) |
| 44 | f32 | `reserved` | 0 |
| 48 | u32 | `raw_size` | = 2·(2·nmonth·nlat·nlon) |
| 52 | u32 | `comp_size` | размер файла **ровно** 64 + `comp_size` |
| 56 | u32 | `year0` | первый год климатологии |
| 60 | u32 | `year1` | последний год (включительно) |

**Данные** — один поток brotli; после распаковки — два блока int16 подряд, каждый nmonth·nlat·nlon:
1. `TX` — средний за месяц суточный максимум температуры на 2 м, °C: `tx_c = raw·tx_scale + tx_offset`.

Сутки — местные (по долготе ячейки), не UTC. Если сроков меньше 24 — поправка на недобор максимума/минимума
(оценённая на годах с часовыми данными) уже внесена; величина — в README владельца.

**Отсутствие данных:** не допускается (−32768 — ошибка формата).

**Инварианты:** `tx_c` ∈ [−70, 55] °C; `dtr_k` ∈ [0, 30] К; `raw_size` по формуле; распаковка в Godot — ровно `raw_size`.

**Контрактный тест** (`tests/contracts/test_haze_humidity_contracts.gd`, `test_surface_t_format`): если файл есть —
заголовок, размер, `raw_size`, распаковка, диапазоны; нет файла — пропуск (сетку кладёт HH-1e).
