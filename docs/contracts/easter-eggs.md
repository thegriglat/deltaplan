## К1. Планировщик ↔ Game (владелец E0)

- `class_name EasterEggs extends Node3D` — `scripts/world_objects/easter_eggs.gd`; узел
  `Game/EasterEggs`, создаётся в `Game._ready()` (как `Bots`, `WorldLink`).
- **Ход — только кадром**: `EasterEggs._process(dt)` → `update()`. Из `Game.tick()` (шаг
  физики) планировщик не вызывается и сам ничего в шаге физики не делает. Тесты, отключившие
  `process_mode`, зовут `update()` вручную.
- **Активен только в полёте**: `game.settings != null and game.flying_enabled`. В меню, на
  загрузке и на паузе (`game.is_paused()`) — не бросает кубик; в меню и на загрузке детей нет.
- **Время** — `game.world_time()` (с, время атмосферы; в сети — часы зоны). Не `sim_time_s`,
  не накопленный `dt`. Всё, что видно, — функция этого времени (скачок времени в сети —
  пасхалка сразу в нужном месте своей траектории).
- `reset()` — убрать всех детей и забыть расписание; зовётся из `Game.start()` и
  `Game.restart()`. После него набор активных пасхалок восстанавливается из времени мира.
- `force(id: String, delay_s := 0.0)` — вызвать пасхалку `id` (или `"all"` — все включённые)
  через `delay_s` с времени мира: **без кубика и без условий** (`can_appear` не спрашивается).
  Для кадров и тестов.
- `active() -> Array[EasterEgg]` — живые пасхалки (для `--look-at=egg` и тестов).
- `step(ctx: EggContext)` — тот же ход без Game (тесты); `update()` строит контекст из Game и
  зовёт `step`. Для тестов открыты `cfg`, `enabled` (подменять), `spawn_log` (`[id, t0]`),
  `roll_count`.

## К2. Контекст пасхалки — `EggContext` (владелец E0)

`class_name EggContext extends RefCounted` — `scripts/world_objects/egg_context.gd`.
Планировщик заполняет один раз за `update()` и отдаёт всем пасхалкам. **Только чтение.**

| Поле | Тип | Смысл, единицы |
|---|---|---|
| `t` | float | время мира, с (К1) |
| `hour` | float | час по часам места (`game.sky.clock.hour`), 0–24 |
| `to_sun` | Vector3 | единичный вектор к солнцу, мир (Y вверх); `y < 0` — солнце под горизонтом |
| `world_key` | String | ключ мира (`game.world_key()`): сид, место, дата, погода |
| `camera` | Camera3D | текущая камера (может быть `null` headless) |
| `pilot_pos` | Vector3 | положение крыла игрока, мир, м |
| `weather` | Dictionary | погода атмосферы (`air.weather`) — не менять, не хранить ссылку дольше кадра |
| `cloudbase_msl` | float | кромка облаков над уровнем моря, м (`air.get_cloudbase_msl()`, нет — NAN) |
| `graphics` | String | пресет графики: `low` / `medium` / `high` |
| `height_at` | Callable(x: float, z: float) -> float | высота рельефа, м |
| `cloud_density_at` | Callable(p: Vector3) -> float | плотность облака в точке, 0–1 (нет — всегда 0) |
| `terrain` | Terrain | рельеф и слои OSM — **только чтение** (E6, E7, E8, E10) |
| `air` | Node3D | воздух — **только чтение**; `air_velocity_at` можно звать, только если К7 зелёный с этим вызовом (E9) |

Координаты — мировые Godot (м, Y вверх, начало — центр локации), как во всём проекте.

## К3. Пасхалка — `EasterEgg` (владелец E0; реализуют E1–E11)

`class_name EasterEgg extends Node3D` — `scripts/world_objects/easter_egg.gd`. Каждая пасхалка —
скрипт `scripts/world_objects/easter_eggs/<id>.gd` (при необходимости сцена
`scenes/world_objects/easter_eggs/<id>.tscn`), ассеты — `assets/easter_eggs/<id>/`.

- `static func can_appear(ctx: EggContext, cfg: Dictionary) -> bool` — условия (ночь, погода,
  геометрия); дёшево; по умолчанию `true`.
- `func begin(ctx: EggContext, cfg: Dictionary, rng: RandomNumberGenerator, t0: float) -> void`
  — все случайные параметры (направление, высота, цвет…) — **только** из `rng` и только здесь;
  `t0` — время мира появления.
- `func update(ctx: EggContext) -> bool` — поставить себя в момент `ctx.t` (функция
  `ctx.t - t0` и параметров); `false` — кончилась, планировщик удаляет (`queue_free`).
- `cfg` — свой блок `configs/easter_eggs.json → eggs.<id>`.
- `lifetime_s` (в блоке, обязателен): жизнь, с; планировщик удаляет по нему и `update() == false`;
  `0` — постоянная до `reset()`.

**Запрещено** в коде пасхалки и её поддереве:
- `PhysicsBody3D`, `Area3D`, `CollisionShape3D`, `RayCast3D`; запись в `ObstacleIndex`,
  `world_link.objects`, `collisions`;
- глобальный генератор: `randf`, `randi`, `randf_range`, `randi_range`, `randfn`, `randomize`,
  `seed`, `Array.shuffle`, `Array.pick_random` — только свой `rng`;
- запись в чужие узлы и объекты (air, glider, terrain, bots, sky, stats, camera, Engine,
  `Engine.time_scale`); вызов методов, меняющих их состояние;
- тексты, подсказки, HUD, сигналы в игру;
- тени у дальних мешей (дальше ~1 км — `cast_shadow = SHADOW_CASTING_SETTING_OFF`).

Разрешено: свои меши, частицы, шейдеры, анимации; свой `AudioStreamPlayer3D` на шине
`Ambient` (audio.json → buses.ambient); реакция на положение игрока/камеры **только анимацией
самой пасхалки** (E6 разбегаются, E8 машут).

## К4. Расписание и детерминизм (владелец E0)

Режим пасхалки — `eggs.<id>.mode`:

- `"interval"` — время мира делится на окна по `slot_s` с; окно `n = floor(t / slot_s)`:
  `rng.seed = ("%s|%s|%d" % [world_key, id, n]).hash()`; появление, если
  `rng.randf() < slot_s / mean_interval_s`, в момент `t0 = (n + rng.randf()) * slot_s`, если
  в `t0` выполнено `can_appear`. Дальше тот же `rng` уходит в `begin`.
- `"per_flight"` — один бросок на полёт: `rng.seed = ("%s|%s|flight" % [world_key, id]).hash()`;
  появление с вероятностью `chance`, в момент `t0 = rng.randf_range(window_s[0], window_s[1])`
  от начала мира полёта (если выполнено `can_appear`).
- `"condition"` — без кубика: раз в `check_s` с `can_appear`; появилась — живёт, пока
  `update` не вернёт `false` (E5 — пока условие держится). `rng.seed = ("%s|%s|%d" % [world_key,
  id, floor(t0)]).hash()`.
- `force` — `rng.seed = ("%s|%s|force" % [world_key, id]).hash()`.

Порядок: в `interval` первый `randf` — появление, второй — фаза `t0` в окне; в `per_flight`
первый — шанс, потом `randf_range(window_s)`. `can_appear` спрашивается в первый кадр, когда
планировщик увидел `t ≥ t0` (строго «в `t0`» — только при мелком шаге). Если вся жизнь пасхалки
прошла до первого взгляда (прыжок времени) — она не создаётся.

Инварианты: одно и то же `(world_key, id, окно)` → те же `t0` и параметры на любой машине и
при любом шаге кадра; другой сид → другое расписание; прыжок во времени (сеть) даёт то же, что
прогон подряд (пасхалка, чья жизнь ещё идёт, появляется посреди траектории). Траектории
«через всё небо» (E1–E3, E9) — в мировых координатах от центра локации или от заданной точки
мира, **не от пилота**, чтобы у двоих в зоне было одно и то же. Локальные по смыслу (E5 от
камеры, реакции E6/E8) — от игрока, это только картинка.

## К5. Конфиг `configs/easter_eggs.json` (владелец E0; блок `eggs.<id>` — задача пасхалки)

```
{
  "_doc": "...",
  "enabled": true,            "enabled_doc": "...",   // false — планировщик ничего не делает
  "force": "",                "force_doc": "...",     // то же, что --egg (ниже)
  "eggs": {
    "_doc": "...",
    "<id>": {
      "_doc": "...",
      "enabled": true,        "enabled_doc": "...",
      "script": "res://scripts/world_objects/easter_eggs/<id>.gd",  "script_doc": "...",
      "mode": "interval",     "mode_doc": "...",       // interval | per_flight | condition
      "slot_s": 60,  "mean_interval_s": 300,           // interval
      "chance": 0.3, "window_s": [60, 1800],           // per_flight
      "check_s": 1.0,                                  // condition
      "lifetime_s": 20,                                // обязательно; 0 — постоянная
      "...свои поля": ...     // у каждого — "<поле>_doc" (смысл и единицы)
    }
  }
}
```
У каждого поля — `<поле>_doc`, у каждого объекта — `_doc`. Блок каждой пасхалки добавляет её
задача; остальное меняет только E0/координатор.

## К6. Форс для кадров — ключ запуска (владелец E0)

- `--egg=<id>[:<через_с>][,<id2>[:<с>]…]` (или `all`) — `EasterEggs.force(...)` в начале
  полёта и после «Ещё раз»; то же — `configs/easter_eggs.json → force` (если `--egg` не задан;
  `--egg=none` — ничего). По имени форсится и выключенная (`enabled: false`) пасхалка, `all` —
  только включённые; при общем `enabled: false` форс тоже не работает.
- `--gpu-report=<метка>` — перед снимком 2 с мерит кадр и печатает
  `EGG_GPU_MS <метка> <мс GPU> draws <вызовы отрисовки> prims <примитивы>` (средние за кадр).
- `--look-at=egg` — камера кабины смотрит на первую живую пасхалку; `--look-at=egg:<id>` — на
  живую пасхалку с этим id (добавлено в E7).
- `--fov=<°>` — вертикальный угол зрения активной камеры поверх настройки (2–100°, в user:// не
  пишется) — только для кадров дальних пасхалок.
- Скрипт кадров `tools/shots/easter_egg_shot.sh <id> <файл.jpg> [аргументы игры…]` — главный
  сцены с `--autostart --autopilot --egg=<id> …`, окно 1920×1080, под
  `flock -w 1800 /tmp/heat_ca_gpu.lock` (не мешать исследованиям на GPU); умолчания
  `--egg=<id>:5 --time=12 --look-at=egg --gpu-report=<id>`, аргументы после них перекрывают;
  тот же запуск с `--egg=none` — база для разницы. Файл кадра — абсолютным путём в основную копию:
  `build/screenshots/easter_eggs/<№>_<имя>.jpg` (не в git).

## К7. Тест «не трогает физику» (владелец E0; каждая пасхалка обязана держать его зелёным)

`tests/world_objects/test_easter_eggs.gd`:

1. **Физика побитно.** Главная сцена `--autostart` (сид из atmosphere.json), автопилот,
   `game.process_mode = DISABLED`, `Game.tick(1/120)` вручную 90 с, `EasterEggs.update()` каждый
   4-й шаг. Прогон A — `enabled = false`; прогон B — `force("all")` в начале (каждая новая
   пасхалка, добавленная в конфиг, попадает сюда сама). Раз в 1 с записать: положение, скорость
   и ориентацию крыла игрока, положения ботов, `air.air_velocity_at` в 8 фиксированных точках
   (у старта, 0–1500 м над рельефом). Сравнение — `==` (побитно), не допуск.
   Сначала — база: два прогона A подряд совпадают побитно; если нет — это не допуск, а шлюз
   координатору.
2. **Жизнь**: у каждой пасхалки `force(id)` → появилась в дереве → `update` до конца →
   удалена не позже `lifetime_s` (+1 с) из её блока; постоянные (`lifetime_s = 0`) —
   удаляются `reset()`.
3. **Запреты**: после `force("all")` и нескольких `update` в поддереве `EasterEggs` нет
   `CollisionObject3D`, `CollisionShape3D`, `RayCast3D`; в исходниках
   `scripts/world_objects/easter_eggs/*.gd` нет вызовов глобального генератора (К3, по
   регулярному выражению: не через `rng.`).
4. **Расписание**: один ключ мира → один и тот же список `(id, t0)` за 0–7200 с при шаге 1/30
   и 5 с и при прыжке; другой сид → другой список.
5. **Конфиг**: у каждого поля `_doc`; `mode` из трёх; `script` грузится и `extends EasterEgg`.
6. **Меню**: пока не в полёте — детей нет, кубик не бросается.

7. **Боты и ключ мира (v5)**: в прогоне B `game.bots.agents.size()` и `game.world_key()` (в начале
   и в конце) те же, что в A. Боты в журнале — только `game.bots.agents` (боты пасхалок туда
   не попадают, К9).

## Цена (не тест, приёмка каждой пасхалки)

«Высокий» пресет, ≤ 0,2 мс GPU на все живые одновременно; в покое — ноль узлов под `EasterEggs`.
Время GPU между запусками шумит на ~1 мс (E0: проба 8,71, база 9,50) — сильнее цены лёгкой
пасхалки. Поэтому в отчёте: разница `draws` и `prims` с пасхалкой и без (почти детерминированы)
и медиана `EGG_GPU_MS` по 3 парам запусков (с / без). Приёмка — по устройству: несколько вызовов
отрисовки, дальние меши без теней, без полноэкранных проходов и без постоянных частиц в покое;
медиана разницы GPU — не больше шума.

## К8. Место и условия — `EggPlace` и поля контекста (v4, владелец E0б; потребители E3, E6–E11)

Требование пользователя: пасхалка появляется только там и тогда, где она логична («не запускать
кукурузник на Эльбрусе»). Условия каждой — таблица в плане. Проверка — только по имеющимся
данным (рельеф, карта поверхности WorldCover, OSM локации, погода прогноза, часы), дёшево;
новых систем и данных не строить — чего нет, то упростить до высоты + поверхности + времени.

**Новые поля `EggContext`** (заполняет планировщик, только чтение):

| Поле | Тип | Смысл, единицы |
|---|---|---|
| `month`, `day` | int | дата полёта (`sky.clock`) |
| `sun_elev_deg` | float | высота солнца над горизонтом, ° (из `to_sun`) |
| `sky` | String | облачность прогноза: `clear` / `partly` / `overcast` |
| `wind_ms` | float | ветер у земли по прогнозу, м/с |
| `wind_from_deg` | float | откуда ветер, ° (0 — с севера, 90 — с востока), как в прогнозе пилота; при «ветре в старт» (`settings.wind_into_launch`) — курс выбранного старта (уточнение 01.10, смысл поля прежний) |
| `temp_c` | float | температура днём по прогнозу, °C |
| `lat_deg` | float | широта места, ° (`sky.clock.latitude_deg`; < 0 — южное полушарие, сезоны зеркально); v9, поставщик EE-6; по умолчанию 45 |
| `place` | EggPlace | место (ниже); `null` — рельеф не загружен (тесты без мира) |

**`class_name EggPlace extends RefCounted`** — `scripts/world_objects/egg_place.gd`. Строится
планировщиком один раз на полёт (после загрузки мира, лениво при первом обращении), дальше —
только чтение; все функции чистые (одинаковы у всех в сети при одном ключе мира).

- `height_at(x, z) -> float` — высота рельефа, м н.у.м.
- `slope_deg_at(x, z) -> float` — крутизна склона, °.
- `surface_at(x, z) -> int` — класс поверхности `SurfaceLayer` (FOREST, GRASS, CROP, SHRUB,
  BARE, WATER, BUILT, SNOW; NONE — нет данных), как `Terrain.surface_at` (круто — BARE).
- `valley_msl() -> float` — «дно» локации: низкий перцентиль высот по грубой сетке (как
  `WeatherModel.ground_context`), м.
- `above_valley_m(x, z) -> float` — высота рельефа над дном, м (горы против долины).
- `is_mountain(x, z) -> bool` — над дном выше порога или круче порога (пороги — в конфиге
  планировщика, `_doc`).
- `places() -> Array[Dictionary]` — «посёлки» места (копия): пятна застройки `BuiltPatches`
  (no-osm N2), `{x, z, radius_m, src: "built"}`, `radius_m` = √(area_m2/π); если пятен нет —
  опорные точки по рельефу `{x, z, radius_m, src: "relief"}` (низко над дном долины, ровно, открытый
  грунт, ближе к воде; не меньше `place.relief_places_min` штук, если такие точки в месте есть).
  Порядок детерминированный; считается один раз на полёт.
- `nearest_place(x, z) -> Dictionary` — ближайший из `places()` + `dist_m`; `{}` — только если
  `places()` пуст (нет рельефа). Имени и населения нет (OSM не используется).
- `near_water_m(x, z) -> float` — до воды, м: класс WATER покрова (WorldCover, маска воды 10 м — канал A,
  no-osm N1) и реки по рельефу (`<слой>_water.png`); точность — клетка
  сетки (10–25 м); дальше `place.water_search_m` — INF.
- Дорог OSM в `EggPlace` нет (`roads`, `road_maybe_near`, `nearest_road_m` удалены): УАЗ ездит по
  бездорожью — маршрут по ровному открытому грунту вдоль долины строит сама пасхалка.
- `start_sites() -> Array[Dictionary]` — старты локации (`Terrain.get_start_sites()`, копия).
- `camp() -> Array[Dictionary]` — лагерь у старта (`WorldObjects.camp`), `[]` — нет.
- `find_point(rng, around: Vector2, radius_m: float, accept: Callable, tries := 48) -> Variant` —
  случайная точка (от `rng`) в круге, для которой `accept.call(x, z)` истинно; `Vector3` на
  рельефе или `null`. Основной способ выбрать место появления.

Правила: всё только чтение (рельеф, покров, WorldObjects не менять); тяжёлое (сетка высот для
`valley_msl`, `places()`) — один раз на полёт, ≤ ~20 мс вместе; вызовы в `can_appear` / `begin` — не
каждый кадр. OSM в `EggPlace` не используется (v4). Нет покрова (`surface_at` → NONE) — пасхалки,
фильтрующие по классу, принимают NONE как открытый грунт и решают по уклону и высоте; пасхалки
появляются и без OSM — без ошибок в логе.

## К9. Другая группа — доп. боты пасхалки (v5, владелец E10)

Решение пользователя: 1–3 доп. бота сразу в воздухе над дальним склоном, дальше — существующая
логика ботов; новой логики не писать. Чтобы это осталось «только картинкой» для игры и сети:

- Пасхалка `group` (`scripts/world_objects/easter_eggs/group.gd`) держит **свой** узел
  `BotPilots` (дочерний, `scripts/game/bot_pilots.gd` без изменений) и настраивает его
  `setup_in_world(terrain, air, старт_дальнего_склона, его_курс, n)` с опцией
  `airborne_share = 1.0` (через `setup(opts)`; при нужде — тот же набор opts, что строит
  `setup_in_world`). `n` ∈ [1, 3] — от `rng` пасхалки; `seed` в opts — от `rng`.
- **Не трогать `game.bots`**: не добавлять агентов, не менять `count`, `others`, `claims`;
  `game.world_key()` (число ботов игры) не меняется. Боты группы не видят ботов игры и наоборот
  (разделение и захват термиков — внутри своего экземпляра). Воздух — только чтение
  (`air_velocity_at`), как у ботов игры.
- **Шаг**: из `update(ctx)` пасхалки (кадр, К1), не из `Game.tick`; фиксированными подшагами
  1/120 с по времени мира (`ctx.t`) — число подшагов `floor(t·120) − уже_сделано`, не больше
  ~0,5 с за кадр (прыжок времени — догнать без вида не требуется: группа локальна). Телеметрия
  игрока в `tick` — `game.glider.get_telemetry()` раз в кадр (только чтение).
- Место: только реальный старт локации (`EggPlace.start_sites()`) дальше ~3 км от выбранного
  игроком, ветер прогноза к курсу того старта ≤ ~45–60°; день, лётная погода. Нет такого
  старта — не появляется.
- Локальная (у каждого пилота своя, в сеть не идёт); `reset()` — `queue_free` узла с ботами.
- Цена — вид ботов существующий (`BotGlider`), ≤ 3 бота.

Контрактная проверка — К7 п. 1 и 7 (боты игры и ключ мира те же, физика побитно) + свой тест E10.

## К10. Участки полей — `FieldPlots` (v7, владелец EE-1; потребители EE-3 рисунки на полях, EE-4 рулоны сена)

Поля в игре рисует шейдер рельефа (`scripts/terrain/terrain_common.gdshaderinc` → `field_plot_color`,
`scripts/terrain/terrain.gdshader` → `field_detail`): прямоугольные участки `field_size_m`
(`configs/world.json`, сейчас 260 × 140 м, восток × юг), ряды участков сдвинуты на 0,37 участка через
каждые 6 рядов; цвет участка — `hash12(cell)`: `fh < 0.45` — `field_color` (спелые колосья),
иначе `mix(луг, сухая трава, fh)`. Пасхалкам нужно знать, где участок и какой он, — **зеркало этой
математики в GDScript**, шейдер рельефа не меняется.

`class_name FieldPlots extends RefCounted` — `scripts/world_objects/field_plots.gd`:

- `static func from_world_config() -> FieldPlots` — размер участка из того же ключа `configs/world.json`,
  что читает рельеф; `func _init(size_m: Vector2)`.
- `static func hash12(p: Vector2) -> float` — та же формула, что в шейдере (`mod 4096`, 0.1031, 33.33).
- `func cell_at(x: float, z: float) -> Vector2i` — участок мировой точки (x — восток, z — юг; те же
  мировые координаты, что `wp.xz` шейдера).
- `func rect(cell: Vector2i) -> Rect2` — участок в мире: `position` = (x_min, z_min), `size` = `size_m`
  (с учётом сдвига ряда).
- `func center(cell: Vector2i) -> Vector2`.
- `func tone(cell: Vector2i) -> float` — `fh` = `hash12(cell)` (как в шейдере).
- `func kind(cell: Vector2i) -> int` — `STANDING` (`fh < 0.45`, колосья), `GREEN` (луг/всходы),
  `MOWN` (сухая трава/стерня, верхняя часть `fh`); порог GREEN/MOWN — константа класса с комментарием
  (по `mix(луг, сухая трава, fh)`).
- `func rows_axis(cell: Vector2i) -> Vector2` — единичный вектор вдоль борозд/колей участка (из
  `field_detail`: `hash12(cell + 19.1)`), для ориентации узоров и рядов рулонов.
- `func brightness(cell: Vector2i) -> float` — множитель `0.85 + 0.3·hash12(cell + 7)`.

Инварианты: функции чистые, без состояния мира (одинаково у всех в сети — координаты мировые); GDScript
считает в float64, шейдер — в float32: у порогов возможны редкие расхождения — потребители берут участки
с запасом от порога (напр. `fh < 0.40` для STANDING) и проверяют, что весь участок — класс CROP
(`EggPlace.surface_at` в центре и углах; NONE — не поле). Поле рисуется только на классе CROP.

Контрактный тест (EE-1) `tests/contracts/test_field_plots_contracts.gd`: значения `hash12` на
наборе точек равны эталону, посчитанному по формуле шейдера (зафиксированы в тесте); точка внутри
`rect(cell_at(p))`; сдвиг рядов; `kind` по порогам; размер из `configs/world.json`.

  шнурка не моделируется).
- Качание — физический затухающий маятник (точечная масса на нерастяжимой нити) от ускорения точки

отклоняется назад (и в бок — в обратную сторону), при постоянной перегрузке n висит вдоль `g − a`,
