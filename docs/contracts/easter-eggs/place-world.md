# Контракты пасхалок: К8–К12: место, группа, поля, рулоны, стёкла

Стыки К8–К12. Вход (правила изменения, общие соглашения, список стыков и частей) — [easter-eggs.md](../easter-eggs.md).

## К8. Место и условия — `EggPlace` и поля контекста (v4, владелец E0б; потребители E3, E6–E11)

Требование пользователя: пасхалка появляется только там и тогда, где она логична («не запускать
кукурузник на Эльбрусе»). Условия каждой — таблица в плане. Проверка — только по имеющимся
данным (рельеф, карта поверхности WorldCover, OSM локации, погода прогноза, часы), дёшево;
новых систем и данных не строить — чего нет, то упростить до высоты + поверхности + времени.

**Новые поля `EggContext`** (заполняет планировщик, только чтение):

| Поле | Тип | Смысл, единицы |
|---|---|---|
| `month`, `day` | int | дата полёта (`sky.clock`) |
| `sun_elev_deg` | float | высота солнца над горизонтом, ° (из `to_sun`) |
| `sky` | String | облачность прогноза: `clear` / `partly` / `overcast` |
| `wind_ms` | float | ветер у земли по прогнозу, м/с |
| `wind_from_deg` | float | откуда ветер, ° (0 — с севера, 90 — с востока), как в прогнозе пилота; при «ветре в старт» (`settings.wind_into_launch`) — курс выбранного старта (уточнение 01.10, смысл поля прежний) |
| `temp_c` | float | температура днём по прогнозу, °C |
| `lat_deg` | float | широта места, ° (`sky.clock.latitude_deg`; < 0 — южное полушарие, сезоны зеркально); v9, поставщик EE-6; по умолчанию 45 |
| `place` | EggPlace | место (ниже); `null` — рельеф не загружен (тесты без мира) |

**`class_name EggPlace extends RefCounted`** — `scripts/world_objects/egg_place.gd`. Строится
планировщиком один раз на полёт (после загрузки мира, лениво при первом обращении), дальше —
только чтение; все функции чистые (одинаковы у всех в сети при одном ключе мира).

- `height_at(x, z) -> float` — высота рельефа, м н.у.м.
- `slope_deg_at(x, z) -> float` — крутизна склона, °.
- `surface_at(x, z) -> int` — класс поверхности `SurfaceLayer` (FOREST, GRASS, CROP, SHRUB,
  BARE, WATER, BUILT, SNOW; NONE — нет данных), как `Terrain.surface_at` (круто — BARE).
- `valley_msl() -> float` — «дно» локации: низкий перцентиль высот по грубой сетке (как
  `WeatherModel.ground_context`), м.
- `above_valley_m(x, z) -> float` — высота рельефа над дном, м (горы против долины).
- `is_mountain(x, z) -> bool` — над дном выше порога или круче порога (пороги — в конфиге
  планировщика, `_doc`).
- `places() -> Array[Dictionary]` — «посёлки» места (копия): пятна застройки `BuiltPatches`
  (no-osm N2), `{x, z, radius_m, src: "built"}`, `radius_m` = √(area_m2/π); если пятен нет —
  опорные точки по рельефу `{x, z, radius_m, src: "relief"}` (низко над дном долины, ровно, открытый
  грунт, ближе к воде; не меньше `place.relief_places_min` штук, если такие точки в месте есть).
  Порядок детерминированный; считается один раз на полёт.
- `nearest_place(x, z) -> Dictionary` — ближайший из `places()` + `dist_m`; `{}` — только если
  `places()` пуст (нет рельефа). Имени и населения нет (OSM не используется).
- `near_water_m(x, z) -> float` — до воды, м: класс WATER покрова (WorldCover, маска воды 10 м — канал A,
  no-osm N1) и реки по рельефу (`<слой>_water.png`); точность — клетка
  сетки (10–25 м); дальше `place.water_search_m` — INF.
- Дорог OSM в `EggPlace` нет (`roads`, `road_maybe_near`, `nearest_road_m` удалены): УАЗ ездит по
  бездорожью — маршрут по ровному открытому грунту вдоль долины строит сама пасхалка.
- `start_sites() -> Array[Dictionary]` — старты локации (`Terrain.get_start_sites()`, копия).
- `camp() -> Array[Dictionary]` — лагерь у старта (`WorldObjects.camp`), `[]` — нет.
- `find_point(rng, around: Vector2, radius_m: float, accept: Callable, tries := 48) -> Variant` —
  случайная точка (от `rng`) в круге, для которой `accept.call(x, z)` истинно; `Vector3` на
  рельефе или `null`. Основной способ выбрать место появления.

Правила: всё только чтение (рельеф, покров, WorldObjects не менять); тяжёлое (сетка высот для
`valley_msl`, `places()`) — один раз на полёт, ≤ ~20 мс вместе; вызовы в `can_appear` / `begin` — не
каждый кадр. OSM в `EggPlace` не используется (v4). Нет покрова (`surface_at` → NONE) — пасхалки,
фильтрующие по классу, принимают NONE как открытый грунт и решают по уклону и высоте; пасхалки
появляются и без OSM — без ошибок в логе.

## К9. Другая группа — доп. боты пасхалки (v5, владелец E10)

Решение пользователя: 1–3 доп. бота сразу в воздухе над дальним склоном, дальше — существующая
логика ботов; новой логики не писать. Чтобы это осталось «только картинкой» для игры и сети:

- Пасхалка `group` (`scripts/world_objects/easter_eggs/group.gd`) держит **свой** узел
  `BotPilots` (дочерний, `scripts/game/bot_pilots.gd` без изменений) и настраивает его
  `setup_in_world(terrain, air, старт_дальнего_склона, его_курс, n)` с опцией
  `airborne_share = 1.0` (через `setup(opts)`; при нужде — тот же набор opts, что строит
  `setup_in_world`). `n` ∈ [1, 3] — от `rng` пасхалки; `seed` в opts — от `rng`.
- **Не трогать `game.bots`**: не добавлять агентов, не менять `count`, `others`, `claims`;
  `game.world_key()` (число ботов игры) не меняется. Боты группы не видят ботов игры и наоборот
  (разделение и захват термиков — внутри своего экземпляра). Воздух — только чтение
  (`air_velocity_at`), как у ботов игры.
- **Шаг**: из `update(ctx)` пасхалки (кадр, К1), не из `Game.tick`; фиксированными подшагами
  1/120 с по времени мира (`ctx.t`) — число подшагов `floor(t·120) − уже_сделано`, не больше
  ~0,5 с за кадр (прыжок времени — догнать без вида не требуется: группа локальна). Телеметрия
  игрока в `tick` — `game.glider.get_telemetry()` раз в кадр (только чтение).
- Место: только реальный старт локации (`EggPlace.start_sites()`) дальше ~3 км от выбранного
  игроком, ветер прогноза к курсу того старта ≤ ~45–60°; день, лётная погода. Нет такого
  старта — не появляется.
- Локальная (у каждого пилота своя, в сеть не идёт); `reset()` — `queue_free` узла с ботами.
- Цена — вид ботов существующий (`BotGlider`), ≤ 3 бота.

Контрактная проверка — К7 п. 1 и 7 (боты игры и ключ мира те же, физика побитно) + свой тест E10.

## К10. Участки полей — `FieldPlots` (v7, владелец EE-1; потребители EE-3 рисунки на полях, EE-4 рулоны сена)

Поля в игре рисует шейдер рельефа (`scripts/terrain/terrain_common.gdshaderinc` → `field_plot_color`,
`scripts/terrain/terrain.gdshader` → `field_detail`): прямоугольные участки `field_size_m`
(`configs/world.json`, сейчас 260 × 140 м, восток × юг), ряды участков сдвинуты на 0,37 участка через
каждые 6 рядов; цвет участка — `hash12(cell)`: `fh < 0.45` — `field_color` (спелые колосья),
иначе `mix(луг, сухая трава, fh)`. Пасхалкам нужно знать, где участок и какой он, — **зеркало этой
математики в GDScript**, шейдер рельефа не меняется.

`class_name FieldPlots extends RefCounted` — `scripts/world_objects/field_plots.gd`:

- `static func from_world_config() -> FieldPlots` — размер участка из того же ключа `configs/world.json`,
  что читает рельеф; `func _init(size_m: Vector2)`.
- `static func hash12(p: Vector2) -> float` — та же формула, что в шейдере (`mod 4096`, 0.1031, 33.33).
- `func cell_at(x: float, z: float) -> Vector2i` — участок мировой точки (x — восток, z — юг; те же
  мировые координаты, что `wp.xz` шейдера).
- `func rect(cell: Vector2i) -> Rect2` — участок в мире: `position` = (x_min, z_min), `size` = `size_m`
  (с учётом сдвига ряда).
- `func center(cell: Vector2i) -> Vector2`.
- `func tone(cell: Vector2i) -> float` — `fh` = `hash12(cell)` (как в шейдере).
- `func kind(cell: Vector2i) -> int` — `STANDING` (`fh < 0.45`, колосья), `GREEN` (луг/всходы),
  `MOWN` (сухая трава/стерня, верхняя часть `fh`); порог GREEN/MOWN — константа класса с комментарием
  (по `mix(луг, сухая трава, fh)`).
- `func rows_axis(cell: Vector2i) -> Vector2` — единичный вектор вдоль борозд/колей участка (из
  `field_detail`: `hash12(cell + 19.1)`), для ориентации узоров и рядов рулонов.
- `func brightness(cell: Vector2i) -> float` — множитель `0.85 + 0.3·hash12(cell + 7)`.

Инварианты: функции чистые, без состояния мира (одинаково у всех в сети — координаты мировые); GDScript
считает в float64, шейдер — в float32: у порогов возможны редкие расхождения — потребители берут участки
с запасом от порога (напр. `fh < 0.40` для STANDING) и проверяют класс CROP (`EggPlace.surface_at`; NONE — не поле): пятна CROP WorldCover мельче участка, поэтому
участок годится по доле точек сетки на CROP (порог — конфиг потребителя), а каждый объект (рулон, горка, круг
рисунка) проверяется на CROP отдельно (уточнение 11.10, находка EE-4). Поле рисуется только на классе CROP.

Контрактный тест (EE-1) `tests/contracts/test_field_plots_contracts.gd`: значения `hash12` на
наборе точек равны эталону, посчитанному по формуле шейдера (зафиксированы в тесте); точка внутри
`rect(cell_at(p))`; сдвиг рядов; `kind` по порогам; размер из `configs/world.json`.

## К11. Модель рулона сена (v7, владелец EE-2; потребитель EE-4)

- Файл `assets/easter_eggs/hay_bales/hay_bale.glb`, генерирует `tools/blender/build_hay_bale.py`
  (headless Blender, как `build_osm_traffic.py`; команда воспроизведения — в шапке скрипта); своя
  модель, в `ASSETS.md` — строка (CC0, собственная).
- Круглый рулон: диаметр 1,5 м, ширина 1,2 м; **ось цилиндра — локальная X**; Y вверх; метры,
  масштаб 1; **начало координат — низ в центре** (точка касания земли: AABB по y от 0 до 1,5,
  по x от −0,6 до 0,6, по z от −0,75 до 0,75), трансформы применены.
- Один меш (`MeshInstance3D` первым в сцене), ≤ 200 треугольников, один материал; цвет — цвета
  вершин или материала (солома, торцы чуть темнее, намотка видна по торцу кольцами), без
  текстур; нормали сглажены по боку, торцы плоские.
- Инвариант для потребителя: рулон на земле — `Transform3D` с поворотом вокруг Y и сдвигом в точку
  рельефа; горка — рулоны друг на друге (второй ярус — на высоте ~1,3 м между двумя нижними).

Контрактный тест (EE-2) `tests/contracts/test_hay_bale_model_contracts.gd`: glb грузится, первый
меш, AABB (1,2 × 1,5 × 1,5 м ± 5 %), min y ≈ 0 (± 2 см), треугольников ≤ 200.
До слияния модели потребитель работает на `CylinderMesh` тех же размеров и оси (подмена — одна строка).

## К12. Стёкла машин — `OsmTraffic.glass()` (v7, владелец EE-5; потребитель — блики EE-5)

- `OsmTraffic` (scripts/world_objects/osm/osm_traffic.gd) добавляет себя в группу `"osm_traffic"`
  (в `_init`/`_ready`) и открывает только чтение:
  `func glass(out_pos: PackedVector3Array, out_n: PackedVector3Array, out_size: PackedFloat32Array) -> int`
  — для каждой видимой машины (активной, масштаб > 0): мировая точка центра лобового стекла,
  единичная внешняя нормаль стекла (по курсу машины и наклону стекла типа, 0 — к небу при
  горизонтали), размер стекла, м (≈ ширина); массивы очищаются и заполняются, возвращает число.
  Состояние трафика не меняет, ≤ O(число машин), без аллокаций сверх массивов вызывающего.
- Наклон стекла по типу — константы/конфиг `world_objects.json → osm_traffic` с `_doc`.
- Потребитель находит узел через `get_tree().get_first_node_in_group("osm_traffic")`; нет узла
  (нет OSM, нет дорог) — бликов машин нет, без ошибок.

Окна домов OSM: блик считается в шейдере стен `scripts/world_objects/osm/building.gdshader` (контракт
L2 модуля osm-look — данные экземпляра **не меняются**, только вывод шейдера на пикселях стекла).

Контрактный тест (EE-5) `tests/contracts/test_traffic_glass_contracts.gd`: трафик на тестовой сети
дорог → `glass()` = числу видимых машин, нормали единичные, точка в пределах длины машины от её центра,
нормаль поворачивается вместе с курсом; вызов не меняет `s`, `v` машин.
