# Контракты модуля «pilot-view»

Внутренний документ. План — `docs/plan/pilot-view.md`. Контрактный тест — `tests/game/test_pilot_view_contracts.gd` (заводит PV-3 для PV1–PV2, PV-5 дописывает PV3). ## PV1. Направление крена — `controls.roll_input` — версия 2 (дополняет У1 v3 из `docs/contracts/ui-controls.md`)

v2 (08.10, по вопросу PV-3: скачок `roll` +0,5 → −0,5 на отрыве при удержании): `roll_input` действует в режиме `weight_shift` и **на земле** (стоя/шагом/разбег) — руки на стойках: трапеция вправо = крыло кренится влево, то же соответствие, что в полёте; на отрыве знак не меняется. Потребители — PV-3.
Владелец: PV-3. Потребители: `InputController` (полёт), панель настроек (`scripts/ui/settings_panel.gd`), `locale/ui.csv`, экран «Управление», `site/content/mechanics/flight.md` и `docs/guide/flight.md` (абзацы о крене), тесты крена.

- `configs/controls.json → roll_input`: `"bar"` | `"body"` (+ `roll_input_doc`). Выбор пилота пишется в `user://configs/controls.json` так же, как `invert_pitch`, и применяется сразу.
  - `"bar"` — устройство двигает **трапецию**: мышь вправо, → и стик вправо = штанга вправо относительно пилота = вес пилота влево = крен влево (`ControlInput.roll` −). Так же, как тангаж уже устроен «по трапеции» (вперёд = от себя).
  - `"body"` — устройство двигает **тело** (поведение до модуля): вправо = вес вправо = крен вправо (`roll` +).
- Действует в режиме `roll_control_mode = weight_shift` — в полёте и на земле (v2); в режиме `rate` (простое/аркадное) — как до модуля, без инверсии. Инвариант: удержание мыши/стрелки вбок через отрыв не меняет знак `roll`. Автопилот и боты не затрагиваются (они в `rate`).
- Одна настройка меняет знак крена для мыши, стрелок и стика разом (как `invert_pitch` для тангажа).
- **Умолчание — `"bar"`** (решение координатора 08.10, обоснование — в журнале `dp log pilot-view`).
- Настройки: строка в разделе управления (рядом с «Управление креном»), выбор из двух вариантов, тексты ru/en в `locale/ui.csv`; без поясняющих подсказок в полёте.
- Инварианты (тест): weight_shift + `bar`: мышь вправо (relative.x > 0), → , стик вправо → `roll` < 0 и крен влево через ≤ 3 с; `body` — наоборот; `rate` — знак не зависит от `roll_input`.

## PV2. X — мышь-трапеция в нейтраль — версия 1
Владелец: PV-3. Потребители: `InputController`, экран «Управление» / `controls.json → keys.center_doc`, тесты крена и центровки.

- Нажатие `center` (X) в полёте **один раз** (достаточно короткого нажатия) обнуляет накопленное положение мыши-трапеции по обеим осям (крен и тангаж) и накопленное положение от стрелок; дальше трапеция плавно идёт в нейтраль (`keyboard.center_time_s`, как было) и **остаётся в нейтрали после отпускания X**, пока пилот снова не сдвинет мышь/стрелки/стик.
- После отпускания X крыло не возвращается к прежнему крену: в weight_shift пилот в центре — крыло само выравнивается и летит прямо; в rate — крен держится у горизонта, как сейчас при удержании.
- Стик — физически возвращается сам; X его не трогает.
- Инвариант (тест): сместить мышь-трапецию на полный ход вбок и вперёд → нажать и отпустить X (одним кадром) → через 3 с `ControlInput.roll` и `pitch` ≈ 0 (|·| < 0,05), крен крыла < 5° и не растёт; движение мыши после X снова двигает трапецию от нейтрали.

## PV3. Изгиб базовой штанги — `glider_params.json` — версия 2 (дополняет A1 v3 и A2 v1)

v2 (08.10, по итогам PV-5): (1) новые маркеры `BarGripL`, `BarGripR` в `.glb` и в заглушке — точки хвата на оси штанги при |x| = `control_frame.bar_grip_hand_x_m` (= `configs/flight.json → visual.arms.bar_grip_half_width_m`, тест); профиль дуги есть только в сборке, игра берёт хваты из маркеров; нет маркера — `push_error`. (2) `bow_m` — вынос **вперёд** (по горизонтали в плоскости штанги); у безмачтовых провис спидбара вниз (`speedbar_dip_m`) — отдельно, не входит в `bow_m`. (3) Общие функции профиля (`basebar_spec`, `bow_at`) — `tools/blender/aframe_geom.py`, их используют сборка и `cockpit_view.py`. Потребители — `GliderVisual.bar_grip()`, `test_basebar_curve`, `test_pilot_arms`, PV-4 (хват/поза).
Владелец данных: PV-2 (исследование, числа и источники); владелец геометрии: PV-5 (`tools/blender/build_gliders.py`, заглушка `scripts/flight/glider_visual.gd → _fallback_wing`). Потребители: сборка `.glb`, `GliderVisual` (IK рук, хваты на штанге), камера/вид из кабины (A3.3), `render_views.py`, тесты крыльев.

- `tools/blender/glider_params.json → wings.<id>.basebar` (обязательно у всех 48 крыльев после PV-2):
  - `shape`: `"straight"` | `"curved"`;
  - `bow_m`: вынос середины оси штанги вперёд относительно прямой между осями штанги в углах, м (в плоскости штанги, перпендикулярно прямой, вперёд по ходу); `0` для `straight`; для `curved` — число из источника или оценка класса (`bow_src: "measured"|"passport"|"class_estimate"`);
  - `straight_len_m` (необязательно) — длина прямых участков у углов, если изгиб не по всей длине (иначе — дуга по всей длине между углами);
  - `ref`: URL / ключ `wings_merged.json` / описание фото + цитата; у оценки — по какому образцу.
- `control_frame.basebar_default` — умолчание для крыльев без данных (`shape`, `bow_m` — оценка PV-2 по классу).
- Ось штанги в модели: углы — как сейчас (маркеры `UprightBottomL/R`); середина — вынесена вперёд на `bow_m` (±0,005).
- Маркер `BaseBar` (A2) — середина **оси штанги на изгибе** (вынесенная точка), не середина хорды между углами. Хваты рук (IK) лежат на оси изогнутой штанги (±0,01 м).
- Инварианты (тест): у каждого крыла `basebar.shape` задан; `straight` ⇒ `bow_m = 0`; `curved` ⇒ `bow_m` в 0,03…0,25; в `.glb` вынос `BaseBar` вперёд от хорды `UprightBottomL–R` = `bow_m` ±0,005 (провис — отдельно = `speedbar_dip_m`); `BarGripL/R` на оси ±0,01.
