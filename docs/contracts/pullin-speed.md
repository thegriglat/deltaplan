## VM-К1. Итог разбора VM-1 (v2)
v2 (2026-10-19): добавлен раздел `## VG` (решение пользователя: оценить VG в VM-1).
Владелец: VM-1. Потребители: координатор (шлюз Q1), волна 2.

Файл `docs/research/pendulum/pullin-speed.md`, frontmatter по правилам docs (`type: research`, `module: pullin-speed`,
`area: flight`, `summary` — вывод с числами ≤ 140 символов). Обязательные разделы второго уровня, в этом порядке
(заголовок начинается ровно так):
1. `## Паспортная Vmax` — что измеряет DHV/производитель (режим, VG, поза, ход трапеции), источники с URL.
2. `## VG` — сколько даёт VG по данным: пары Vmax VG 0 / VG full (DHV, производители, с URL), что VG меняет
   физически (натяжение паруса, крутка, Cm0, CL_α), закроет ли он разрыв по классам; нет пар — так и написать.
3. `## Ход рук` — какой ход и угол крыла к стропе нужны в модели для паспортной Vmax; откуда 0,45 м; сколько
   км/ч даёт 0,45 м по классам.
4. `## Точка подвески` — таблица по всем крыльям с блоком `pendulum` в `configs/wings/`: подвеска в модели,
   паспорт / «ЦМ + 2–3 см», Vmax модели на полном «на себя», паспортная Vmax, вклад смещения подвески (км/ч на см).
5. `## Прочие вклады` — Cm0/центровка паруса, CL_α полос (4,5 без взаимной индукции), сопротивление пилота:
   оценка вклада каждого в км/ч.
6. `## Причина` — строка `Класс: физика` | `Класс: граница модели` | `Класс: ошибка модели` (одна или несколько
   через `; ` с долями) и обоснование числами.
7. `## Варианты правки` — каждый вариант: что меняется, ожидаемый эффект в км/ч по классам, риск (устойчивость Kn,
   трим, посадка), нужна ли новая модель полос (тогда — пометка «шлюз»).
8. `## Воспроизведение` — команды, которыми получены новые числа; ссылки на данные в `tools/research/pullin_speed/`.

Числа — только из готовых документов (со ссылкой `путь#раздел`) или из новых прогонов, сохранённых в
`tools/research/pullin_speed/` (скрипт + таблица csv/json + README с frontmatter). Нет данных — так и написать.

Контрактный тест — проверки карточки VM-1 `vm-k1-sections` и `vm-k1-class`.

## VM-К2. Проект нелинейной Cm(α) и хода «на себя» на прототипе (v1)
Владелец: VM-2. Потребители: координатор (контракт порта PD-К2 v8), VM-3 (порт в игру).
Основание: решение пользователя 2026-10-19 (правка модели: нелинейная Cm(α), ход до «штанги у бёдер»); PB-2
`docs/research/pendulum/vg.md` п. 1 и 5; VM-1 `docs/research/pendulum/pullin-speed.md`.

**Документ** `docs/research/pendulum/pitch-nonlinear.md` (frontmatter docs: `type: research`, `module: pullin-speed`,
`area: flight`, `summary` с числами, `conclusion`, `data`, `applied_in`). Разделы второго уровня, по порядку:
1. `## Физика` — откуда нелинейность Cm(α) гибкого крыла (податливость паруса, luff lines/спроги, киль-карман),
   измеренные кривые Cm(α) или требования испытаний тангажа (DHV/HGMA) — с URL; чего модель не учтёт.
2. `## Модель` — формула добавки к моменту крыла (аргумент — α или CL, оси и знак как в прототипе: момент нос вверх +),
   параметры: какие общие (`configs/pendulum.json`), какие по классу, какие выводит генератор из геометрии крыла;
   обоснование каждого числа. **Без подгонки под Vmax отдельного крыла.** При выключенной добавке — прежняя модель.
3. `## Ход «на себя»` — какой величине модели соответствует «штанга у бёдер» 0,6–0,7 м (сдвиг пилота по стропе против
   хода штанги, плечо штанги — расхождение VM-1 «Варианты правки» Г и PB-2), выбранное значение `arms.shift_x_pull_m`
   и при необходимости `arms.force_max_n` — с обоснованием.
4. `## Результаты` — таблица по всем 48 крыльям `configs/wings/` (до / после): трим, Vmax полного «на себя», паспорт VG 0,
   Kn на триме, фугоида (период, затухание), усилие на штанге на 1,15·Vтрим, 1,3·Vтрим и на Vmax, скорость срыва,
   отпускание штанги с Vmax (мин. тангаж киля, мин. α).
5. `## Порт в игру` — точный список ключей конфига (имя, тип, единицы, умолчание, где лежит: `configs/pendulum.json`
   или блок `pendulum` крыла), формула для `scripts/flight/pendulum/pendulum_model.gd` и что меняется в
   `tools/flight/pendulum_params.py` (если нужно); ожидаемые значения для контрактного теста (3–5 крыльев разных классов).
6. `## Границы` — чего не умеет, где модель врёт.
7. `## Воспроизведение` — команды.

**Сводка** `tools/research/pendulum/out/vm2/summary.json` (JSON-объект, числа — float/int; все ключи обязательны):

| Ключ | Смысл | Порог приёмки |
|---|---|---|
| `wings` | число крыльев в прогоне | = 48 |
| `vmax_ratio_median` | медиана Vmax/паспорт VG 0 по крыльям без цензуры Vne (`tools/research/pullin_speed/out/passport_censoring.csv`) | 0,9…1,1 |
| `vmax_ratio_p10` | 10-й перцентиль того же | ≥ 0,8 |
| `vmax_ratio_median_base` | то же для прежней модели (справочно) | — |
| `trim_dev_max_kmh` | макс. \|трим − паспорт\| | ≤ 0,3 |
| `kn_trim_min` | мин. запас устойчивости на триме | > 0 |
| `phugoid_unstable_count`, `phugoid_unstable_count_base` | крыльев с нарастающей фугоидой на триме, после / до | после ≤ до |
| `bar_force_vmax_max_n` | макс. усилие на штанге на Vmax | ≤ `arms_force_max_n` |
| `arms_force_max_n`, `pull_m` | выбранные предел рук и ход «на себя» | — |
| `stall_dev_max_kmh` | макс. изменение скорости срыва | ≤ 2 |
| `tuck_count` | крыльев, у которых при отпускании штанги с Vmax тангаж киля < −60° или нет возврата к триму за 30 с | = 0 |

Записывается один раз (временный файл + переименование). Контрактный тест — проверки карточки VM-2 `vm-k2-sections`
и `vm-k2-summary`.
