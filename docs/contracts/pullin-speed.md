## VM-К3. Добор «на себя» до бёдер — модификатор ввода (v2)
v2 (2026-10-19): после отпускания модификатора предел возвращается плавно (`arms.pull_full_release_m_s`), не скачком.
Владелец: координатор (по решению пользователя 5855f8a5, 2026-10-19). Реализует VM-3. Потребители: `InputController`,
`PendulumModel`/`pilot_arms.gd`, экран «Управление» (`configs/ui.json → controls_help`), автопилот и тесты.
При порте VM-3 координатор поднимает версии затронутых контрактов закрытых модулей: `docs/contracts/ui-controls.md`
У1 v3 → v4, `docs/contracts/control-bar.md` CB-К1 v2 → v3, `docs/contracts/pendulum.md` PD-К2 v7 → v8; их контрактные
тесты VM-3 правит в том же шаге.

- **Смысл.** Как ходьба/бег: обычный полный «на себя» (`pitch` = −1) — штанга у груди, ход `arms.shift_x_pull_m` (0,45 м,
  как сейчас); с зажатым модификатором — штанга у бёдер, ход `arms.shift_x_pull_full_m` (значение — VM-2). Большой разгон —
  осознанное действие; без модификатора игра ведёт себя как сейчас.
- **Поле** `ControlInput.pull_full: bool` (`scripts/core/control_input.gd`), по умолчанию `false`; `true`, пока зажат
  модификатор, в полёте и на земле (на земле не влияет: ход у земли — `arms.flare_reach`, PD-К2 v7).
- **Клавиатура.** Действие `pull_full` = [Shift] в `configs/controls.json → keys` (с `_doc`). Shift уже у `run` — роли не
  пересекаются: на земле `run` (разбег, CF-3), в полёте `pull_full`; `run` на земле и `pull_full` в полёте от одной клавиши
  оба `true` — модель берёт `pull_full` только в полёте.
- **Геймпад.** `configs/controls.json → gamepad.pull_full_button: int` — по умолчанию 10 (`JOY_BUTTON_RIGHT_SHOULDER`,
  правый бампер), с `_doc`; предпочтение пилота (не машинный ключ). Нажата → `pull_full = true`.
- **Мышь.** Модификатор — та же клавиша Shift.
- **Самодельная трапеция (CB, `gamepad.device_guid` ≠ "", устройство подключено)** — решение пользователя 2026-10-19
  (вариант «б», KISS): полный ход устройства = «штанга у бёдер» пропорционально, без модификатора — `InputController`
  ставит `pull_full = true`, пока тангаж идёт с этого устройства; красный индикатор — за обычным пределом, как у всех.
  Сложного (зоны, отдельные калибровки хода) не делать.
- **Модель (`pilot_arms.gd`).** Цель к носу: `pitch < 0` → `−pitch · (pull_full ? shift_x_pull_full : shift_x_pull)`;
  `pitch ≥ 0` — без изменений (`shift_x_push`). Отпустил модификатор — предел цели к носу возвращается от `shift_x_pull_full`
  к `shift_x_pull` **плавно**, с постоянной скоростью `arms.pull_full_release_m_s` (м/с, `configs/pendulum.json`, с `_doc`;
  умолчание 0,5 — штанга от бёдер к груди за ≈ 0,5 с), как пилот отдаёт штангу от бёдер; начинается в тот же кадр, без
  задержки ввода; снова зажал — предел растёт без рампы. Дальше положение догоняет цель физикой рук (`arms.tau_s`).
  Это удобство ввода, не средство от переворота (решение пользователя 2026-10-19, 08:44). `FlightModel`
  (`weight_shift`/`rate`) поле не читает.
- **HUD (PH-К1 v1 → v2 при порте).** Новое поле `Telemetry.pull_over: float` ∈ [0, 1] =
  `clamp((сдвиг пилота к носу − shift_x_pull) / (shift_x_pull_full − shift_x_pull), 0, 1)` по фактическому положению
  пилота (не по цели); `FlightModel` и земля — 0; до первого шага — 0; всегда конечное. Индикатор подвески
  (`PilotShiftIndicator`) показывает сдвиг до `shift_x_pull_full`; при `pull_over > 0` рамка/точка — красным
  (`configs/ui.json → pilot_shift.over_pull_color` с `_doc`), при 0 — прежний цвет; решение пользователя 2026-10-19:
  «видно, что идёшь за обычный предел». Прочие инварианты PH-К1 сохраняются (`|bar_force| ≤ arms.force_max_n`).
- **Сеть (PD-К4).** Передаётся итоговое положение пилота, как сейчас; новое поле в протокол не добавлять.
- Инварианты (тест): без модификатора — цель и Vmax как до правки (при той же Cm); с модификатором и `pitch` = −1 —
  цель = `shift_x_pull_full`; `pitch` ≥ 0 — модификатор ничего не меняет; на земле — ничего не меняет; отпускание
  модификатора на `pitch` = −1 — цель убывает монотонно без скачка, равна `shift_x_pull` через
  `(shift_x_pull_full − shift_x_pull) / pull_full_release_m_s` ± 1 шаг, `pull_over` → 0 не позже чем ещё через 3·`arms.tau_s`;
  без модификатора `pull_over` = 0 всегда.

## VM-К4. Переворот при отпускании штанги на больших скоростях (v3)
v3 (2026-10-19, ответ на Q2): переворот при мгновенном отпускании с V ≥ ~2·Vтрим — физика (горка Ланчестера, VM-3
`docs/research/pendulum/pitch-release.md`); Cmq-поправку не вносить (`cm_q_add` = 0, в порт не идёт). `tuck_count`
сводки VM-3 — справочно. Новый критерий проверяется в игре (VM-4, VM-К5): подхват 2–4 g без переворота при плавном выходе
(ввод как в игре + плавный возврат добора VM-К3 v2) и при мгновенном отпускании с ≤ 1,8·Vтрим; отдельно — отпускание
обычного полного «на себя» без добора всеми устройствами по всем крыльям; переворот там — шлюз, не прятать.
v2 (2026-10-19, решение пользователя 08:44): объём ограничен — литература по демпфированию тангажа дельтаплана (Cmq/Mq),
замер Cmq прототипа и **одна** обоснованная поправка по образцу `yaw.cn_r_add` (PD-23, PD-К2 v4), например
`pitch.cm_q_add` на qc/2V. Не хватило одной поправки (причина в руках пилота на перегрузке, нестационарной аэродинамике
и т. п.) — `VM-3 blocked` с числами (шлюз), дальше не копать. Сценарий отпускания — ввод 0 скачком, как в v1 (плавный
возврат добора VM-К3 v2 переворот не прячет и в сценарий не входит).
Владелец: VM-3. Потребители: координатор (контракт порта PD-К2 v8), VM-4 (порт в игру).
Основание: ответ на Q1 (2026-10-19): принять Cm(α) и добор VM-2; переворот при отпускании с Vmax — чинить для всех крыльев;
порт — только после починки. VM-2: при вводе 0 скачком с Vmax 37/48 крыльев — петля/переворот при 3–4 g; нынешняя игра со
своих 41–78 км/ч — 17/48, при паспортных скоростях — 40/48; не лечат: плавный возврат ввода 1/с, отпущенные руки,
