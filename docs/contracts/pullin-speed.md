## VM-К3. Добор «на себя» до бёдер — модификатор ввода (v3)
**Заменено RM-К1 (`docs/contracts/roll-modes.md`): в примечании «`FlightModel` (`weight_shift`/`rate`) поле не читает» — режима `weight_shift` нет, `FlightModel` (`rate`, боты) поле по-прежнему не читает.**
v3 (2026-10-19, cf92cbf4): обычный геймпад — до груди, до бёдер только с кнопкой; полным ходом — только самодельная трапеция (CB-К1 v4).
v2 (2026-10-19): после отпускания модификатора предел возвращается плавно (`arms.pull_full_release_m_s`), не скачком.
Владелец: координатор (по решению пользователя 5855f8a5, 2026-10-19). Реализует VM-3. Потребители: `InputController`,
`PendulumModel`/`pilot_arms.gd`, экран «Управление» (`configs/ui.json → controls_help`), автопилот и тесты.
При порте VM-3 координатор поднимает версии затронутых контрактов закрытых модулей: `docs/contracts/ui-controls.md`
У1 v3 → v4, `docs/contracts/control-bar.md` CB-К1 v2 → v3, `docs/contracts/pendulum.md` PD-К2 v7 → v8; их контрактные
тесты VM-3 правит в том же шаге.

- **Смысл.** Как ходьба/бег: обычный полный «на себя» (`pitch` = −1) — штанга у груди, ход `arms.shift_x_pull_m` (0,45 м,
  как сейчас); с зажатым модификатором — штанга у бёдер, ход `arms.shift_x_pull_full_m` (значение — VM-2). Большой разгон —
  осознанное действие; без модификатора игра ведёт себя как сейчас.
- **Поле** `ControlInput.pull_full: bool` (`scripts/core/control_input.gd`), по умолчанию `false`; `true`, пока зажат
  модификатор, в полёте и на земле (на земле не влияет: ход у земли — `arms.flare_reach`, PD-К2 v7).
- **Клавиатура.** Тангажа с клавиатуры нет (У1 v5); действие `pull_full` = [Shift] — модификатор для мыши в `configs/controls.json → keys` (с `_doc`). Shift уже у `run` — роли не
  пересекаются: на земле `run` (разбег, CF-3), в полёте `pull_full`; `run` на земле и `pull_full` в полёте от одной клавиши
  оба `true` — модель берёт `pull_full` только в полёте.
- **Геймпад.** `configs/controls.json → gamepad.pull_full_button: int` — по умолчанию 10 (`JOY_BUTTON_RIGHT_SHOULDER`,
  правый бампер), с `_doc`; предпочтение пилота (не машинный ключ). Нажата → `pull_full = true`.
- **Мышь.** Модификатор — та же клавиша Shift.
- **Самодельная трапеция** — выбранное устройство без известной раскладки геймпада (`BarAxis.is_bar(id)`, CB-К1 v4): полный ход
  устройства = «штанга у бёдер» пропорционально, без модификатора — `pull_full = true`, пока тангаж идёт с него (вариант «б», KISS).
  Обычный геймпад (известная раскладка, выбран он в настройках или нет) — полный ход стика до груди, до бёдер только с
  `pull_full_button` (решение пользователя cf92cbf4). Красный индикатор — за обычным пределом, как у всех.
- **Модель (`pilot_arms.gd`).** Цель к носу: `pitch < 0` → `−pitch · (pull_full ? shift_x_pull_full : shift_x_pull)`;
  `pitch ≥ 0` — без изменений (`shift_x_push`). Отпустил модификатор — предел цели к носу возвращается от `shift_x_pull_full`
  к `shift_x_pull` **плавно**, с постоянной скоростью `arms.pull_full_release_m_s` (м/с, `configs/pendulum.json`, с `_doc`;
  умолчание 0,5 — штанга от бёдер к груди за ≈ 0,5 с), как пилот отдаёт штангу от бёдер; начинается в тот же кадр, без
  задержки ввода; снова зажал — предел растёт без рампы. Дальше положение догоняет цель физикой рук (`arms.tau_s`).
  Это удобство ввода, не средство от переворота (решение пользователя 2026-10-19, 08:44). `FlightModel`
  (`weight_shift`/`rate`) поле не читает.
- **HUD (PH-К1 v1 → v2 при порте).** Новое поле `Telemetry.pull_over: float` ∈ [0, 1] =
  `clamp((сдвиг пилота к носу − shift_x_pull) / (shift_x_pull_full − shift_x_pull), 0, 1)` по фактическому положению
  пилота (не по цели); `FlightModel` и земля — 0; до первого шага — 0; всегда конечное. Индикатор подвески
  (`PilotShiftIndicator`) — шкала прежняя (до `shift_x_pull`), за пределом точка у края; при `pull_over > 0` рамка/точка — красным
  (`configs/ui.json → pilot_shift.over_pull_color` с `_doc`), при 0 — прежний цвет; решение пользователя 2026-10-19:
  «видно, что идёшь за обычный предел». Прочие инварианты PH-К1 сохраняются (`|bar_force| ≤ arms.force_max_n`).
- **Сеть (PD-К4).** Передаётся итоговое положение пилота, как сейчас; новое поле в протокол не добавлять.
- Инварианты (тест): без модификатора — цель и Vmax как до правки (при той же Cm); с модификатором и `pitch` = −1 —
  цель = `shift_x_pull_full`; `pitch` ≥ 0 — модификатор ничего не меняет; на земле — ничего не меняет; отпускание
  модификатора на `pitch` = −1 — цель убывает монотонно без скачка, равна `shift_x_pull` через
  `(shift_x_pull_full − shift_x_pull) / pull_full_release_m_s` ± 1 шаг, `pull_over` → 0 не позже чем ещё через 3·`arms.tau_s`;
  без модификатора `pull_over` = 0 всегда.

## VM-К5. Проверка порта в игре (v3)
v3 (19.10, ответ на Q3): переворот при выходе из разгона пока не чиним — пороги `tuck_smooth_count`, `tuck_1p8_count` сняты (справочно); переворот — в «Границы модели» `docs/guide/flight/pendulum.md` и TODO.
v2 (19.10, решение пользователя dceacaaa): тангажа с клавиатуры нет — плавный выход мышью/стиком, не клавишей.
Владелец: VM-4. Потребители: координатор (приёмка модуля), главная (тестовая сборка).
Замер — расширение скрипта VM-1 `tools/research/pullin_speed/pullin_speed.gd` (собирает `PendulumModel` как
`tests/flight/pendulum/pendulum_sim.gd`, конфиги игры как есть после порта), 48 крыльев, штиль, ρ = 1,225, эталонная масса.
Случаи:
- `normal` — `pitch` −1 рампой 6 с, 70 с, среднее V за 50–70 с, без добора; `full` — то же с `pull_full = true`;
- `release_smooth` — с установившегося `full`: модификатор отпущен в начале (предел возвращается по VM-К3 v2), `pitch`
  линейно −1 → 0 за 0,5 с — пилот возвращает мышь/ручку рукой (0,5 с — допущение координатора, правдоподобный жест), 30 с;
- `release_1p8` — установившаяся V = min(1,8·Vтрим, V `full`) (постоянный `pitch` < 0, с добором при необходимости),
  затем `pitch` = 0 и `pull_full` = false в один шаг, 30 с.
Переворот — тангаж киля < −60° или |α| > 90° в любой момент 30 с, или средняя V за 25–30 с вне ±10 % трима (как VM-2/VM-3).

## VM-К8. Руки отпускают только при выходе из «на себя» — проект на прототипе (v1)
Владелец: VM-11. Потребители: координатор (контракт порта PD-К2 v9), задача порта.
Основание: ответ на Q5 (2026-10-19): VM-9 не вливать; руки отпускают пилота только при возврате ввода к 0 после «на себя»
(или податливая рука), в обычном полёте держат — крен и фугоида как сейчас; затем порт в игру.
Исходные числа: VM-6 `docs/research/pendulum/release-tumble.md` (причина — руки держат пилота на вводе 0); VM-9 (ветка
`pullin-speed/VM-9`, `tools/research/pullin_speed/out/vm9/`): «брошенная ручка» всегда на вводе 0 — перевороты 1,8·Vтрим 29→0,
normal ≤ 2·Vтрим 14→0, но переложение 45→45 sport 2,55 с против 4,54 с, крен Очи 39° против 50°, фугоида разошлась,
болтанка 5→10 из 60.

**Модель** — прототип `tools/research/pendulum/` в состоянии игры после VM-4 (руки держат), плюс правка за ключом (выключена =
нынешнее). Варианты: (1) отпускание по событию — после «на себя» (`pitch` < −порог) ввод вернулся к 0 → руки вдоль киля не
держат, пока пилот не вернулся к нейтрали / ввод не изменился (числа — с обоснованием, время возврата руки пилота);
(2) податливая рука — жёсткость вдоль киля на вводе 0 из литературы (Mussa-Ivaldi 1985, Tsuji 1995), без порога. Выбрать
по замеру; без ограничителей угловой скорости и без подгонки по крылу.

**Документ** — раздел `## Отпускание по событию (VM-11)` в `docs/research/pendulum/release-tumble.md` (подразделы: что меняется,
обоснование чисел, результаты, порт в игру — ключи, формула для `scripts/flight/pendulum/pilot_arms.gd`, эталоны для теста).
