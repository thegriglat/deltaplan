## VM-К1. Итог разбора VM-1 (v2)
v2 (2026-10-19): добавлен раздел `## VG` (решение пользователя: оценить VG в VM-1).
Владелец: VM-1. Потребители: координатор (шлюз Q1), волна 2.

Файл `docs/research/pendulum/pullin-speed.md`, frontmatter по правилам docs (`type: research`, `module: pullin-speed`,
`area: flight`, `summary` — вывод с числами ≤ 140 символов). Обязательные разделы второго уровня, в этом порядке
(заголовок начинается ровно так):
1. `## Паспортная Vmax` — что измеряет DHV/производитель (режим, VG, поза, ход трапеции), источники с URL.
2. `## VG` — сколько даёт VG по данным: пары Vmax VG 0 / VG full (DHV, производители, с URL), что VG меняет
   физически (натяжение паруса, крутка, Cm0, CL_α), закроет ли он разрыв по классам; нет пар — так и написать.
3. `## Ход рук` — какой ход и угол крыла к стропе нужны в модели для паспортной Vmax; откуда 0,45 м; сколько
   км/ч даёт 0,45 м по классам.
4. `## Точка подвески` — таблица по всем крыльям с блоком `pendulum` в `configs/wings/`: подвеска в модели,
   паспорт / «ЦМ + 2–3 см», Vmax модели на полном «на себя», паспортная Vmax, вклад смещения подвески (км/ч на см).
5. `## Прочие вклады` — Cm0/центровка паруса, CL_α полос (4,5 без взаимной индукции), сопротивление пилота:
   оценка вклада каждого в км/ч.
6. `## Причина` — строка `Класс: физика` | `Класс: граница модели` | `Класс: ошибка модели` (одна или несколько
   через `; ` с долями) и обоснование числами.
7. `## Варианты правки` — каждый вариант: что меняется, ожидаемый эффект в км/ч по классам, риск (устойчивость Kn,
   трим, посадка), нужна ли новая модель полос (тогда — пометка «шлюз»).
8. `## Воспроизведение` — команды, которыми получены новые числа; ссылки на данные в `tools/research/pullin_speed/`.

Числа — только из готовых документов (со ссылкой `путь#раздел`) или из новых прогонов, сохранённых в
`tools/research/pullin_speed/` (скрипт + таблица csv/json + README с frontmatter). Нет данных — так и написать.

Контрактный тест — проверки карточки VM-1 `vm-k1-sections` и `vm-k1-class`.

1. `## Физика` — откуда нелинейность Cm(α) гибкого крыла (податливость паруса, luff lines/спроги, киль-карман),

2. `## Модель` — формула добавки к моменту крыла (аргумент — α или CL, оси и знак как в прототипе: момент нос вверх +),
   параметры: какие общие (`configs/pendulum.json`), какие по классу, какие выводит генератор из геометрии крыла;
   обоснование каждого числа. **Без подгонки под Vmax отдельного крыла.** При выключенной добавке — прежняя модель.

   `tools/flight/pendulum_params.py` (если нужно); ожидаемые значения для контрактного теста (3–5 крыльев разных классов).

## VM-К3. Добор «на себя» до бёдер — модификатор ввода (v1)
Владелец: координатор (по решению пользователя 5855f8a5, 2026-10-19). Реализует VM-3. Потребители: `InputController`,
`PendulumModel`/`pilot_arms.gd`, экран «Управление» (`configs/ui.json → controls_help`), автопилот и тесты.
При порте VM-3 координатор поднимает версии затронутых контрактов закрытых модулей: `docs/contracts/ui-controls.md`
У1 v3 → v4, `docs/contracts/control-bar.md` CB-К1 v2 → v3, `docs/contracts/pendulum.md` PD-К2 v7 → v8; их контрактные
тесты VM-3 правит в том же шаге.

- **Смысл.** Как ходьба/бег: обычный полный «на себя» (`pitch` = −1) — штанга у груди, ход `arms.shift_x_pull_m` (0,45 м,
  как сейчас); с зажатым модификатором — штанга у бёдер, ход `arms.shift_x_pull_full_m` (значение — VM-2). Большой разгон —
  осознанное действие; без модификатора игра ведёт себя как сейчас.
- **Поле** `ControlInput.pull_full: bool` (`scripts/core/control_input.gd`), по умолчанию `false`; `true`, пока зажат
  модификатор, в полёте и на земле (на земле не влияет: ход у земли — `arms.flare_reach`, PD-К2 v7).
- **Клавиатура.** Действие `pull_full` = [Shift] в `configs/controls.json → keys` (с `_doc`). Shift уже у `run` — роли не
  пересекаются: на земле `run` (разбег, CF-3), в полёте `pull_full`; `run` на земле и `pull_full` в полёте от одной клавиши
  оба `true` — модель берёт `pull_full` только в полёте.
- **Геймпад.** `configs/controls.json → gamepad.pull_full_button: int` — по умолчанию 10 (`JOY_BUTTON_RIGHT_SHOULDER`,
  правый бампер), с `_doc`; предпочтение пилота (не машинный ключ). Нажата → `pull_full = true`.
- **Мышь.** Модификатор — та же клавиша Shift.
- **Самодельная трапеция (CB, `gamepad.device_guid` ≠ "", устройство подключено)** — решение пользователя 2026-10-19
  (вариант «б», KISS): полный ход устройства = «штанга у бёдер» пропорционально, без модификатора — `InputController`
  ставит `pull_full = true`, пока тангаж идёт с этого устройства; красный индикатор — за обычным пределом, как у всех.
  Сложного (зоны, отдельные калибровки хода) не делать.
- **Модель (`pilot_arms.gd`).** Цель к носу: `pitch < 0` → `−pitch · (pull_full ? shift_x_pull_full : shift_x_pull)`;
  `pitch ≥ 0` — без изменений (`shift_x_push`). Отпустил модификатор — цель рук **сразу** (в тот же кадр, без задержки и
  рампы ввода) возвращается в нормальный диапазон `[−shift_x_push, shift_x_pull]`; дальше положение догоняет цель физикой
  рук (`arms.tau_s`) — решение пользователя 2026-10-19 «выход простой». `FlightModel` (`weight_shift`/`rate`) поле не читает.
- **HUD (PH-К1 v1 → v2 при порте).** Новое поле `Telemetry.pull_over: float` ∈ [0, 1] =
  `clamp((сдвиг пилота к носу − shift_x_pull) / (shift_x_pull_full − shift_x_pull), 0, 1)` по фактическому положению
  пилота (не по цели); `FlightModel` и земля — 0; до первого шага — 0; всегда конечное. Индикатор подвески
  (`PilotShiftIndicator`) показывает сдвиг до `shift_x_pull_full`; при `pull_over > 0` рамка/точка — красным
  (`configs/ui.json → pilot_shift.over_pull_color` с `_doc`), при 0 — прежний цвет; решение пользователя 2026-10-19:
  «видно, что идёшь за обычный предел». Прочие инварианты PH-К1 сохраняются (`|bar_force| ≤ arms.force_max_n`).
- **Сеть (PD-К4).** Передаётся итоговое положение пилота, как сейчас; новое поле в протокол не добавлять.
- Инварианты (тест): без модификатора — цель и Vmax как до правки (при той же Cm); с модификатором и `pitch` = −1 —
  цель = `shift_x_pull_full`; `pitch` ≥ 0 — модификатор ничего не меняет; на земле — ничего не меняет; отпускание
  модификатора на `pitch` = −1 — цель в тот же шаг = `shift_x_pull`, `pull_over` → 0 за ≤ 3·`arms.tau_s`; без
  модификатора `pull_over` = 0 всегда.
