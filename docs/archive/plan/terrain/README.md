## Порядок и параллельность (вместе с `../vegetation/`)
- **Волна 0:** T01 ‖ V01 (V01 выносит `grass`/`trees` из `configs/world.json` — дальше растительность его не трогает).
- **Волна 1:** T02 (один: `terrain.gdshader`, `terrain.gd`, `world.json`, docs/guide/terrain.md).
- **Волна 2:** T03 ‖ T04 ‖ V02. Общих файлов нет: `world.json` — только T04, docs/guide/terrain.md — только T03 (T04 даёт абзац в отчёте).
- **Волна 3:** T05. **Волна 4:** T06 (последней — меряет итоговый шейдер).
- Каждая карточка перед сдачей гоняет `tools/terrain/shots.sh` и прикладывает `metrics.json`/`bench.json` и монтажи.
- Ограничение GPU для T02–T05: «рельеф» не растёт больше чем на 0,1 мс за карточку; снижение — в T06.

## Внешние зависимости (не карточки группы)
- Группа «Сцена игры»: `set_clearings`, `set_wind_sources` (+ `air_fn` после T05), `set_pilot`, `sun_fn`, инверсия
  (`set_inversion_height_msl`), `default_location = ongudai`, `GrassField.set_landing_sites` (после V01).
- Группа 6: вода в `data/osm/<id>.json` (T03 только читает).
- Вопросы пилотам (старты Онгудая/Биягоды/Аушкуля, VR-17 «видно термик по траве?») — не блокируют.


**Решение пользователя:** T06 (бюджет GPU рельефа) — оптимизация, откладывается на потом, в текущий объём не входит.
