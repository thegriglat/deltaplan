## Контракты (версия 1)

Контрактный тест: `uv run -q --with pillow python tools/site/check_contracts.py` (из корня копии) — проверяет C1 и C3, для C2 вызывает `tools/site/gen_wings.py --check`, если генератор уже есть. Менять интерфейс — только через координатора (версия +1, потребители уведомлены).

### C1. Рендер крыла (владелец SU-3; потребители SU-4, SU-5) — v1

- Файл: `docs/models/screenshots/glider_<id>/iso45.jpg`, где `<id>` — имя `configs/wings/<id>.json` (все 48, ни одного лишнего не требуется).
- Источник: модель `assets/models/glider_<id>.glb` (экспорт исходника `assets/source/glider_<id>.blend` — то же, что видит игра), вид `iso45` скрипта `tools/blender/render_views.py`: одинаковые направление камеры, свет и фон (0.80, 0.81, 0.83) для всех.
- Формат: JPEG, 1280×720, качество 85, sRGB; крыло обрезано по содержимому и отцентровано с полем ≈ 5 % (досыпано цветом фона), масштаб — вписать в кадр (размеры крыла — в таблице, не на картинке).
- Размер: 40–250 КБ каждый; все 48 вместе — не больше 8 МБ.
- Нет файла → генератор строит страницу без картинки, `--check` падает.

### C2. Страницы «Модели аппаратов» (владелец SU-4; потребитель SU-5) — v1

- Генератор: `tools/site/gen_wings.py` (Python 3, только стандартная библиотека), запуск из корня копии; `--check` — ничего не пишет, код 1, если сгенерированное расходится с файлами или чего-то не хватает (рендера, обязательного поля).
- Входные данные (только чтение): `configs/wings/*.json` (поля и `_doc`), `configs/wing_groups.json` (группы и их порядок), `locale/ui.csv` (названия: ключ `name` крыла, русский столбец; названия групп), `tools/research/data/wing_passports/` (`wings_merged.json`, `out/wings3d_spec.json`, `wings3d_overrides/`, источники), `docs/research/wings_config_sources.md`, `docs/research/glider_3d_tz.md`.
- Файлы:
  - `site/content/wings/_index.md` — раздел «Модели аппаратов»: сводная таблица всех крыльев по группам;
  - `site/content/wings/<group>/_index.md` — группа (`<group>` — id из `configs/wing_groups.json`, вес = порядок в массиве): таблица крыльев группы;
  - `site/content/wings/<group>/<id>.md` — страница крыла, адрес `/wings/<group>/<id>/`; порядок в группе — как в меню игры (`reference.best_glide`, при равенстве `wind_max_ms`; `scripts/game/wing_catalog.gd`) → `weight`.
- Владение текстом: страницы крыльев генерируются целиком. В `_index.md` генератор меняет только блок между строками `<!-- gen:begin tools/site/gen_wings.py -->` и `<!-- gen:end -->`; остальное (шапка, вступление, пояснения) — ручной текст (SU-5), генератор его сохраняет; нет файла — создаёт с шапкой по умолчанию и пустым ручным текстом.
- Страница крыла: название (из `locale/ui.csv`), прототип и годы, группа, мачтовое/безмачтовое, рендер (C1, путь `/docs/models/screenshots/glider_<id>/iso45.jpg`), таблица данных: размах, площадь, масса крыла, диапазон пилота, доля двойной обшивки, класс/сертификат DHV (или HGMA), годы, скорости (DHV Vmin/Vmax — если есть; скорости модели игры — трим, полностью на себя — с пометкой «модель игры»), качество модели. У каждого значения — отметка происхождения: **паспорт** (со ссылкой на источник: карточка DHV, страница/PDF производителя), **аналог** (паспорт близкой модели — какой), **оценка** (не из паспорта: подобие от базы, ТЗ, координатор). Числа — как в конфиге (то, что в игре); если паспорт расходится с конфигом — показать оба. Внизу — ссылки на конфиг и раздел ТЗ в репозитории, ссылка на благодарность DHV на главной.
- Ссылки — только на существующие страницы/файлы (Hugo падает на битых) и внешние адреса источников, найденные в данных репозитория (не выдумывать).
