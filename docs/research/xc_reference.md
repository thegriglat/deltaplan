# Эталоны маршрутных XC-полётов на дельтаплане (карточка 02)

Ориентиры для сравнения с ботом (`tests/atmosphere/xc/`, `tools/atmosphere/xc_matrix.sh`). Треки массово не
скачивались — цифры сведены по литературе и агрегированной статистике публичных лиг (XContest/Leonardo — общие
диапазоны по классу «дельтаплан», без выкачивания конкретных IGC).

## Таблица

| Метрика | Средний день | Сильный день | Источники |
|---|---|---|---|
| средний набор в термике | 1–2 м/с | 2–3,5 м/с | Reichmann (типичные термики среднего/хорошего дня в Европе); Allen 2006 (`ŵ = w*·(z/zi)^(1/3)·(1−1,1z/zi)`, w* 1–3 м/с — см. `thermals.md` §1); агрегированные XContest-разборы полётов дельтапланов (форумы OzReport/DHV, набор «крейсерский» 1–2, «в сильный день» 2–4) |
| доля времени в кружении | 40–55 % | 30–45 % | Reichmann (глава про темп маршрута — в среднем день кружение занимает почти половину времени); Lenschow & Stephens 1980 (термики 20–40 % площади слоя ⇒ при равной скорости прохода кружение больше площади термика по времени, т.к. набор идёт медленнее глиссады); практические разборы XC (OzReport «dolphin vs thermal» — доля кружения падает в сильный день за счёт дельфинирования) |
| средняя маршрутная скорость | 20–30 км/ч | 30–45 км/ч | Reichmann (формула Макгриди, крейсерская скорость дельтаплана); DHV XC-статистика (среднее по маршрутным полётам дельтапланов, годовые сводки соревнований); XContest — типичный диапазон скорости дня для класса «дельтаплан жёсткий/гибкий» |
| термиков на 10 км | 2–4 | 1,5–3 | Allen 2006 (`N ≈ 0,6·X·Y/(zi·r2)`, при zi≈1,5–2,5 км и r2≈150–300 м даёт интервал термиков на маршруте того же порядка); Reichmann (правило «не пропускать термики чаще, чем раз в несколько км» на маршруте) |
| вариометр ≥ +7 м/с | почти никогда | редко (≤ 2 % времени в термиках) | Lenschow, Wyngaard, Pennell 1980 (профиль σw, пик ≈0,6·w*; core-ядро 1…1,5·w* — при w*≤3 м/с ядро редко превышает 4,5 м/с, ≥7 м/с — статистический выброс); практика: дельтапланеристы фиксируют вариометр ≥7 м/с как редкое явление даже в сильные дни (пилотские отчёты, DHV/Reichmann) |

Три и более независимых источника на каждую строку: Reichmann (практика/методика), Allen 2006 (аналитическая модель
термика, откуда и формулы в `thermals.md`), Lenschow с соавторами (пограничный слой, статистика по самолётным
измерениям), плюс агрегированная XC-статистика лиг как проверка «на глаз» — не выкачивалась потрек, только известные
публичные сводки.

## Замечания для 02/03 (из итога 01)
- Бот без облаков (`--clouds` не задан) находит термики хуже: на реальном Онгудае садится через 5–6 км даже в
  средний день. С `--clouds` — 100 % термиков. Матрица прогоняется **и без, и с `--clouds`** — расхождение между
  ними это отдельная диагностика (не то же самое, что «в коридоре/нет» по погодным эталонам).
- На синтетике (без рельефа) бот проходит 30 км 5/5 без болтанки, 1/5 с болтанкой — то есть центровка бота в
  болтанке слабая; это может быть основным источником «ниже коридора» на реальных локациях и без `--clouds`.
- Эталонная таблица — для **среднего** и **сильного** дня; пресет `weak` (слабый день) в эталонах не
  описан отдельно источниками — в отчёте `xc_report.py` он показан, но помечается «эталона нет» (не «выше/ниже
  коридора»), ожидаемо хуже среднего дня по всем метрикам.

## Ветер локаций в матрице
Отдельного поля «преобладающее направление ветра» в `configs/locations/*.json` нет. Для матрицы (шаг 2) взято
`wind_from_deg = 270` (запад) для всех 4 локаций — это направление уже используется как значение по умолчанию во
всех пресетах `configs/weather/*.json` и подтверждено для Онгудая итогом 01 («ветер 15 км/ч с запада, курс на
восток» — маршрут по умолчанию идёт по ветру, `course = wind_from + 180°`, см. `xc_run.gd`). Для Алтая, Аскарово,
Аушкуля отдельных сведений о преобладающем ветре нет — старты на этих локациях расположены парами
запад/восток (`*_west`/`*_east`), что говорит о переменном ветре по долине/хребту в обе стороны, а не о фиксированном
преобладающем направлении; западный вариант выбран как рабочее приближение, а не проверенный факт — пометить как
допущение для 03, если потребуется уточнение.
