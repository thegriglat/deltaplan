# Опускание горно-равнинной циркуляции (CLF-10)

Часть [cloud_field.md](../cloud_field.md) (§7); схема поля, границы (§4) и z_i по рельефу (§6) — там.

Решение пользователя Q3 (2026-10-17): днём над хребтом подъём, над прилегающей равниной — компенсирующее опускание
возвратной ветви горно-равнинной циркуляции; оно гасит конвекцию и облака над равниной у хребта (Whiteman 2000,
«Mountain Meteorology», гл. 11; Zardi & Whiteman 2013; De Wekker & Kossmann 2015). До CLF-10 `AirThermals` и
`CloudFieldSources` брали только W̄⁺ (Φ = F̄ + max(W̄, 0)), опускание W̄ < 0 не входило никуда, кроме «между» пилоту.

**Сначала проверка: даёт ли поле опускание над равниной.** Кадр 13:00 (`out/before/*_h13.json`, `col_w` — средний
w_conv столбца по слою 0..h): Алматы, сильный день — над низиной (< 1200 м, 4873 столбца) W̄ < 0 у **69 %**
столбцов, медиана −0,037 м/с, среднее по всем −0,017, среднее по опускающимся **−0,08 м/с** (p10 −0,10); над
хребтом (> 3000 м) W̄ < 0 у 60 %, среднее −0,046 (подветренные склоны и лощины). Слабый день Алматы — 63 %,
среднее −0,003; Онгудай сильный/слабый — 55/70 %, по опускающимся −0,09; Аскарово — 62/53 %, −0,05. То есть
опускание в поле **есть**, порядка нескольких см/с — как у возвратной ветви по обзорам, но не гладкой полосой вдоль
хребта, а ячейками организованной конвекции 400-метровой сетки вперемежку с подъёмом (границы — cloud_field.md §4). Вариант А
(«поле не даёт») не случился — модель применена, без подгонки.

**Схема (одно место — `AirThermals.build`).** Бюджет верха слоя перемешивания dz_i/dt = w_e − |w_s| (Stull 1988,
§11.2; Tennekes 1973): слой без опускания за то же время был бы выше ровно на ∫|w_s|dt. Над столбцом с W̄ < 0
верх слоя ниже z_i поля (CLF-9, по рельефу, cloud_field.md §6) на **Δz_s = |W̄⁻|·τ_s**, не ниже рельефа + 300 м; свободная атмосфера
над ним опущена на столько же (изэнтропы при адиабатическом опускании): фон θ̄ столбца = θ̄(z + Δ). По этому
`col_zi` столбца считаются h, w* Дирдорфа, F̄, потолок частицы, радиус и плотность Аллена, w* источника, и его же
берёт `CloudFieldSources` для проникновения к основанию (`penetration`) — термики и облака меняются согласованно.
Φ не трогаем: подсеточный поток есть, пока греет земля; W̄⁻ работает через глубину слоя и потолок, а пилоту в
«между» приходит как w_conv поля (`with_between`). **τ_s = 3 ч** (`thermal.subsidence_tau_s`, с `_doc`): столько
к середине дня действует установившаяся циркуляция — дневной ток равнина → горы складывается к позднему утру и
держится до вечера (Whiteman 2000, гл. 11). Проверка τ_s = 0 — побитно как без опускания (`test_subsidence`).
Чувствительность: 1 см/с → 108 м; шум поля ±3 мм/с по клеткам → ±6 м потолка (допуск сетевого теста 5 → 25 м).

Что видно:
- **Над равниной у хребта облаков меньше на треть**: Алматы сильный день — низина 0,25 → 0,17, площадь облаков
  ≥ 0,3 по всей сетке 0,47 → 0,27 (сплошная пелена над предгорьями распалась на отдельные кучевые); Онгудай
  сильный 0,25 → 0,17. Слабые дни и Аскарово (равнина, W̄ ≈ 0 в среднем) — −0,01…−0,05, как и должно: там опускание
  мало и пятнисто.
- **Ожидание пользователя «над городом заметно ясно» (≤ 0,1) — не выполнено** (0,17): у трети низины W̄ ≥ 0, а
  там, где опускание есть, медиана Δz_s 400 м меньше запаса z_i − LCL = 850 м — потолок частицы над LCL остаётся у
  92 % столбцов низины. Дальше либо точка росы по месту (сухой воздух равнины — граница cloud_field.md §4), либо W̄ поля над
  равниной как гладкая возвратная ветвь, а не ячейки (модель воздуха, не эта задача). Проверка, не подгонка: τ_s
  под 0,1 не крутился.
- **Термики: больше и ниже.** Источников в 1,5–2 раза больше, медиана потолка на 70–350 м ниже, p10 — на
  0,5–2 км: на опущенных столбцах слой тоньше → радиус Аллена r₂ ∝ z_l и площадь на поток меньше → источников
  больше и слабее (w* ∝ h^(1/3)). p90 почти не меняется — столбцы с подъёмом (W̄ ≥ 0) как были. Хребет Алматы
  опускается тоже (W̄ < 0 у 60 %, Δz_s p50 435 м) — покрытие хребта 0,89 → 0,83, вершины в облаке остались.
- Шаг CloudField 6,8 мс медиана (`test_cloud_field_perf`, load average 16 при GPU-прогонах соседей) — схема
  целиком в `AirThermals.build` (раз в 15 мин, в рабочем потоке), цена шага не изменилась.
