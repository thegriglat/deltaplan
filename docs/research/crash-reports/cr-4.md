# CR-4: драйвер рендера Windows и вылеты #3–#15

## Отчёты
Сводка — `tools/research/crash-reports/cr-4/summarize_reports.py` (поля «Драйвер / API», «Рендер» — `scripts/core/crash_report.gd:149-158`: `get_video_adapter_api_version()` + тип устройства и `get_current_rendering_driver_name()` / метод рендера; «1.4.351» — версия Vulkan API драйвера, «12_0» — уровень возможностей D3D12).

| Группа | Issues | Версия | GPU | Рендер | Стадия | Графика |
|---|---|---|---|---|---|---|
| C | #3 | 1.5.15 (dbfea4) | RTX 5060 Laptop | vulkan | trees | high |
| A | #4–#10 (7) | 1.5.18 (cd1a8b) | GTX 1050 Ti | d3d12 | wind | low |
| B | #11–#15 (5) | 1.5.19 (b0da8b) | RTX 5060 Laptop | vulkan | objects (1), wind (4) | high |

ОС везде Windows 10. Все 13 отчётов — NVIDIA, Forward+, дискретная карта. Данные, вероятно, от двух пилотов (по одной карте на группу; группа A — 7 почти идентичных отчётов), поэтому «13 вылетов» — это две системы, а не 13 независимых. Другого производителя GPU и других версий Windows в выборке нет.

Признаки по драйверу:
- Группа A: в хвосте лога `Required Vulkan instance extension VK_KHR_surface not found` (`rendering_context_driver_vulkan.cpp:494`), затем предупреждение движка «Your video card drivers seem not to support Vulkan, switching to Direct3D 12». То есть D3D12 у группы A — не выбор проекта, а автоматический откат Godot. Далее во всех 7 отчётах ошибки D3D12: `Can't create buffer … error 0x887a0005` (83–89 раз; 0x887A0005 = DXGI_ERROR_DEVICE_REMOVED), `Close/Reset failed` с 0x80070057 (E_INVALIDARG) и 0x80004005 (E_FAIL). Первая ошибка 0x887a0005 — раньше всех остальных D3D12-ошибок, то есть они вторичны (устройство потеряно, всё дальнейшее — каскад).
- Группа B и #3: Vulkan 1.4.351 на RTX 5060 Laptop, в логе нет ни одной ошибки RenderingDevice/Vulkan; отчёт обрывается на смене стадии (в #12 — после `[stage] wind`, uptime сессии ~3335 с).

## Механизм отчёта
Отчёт собирается при запуске по метке «прошлый запуск не завершён»: `scripts/core/crash_reporter.gd` ведёт замок со стадией (`note_stage`, `crash_reporter.gd:104-111`), `crash_report.gd` формирует тело (система, настройки, хвост лога, VRAM). Стадия — последняя отмеченная перед обрывом; хвост лога — конец `godot.log` прошлого запуска. Важное для драйвера: отчёт фиксирует драйвер, который был активен на момент вылета, а не запрошенный — поэтому группа A видна как d3d12, хотя project.godot просит Vulkan. Если процесс убит драйвером или ОС без записи в лог (TDR, access violation), в логе ничего нет — это группа B.

## Причина
**Какой драйвер выбирает Godot 4.7.2 на Windows.** В `project.godot` ключа `rendering/rendering_device/driver.windows` нет (в `[rendering]` только `renderer/rendering_method="forward_plus"`; `config_version=5`, features "4.7"). Значение по умолчанию — `vulkan` (`main/main.cpp:2384`, `GLOBAL_DEF_RST("rendering/rendering_device/driver.windows", …, "vulkan")`). Документация ProjectSettings 4.7: с Godot 4.6 *новые* проекты получают `d3d12`, старые сохраняют `vulkan` для совместимости; проекту deltaplan это не присвоено.

**Откат есть и включён по умолчанию.** `rendering/rendering_device/fallback_to_d3d12 = true` и `fallback_to_vulkan = true` (`main.cpp:2391-2392`). Логика — `platform/windows/display_server_windows.cpp:7863-7945`: список драйверов `[запрошенный, другой]`, перебор до первого, у которого создались контекст окна и `RenderingDevice::initialize`; при успехе второго пишется WARN «switching to Direct3D 12». Далее `fallback_to_opengl3` (по умолчанию выключен; в Forward+ не нужен). Вывод: откат срабатывает только при **сбое инициализации** драйвера, а не при сбое или потере устройства во время работы. Группа A — типичный случай: у пилота сломана Vulkan-регистрация драйвера NVIDIA (нет расширения поверхности), Godot ушёл на D3D12.

**Связь вылетов с драйвером** (уверенность):
- Группа A — `вероятно` связана с D3D12/драйвером NVIDIA GTX 1050 Ti: потеря устройства (0x887A0005) во время стадии wind = задачи ветра на GPU; D3D12 здесь используется из-за неисправного Vulkan-слоя на этой машине. Сломанный Vulkan-драйвер сам по себе — признак повреждённой/частичной установки драйвера NVIDIA (гипотеза; проверить можно только на машине пилота: чистая установка драйвера). Причину потери устройства (TDR из-за долгого compute, неверный доступ к буферу, нехватка VRAM — 1166–1190 МБ занято при 4 ГБ карты) разбирает CR-1.
- Группа B и #3 — `гипотеза`, что виновен Vulkan: Vulkan работает корректно в инициализации, ошибок нет, а на Linux с Vulkan (RTX 4070 SUPER) аналогичные вылеты не отмечены. Но доказательств против «обрыв по иной причине (память, исключение в игре)» нет; CR-2/CR-3 разбирают места.
- Общая гипотеза «Vulkan виноват во всех» опровергается группой A: она уже на D3D12 и вылетает на той же стадии wind. Общая гипотеза «D3D12 виноват» опровергается группами B и C: они на Vulkan. Общее у A и B — стадия wind и запуск GPU-ядер ветра (RenderingDevice compute), то есть возможна причина вне выбора API (общий путь кода/нагрузка); это согласуется с тем, что смена драйвера — не панацея.

**Работают ли GPU-расчёты игры на D3D12.** Да, в принципе: шейдеры ветра (`scripts/atmosphere/air_model/*.glsl`) уже содержат обходы для D3D12 в Godot 4.7 (знаковые константы специализации, два буфера на одной привязке — `air_picard.glsl:42`, `air_gpu.gd:79`), коммит `85fcd70c` «Ветер на D3D12: ядра собираются, без ядер — аналитика»; есть режим проверки Windows-сборки под wine + vkd3d-proton (`tools/gpu_validate.sh --mode=wine --driver=d3d12`). Ограничение: это показывает, что ядра собираются на D3D12 (в том числе у пилота 1.3.2), но не то, что они устойчивы на GTX 1050 Ti — отчёты группы A как раз показывают потерю устройства на D3D12.

## Исправлено ли в main
`нет`. Ни `project.godot`, ни сборка не менялись по теме драйвера (`git log -- project.godot` — только версии); `driver.windows` не задан. Отдельно: обходы D3D12 для ядер (`85fcd70c`) уже в истории до 1.5.18, а вылеты после них продолжаются.

## Воспроизведение
Драйвера рендера Windows на Linux нет (D3D12 недоступен нативно; Vulkan на RTX 4070 SUPER не воспроизводит). Что можно:
1. Проверка дефолтов — по исходникам Godot 4.7-stable (ссылки в `tools/research/crash-reports/cr-4/README.md`); не запускалось — достаточно чтения кода и документации.
2. D3D12 косвенно: `tools/gpu_validate.sh --mode=wine --driver=d3d12 --exe=build/windows/deltaplan.exe` (vkd3d-proton под wine) — покажет ошибки ядер ветра на D3D12, но не поведение драйвера NVIDIA для Windows на GTX 1050 Ti и не TDR (в wine TDR нет). Не запускалось в CR-4 (нужен собранный exe и дисплей; замеры не нужны).
3. Откат Vulkan→D3D12 воспроизвести нельзя без Windows-машины с неисправной регистрацией Vulkan.
Итог: связь «драйвер ↔ вылет» на этой машине не подтверждается и не опровергается; решающий эксперимент — запуск у тех же пилотов на другом драйвере (см. ниже).

## Предложение правки
Сравнение вариантов:

| Вариант | Что менять | Эффект | Цена и риск |
|---|---|---|---|
| 1. `driver.windows="d3d12"` по умолчанию | `project.godot` `[rendering]`: `rendering_device/driver.windows="d3d12"` | Группа A не меняется (уже D3D12). Группа B/#3 — меняется Vulkan→D3D12, эффект неизвестен | D3D12 в Godot 4.7 моложе Vulkan (в проекте уже понадобились обходы шейдеров); у пилотов с рабочим Vulkan можно получить регрессии; тот же откат на Vulkan включён по умолчанию, поэтому не теряем поддержку. Нельзя проверить на Linux |
| 2. Автооткат (как есть) | ничего | Уже работает при сбое **инициализации** (подтверждено группой A) | Не ловит потерю устройства/обрыв во время игры; отката «по факту вылета» нет |
| 2а. Откат по метке вылета | при старте, если прошлый запуск оборвался на стадии X на драйвере Y, предложить/выставить другой драйвер и перезапуститься (`OS.create_process` с `--rendering-driver`) | Автоматизирует переключение | Это код (`scripts/core`), нужен `dp-engineer`; драйвер выбирается до запуска скриптов — только перезапуск; риск петли перезапусков; здесь не делалось |
| 3. `.itch.toml` с двумя действиями | см. `tools/research/crash-reports/cr-4/itch.toml.draft`: `play` с `--rendering-driver vulkan` и «Play (DirectX 12)» с `--rendering-driver d3d12`, `platform="windows"` | Пилот выбирает драйвер в приложении itch; цель — быстро получить от пилотов A и B сведения «на другом драйвере не падает» | Правка `tools/build.sh:76-78` (сейчас пишет одно действие) и публикация — только по команде пользователя; работает только в приложении itch (запуск из браузерной загрузки/zip — без манифеста); для 1.5.21 и далее; пилот на сломанном Vulkan, выбрав Vulkan явно, всё равно получит тот же откат (fallback включён) |
| 4. `override.cfg` рядом с exe | пилот кладёт файл с `[rendering] rendering_device/driver.windows="d3d12"` | Переключение без пересборки | Ручная правка; подходит для разовой диагностики с конкретным пилотом |

Рекомендация: драйвер по умолчанию не менять (вариант 1 не лечит A, для B непроверен). Для проверки гипотезы дать конкретным пилотам вариант 3 или 4 (пилоту группы B — D3D12 для проверки, группе A — чистая переустановка драйвера NVIDIA и поиск ошибок Vulkan-слоя; 0x887A0005 как потеря устройства требует CR-1). Тест: контрольный пилот запускает сборку с `--rendering-driver d3d12` / `vulkan` и сообщает, повторяется ли вылет на стадии wind. Риск: выборка — два пилота, обе машины NVIDIA, вывод по другим производителям невозможен.
