## Выводы

1. **Поле и `turb`** — только шесть случаев на Онгудае (≈ 1 000 ненулевых точек-моментов `turb`). На синтетике поля нет: путь аналитики (`gust`, `analytic`, `ridge`) проверяется там, а путь поля (RW-8) — нигде, кроме Онгудая.
2. **`turb` и `gust` — значения шума**: поточечно их нельзя сравнить, пока шум не воспроизведён побитно (W8: «итог SAMPLE_FULL … при заменённом шуме не сравнивается»). Детерминированная часть RW-8 — **σ** (`total.w`, `sigma[turb]` = σ_u поля, `sigma[gust]`) и `SAMPLE_MEAN`; σ в MEAN полная (README эталонов). То есть формулы `FieldTurbulence.sigma/lee/sep_sigma`, `taylor_stretch`, `_analytic_amp` проверяются по σ, а вид шума — только T3 (статистика) либо побитно, если RW-8 портирует `FastNoiseLite` (см. `godot-compat.md`).
3. **`storm`** — два случая (`synth_storm`: 182 точки-момента, `ongudai_day_2`: 10), **`wave`** — два (`synth_wave`, `ongudai_wave`). Мало независимых раскладок: одна гроза, одна волна. Для RW-11 стоит добавить случай RW-2c (гроза на Онгудае с полем; волна с окнами) — решение координатора.
4. **`cloud`** (выброс из облака) — 0–33 точки-момента на случай, облака поля в основном вне выборок точек; `above_base` — по 3 точки на момент. Подсос облаков (`CloudPhysics.suck`) входит в `thermal`, отдельного слагаемого нет: у термиков с облаком под базой (на 250 м, `thermal.suck_depth_m`) `thermal` не воспроизвести без RW-11 (см. «Порядок», тег `above_base`).
5. **`thermal`** есть везде (≥ 94 % точек-моментов), но источники — разные пути: синтетика — сетка клеток (`_spawn`, статичный термик у `synth_weak/medium`), Онгудай — источники из поля (`_spawn_air`). Оба пути переносит RW-10.
6. **Описания** (`*.desc.json`: ядра шаг 15, облака 10, гребни 4) — на каждый `t`; ядра — для RW-10, облака и гребни — RW-11. Id ядер — 32-битные хеши, в f32 неточны: сверка «по ближайшему» (W8).
7. **Дневные случаи** `ongudai_day_*` (набор RW-1b) — единственные с прогнозом и ходом дня: вход RW-12 (`WeatherModel.derive`, `AtmoDay`) и пересчёт поля; остальные — пресеты (`AtmoDay` нет, `day == null`).
8. **Не покрыто эталонами:** `air_model.enabled = off` (упрощённый профиль `wind_profile_simple`, термики без поля на реальном рельефе), `SAMPLE_MEAN` для `off`, статичные термики на Онгудае, сдвиг фокуса (точки внимания неподвижны), несколько фокусов, `GustDust` (быстрый ветер по слотам времени), `mean_wind_at`. Для `off` поможет случай RW-2c на синтетике с `air_model.enabled = "off"` (RW-9).
