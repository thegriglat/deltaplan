## T9 30 км против RW-21a

RW-21a: 4885 игровых с, 1003 с CPU (0,21 с/с). Сейчас: 4689 с, 1483 с CPU (0,32 с/с, в 1,5 раза дороже на игровую секунду), 13 термиков вместо 14, средний набор 1,34 против 1,36 м/с. Бот долетел. Рост CPU не разобран: между прогонами влиты RW-25 (синхронная первая сборка), RW-26 (число термиков идёт за `thermal_duty`), RW-27, RW-28, RW-29; машина в обоих случаях делилась с чужими задачами. Один сид, один прогон, синтетика (плоская земля, статичные термики, без ветра).

## Первая сборка термиков на месте 30 км

`tools/smoke/first_build/` (отдельный cargo-проект, зависит от `rust/dp-air` по пути): порядок игры из RW-25 - прогноз без `rebuild`, `load_place`, READY, `advance_to` кадрами по 1/60 с, фокус стоит. Место синтетическое 1201x1201 узлов при шаге 25 м (30 км), холмы, луг, один статичный термик; конфиги игры и климат ERA5 из репозитория, недетерминированный режим. Первый шаг 62 мс против 22-36 мс на rig 10 км (RW-25): рост ~2 раза при росте площади 9 раз. Это главный поток игры: один кадр 62 мс (~4 кадра при 60 Гц) один раз за загрузку места, порог 100 мс не превышен. Запас небольшой: на реальном месте с неровным рельефом и источниками из поля цена может быть выше (не мерилась). Сборка проекта - release без fat LTO (профили задаёт workspace, у отдельного проекта свой), поэтому в игре (LTO) должно быть не медленнее. Команда: `cd tools/smoke/first_build && cargo build --release && ./target/release/first_build --n=1201 --reps=3` (в сохранённом json `size_km` исправлен вручную с 0,03 на 30; делитель в коде поправлен).

## Падения против main: разбор

Критерий: «пропал/сломан элемент игры» против «разошлись числа, таймаут, флейк, устаревший тест». Подтверждение (повтор файла на обеих сторонах) закончено не было, поэтому список - пересечение прогона и повтора в копии минус база (скрипт `sets.py` в scratchpad, json в results).

1. **Ожидание READY воздуха дольше бюджета теста (не пропажа).** Тесты ждут `state == 2` 1200 кадров (~20 с), игра ждёт воздух. На ongudai Пикар считает `solve_heat` 228-260 с на tune-сборке под квотой; `presence_check` с большим бюджетом дошёл до полёта за 822 с (tune + headless). Падают: `test_gameplay` (13/13), `test_bar_mouse_input`, `test_camera_bar_look`, `test_mouse_routing`, `test_mouse_bar_flight`, `test_qol_cycle`, `test_cockpit`, `test_collisions`, `test_pendulum_game`, `test_tow_session`, `test_sky_shade_cockpit`, `test_trike_anywhere_k2`, `test_achievements_e2e`, `test_steam_contracts_s2`, таймауты `test_forecast_game`, `test_game_flight`, `test_goals_game`, `test_catch_up_game`, `test_input_launch`, `test_inspect_mode`, `test_motion_gate`, `test_net_flight`, `test_start_pick_*`, `test_start_regression`, `test_wait_hour`, `test_world_seed`. Вывод: на release (7 с READY на training_island, 18 с на синтетике 30 км) блокера нет, но эти ~25 игровых тестов на ongudai не проверяют игру в текущем виде; им нужен либо другой бюджет, либо быстрое место (`tests/` вне скоупа).
2. **Устаревшие ожидания тестов (не пропажа).** `test_dp_air_ext` ждёт `api_version == 4` и «Calm: ветер 0», расширение отдаёт 6 с Formula; `test_rust_wind_consumers` и `test_wind_fixtures_format` читают ключи `climate`/`place`/`conditions`, убранные RW-14c, и размер .bin 8320 против 45760; `test_rust_wind_purity` не знает файлов `weather.gd` и `surface_snapshot.gd` (список ведёт координатор, W10).
3. **Числа.** `test_wing_physics_contracts::test_k3_menu_wind_is_u10`: U(10 м) = 5,696 вместо 6,0 +-0,05; `test_feedback_1013_contracts::test_k2_weather_evening`: прогрев сразу после заката не равен 0 (две площадки). Второе - вопрос к модели хода дня (RW-14), не пропажа: `Weather.derive` отдаёт `heat` через 3 мин после заката; решение за координатором.
4. **Флейки и цена.** `test_cloud_select_chunked`, `test_ridge_starts`, `test_egg_herds::test_cpu_cost`, `test_easter_eggs`, `test_egg_place`, `test_motion_flow` - таймауты и cpu-цена под нагрузкой, часть падает и на базе.

## Границы

* Подтверждение копии не закончено (таймаут job 4 ч), базу точечно не перегоняли: список «новых» падений завышен там, где база тоже флейкует. Бисекцию по слияниям не делали: критерий пользователя - присутствие, пропажи нет.
* Присутствие мерилось на ongudai и одном сиде, на tune-сборке; облака и грозы - только через плотность на кромке, шторм и волна на фикстуре не вызывались.
* Первая сборка и T9 - синтетические места; реальное место 30 км с рельефом не мерилось.
* Числа cargo сняты до sync RW-29 (изменены только GD и smoke).
