# Отладочные слои F3–F7 на фасаде W2 (RW-P2)

Проверено в копии: расширение `tools/build_rust.sh tune linux`, headless, не запечённое место из
массивов (9,6 км, шаг 25 м, холм 400 м), прогноз (28 °C, 6 м/с с запада, 13 ч), статический термик
4 м/с, детерминированный режим, малая область поля 7,2 км. До READY поле считается ~1 с.

## Слои

Смещение растров: прежний GD-код брал `x0` как край сетки для `heat_flux` и центр для `phase_main`
(полшага 400 м). Теперь оба растра — центр первой ячейки, как требует W7.

## Что нашлось попутно (не мой скоуп)

- **Фасад молча глотает отказ крейта на `set_conditions`.** `_dp_start` не проверяет код
  `dp.set_conditions(json)`: прогноз без `speed` или `quantum_h` (W5) отвергается, поле не считается,
  состояние — READY, `field_on` показывает true. Проверка `_check_conditions` фасада этих ключей не
  требует. В тесте это стоило двух итераций. Так же тихо проходит место не 25 м (крейт отвечает
  FAILED только после запуска задачи).
- При FAILED поля (`state 3`) аналитический ветер всё равно отвечает, слои F3/F5 рисуют стрелки.
- В режиме без прогноза (эталон погоды) поле не считается, фаз и потока тепла нет: F4 пишет «нет»,
  F7 пуст — это не поломка.
- Растры фаз и потока тепла для поля из файла или кеша не строятся (фазы запоминает только расчёт).
  Тогда F4 пишет «нет (поле без фаз)». Запечённые места (учебный остров, Онгудай) — F4 покажет карту
  только после пересчёта поля в полёте.

## Что осталось проверить глазами в тестовой сборке

1. F3: стрелки видны вокруг пилота, направлены по ветру, длина растёт со скоростью.
2. F4: карта фаз видна на запечённом месте (по сказанному выше — может быть «нет» до пересчёта) и на
   незапечённом (должна быть).
3. F5, F6: проверить, что слои включаются и рисуются в экспортной сборке (в тесте — по данным и по
   вершинам, не по пикселям; причина «не показывались» у пилота для F5/F6 данными не воспроизвелась —
   вероятно, воздух не был READY, это ведёт RW-P1).
4. F7: карта тепла на рельефе, шкала в углу.
