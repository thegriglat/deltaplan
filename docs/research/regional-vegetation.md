# Деревья и дома по региону (T-83)

Вывод одной строкой: **регион выбирает маленькое дерево решений в конфиге (КБ); основная стоимость — новые модели деревьев (§4) и три процедурные формы дома (§5)**. Перекраска — добавка к моделям, не замена.

## 1. Как сейчас

**Деревья.**
- 5 пород: `pine, cedar, larch, birch, spruce` — константа `TreePlacer.SPECIES`, параметры Алтая (`tools/blender/tree_params.json`, генератор `tools/blender/build_trees.py`, процедурные текстуры, свои — лицензия не вопрос, ASSETS.md). Понятия региона нет: любое место получает те же 5 пород.
- Выбор породы: `TreeCell.species(высота, экспозиция, хеш клетки, веса…)` — `configs/world.json → trees.species` (вес, пояс `min_m/max_m`, `aspect`, высота). Локация может переопределить веса (ongudai — лиственница ×4). Функция одна и та же на CPU (`TreePlacer`) и в GPU-шейдере (`tree_cell.gdshaderinc`) — индексы пород зашиты в оба.
- Три плана: модели LOD0/LOD1 до 60/180 м (MultiMesh на породу × 8 вариантов × LOD), кресты LOD2 до 0,9–1,5 км, билборды из атласа `trees_impostor_atlas.png` (1024×1024, ячейки 256×512, сетка 4×2, занято 5 из 8) до 3,5 км, дальше **полог в шейдере рельефа** (клетки Вороного, `conifer_share`, цвета). Выше 900 м над землёй модели не рисуются: **с высоты полёта лес в основном — полог шейдера**, так что тон полога и доля хвойных по региону — бесплатная часть решения.
- Сезон SL-6 (`SeasonLook`) красит лиственные осенью и сбрасывает листву, считая по широте; **вечнозелёных тропиков он не знает** (в Бразилии листва по календарю севера).
- Лес берётся из маски WorldCover 10 м («Tree cover»); **типа листа в данных места нет**. OSM-тайлы проекта несут дороги, дома, ЛЭП и т.п.; landuse/`natural=wood`/`leaf_type` не возвращаются (docs/contracts/osm-tiles.md, no-osm).

**Вес пород в сборке (измерено в этой копии).**

| Что | Размер |
|---|---|
| `assets/models/trees/` целиком (с `.import` и исходными PNG импостеров) | 15 МБ |
| `tree_*.glb` на породу (8 вариантов × LOD0–2) | 1,4 (сосна) … 2,1 (лиственница) МБ; всего ≈ 9,3 МБ |
| текстуры породы: листва 512×512 RGBA, кора 256×512 RGB | ≈ 60–100 КБ PNG каждая (в паке — сжатые BC7/ASTC: включены `import_s3tc_bptc` и `import_etc2_astc`) |
| `trees_impostor_atlas.png` | 0,5 МБ PNG |
| `assets/source/trees` (не в пак) | 12 МБ |

Оценка VRAM существующего набора (расчёт, не замер): сетки ≈ 1,8 МБ на породу (равно размеру glb), текстуры с мипами BC7 ≈ 0,5 МБ на породу, атлас 1024² BC7 с мипами ≈ 1,4 МБ → ≈ 11…12 МБ на 5 пород.

**Дома.**
- Дом — не модель: `BuildingPlacer` строит `BoxMesh` (стены) + `PrismMesh` (двускатная крыша) + коробку трубы, MultiMesh с цветом экземпляра; окна, крыша, затемнение — в шейдере `building.gdshader`, **текстур нет**. `BuildingStyle`: CITY/INDUSTRIAL — плоская крыша, VILLAGE — двускатная; палитры — `configs/world_objects.json → buildings.palettes` (крыши красные/зелёные/серые — «европейские»); угол ската — `roof_pitch_deg`; этажность — `height_rule` по типу и площади, поправка мегаполисов `metro`. О регионе ничего не знает (отсюда многоэтажки на острове Пасхи).
- Из OSM в тайле: прямоугольник, угол, высота (из `height` или `building:levels·3`), тип O3. **`roof:shape`, `roof:colour`, `building:colour` в формате не хранятся.**

### Три способа выбора набора — замер

Эталон — карта Кёппена 1 км; 30 классов сведены в 8 наборов: `arid` (BW, BSk), `tropical_wet` (Af, Am), `savanna` (Aw, BSh), `mediterranean` (Cs*), `subtropical` (Cfa, Cwa), `temperate` (Cfb, Cfc, Cwb, Cwc, Df[ab], Ds[ab], Dw[ab]), `boreal` (Dfc, Dfd, Dsc, Dsd, Dwc, Dwd), `alpine_ice` (ET, EF). Сведение — моё допущение. Признаки — только (lat, lon): высоты нет (см. ниже).

- Тест: 173 156 случайных точек суши мира (равная площадь) на карте 1 км — независимы от обучения (дерево училось на карте 0,5°, то есть ещё и проверяется перенос на мелкий масштаб); и 683 старта из `data/places/hg_takeoffs.json` на суше.
- «Склейка» — умеренный/бореальный/альпийский считаются одним набором: их различает высота над морем, которую всё равно ведут высотные пояса `trees.species`, а карта 1 км в горах помечает Альпы то Dfc, то ET.
- Воспроизведение: `tools/research/regional_veg/README.md`.

| Способ | Размер JSON | Мир, точно | Мир, склейка | Каталог, точно | Каталог, склейка |
|---|---|---|---|---|---|
| (а) срезы по широте, 5 штук | ~60 Б | 52,4 % | 63,0 % | 70,6 % | 87,4 % |
| (а) срезы по широте, 9 штук | ~100 Б | 58,2 % | 66,4 % | 52,1 % | 66,2 % |
| (б) 43 прямоугольника руками (+ запасные срезы по широте) | 0,8 КБ | 70,1 % | 78,3 % | 71,4 % | 85,5 % |
| (в) дерево решений, 16 листьев | 0,3 КБ | 69,5 % | 76,3 % | 64,6 % | 86,4 % |
| (в) 32 листа | 0,7 КБ | 78,0 % | 81,9 % | 71,4 % | 87,7 % |
| (в) 64 листа | 1,4 КБ | 81,5 % | 85,0 % | 71,7 % | 87,6 % |
| **(в) 128 листьев** | **3,0 КБ** | **85,2 %** | **88,3 %** | 73,5 % | 89,5 % |
| (в) 256 листьев | 6,1 КБ | 87,7 % | 90,5 % | 66,9 % | 78,6 % |
| (в) 1024 листа | 26 КБ | 91,4 % | 93,6 % | 74,5 % | 89,2 % |
| сетка 1° (центры ячеек, для сравнения) | 65 КБ | 87,7 % | 90,3 % | 69,7 % | 87,0 % |

Что видно:
1. **Срезы только по широте (а) слабы** (52–58 % мира): долгота нужна (суша/океанские фасады, Казахстан против Европы). Срезы по высоте и «климату/landcover места» в замер не вошли: высоты у меня нет без DEM, а климат/landcover места — это и есть эталон; в игре высоту дают пояса уже сейчас.
2. **Прямоугольники руками (б)** — 70 % мира, примерно как дерево на 16 листьев. Руками 43 коробки писались час, и ошибка ручного порядка видна на контрольных местах: Алтай (Манжерок) попал в «Центральную Азию» (arid), потому что коробка 36–52°N, 50–90°E стоит раньше алтайской. Хрупко и растёт трудно.
3. **Дерево решений (в)** — 128 листьев = 3 КБ и 85 % мира, 1024 листа = 26 КБ и 91 %. То есть **при тех же килобайтах, что у списка прямоугольников, на 15 п.п. точнее для произвольной точки мира**, строится скриптом без ручной работы и пересобирается при смене набора. Вычисление в игре — ~7 сравнений (глубина), ничего не стоит. Дерево — это и есть «срезы», только подобранные по данным (оси lat/lon); бустинг ради этого не нужен — один неглубокий ствол уже у потолка точности для двух признаков (дальше растёт заучивание карты).
4. **На каталоге стартов** (684 точки, ≈ 70 % умеренные Альпы/Европа; тропиков 3, саванны 10, средиземноморья 49) точность всех способов в пределах шума: 683 точки дают ±1,5…1,8 п.п. (σ биномиальная), поэтому различия 128 против 256 листьев (89,5 против 78,6 %) — случайность отдельных кластеров (Альпы с границей Cs/Cf), а не качество. Вывод по каталогу: для популярных мест подойдёт любой из (б)/(в); (в) предпочтительнее для «прочего мира».
5. **Мелкие и береговые места все способы lat/lon пропускают**, и это не дерево, а разрешение. Контрольные места (истина Кёппена / (б) / дерево 128 / сетка 1°):

| Манаус | tropical_wet | tropical_wet | tropical_wet | tropical_wet |
| Анси, Альпы | temperate | temperate | temperate | temperate |
| Манжерок, Алтай | temperate | arid (порядок коробок) | temperate | boreal |
| Алматы | temperate | arid | arid | arid |

Горы и острова — слабое место lat/lon-признаков: Гималаи режет климат по высоте на километры, дерево на 128 листьев их усреднило до «arid». Лечится высотой (в игре есть) и **малым списком ручных исключений** (Рапа-Нуи, Ницца и побережье Средиземноморья, Непал и Гималаи, Кернс/Квинсленд) — 3–10 прямоугольников поверх дерева.

**Простота.** (б) — ручной файл, растёт и путается; (в) — генерируется скриптом из исходной карты (скрипт в репозитории), в игре — цикл по массиву узлов; правка «хочу, чтобы здесь было иначе» — один прямоугольник-исключение. Исходный Кёппен в репозиторий не идёт (атрибуция в ASSETS.md и README).

**Вывод по выбору набора.** Интерфейс `biome_at(lat, lon, alt_m) -> id` = исключения (прямоугольники) → дерево решений 128 (при нужде 256) листьев → высотный пояс (как сейчас). Цена — 3–6 КБ в `configs/`. Если на пробных местах (Бразилия, Рапа-Нуи, Непал, ЮАР, Кавказ) нужно точнее — поднять число листьев до 1024 (26 КБ) или добавить признак «ближайшее побережье»; сетку 1° не брать (65 КБ, не лучше).

## 3. Ограничения замера
- Эталон — тот же Кёппен, по которому дерево обучено: показывает, как хорошо lat/lon воспроизводят климат, а не как хорошо климат описывает растительность (между Cwa и реальным лесом Непала есть разрыв).
- Сведение 30 классов в 8 наборов — допущение; смена сведения меняет цифры на единицы процентов.
- Ни одна из величин не учитывала высоту; склейка умеренный/бореальный/альпийский — её заменитель.
- Каталог стартов — выборка Европы/Альп, оценка на нём малоинформативна для тропиков (3 точки).

## 4. Какие новые модели деревьев нужны

Принцип: сверху (с 100–500 м) читаются **силуэт и тон кроны**, поэтому нужны разные формы кроны, а не ботанические виды. Модель = запись в `tree_params.json` + текстура листвы/коры + запекание в `build_trees.py` (генератор параметрический; есть кроны `umbrella`, `ovoid`; для пальмы и колонны нужны новые типы кроны — доработка генератора).

Остаются: ель `spruce`, сосна `pine`, кедр `cedar` (≈ деодар/голубая сосна Гималаев), лиственница `larch`, берёза `birch`.

| # | Новая модель | Где нужна | Что заменяет | Как получить |
|---|---|---|---|---|
| 1 | **Дуб/бук** (широкая округлая лиственная) | умеренная Европа (Альпы ниже ~1200 м, Германия, Франция, Карпаты), Кавказ, Япония, восток США | берёза как единственная лиственная (берёза остаётся для бореала/Алтая) | крона `ovoid`, листва широкая |
| 2 | **Дуб вечнозелёный** (каменный/пробковый) | Средиземноморье, Калифорния, центр Чили, часть ЮАР | сосна/берёза, дающие «северный» вид | низкая плотная крона, тёмная листва |
| 3 | **Кипарис** (колонна) | Средиземноморье, Иран, Тоскана | — (такого силуэта нет) | новая крона `column`, малая сетка |
| 4 | **Пальма** (кокосовая/королевская) | побережье Бразилии, Карибы, Гавайи, Таити, Канары, Юго-Вост. Азия, Рапа-Нуи | сосна у побережья | новый тип: перья-карточки на конусном стволе |
| 5 | **Тропическая лиственная вечнозелёная** (крупная купольная) | Бразилия (Атлантический лес), Амазония, Индонезия, влажная Африка, предгорья Гималаев | сосна, берёза (в Бразилии сейчас они) | крона `ovoid` крупная, листва без листопада |
| 6 | **Акация** (зонтичная) | саванны Африки, сухие склоны Австралии | сосна — единственная плоская крона | существующий тип `umbrella` — дёшево |
| 7 | **Эвкалипт** (высокий, редкая свисающая крона, светлый ствол) | Австралия (15 стартов каталога), Бразилия (плантации), Португалия, Калифорния, ЮАР | сосна/берёза | `droop` > 0, узкая крона |
| (0) | **Каменная сосна (зонтик)** — не модель, а запись параметров на тех же ассетах/текстуре | Средиземноморье | — | `crown: "umbrella"` в `pine` |

«Чтобы Бразилия перестала быть Алтаем» — минимум #4 и #5 (+ #1 для умеренной Европы). Набор по регионам:

## 5. Дома по региону

Сверх палитры нужны **3 процедурные формы** (корпус + крыша, десятки–сотни треугольников в `BuildingPlacer`; ни файлов, ни текстур):

| # | Форма | Регионы | Заменяет |
|---|---|---|---|
| H1 | Плоская крыша с парапетом | Иран/Ближний Восток, юг Испании/Греции, Северная Африка, Непал (города) | двускатная VILLAGE |
| H2 | Вальмовая низкая крыша 15–25°, черепица | Средиземноморье, Бразилия, Австралия | двускатная 35–45° |
| H3 | Хижина: цилиндр/куб + конус или односкат из листа | тропики, Африка, высокие гималайские деревни | двускатная |

Альпы (шале) — остаётся двускатная, меняется угол ската и свес (конфиг). Остальное — профиль региона в конфиге: палитра стен (белая/охра/бетон/саман), палитра крыш (терракота, жесть, красный шифер вместо зелёных), угол ската, потолок этажей для **процедурных** домов и `metro`-множитель (на острове Пасхи многоэтажек быть не должно; сейчас `height_rule` региона не знает). OSM даёт `building:levels` и `height` (уже используются); `roof:shape`/`roof:colour`/`building:colour` в тайлах нет, теги редки (впечатление, на выборке не проверял) — правка пакера ради них не окупается.

## 6. Размер и VRAM

Допущения: новая порода ≈ существующая (glb 1,4–2,1 МБ при 8 вариантах; текстуры 0,15–0,3 МБ в паке; при 4 вариантах сетки вдвое меньше); пальма и кипарис проще (≈ 1 МБ). **Оценки, не замеры** — измерить на первой модели.

| Вариант | Состав | Пак | VRAM |
|---|---|---|---|
| **A. Минимум** | дерево решений + профиль региона (палитры, угол крыши, тон полога, вечнозелёность SL-6) без новых моделей | +0,05 МБ | 0 |
| **B. Средний** | A + модели #1, #4, #5 (+ запись 0) + H1, H2 | +3…6 МБ (8 вар.) или +2…3 (4 вар.) | пока грузится набор места (≤ 5 пород) — без роста, ≈ 12 МБ; атлас: 3 свободные ячейки хватает на 3 породы |
| **C. Полный** | A + все 7 моделей + запись 0 + H1–H3 | +6…13 МБ (≈ 4…9 % пака; при 4 вариантах +5…7) | с набором места ≤ 6 пород ≈ 14 МБ; все 12 сразу ≈ +16 МБ — не делать |

Ключевое решение: **набор в памяти = набор места.** Тогда растёт пак, VRAM — нет. Для этого `SPECIES`/`models` и раскладка атласа должны стать списком места (сейчас константа на 5 и индексы зашиты в `tree_cell.gdshaderinc`); атлас импостеров — на набор (≈ 0,5 МБ PNG) либо единый второй ряд (+4 ячейки ≈ +0,7 МБ).

## 7. Кандидаты-источники моделей
Лицензию проверять при скачивании, записывать в `ASSETS.md`:
1. **Свой генератор** (`build_trees.py`, Blender) — рекомендуется: единый стиль с 5 существующими, три LOD и импостер уже есть, лицензия своя. Минус — время на кроны пальмы и эвкалипта.
2. CC0-наборы: Quaternius (Ultimate Stylized Nature и пальмы/акации — CC0, малополигональные), Kenney Nature Kit (CC0, мультяшные), Poly Haven (CC0, высокополигональные — потребуют децимации в LOD и запекания импостера). Стиль не совпадёт с процедурными текстурами — годятся как база в наш конвейер, не как готовые.
3. Sketchfab: только модели с явным CC0 (не CC-BY-NC), каждую проверять; не опираться.
4. Sapling Tree Gen (Blender-аддон, GPL): код аддона в игру не идёт, сгенерированные деревья свободны; проще свой скрипт.

## 8. Рекомендация (KISS) и план

**Рекомендация.** Вариант **B → C по необходимости**. Регион = исключения + дерево решений 128–256 листьев (3–6 КБ) + высотные пояса. Новые породы — своим конвейером (4 варианта на новую породу). В память — набор места. Перекраска (тон полога, `dryness`, вечнозелёность) — сопутствующая мелочь.

**Задачи будущего модуля `regional-veg`.**
1. Скрипт запекания `configs/biomes.json` (дерево решений из Кёппена, исключения, наборы пород с весами/поясами, профили домов, вечнозелёность, тон полога) + `biome_at(lat, lon, alt)`; тест на 10 эталонных точках (Альпы, Алтай, Бразилия, Рапа-Нуи, Непал, ЮАР, Австралия, Средиземноморье, Кавказ, Иран); атрибуция Кёппена в ASSETS.md.
2. Рефакторинг: список пород и атлас — по месту (`TreePlacer.SPECIES`, `tree_cell.gdshaderinc`, `ForestImpostors`); тест, что Алтай не изменился.
3. Дома: профиль региона в `BuildingPlacer`/`BuildingStyle` (палитры, угол ската, потолок этажей процедурных), формы H1–H3.
4. Сезон: вечнозелёные/сухой сезон по региону в `SeasonLook` (+ правка контракта SL-6).

7. Опционально: MODIS/CGLS тип листа, если окажется, что Кёппена мало.
