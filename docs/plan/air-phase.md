# air-phase — замеры фаз на идеальном рельефе

## 0. Цель
Получить данные для чётких границ фаз (пороги, ширины переходов, гистерезис) — опыты `docs/research/air_phase.md` §9 на
идеальном рельефе. Зачем — целевая архитектура «сборка поля по фазам на GPU» (`air_phase_experts.md` §15): классификатору
нужны сигмоиды с шириной из опытов, гистерезису — полосы ±w. Этот этап — **только инструмент и счёт**: один скрипт всех
серий → пробный прогон с оценкой времени → шлюз → один большой запуск. Разбор (подгонка сигмоид, ширины, гистерезис,
обновление air_phase.md) — следующий этап, после счёта.

## Решения пользователя (не обсуждаются)
1. Один скрипт прогона всех замеров разом: все серии одной командой, с продолжением после обрыва; затем один большой
   запуск. Не дробить на ручные прогоны.
2. На GPU — батчами (несколько случаев одновременно); выигрыш батча замерить на пробе и выбрать размер.
3. Генератор рельефов (с эрозией) и готовые наборы уже есть — переиспользовать (`reliefs.py`, корпус S1, `fs1_10k`,
   решатель `tools/research/air_synth/solver/`, `air3d`); генерировать только недостающее (идеальные формы).
4. Форматы: массивы — HDF5, манифест — protobuf с контрактом, логи — jsonl; долгие счёты — `dp job --lock gpu`; Godot не нужен.
5. Шлюз до большого запуска: оценка времени и состав серий → пользователь одобряет.
6. Не шлифовать; физика прежде всего.
7. Огибающая «линии тени» (06.10): серии ENVELOPE / ENVELOPE_REAL — Пикар 400 м на h_eff, сравнение с окном 100 м и на реальных крутых местах (несходимость); состав и цена — на шлюзе.
9. Шлюз до большого запуска снят (06.10, ночь у пользователя): скрипт и пробный прогон прошли → сразу полный счёт всех серий через `dp job` (с продолжением); CPU и GPU можно грузить параллельно; состав и оценку — в журнал и отчёт, не ждать ответа.
8. Сеть — не цель модуля (06.10): никаких прикидок и задач на обучение новой нейросети; по итогам замеров сеть либо удаляется, либо остаётся только заменой Пикару в подходящих фазах.

## 2. Физика опыта (зафиксировано координатором по §9)
- Область 38,4 км, клетка 400 м (как корпус), окно 100 м — только серия SEPARATION. Ветер с запада (φ = 270°), поперёк
  хребта и уступа; в SEPARATION (г) — 300° и 330° (30° и 60° к нормали хребта).
- Формы (h = 500 м, база 1000 м н. у. м.), крутизна s = max|∇z| (тангенс): холм (гаусс), хребет (длина 20 км, гауссово
  сечение и гауссовы концы), уступ (tanh): в GRID — подъём по ветру (блокирование), в SEPARATION — спуск по ветру (подветренная бровка). Формулы — контракт P1. Оговорка: s = 0,5 даёт a ≈ 0,86 км —
  2 клетки по 400 м, форма на 400 м недоразрешена (для этого окно 100 м).
- Стратификация: N = 0,01 с⁻¹ над z_i (override), под z_i — слой перемешивания; h/z_i = 0,3 / 1 / 3 (z_i над базой
  1667 / 500 / 167 м). Нагрев — однородный поток H = 0 / 100 / 250 Вт/м² (−z_i/L записывается в результат).
- Fr = U_sat/(N·h) — как `froude` в S2 (`conditions.derive`, relief_m = h); U10 подбирается из профиля притока
  (α, max_profile — постоянные плана). Точки Fr: 20 логарифмических на 0,1…5 ∪ шаг 0,05 на 0,3–0,6 и 0,8–1,3, без
  повторов — 30 точек на линию.
- Нижний предел K (гипотеза N1, air_phase.md §5.3): сейчас k_fa = 1 м²/с; физический K_min ~ σ_w·l ≈ 0,3 м/с × 33 м ≈ 10 м²/с.
- Относительный критерий сходимости: метрика решателя, делённая на её естественный масштаб (скорость — на U_sat, невязка
  импульса — на U_sat²/a), порог подобран так, чтобы при U_sat = 5 м/с совпадать с нынешним абсолютным.

## 6. Риски
- Пакетный счёт меняет порядок редукций → не побитно; допуск фиксирован в P4, расхождение измеряется.
- Тёплый старт в цепочке последовательный: пакет собирается поперёк линий (одна точка k у многих линий) — при 81 линии
  этого хватает на батч до ~32.
- Слабый ветер (Fr ≤ 0,3: U_sat ≤ 1,5 м/с) — несходимость и долгий счёт до max_outer: время серии оценивать по пробе
  именно на этих точках.
- Диск: свободно ≈ 52 ГБ; бюджет результатов ≤ 20 ГБ (поля float16, снимки — 2 уровня).
- Venv в копии закрытого модуля air-synth — может исчезнуть при `dp gc`.

## 7. Идеи (на потом, не в работе)

- **Сшивка фаз по минимуму невязки уравнений** (обсуждение 06.10.2026, вернуться после замеров). Поле в области — смесь u = Σ w_φ·u_φ готовых полей механизмов фаз; веса w_φ — двумерные карты 96×96 только в полосах переходов (или по числу на зону). Искать веса, минимизирующие невязку уравнения импульса того же решателя для смеси плюс малый штраф за негладкость весов, с ограничением Σ w_φ = 1; при готовых полях фаз это линейные наименьшие квадраты (1–2 шага Гаусса — Ньютона), неизвестных — тысячи, решать V-циклом/сопряжёнными градиентами; затем обычная проекция ∇·u = 0. Почему невязка, а не гладкость шва: физические переходы бывают резкими (разделяющая линия тока, гидравлический прыжок, кромка срыва) — штраф за гладкость их размажет. Цена — десятки мс (одна оценка невязки ≈ итерация Пикара, 3,6 мс на 400 м) при пересчёте раз в 15 игровых минут. Не работает в статистических фазах (F, H): там веса с ограничением массы. Дешёвая альтернатива того же смысла — тёплый старт Пикара из собранного поля, 20–50 итераций с маской только в полосах швов. Проверка — прототип на SY-12 против Пикара там, где он сошёлся, отдельно ошибка в швах; уровни: проекция (есть) → веса по невязке → тёплый старт.
