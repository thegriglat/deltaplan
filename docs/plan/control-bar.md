# control-bar — ввод с физической трапеции

## Цель
Человек собирает раму с трапецией и датчиками положения ручки и управляет игрой как на тренажёре (вместе с платформой
подвижности из motion-rig или без неё). Ход ручки вбок → крен/смещение веса, вперёд-назад → тангаж — то же управление,
что сейчас дают мышь и геймпад (`scripts/game/input_controller.gd`, `_apply_gamepad`, конфиг `gamepad`).

## Решения пользователя (не обсуждаются)
- 10.10: не упарываться — эмулируем только трапецию (положение ручки: вбок, вперёд-назад). Разбег и прочие действия —
  с клавиатуры, как сейчас. Нужен ли модуль вообще — ещё непонятно, объём минимальный.
- 10.10: перед реализацией — исследование готовых протоколов и решений самодельщиков (шлюз): записка с URL и рекомендацией
  «что поддерживаем» (ожидаемо — стандартный HID-джойстик, без своего протокола). Реализация — только после одобрения.
- Не сливать в main и не пушить без команды.

## Физика и границы модели
Трапеция в модели — абсолютное положение ручки относительно пилота (мышь даёт относительные смещения и держит
«виртуальную ручку»). Ход ручки отображается в те же величины, что и от мыши/геймпада, без подгонки ощущений:
калибровка (нейтраль, крайние положения) только приводит сырой ход датчика к нормированному [-1, 1].
Обратной силы (усилие на ручке, демпфирование) модуль не даёт — это механика рамы.

## Задачи

### CB-1 Исследование: готовые протоколы и решения (dp-researcher, веб)
Чем реально пользуются самодельщики симуляторов для абсолютных осей: USB HID joystick (Arduino Leonardo/Pro Micro +
ArduinoJoystickLibrary, ESP32 BLE Gamepad), готовые прошивки/платы (FreeJoy, MMJoy2, DIY-джойстики авиасимов),
vJoy и аналоги (Linux uinput, macOS), датчики (потенциометры, Холл, AS5600/магнитные энкодеры, тензо). Существующие
DIY-трапеции/тренажёры для дельтапланов и парапланов (что используют, какая геометрия, ход). Godot 4.7 Input: оси
джойстика на Win/Linux/macOS (SDL-маппинг, `Input.get_joy_axis`, число осей, неизвестные устройства без маппинга,
BLE-геймпады, разрешение/дрожание), что есть в нашем `input_controller.gd`.
Итог: `docs/research/control-bar-input.md` (frontmatter type research, conclusion) — таблица «решение → интерфейс к ПК →
цена/сложность → URL», рекомендация «что поддерживаем» (одна, с обоснованием), рекомендуемая сборка для инструкции
(плата + датчики + готовая прошивка/скетч), ограничения Godot по ОС, предложение по объёму CB-2/CB-3.
Приёмка: файл есть, `dp docs check`, ≥ 8 URL, рекомендация явно. **Шлюз**: с запиской — к главной сессии до реализации.

### CB-2 Трапеция/джойстик во вкладке «Управление» (dp-engineer)
Контракты CB-К1 (ключи `gamepad`), CB-К2 (`BarAxis`) — `docs/contracts/control-bar.md`. Поверх существующего ввода геймпада,
без нового протокола. `scripts/game/bar_axis.gd` (новый), `scripts/game/input_controller.gd` (`_apply_gamepad` через
`BarAxis`, устройство по `device_guid`), `configs/controls.json` (новые ключи с `*_doc`), `scripts/ui/settings_panel.gd`
(раздел во вкладке «Управление»; вынести в свой файл, если панель разрастается), `locale/ui.csv` (ru + en).
Раздел «Трапеция / джойстик» (en «Control bar / joystick») во вкладке «Управление» (en «Controls»):
- устройство — список подключённых (`get_joy_name`), пункт «Первое подключённое» (`device_guid = ""`); выбранное, но
  не подключённое — «не подключено: <имя>»;
- ось крена, ось тангажа — номер оси (0…7 или по числу осей устройства); инверсия крена, инверсия тангажа;
- мёртвая зона, экспонента (`expo`, «0 — линейно»: для трапеции честнее линейно; решение координатора — один ползунок);
- калибровка: кнопка «Нейтраль» (en «Set neutral») — текущие сырые значения обеих осей → `center`; кнопка «Края»
  (en «Record range») — запись min/max, пока пилот водит ручку по всему ходу, повторное нажатие — стоп; «Сброс» (en «Reset») —
  `[-1, 0, 1]`;
- индикатор — сырые значения осей и итог `BarAxis.axis_value` (точка в квадрате или две полосы), обновляется каждый кадр,
  пока вкладка видна.
Сохранение — общей кнопкой «Сохранить» через `UserSettings.save_patch("controls", {"gamepad": …})`.
Приёмка: `tests/contracts/test_control_bar_contracts.gd` зелёный; свои тесты (калибровка, инверсия, выбор устройства по GUID
на подставном списке, сохранение настроек в `config_dir` теста); тесты `ui`, `input`, `settings`, `ui_controls` — без новых
падений (`test_language.gd::test_main_menu_selector_rebuilds_ui` падает в main — не чинить); `tools/lint.sh` по своим файлам.
Без устройства в тестах — функции чистые, UI проверяется сборкой панели в headless.

### CB-3 Инструкция «Build your own control bar» (dp-writer)
`tools/control_bar/README.md` (англ., коротко, по образцу `tools/motion_rig/README.md`): игре нужен любой USB HID-джойстик
с двумя осями; варианты ссылками без подробной сборки — Arduino Pro Micro/Leonardo + ArduinoJoystickLibrary, STM32 Blue Pill
+ FreeJoy (из записки CB-1); датчики — потенциометры или AS5600, коротко; в игре — Settings → Controls → Control bar /
joystick: выбрать устройство, оси, инверсия, Set neutral, Record range, мёртвая зона, экспонента 0. Знаки: ручка вправо —
индикатор вправо, ручка от себя — индикатор вверх/вперёд, иначе — инверсия. Ссылка из `tools/motion_rig/README.md` и обратно.
Приёмка: файл есть, ≥ 3 URL, без выдуманных деталей (только из записки CB-1 и плана).

## Итог CB-1 (принят 10.10)
Записка — `docs/research/control-bar-input.md` (17 URL). Готовых DIY-трапеций дельтаплана не найдено (ближайшее — самодельный
контроллер для парапланерных игр на Arduino Micro + ползунковые потенциометры). Рекомендация: стандартное USB HID-устройство
«джойстик» (две оси), без своего протокола, vJoy/uinput не нужны. Godot 4.5+ (SDL3) открывает устройство без маппинга как сырой
джойстик, оси по индексу SDL в −1…1 — `Input.get_joy_axis(dev, i)` работает. Сборка для инструкции: Arduino Pro Micro/Leonardo
+ 2 потенциометра (или AS5600) + скетч на ArduinoJoystickLibrary; без кода — FreeJoy на STM32 Blue Pill. В `_apply_gamepad`
уже есть две оси, мёртвая зона, экспонента; нет выбора устройства (берётся первое), инверсии крена, калибровки.
Не проверено на железе: порядок/число осей конкретной платы на трёх ОС. **Шлюз**: одобрение CB-2 и нужен ли CB-3.
