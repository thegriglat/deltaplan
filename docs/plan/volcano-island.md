# volcano-island — Вулканический остров

Ветка `feature/volcano-island` от `main`, копия `~/deltaplan-volcano-island`, код задач — `VI`. Слияние в `main` — главная сессия;
выпуск — только по команде пользователя. Кадры — `/home/greg/deltaplan/build/screenshots/volcano-island/<задача>/`.

## Цель пользователя
Второе тренировочное место — реальный вулканический остров в океане (рельеф как есть), доступный только через «Тренировку».

## Решения пользователя (2026-10-17)
- Место доступно ТОЛЬКО через «Тренировку» (кнопка главного меню, окно с карточками); в «популярные места» и списки мест не добавлять.
- Название нейтральное — «Вулканический остров» / «Volcanic Island»; реальное имя острова и мест не раскрывать нигде в публичном (сайт, тексты, меню).
- Рельеф не править (реальный, как есть).
- Дома и деревья острова не трогать: своих наборов деревьев и стилей домов нет — как игра рисует по данным, так и остаётся.
- По образцу учебного острова: данные места в сборке (рельеф, покров, OSM, ~8 МБ, без сети при первом входе), центр на суше; старты под тренировки
  (склон восточного плато, склон/гребень кратера, термики — если есть подходящий, посадка на плато); фиксированная погода старта (пассат ВЮВ, разумное время);
  запечённые поля ветра с хешем модели воздуха; проверка воздуха числами (подъём на склонах, ротор, термики); карточки в окне «Тренировка» (второй группой,
  первые 4 карточки не ломать); посадки; `bake_all.sh --check` для нового места — в шаге new-release.
- Исполнители: sonnet по умолчанию, opus — воздух/запекание. Тестовых сборок не делать, цену GPU не мерить. Мелкие визуальные детали — не больше 2 заходов.
- Общие файлы с модулем fast-load (кеш поля воздуха, загрузка, OSM) — через главную сессию.

## Задачи

### Волна 1 (параллельно)

#### VI-1. Данные места, старты, посадки (dp-researcher, sonnet)
VI-К1 (данные): `tools/terrain/volcano/build.sh` — сборка места обычным сборщиком во временном профиле → `data/locations/volcano_island/` (+ `osm/` тайлы);
`configs/locations/volcano_island.json` (`bundled`, `training_only`, центр на суше, `utc_offset_h` −6), старты `east_cliffs`, `crater_ridge`, `plateau_landing`
и, если найдётся, `thermal_slope` (быстрая проверка: полдень южного лета, слабый ветер — есть ли термики над сушей), посадки, имена в `locale/ui.csv`,
`configs/world_objects.json → landing.sites.volcano_island`; контрактный тест K1 (данные). Быстрая проверка воздуха (без запекания): w у стартов при 6 м/с с 110°.
Кадры со стартов и сверху — `…/volcano-island/VI-1/` (свой профиль, тайлы OSM — из кеша профиля).
Приёмка: место грузится из `res://` без сети, правила стартов и посадок, размер папки, кадры, таблица w.

#### VI-4. Запекание всех встроенных мест (dp-engineer, sonnet)
VI-К3: `tools/terrain/bake_all.sh` по конфигам вместо `tools/terrain/island/bake_all.sh`; ссылки new-release и docs; `--check` на учебном острове = 0.

### Волна 2 (после VI-1)

#### VI-2. «Только для тренировки» и OSM из папки места (dp-engineer, sonnet)
VI-К1 (код): `Locations.is_training_only`, `builtin_at`, каталог «Популярные места» (перегенерировать), списки мест меню полёта, восстановление последнего полёта;
`Locations.osm_root` и вызовы `OsmData.load_for`; экспорт `osm/**/*.dpt`; тесты мест (`tests/ui/test_menu_setup.gd`, `tests/terrain/test_locations.gd`,
`tests/contracts/test_osm_any_contracts.gd`, `tests/stability/test_matrix.gd`, `tests/game/test_e2e.gd`) — под новое место; контрактный тест K1 (код).
Общий файл с fast-load (FL-4: OSM) — вызов `OsmData.load_for`.

#### VI-3. Окно «Тренировка» с группами мест (dp-engineer, sonnet)
VI-К2: `configs/training.json` v2 (группы), вкладки в `TrainingMenu`, `start_menu.gd`, карточки острова, тексты; тесты окна; контрактный тест K2.

### Шлюз 1 (после VI-1)
Главной: кадры VI-1 (со стартов и сверху), таблица w, какие старты есть (есть ли термики). Волна 2 идёт параллельно.
Ответ Q1 (2026-10-17): east_cliffs — на кромку морского обрыва, если проходит правила старта, иначе с подлётом; crater_ridge — на кромке ЮЗ обрыва (обратный ветер 5 % — честно); термики — только погодой (ясно, жарче, честно для января на 27° ю. ш.), без подгонки модели, не выйдет — без карточки; посадки на уклоне 4–8° — приемлемо; ротор — только у кратера. В main влит fix/lee-start-calibration (k притока ≤ 1): ветка модуля синхронизирована, числа стартов — заново в VI-5, затем запекание.

### Волна 3 (после шлюза 1, VI-2, VI-4)

#### VI-5. Погода стартов, проверка воздуха, запекание (dp-researcher, opus)
Наборы TI-К2 v2 для каждого старта (пассат ВЮВ; южное полушарие — месяц южного лета/пассатного сезона с обоснованием; час из 9/12/15/20);
проверка воздуха числами, как `tools/terrain/island/air_check.py` / `docs/research/training_island_air.md`: склоны — подъём при 5–8 м/с, ротор — за обрывами
(где и насколько), термики — над сушей есть, над морем нет; запечь все старты (`tools/terrain/bake_all.sh --id volcano_island`), `--check` = 0, размер;
тест, что каждый старт берёт запечённое поле. Если термик-старт есть — карточка термиков (VI-К2 v2). Кадры F3/F6 — `…/volcano-island/VI-5/`.
Первым шагом (Q1): перенести east_cliffs на кромку морского обрыва (правила tools/terrain/volcano/check_sites.py; не проходит — оставить, в отчёт), посадку у него — в пределах планирования; кадры нового старта. Все числа стартов — заново после fix/lee-start-calibration (k притока ≤ 1).

#### VI-6. Тексты и документация (dp-writer, sonnet)
`docs/guide/location-data.md` (раздел о втором острове: реальные данные в сборке, `training_only`, OSM из папки места), `CHANGELOG.md` «В работе»,
`ASSETS.md` (Copernicus GLO-30, ESA WorldCover CC-BY 4.0, OSM ODbL — без названия острова), описание места ru/en (нейтрально), `registry/findings.md`.

### Шлюз 2 (финал)
Кадры всех стартов, числа воздуха (VI-5), коммит ветки модуля для слияния → главной.

## Условия остановки
- Старт не проходит правила без правки рельефа → другой ориентир того же вида; вида нет — шлюз.
- Поле на склоновом старте упирает приток в предел (k 3,0) или ветер > 15 м/с у старта при 6 м/с — старт не брать, шлюз.
- Нужна правка модели воздуха, формата поля (TI-К3) или общих с fast-load файлов сверх вызова `OsmData.load_for` — шлюз.
