# План: погода из прогноза — температура и ветер вместо пресетов

**Запрос пилота** (пилот-консультант, опытный дельтапланерист): выбор «Слабый / Средний / Сильный день /
Гроза / Волна» для пилота странный. Пилот знает из прогноза **температуру воздуха, направление и силу ветра** —
это и задаём. Всё остальное (сила и частота термиков, кромка, облачность, сухие термики, пылевые вихри, грозы,
болтанка…) выводится из этих трёх чисел плюс уже известных даты, места и рельефа — правдоподобно физически.

**Дополнение пилота:** слово «волна» ей незнакомо, в её практике его не используют. Поэтому «волны» **нигде
в интерфейсе нет** (ни пресета, ни подписи, ни текста на планшете). Физика подветренной волны остаётся только
скрытым эффектом (сильный ветер поперёк хребта + устойчивый воздух) и **по умолчанию выключена** конфигом
(см. §2.8, вопрос 2). Роторы и «прижим» за хребтом (подветренная зона) остаются — их знает каждый пилот.

## 1. Интерфейс «Полёт…»

Строка «Погода» (выпадающий список пресетов) и «Ветер: встречный / из пресета» **удаляются**.
Вместо них три строки (после «Масса пилота», до «Время старта»):

| Строка | Элемент | Диапазон, шаг | Подпись значения |
|---|---|---|---|
| **Температура днём** | `HSlider` (`UiKit.slider_row`) | 0…+40 °C, шаг 1 (пилот, 28.09) | «+26 °C» |
| (подсказка) | `HintLabel` под ползунком | — | «Обычно днём в этом месяце: +25 °C» — обновляется при смене месяца |
| **Ветер** | `HSlider` | 0…12 м/с, шаг 1 | «3 м/с (11 км/ч)» |
| **Откуда ветер** | `OptionButton` | «Встречный», С, СВ, В, ЮВ, Ю, ЮЗ, З, СЗ | при выбранной площадке рядом подсказка «встречный для этого старта — З» |
| **Облачность** | `OptionButton` | Ясно / Переменная / Облачно (пилот, 28.09) | — |

Почему так:
- **Температура — дневной максимум по прогнозу у земли в долине (на посадке)** («днём до +26») — то, что
  пилот видит в прогнозе. Подпись сразу «Температура днём», чтобы в фазе 2 (ход дня, §7) смысл не менялся:
  утром модель сама возьмёт прохладнее, чем максимум. Ползунок, а не поле ввода: мышью/стрелками, как масса и время. Смена месяца **не двигает**
  ползунок (выбор пилота важнее), только подсказку «обычно…» (таблица `typical_max_c` по месяцам).
  По умолчанию (первый запуск, нет сохранённого) — `typical_max_c` для даты по умолчанию (15 июля → +26).
- **Ветер в м/с**: в русских прогнозах и у наших пилотов ветер в м/с; км/ч — в скобках (в игре везде км/ч).
  Хранится `wind_speed_kmh` = м/с × 3,6. 0…12 м/с ≈ 0…43 км/ч — выше дельтапланеристы не летают. Шаг 1 м/с
  (точнее прогноз всё равно не даёт). Вопрос 1 — в каких единицах привычнее.
- **Направление — 8 румбов + «Встречный»**, а не ползунок в градусах: прогноз даёт румб («ЮЗ 4 м/с»),
  16 румбов избыточны (на игру влияет только угол к склону, а «в лоб» покрывает главный случай).
  «Встречный» — по умолчанию и первым пунктом (как сейчас). При ветре 0 список неактивен.
  Внутри: `wind_into_launch: bool` + `wind_from_deg: float` (0, 45, … 315).
- **Облачность** (пилот, 28.09): «Ясно / Переменная / Облачно», по умолчанию «Ясно». Влажность пилот
  сочла ненужной — не добавляем. Ожидаемую кромку/силу термиков в меню **не показываем** —
  пилот читает день по небу и вариометру (правило «без подсказок», FR-22).

Сводка в главном меню (`start_menu.gd`, сейчас «Средний день · 13:00») → «+26 °C · ветер 3 м/с, встречный
· 13:00» (или «… ветер 3 м/с, ЮЗ · 13:00»; при 0 — «штиль»).

## 2. Модель: из прогноза — в погодный словарь

Новый класс **`WeatherModel`** (`scripts/atmosphere/weather_model.gd`, `RefCounted`, только статические
чистые функции, без узлов):

```gdscript
# forecast: {temperature_c, wind_speed_kmh, wind_from_deg}
# ctx: {month, day, lat, valley_msl_m, mean_msl_m}   (из рельефа; для тестов — reference_context из конфига)
static func derive(forecast: Dictionary, ctx: Dictionary, cfg: Dictionary, hour: float = NAN) -> Dictionary
# hour = NAN — «разгар дня» (фаза 1); фаза 2 передаёт час и получает день в этот момент (§7)
static func ground_context(height_fn: Callable, radius_m, samples, low_percentile) -> Dictionary
static func legacy_forecast(preset_id: String, cfg) -> Dictionary     # "medium" → {26, 11, 270}
```

`derive` возвращает словарь **с теми же ключами, что пресет** (+ служебный `_derived` с промежуточными
величинами для тестов и `tools/weather/derive_table.gd`). Детерминированно: одни входы → один день
(сид атмосферы и так постоянный, `atmosphere.json → seed`).

### 2.1 Скрытые допущения (всё в `configs/weather_model.json`)

1. **Температура** `T` — дневной максимум у земли в долине. Высота долины `h_v` — нижние 10 % высот
   рельефа в радиусе 10 км (`ground_context`, тот же радиус и сетка, что для отсчёта кромки); средняя
   высота `h_m` — как сейчас. В перемешанном слое воздух сухоадиабатический, поэтому верх термиков и кромка
   над уровнем моря не зависят от того, на какой высоте «измерена» температура — достаточно одной точки.
2. **Воздух наверху — климатический для месяца**: температура `T_u(месяц)` на `z_u` = 3000 м н. у. м.
   (≈ 700 гПа), таблица по месяцам для 50–56° с. ш. (Алтай и Башкирия одной таблицей). Выше перемешанного
   слоя градиент `Γ_env` = 4 К/км (умеренно устойчивый воздух хорошей погоды). То есть **жарче у земли при
   том же воздухе наверху = неустойчивее = выше и сильнее термики**. Весной воздух наверху холодный — и
   +15 °C в апреле даёт хороший термический день (как в жизни: «весенние термики злые»).
3. **Влажность — обычная для месяца**: точка росы `Td(месяц)` постоянна в течение дня (таблица по месяцам).
   Кромка ≈ 122 м × (T − Td) — правило, которое пилоты знают.
4. **Перегрев пузыря** над окружающим воздухом у земли `δ` = 1 К.
5. **Солнце**: только сезон — высота солнца в полдень выбранной даты на широте места; от часа старта
   термики не зависят (прежнее решение пользователя). Облачность/пелену не выбираем.
6. **Ветер** — на старте (10 м над ним; пилот, 28.09), одинаковое направление на всех высотах; профиль над
   рельефом — существующий, плюс рост с высотой над стартом (`wind.altitude_gain_per_km`, §6 п. 2).
7. **Перистая пелена** — небольшая постоянная, растёт при грозах (остатки наковален).
8. **Волна** — по умолчанию выключена (`wave.enabled: false`), см. §2.8.

### 2.2 Высота термиков и кромка

Все высоты ниже — в км; `Δ = z − h_v` (над долиной).

```
Пузырь (сухая адиабата):     T_p(z) = T + δ − 9,8·(z − h_v)
Окружающий воздух:           T_e(z) = T_u + Γ_env·(z_u − z)
Верх сухих термиков:         z_dry = h_v + (T + δ − T_u − Γ_env·(z_u − h_v)) / (9,8 − Γ_env)
Уровень конденсации (кромка): z_lcl = h_v + 0,122·(T − Td)
Запас на облако:             m = z_dry − z_lcl            (м)
Верх подъёма:                z_top = min(z_dry, z_lcl)
cloudbase_agl_m = clamp(z_top − h_m, 300, 3800)           (над средней землёй, как сейчас)
top_agl = cloudbase_agl_m                                  (ключ для таблиц силы, §2.3)
```

- `m < −100 м` — **«голубой» день**: пузыри не доходят до конденсации, облаков нет
  (`cloud_min_strength_ms = 99`), термики упираются в `z_dry` (сухие термики, искать по вариометру).
- `m ≥ 0` — кучевые, кромка на `z_lcl`, облака тем мощнее, чем больше `m` (§2.4).
- Устойчивость для волны: `N = √(g/T_K · (9,8 − Γ_env)/1000)` ≈ 0,0145 1/с (пресет «волна» был 0,012).

Числа для опорного места (Алтай, июль: `h_v` ≈ 0,4 км, `h_m` ≈ 0,9 км — **уточнить** в карточке 1
инструментом `derive_table`), `T_u(июль)` = +2 °C, `Td(июль)` = +8 °C, `Γ_env` = 4, `δ` = 1:

| T у земли | z_dry, км | z_lcl, км | m, м | кромка над средней землёй | день |
|---|---|---|---|---|---|
| +12 | 0,5 | 0,9 | −400 | 300 (минимум) | почти мёртвый, голубой |
| +16 | 1,2 | 1,4 | −200 | ~300–500 | слабые сухие термики |
| +20 | 1,87 | 1,86 | ≈ 0 | ~960 | ≈ слабый (редкие облачка) |
| +26 | 2,9 | 2,6 | 300 | ~1700 | ≈ средний |
| +31 | 3,76 | 3,21 | 550 | ~2300 | ≈ сильный, переразвитие |
| +34 | 4,3 | 3,57 | 700 | ~2650 | грозовой: Cb заметно часто |

Рост кромки ≈ 120–140 м на градус — как у пилотов («+1 °C разницы с точкой росы — +120 м»).
Башкирия (`h_v` ≈ 0,35, `h_m` ≈ 0,55) при той же температуре — кромка над землёй на ~300 м выше
(ниже рельеф) — правдоподобно.

### 2.3 Сила, размер и частота термиков — таблица опор по `top_agl`

Физический смысл — масштаб Дирдорфа `w* = (g/T · H0 · zi)^(1/3)`: выше слой и сильнее прогрев → сильнее
и шире термики, реже источники (Allen: шаг ∝ zi). Но куб. корень слишком плоский против наших откалиброванных
пресетов, поэтому берём **кусочно-линейную таблицу опор** `anchors_by_top_agl`, строки которой — **ровно
значения старых пресетов** (калибровка карточки 03 сохраняется):

| top_agl, м | strength, м/с | radius, м | spacing, м | duty | фон, м/с | болтанка σ | cloud_size | extreme |
|---|---|---|---|---|---|---|---|---|
| 300 | [0,4; 1,0] | [40; 80] | 2200 | 0,5 | −0,3 | 0,25 | 1,0 | 0 |
| 1000 (weak) | [1,2; 2,5] | [60; 110] | 1500 | 0,7 | −0,4 | 0,4 | 1,0 | 0 |
| 1700 (medium) | [2,4; 4,4] | [90; 170] | 800 | 0,85 | −0,5 | 0,8 | 0,8 | 0 |
| 2300 (strong) | [2,5; 5,0] | [110; 210] | 700 | 0,9 | −0,7 | 1,3 | 0,9 | 0,04 |
| 3200 | [3,0; 5,5] | [120; 230] | 700 | 0,9 | −0,8 | 1,5 | 1,0 | 0,06 |

Поправки к таблице:
- **Солнце (сезон)**: `sun_k = (sin el_полдень / sin el_ref)^0,5`, `el_ref` = 59,5° (15 июля, 52° с. ш.),
  зажать [0,5; 1,05]. Сила × `sun_k`, `duty` × `sun_k^0,5`. Апрель ≈ 0,93, январь ≈ 0,58.
- **Ветер рвёт термики** (`wind_thermal_factor` по U10, км/ч): 0–15 → 1,0; 25 → 0,85; 35 → 0,65; 45 → 0,5 —
  на силу; `duty` × (1; 1; 0,9; 0,75; 0,6). Механическая болтанка, наклон и снос термиков, склон, подветренные
  роторы **уже** считаются в атмосфере от ветра — их не дублируем.
- **Облачные улицы**: `street_strength` = 0,7 при кучевых, 0,4 в голубой день (улицы сухих термиков);
  включаются ли — уже решает код по ветру (`thermal.street_min/full_wind_ms`: при 3 м/с у земли на половине
  кромки ≈ 5 м/с — частичные улицы, при 5+ м/с — полные).
- **Пылевые вихри**: `dust_devil_chance` по `top_agl`: 1000 → 0; 1700 → 0,15; 2300 → 0,3 × ветровой
  множитель (0–15 км/ч → 1; 25 → 0,3; 30+ → 0 — ветер их сдувает).

- **Грозы редкие** (решение пилота, 29.09.2026; было: `cb_chance` 0,2 уже при +26 — десятки Cb в час
  вокруг старта). `cb_chance` теперь — «грозовость дня» (клеточный день, наковальни в пелене, см.
  ниже), а доля сильных термиков, которые правда становятся Cb, — `cb_thermal_chance` (× `sky.cb_k`).
  Вокруг старта (15 км) за час рождаются ~200–450 сильных термиков, так что 0,0001 ≈ одна гроза на
  20–50 полётов. Онгудай, 100 сидов (`tools/weather/storm_rarity.tscn`): +26 — Cb ближе 15 км за
  первый час в 0–1 % полётов, буря у старта в начале — 0 %; +30 — Cb в 20–40 %, у старта 0–4 %;
  +34 — Cb в 50–70 % (~1 в час), у старта в начале 3–6 %. На низких локациях (Аскарово, Аушкуль,
  «Алтай») запас меньше — грозы там начинаются лишь к +34…+38.

- `cloud_min_strength_ms` — 1,0 (как medium) при `m ≥ −100`.
- `cb_top_above_base_m = tropopause_msl_m (11 000) − z_lcl`.
- Гроза делает день «клеточным»: `thermal_spacing_m × (1 + 1,3·cb_chance)`, `cloud_size_factor + cb_chance`,
  `background_sink_ms − 0,3·cb_chance`, `cirrus_cover = 0,1 + 0,5·cb_chance`, `thermal_extreme_chance`
  + `0,05·cb_chance`.
- **Гроза детерминирована**: какие именно термики станут Cb — как сейчас, по сиду клетки
  (`cb_thermal_chance` — доля). В июле в Онгудае Cb начинаются примерно с +28…+30 °C, при +34 — ≈ 0,5 %
  сильных термиков (гроза где-то в округе — в большинстве полётов, над стартом — редко).
  Весной тот же запас получается при меньшей температуре (холодный воздух наверху) — весенние ливни из Cb.

### 2.5 Опорные прогнозы ≈ старые пресеты (опорное место, июль)

| Прогноз | ≈ старый пресет | Что отличается |
|---|---|---|
| +20 °C, 2 м/с | weak | кромка ~960 (было 1100) |
| +26 °C, 3 м/с | medium | кромка ~1700 (было 1800) |
| +31 °C, 5 м/с | strong | кромка ~2300 (было 2600) |
| +34 °C, 4 м/с | storm | кромка ~2650 (было 1700): постоянная точка росы даёт «сухие» высокие грозы; если пилот скажет, что грозы с низкой кромкой — поднять `Td` при жаре (`td_follow_heat`, по умолчанию 0) |
| +18 °C, 10 м/с (+ `wave.enabled`) | wave | только для тестов волны |

Расхождения кромки ±15 % — «достаточно хорошо»; `T_u`, `Td`, `Γ_env` подгоняются в калибровке карточки 1,
если пилот скажет, что опоры не те (вопрос 3).

### 2.6 Холод и зима
Ниже `m < −100` и `top_agl` 300 — «мёртвый» день: слабые пузыри у склонов, полёт — спуск или склон при ветре.
Это честно (ноябрьский полёт так и выглядит). Облака не рисуются — небо чистое.

### 2.7 Что остаётся постоянным
`thermal_mode` = "dynamic", `static_thermals` = [] (статичные ставит локация, как сейчас), `thermal_extreme_ms`
= [7; 9], `lens_level_above_crest_m` = 2200. Поле `name` больше не нужно (сводка меню строится из прогноза).

### 2.8 Волна (скрыто, по умолчанию выкл.)
`wave.enabled` = **false** → `wave_strength` = 0 всегда. Если включить (после ответа пилота, вопрос 2):
`wave_strength = max_strength (0,5) × clamp((U10 − 24)/16, 0, 1) × clamp((1700 − top_agl)/700, 0, 1)` —
только сильный ветер (≥ 7 м/с у земли, ≥ 12 м/с на 1,5 км) и слабая конвекция (устойчивый воздух);
сильные термики ломают волновую картину. `stability_n_per_s` = N из §2.2. **Подветренная зона** (прижим,
роторная болтанка, ослабленный ветер за хребтом — `atmosphere.json → lee`) работает всегда, от ветра.

## 6. Вопросы пилоту — ответы (28.09.2026)

Ответы пилота (через пилота-консультанта) и что из них сделано:

1. **Ветер — в м/с**, и это **ветер на старте** (не на 10 м в долине). → Ползунок в м/с (км/ч в скобках).
   Профиль ветра опирается на старт: `Game` передаёт высоту старта `Atmosphere.set_wind(скорость, курс,
   ref_msl)`; на старте (10 м над землёй) — ровно ветер прогноза.
2. **Ветер растёт с высотой**: в горах Алтая на ~1 км выше старта ветер до 15 м/с — обычное дело,
   «никуда не улетишь». → `atmosphere.json → wind.altitude_gain_per_km` (0,6), `altitude_min/max_factor`
   (0,5 / 2,0): множитель 1 + 0,6 × (высота над стартом, км) поверх профиля над рельефом (×1,8). 5 м/с
   на старте → ~14 м/с на 1 км выше; в долине ниже старта ветер слабее.
3. **Волну пилот не знает** — остаётся выключенной (`wave.enabled: false`), в интерфейсе её нет.
   **За хребтом (подветренная сторона) — смертельно опасно**: ротор бьёт сверху сразу, туда нельзя.
   → Подветренное опускание и роторная болтанка усилены (растут с ветром поперёк хребта, при слабом ветре
   мягкие), ротор у подветренного склона с обратным потоком — карточка «ротор», без подсказок.
4. **Кромка в грозовой день** зависит от температуры и высоты инверсии. → Кромка Cb выводится так же, как
   у кучевых: уровень конденсации по разнице T − Td, ограниченный верхом перемешанного слоя (инверсией):
   `min(z_dry, z_lcl)`; утром — ещё и приземной инверсией (§7).
5. **Нужна облачность**: «ясно / переменная / облачно» (en: clear / partly cloudy / overcast). Облачно —
   прогрев на порядок слабее и мягче, мало слабых термиков; переменная — между. **Влажность не нужна.**
   → Четвёртая строка экрана «Облачность» (`FlightSettings.sky`, `weather_model.json → sky`): пелена
   (`cirrus_cover`) ослабляет прогрев в атмосфере, плюс мягкость, меньше рождений, без гроз под облачностью.
6. **Температура 0…+40 °C** (снег лежащий не рисуем — ниже нуля не нужно). **+15 °C весной — хорошие
   термики** (проверено тестом: апрель +15 на Алтае — верх ~1,8 км, 2–4 м/с). Зимой термики бывают — от
   прогретых солнцем поверхностей (лес, край белого и зелёного), но без снега на рельефе это только заметка
   к фазе 2 (§7.3 п. 10).

7. **Температура в меню — дневной максимум по прогнозу** (пилот подтвердила 28.09.2026). Модель сама
   считает температуру на каждый час по суточному ходу (фаза 2, §7.2: Parton–Logan от максимума, утренняя
   инверсия) — `WeatherModel.diurnal_state`, `weather_model.json → diurnal`.

Открытым остаётся только общее «похоже ли на правду» по опорам (июль: +20 — слабо, +26 — хороший день,
+31 — сильно, с +30 грозы) — проверит в игре; таблица — `tools/weather/derive_table` → `tmp_weather_table.md`.

## 7. Фаза 2 — «атмосфера следует за солнцем» (после фазы 1, её не блокирует)

дымка; слова пилота: *утром — мягкие термики; днём — жёсткие, всё острее; вечером — тёплый, очень хороший
мягкий воздух, хорошая динамика у склона, термиков мало. Облачно — прогрев на порядок слабее и мягче. Зимой
при ясном небе — термики от леса против снежного поля; утром и вечером — только ветер.*

### 7.1 Что уже есть (проверено по коду)
- **Источники термиков уже следуют за солнцем.** `Game.start` подключает `sky.clock.sun_changed → terrain.set_sun`;
  `Terrain.thermal_source_strength_at` = `class_strength[класс] · exposure_gain · (n·sun)^power · (1 + edge)`
  с живым `_sun_dir`, `GroundField.sun()` не кеширует. Отсечка `thermal.sun_min` = 0,35 уже даёт
  «утром/вечером — только склоны к солнцу»: ровный луг при солнце ниже ~20° не даёт термиков.
  (docs/game.md → «Время суток» тут устарел: пишет, что источники берут статичное солнце.)
- Перистая пелена ослабляет прогрев (`insolation`), тени зрелых облаков гасят новые термики.
- **Нет:** инерции прогрева (поверхность откликается на солнце мгновенно, одинаково для камня и поля);
  хода по времени самой силы, частоты, «жёсткости» термиков, кромки и верха (весь день — «разгар»); тени облаков
  для воздуха берут статичное солнце (`air.set_sun_direction` один раз из `world.json → sun`, а `ThermalField.sun_dir`
  — из `clouds.sun_*`); вечерней дымки; сезонного снега; «облачного» дня.

### 7.2 Что значит температура пилота
**Дневной максимум по прогнозу** («днём до +26»), как в фазе 1 — не температура на час старта. Почему: в
прогнозе крупно пишут максимум; пилот ставит одно число и не пересчитывает его при старте в 9 утра; при
ускорении времени (×10, ×60) смысл не «плывёт». Температура в момент t — из суточного хода (Parton–Logan):

```
T(t) = T_max − A·(1 − f(t)),   A = diurnal_range_k[месяц] (июль ≈ 11 К, апрель ≈ 12, январь ≈ 6)
f — синус от восхода (0) до t_peak = солнечный полдень + 2,5 ч (1), после — спад к закату до f ≈ 0,65
```

### 7.3 Модель
1. **День в момент t:** `WeatherModel.derive(forecast, ctx, cfg, hour)` берёт `T(t)` → верх сухих термиков
   и кромка (§2.2) растут с утра («кромка поднимается весь день»), облака появляются, когда `z_dry` дорос до
   уровня конденсации (утро голубое, кучёвка с ~11–12, Cb — во второй половине дня), вечером тают.
2. **Поток тепла от земли с инерцией** (новый `SurfaceHeating`, 9 классов): для каждого класса
   `dS_c/dt = (a_c · I(t) − S_c)/τ_c`, `I(t) = max(0, sin h_солнца) · insolation`. `τ_c`: поле/луг 0,5 ч,
   скалы/осыпи 1,5 ч, лес 1 ч (и `a_c` ниже — испарение), застройка 2 ч, вода 10 ч (≈ нет хода),
   снег — `a_c` ≈ 0,1 (альбедо). Экспозиция склона берётся по солнцу с запаздыванием класса
   `sun_dir(t − lag_c)` (lag ≈ 0,6 τ_c): вечером камни и деревни ещё греют («вечерние термики с камней»).
   Стоимость — 9 скаляров на шаг часов + по вектору солнца на класс; `thermal_source_strength_at` — +1 умножение.
3. **Сила — от потока, высота — от температуры** (Дирдорф `w* ∝ (H0·zi)^(1/3)`): множитель силы
   `heat_k(t) = (H(t)/H_пик)^(1/3)`, где `H` — поток над ровным лугом из п. 2. Утро: `zi` мал, `H` растёт — слабые
   мягкие; 13–16 ч — пик; вечер: `zi` ещё высокий, `H` мал — редкие широкие слабые термики, воздух тёплый и ровный.
4. **«Жёсткие» и «мягкие»** — один параметр `sharpness(t) = H(t)/H_пик` (0,5…1): при мягких радиус × 1,3,
   ядро × 0,8, болтанка у края (`turbulence.edge_factor`) × 0,6, конвективная σ ∝ `w*`. В полдень — как сейчас.
5. **Вечерний спокойный воздух:** за 2 ч до заката механическая болтанка × 0,6 (устойчивый приземный слой),
   склон работает как днём → «хорошая динамика у склона».
6. **Мягкое обновление атмосферы:** раз в `diurnal.update_s` (60 с игрового времени) `Game.tick` зовёт
   `air.update_weather(derive(..., hour))`; `Atmosphere` плавно (за ~5 мин) ведёт кромку, фон, σ, пороги облаков,
   а `ThermalField` рождает новые термики с новыми параметрами — **без пересоздания** поля (шаг сетки
   `thermal_spacing_m` фиксирован на весь день — по пику, иначе термики «прыгают»). Живые термики доживают
   со старыми числами — переход сам собой плавный.
7. **Тени облаков для воздуха — по часам:** `sky.clock.sun_changed.connect(air.set_sun_direction)`
   (+ `ThermalField.sun_dir` оттуда же).
8. **Вечерняя дымка:** плотность дымки растёт после пика и у низкого солнца, верх дымки — верх
   перемешанного слоя в момент t (`sky.set_inversion_height_msl` на каждом обновлении).
9. **Облачный день** — только если пилот попросит 4-й параметр (вопрос 5): `insolation` × 0,15, `sharpness` 0,5,
   без Cb. Иначе — только перистая пелена и тени своих облаков.
10. **Зима:** нужен сезонный снег на открытых классах (луг/поле/кустарник → снег при устойчивом снежном покрове,
    месяцы из конфига локации) — карточка группы «рельеф». Тогда лес (`class_strength` 0,45) против снега (0,1)
    сам даёт «термики от леса», а низкое солнце и `sun_min` — «утром и вечером только ветер».
