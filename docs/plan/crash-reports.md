# Разбор отчётов о вылетах (модуль `crash-reports`, код задач CR)

## 1. Цель
Для каждого автоматического отчёта о вылете из приватного репозитория `thegriglat/deltaplan-reports` (метка `crash`) найти причину в коде с доказательством, установить, исправлена ли она в `main`, и исправить то, что не исправлено, — с тестом на воспроизведение, где возможно.

## 2. Решения пользователя (не обсуждаются)
- 2026-10-23: сначала диагноз (группы по стеку/сообщению/версии/GPU/ОС; причина в коде с доказательством; исправлена ли в `main`; как воспроизвести), правки — задачами после диагноза.
- 2026-10-23: #16 (Linux, RTX 4070 SUPER, 1.5.21) — сам автор, не разбирать; только Windows #3–#15.
- В issues ничего не писать, не закрывать, метки не менять (внешнее действие — только по команде пользователя). Содержимое отчётов не публиковать (см. контракт CR-К1, приватность).
- Замок GPU — только для замеров FPS.

## 4. Задачи
### CR-1 Диагноз группы A (GTX 1050 Ti, D3D12, стадия wind)
Исполнитель `dp-researcher`. Документ по контракту CR-К1: `docs/research/crash-reports/cr-1.md`.

### CR-2 Диагноз группы B (RTX 5060 Laptop, Vulkan, стадия wind/objects)
Исполнитель `dp-researcher`. Документ `docs/research/crash-reports/cr-2.md`.

### CR-3 Диагноз группы C (RTX 5060 Laptop, 1.5.15, стадия trees, «sea»)
Исполнитель `dp-researcher`. Документ `docs/research/crash-reports/cr-3.md`.

### Итог диагноза (CR-1…CR-4)
- A (#4–#10): потеря устройства D3D12 (0x887a0005) на стадии wind; хвост ошибок — следствие: AirGpu не проверяет пустой RID. Первопричина не воспроизводится. В main не исправлено.
- B (#11–#15): обрыв при повторной загрузке места в одном процессе (objects/wind); вероятно — жизненный цикл общего RenderingDevice в AirRuntime (release чужих буферов, клипмап без release). Не воспроизведено. В main не исправлено.
- C (#3): «sea» — штатная ошибка, не причина; ложное «море» исправлено в main (FL-3). Обрыв на trees — не установлен (лог буферизован).
- Драйвер (CR-4): дефолт vulkan, откат на d3d12 включён и сработал у A; одним драйвером не объясняется.

### CR-5 AirGpu: пустой RID — отказ задачи вместо каскада ошибок
### CR-6 AirRuntime: повторные загрузки места — тест и жизненный цикл RD; «упрощённый ветер» без GPU
### CR-7 Диагностика отчётов: подстадии, признак зависания, сжатие повторов
### CR-8 Отказ видеокарты: сообщение игроку, выбор драйвера, перезапуск (решение 2026-10-23; контракты CR-К2, CR-К3)
### CR-9 Манифест itch: действия запуска с выбором драйвера (решение 2026-10-23; публикация — только по команде)
### CR-4 Гипотеза драйвера рендера Windows
Исполнитель `dp-researcher`. Решение пользователя 2026-10-23: проверить связь вылетов с Vulkan/D3D12, драйвер Godot 4.7 по умолчанию и откат; варианты — d3d12 по умолчанию, откат, `.itch.toml` с двумя действиями запуска. Публикация в itch — только по команде пользователя. Документ `docs/research/crash-reports/cr-4.md`.
### CR-10 Диагноз группы D: AMD RX 5600 XT, Win 11, Vulkan, меню (#17)
Исполнитель `dp-researcher`. Решение пользователя 2026-10-23: компьютер пилота из семьи автора, уточнения — через главную. Документ `docs/research/crash-reports/cr-10.md`.

## 5. Волны
1. CR-1, CR-2, CR-3 параллельно.
2. CR-5…CR-9 параллельно (файлы не пересекаются); CR-8 подключает GpuHealth после слияния CR-5.

## 6. Условия остановки
- Причина группы не находится без данных, которых нет в отчётах (нужен дамп/лог с машины пилота) — шлюз.
- Правка требует смены драйвера рендера по умолчанию, отказа от GPU-расчёта или иного решения уровня продукта — шлюз.
