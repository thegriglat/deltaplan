# osm-any — данные встроенного места для любой точки

## Цель
Пользователь (09.10): «загружать OSM данные для любой локации так же, как и для предсохранённых; пусть сохраняются в
локальный кеш». Уточнение: «игра на предсохранённой локации и на любой точке по количеству данных — одинакова».
Критерий — **паритет**: точка с карты, из «Популярных» или «Недавних» получает тот же набор слоёв того же объёма и
детальности, что `data/terrain/<id>/` + `data/osm/<id>.json`, и кладёт его в `user://locations/<ключ>/`;
второй запуск той же точки — без сети.

## Решения пользователя (не обсуждаются)
- 09.10: OSM и остальные данные для любой точки — как у встроенных мест, с локальным кешем.
- 09.10: паритет по количеству данных между встроенным местом и любой точкой; в отчёте — таблица до/после.

## Решения координатора (в рамках задания, можно пересмотреть)
- **Сборка в самой игре (GDScript)**, вариант Б из `on_demand_location.md`: у пилота нет Python, второй бинарник
  (Go) — подпись, антивирусы, сборка под 3 ОС. Шаги Python-сборки — «скачать → пересчитать в сетку → сгладить/
  подвыборка → растеризовать» — переносимы; тяжёлое — в потоках (`WorkerThreadPool`), меню не замирает.
- **Одна логика получения данных — в игре** (мысль пользователя 09.10, принята как основной вариант): встроенные
  места — те же папки, собранные тем же кодом заранее (headless-запуск сборщика по `configs/locations/<id>.json`),
  Python-сборка (`fetch_dem.py`, `fetch_landcover.py`, `cog.py`, `rivers.py`, `osm_water.py`, `fetch_osm.py`)
  удаляется (OA-7). До удаления порт доказывает равенство: каждая стадия проверяется на входах встроенных мест
  против нынешних `data/terrain/<id>/` и `data/osm/<id>.json` (числа приёмки ниже). Если время сборки в игре
  окажется неприемлемым (цели — в OA-1…OA-3), — шлюз с цифрами: держать ли офлайн-инструмент.
- Высоты кеша — `.f32.zst` (Godot не пишет brotli); `HeightLayer` читает оба по расширению. Остальные файлы — те же.
- Ключ кеша — центр, привязанный к сетке 0,05° (≈5 км): соседние точки берут одно место; точка старта — где выбрал
  пилот (до края детального квадрата ≥ 17 км). Точка внутри встроенного места (запас ≥ 10 км до края детального
  квадрата) — грузится встроенное место со стартом в точке.
- Старый путь точки (сетка web-mercator из Terrarium z12, покров по месту без кеша результата) — заменяется.
  `TerrariumLoader.elevation_at` для карты выбора остаётся.
- Вежливость к источникам: Overpass — запросы по слоям последовательно с ожиданием слота и повторами (OA-9; объединённый запрос отвергался), зеркала из `world_objects.json → osm`,
  User-Agent, таймаут; Copernicus и WorldCover — HTTP range по внутренним тайлам COG, кеш блоков в
  `user://terrain_cache`. Сырой ответ Overpass после упаковки не хранится.
- Отказ источника: без рельефа места нет (сообщение, назад в меню, как сейчас). Нет покрова или OSM — летаем без
  слоя (покров — процедурный, как сейчас), в `build.json` — `missing`, при следующем запуске недостающее догружается.
- Часовой пояс точки — `round(lon/15)` (грубо; границы поясов не знаем — «Границы модели»).

## Не противоречит отложенному плану
`offline_world_data.md` (пакеты регионов из `.osm.pbf`, без домов/заборов, «сеть убрать») отложен. Здесь сеть
нужна только на шаге сборки места; формат места тот же, что у встроенных — пакет потом может стать ещё одним
источником тех же папок. Дома и заборы остаются, пока они есть у встроенных (паритет).

## Задачи
Стадии работают против контракта OA-К3 и проверяются на данных встроенных мест без сети (локальные копии:
`~/.cache/deltaplan_terrain/{copernicus,terrarium,worldcover,cog}`, сырые ответы Overpass
`~/.cache/deltaplan_osm/<id>_<слой>.json`). Только чтение этих кешей, не удалять.

### OA-1. Стадия рельефа (dp-engineer)
Порт `fetch_dem.py` (`build_layer`, `sample_copernicus`, `sample_terrarium`, `gaussian_blur`, квантование,
`patch_from_finer`): Copernicus COG по HTTP range (расширить `cog_reader.gd`: float32, предиктор, источник —
файл или URL), Terrarium z10 для far; запись `.f32.zst` + `meta.json`; `HeightLayer` читает `.f32.zst`.
Приёмка: на центрах askarovo и altai из локальных копий — RMSE к встроенным `detail` ≤ 0,5 м, `far` ≤ 1 м
(макс. отклонение — в отчёт); время стадии без сети — в отчёт; тесты `terrain` зелёные.

### OA-2. Стадия рек по рельефу (dp-engineer)
Порт `rivers.py` (priority-flood по far, водосбор, ширина, привязка к долине detail, растеризация) →
`far_water.png`, `detail_water.png`. Приёмка: на высотах встроенных askarovo и altai — IoU с их `*_water.png` ≥ 0,9
для обоих слоёв; время — в отчёт (цель ≤ 60 с на этой машине).

### OA-3. Стадия покрова (dp-engineer)
Порт `fetch_landcover.py` (мода k×k по уровню COG, классы `surface.worldcover.classes`, detail10 L — доля леса) →
`detail_surface.png`, `far_surface.png`, `detail_detail10.png` (A=0), `surface.json`. Приёмка: на askarovo из
локального кеша COG — совпадение классов с встроенными ≥ 0,98 (оба слоя), |доля леса − встроенная| ≤ 0,005,
средняя |ΔL| detail10 ≤ 2.

### OA-4. Стадия OSM (dp-engineer)
Клиент Overpass в игре (один объединённый запрос на квадрат ±20 км, зеркала, User-Agent, таймаут), порт упаковщиков
`fetch_osm.py` → `osm.json` (схема OA-К2), порт `osm_water.py` → канал A `detail_detail10.png` и
`water_fraction` в `surface.json`. Приёмка: упаковка сырых ответов `~/.cache/deltaplan_osm/askarovo_*.json` и
`altai_*.json` даёт JSON, равный `data/osm/<id>.json` (кроме `_doc`, порядок допускается; числа ±0,1 м); канал
воды из `data/osm/askarovo.json` — IoU с встроенным ≥ 0,97; живой запрос Overpass на одну новую точку — в отчёт
(время, размер).

### OA-5. Сборщик, кеш и путь в игре (dp-engineer, после OA-1…4)
`LocationBuilder` (стадии по порядку, временная папка → переименование, `build.json` последним), `LocationCache`
(ключ, полнота, версия), `Locations` (конфиг и путь OSM для встроенных и кешированных мест — все потребители
`Config.get_config("locations/…")` и `data/osm/<id>.json`), путь точки в `game.gd` (встроенное место по точке /
кеш / сборка), прогресс на экране загрузки, `recent_places` — имя из кеша; удаление mercator-сборки точки.
Приёмка: тест сборки на подставных стадиях; повторный вызов при полном кеше — 0 запросов в сеть; `world_objects`,
`terrain`, `recent_places`, `popular_places`, `menu_setup` — зелёные.

### OA-6. Проверка в игре (dp-mechanic или dp-engineer)
Новая точка (не встроенная, есть OSM-объекты рядом) — сборка в игре с сетью, затем второй запуск в сетевом
пространстве без сети (`unshare -rn`) — из кеша; размер папки, время первой сборки; таблица паритета «после»
(те же слои, числа из `meta.json`/`surface.json`/`osm.json` точки против встроенного места); 3–5 скриншотов
в `/home/greg/deltaplan/build/screenshots/osm-any/` (дороги, ЛЭП, дома, реки у точки).

### OA-7. Встроенные места — тем же сборщиком; Python-сборка удаляется (dp-engineer, после OA-5)
Headless-команда сборки места по id (`configs/locations/<id>.json`: центр, параметры) → `data/terrain/<id>/`
в формате кеша (`.f32.zst`, `osm.json` внутри папки); пересобрать 4 места; `data/osm/` и Python-сборку удалить
(`tools/terrain/{fetch_dem,fetch_landcover,cog,rivers,osm_water,repack_brotli}.py`, `tools/osm/fetch_osm.py`;
`compare_ref.py`, `shots` — оставить, если не зависят); `docs/guide/world-objects.md` «Как добавить локацию» и
связанные guide — по-новому. Приёмка: тесты `terrain`, `world_objects`, `locations`, `vegetation`, `osm_any` зелёные;
`dp docs check`; размер `data/terrain` до/после — в отчёт.

### OA-8. Документация (dp-writer)
`docs/guide/` — откуда данные места (стадии, источники, кеш `user://locations`, ключ, отказ слоёв, как собрать
встроенное место командой); `docs/registry/findings.md` — выводы паритета (числа OA-1…OA-4); CHANGELOG «В работе»;
`on_demand_location.md` → closed со ссылкой сюда, `offline_world_data.md` — заметка, что сеть теперь на шаге сборки
места. OA-7 и OA-5 документацию дальше не трогают.

## Риски
- Copernicus COG: предиктор/сжатие могут отличаться от WorldCover — OA-1 проверяет первым делом.
- Время первой сборки на GDScript (priority-flood 1601², detail10 4001²) — если > 3 мин без сети, вынос тяжёлого на
  GPU отдельной задачей (шлюз).
- Overpass у больших городов — ответ десятки МБ; таймаут и сообщение, без ретраев в цикле.
- Покрытие Copernicus над морем — дыры: заполнение как в Python (Terrarium/0).

## Границы модели
- Часовой пояс точки — по долготе, без границ поясов.
- Посадочные площадки и именованные старты есть только у встроенных мест (ручные данные); у точки — старт по уклону.
