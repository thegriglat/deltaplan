# docs-rework — документация, dpcli и сайт

Ветка `feature/docs-rework`, копия `~/deltaplan-docs-rework`. Код игры не правим (GDScript, шейдеры, сцены, `project.godot`, тесты, игровые tools). Правим: `docs/`, `*.md`, `CLAUDE.md`, `.claude/`, `.dpcli/`, `dpcli.yml`, `site/`, инструменты dp (`tools/dp*`, хук).

## Решения пользователя (не обсуждаются)
1. `dp` заменить на `dpcli` (из ashoo2): `.dpcli/`, `dpcli.yml`, агенты/скилл/процесс dpcli, адаптированные под Deltaplan; старые `tools/dp*` убрать, если dpcli их заменяет; чего нет — в отчёт, не изобретать.
2. `area` у модулей (frontmatter по схеме dpcli).
3. Статусы и текст модулей — по коду и git (слито в main, есть ли код), не по тексту дока.
4. Раскладка: действующее отдельно от исследований и от отклонённого; отклонённое — в архив с пометкой почему; ничего ценного не удалять (исследования модели воздуха — возможна статья).
5. `dpcli docs check` без ошибок (большие доки разбить осмысленно).
6. Сайт: версии в сайдбаре — раскрывающимся списком, как «Механики».
7. Сайт — только текущее состояние игры, без планов; исследования можно; родители — только «родители автора — пилоты»; пасхалки не упоминать; без продающего тона, честно, где симулятор врёт.
8. Читаемость агентом (в первую очередь) и человеком: вход `docs/INDEX.md`, короткие findings, без дублей, живые ссылки.

## Схема
Каталоги, frontmatter, area, разбиение — `docs/contracts/docs-rework.md` (D1–D4).

## Волна 1
### dpcli-хвосты
`tools/dp`, `tools/dp.md`, `tools/dp_docs.py`, `tools/dp_migrate.py` убрать; `dp check gd` (хук pre-commit) — перенести как есть в `tools/check_gd.py`, хук — на него; скиллы `diary`, `new-release` — на команды dpcli. Приёмка: хук работает (`tools/check_gd.py` на изменённом `.gd` из main), `git grep "tools/dp"` вне docs/, tools/research — пусто.

### Статусы и area модулей
По таблице сверки с кодом (в карточке): area всем модулям (план, контракты, module.json), статусы, перенос завершённых планов в `docs/archive/`, отклонённых — в `docs/archive/rejected/` с «почему», `docs/archive/README.md`, ссылки. Приёмка: в `docs check` нет ошибок «нет area», планы в `docs/plan/` — только живые.

### Сайт: сайдбар и планы
Версии в сайдбаре свёрнуты (как «Механики»); раздел планов с сайта убрать (mounts `docs/plan`, `docs/archive/plan`, `content/plans`). Приёмка: `hugo --minify` без ошибок.

### Сайт: тексты
Главная, «Подходы», «Механики», «Крылья» (ru/en) — сверить с текущим состоянием игры (код main, CHANGELOG); убрать планы и «скоро будет»; правила публичных текстов. Приёмка: `hugo --minify` без ошибок, нет «план»-формулировок о будущем.

## Волна 2 (после «Статусы и area»)
### Разбиение и сверка гайдов
`docs/guide/*` > 40 КБ — разбить (D4); текст сверить с кодом main (описанное, но отсутствующее — убрать или пометить), summary ≤ 140.

### Разбиение контрактов
`docs/contracts/*` > 40 КБ — разбить; summary ≤ 140 у всех контрактов.

### Разбиение исследований
`docs/research/*` > 40 КБ — разбить; статусы research (D1); summary ≤ 140.

### findings и tools/research
`docs/registry/findings.md` — строка на вывод, ≤ 40 КБ, без дублей; `docs/perf/`, `tools/research/**/{README,summary}.md` — frontmatter, summary, размер.

## Волна 3
### Замена dp → dpcli и сборка
Все упоминания `dp …`/`tools/dp` в `docs/`, `tools/research/**`, `site/` → команды dpcli; `dpcli docs index`; `dpcli docs check` без ошибок; `hugo --minify` без ошибок.

## Условия остановки
- Статус модуля по коду и git неоднозначен так, что меняет раскладку (влито частично, код есть, но отключён) — решение координатора по KISS, спорное — в отчёт.
- dpcli не умеет нужного из dp — не изобретать, записать в отчёт.
