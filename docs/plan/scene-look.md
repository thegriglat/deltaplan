# Картинка сочнее (модуль `scene-look`, код задач SL)

Цель пользователя: картинка красивее и сочнее («сочно, но не приторно», T-31) — только шейдерами и несложно.
Контракты — `docs/contracts/scene-look.md` (SL-К1…К3).

## 1. Решения пользователя (не обсуждаются)
- Физику, высоты, `height_at`, поле воздуха не трогать.
- Целевое железо — RX 5600 XT 6 ГБ: каждое улучшение дешёвое; суммарно не дороже ~1 мс на «Высоком»
  (≈ 0,4 мс на RTX 4070 SUPER 1080p, где меряем; SL-К3). Бережно к VRAM: лучше без новых текстур; новые — по экранному размеру, сжатие + мипмапы.
- Уже сделанное (тени облаков, дымка, блики воды, цветокоррекция, тона скал, трава без тайлинга) не переделывать — доводить.
- Снег и скалы (п. 12–13, анти-тайлинг скал) — только после влития `mountain-look` в main и поверх него; до этого код снега, скал,
  вершинный `relief_*` не трогать. Новый код — в своём include (SL-К1).
- Минорный визуал — не больше двух попыток, берётся лучшая; не шлифовать. Физика прежде «нравится»: формулы с физическим смыслом
  (фенология — закон Хопкинса, фаза рассеяния — Рэлей/Хеньи–Гринстейн, освещённость склона — по солнцу в полдень на широте места).
- Исполнители — Sonnet (Opus — только свет SL-2). Godot — только с временным `XDG_DATA_HOME`; тяжёлые прогоны —
  `systemd-run --user --scope -p MemoryMax=12G`, не больше 4 тестов Godot параллельно.
- Скриншоты до/после — только `tools/shots/menu_art.py`, одни ракурсы, в `/home/greg/deltaplan/build/screenshots/scene-look/`;
  исполнители картинки не разглядывают (кроме паруса — 3D-модель, 1–2 кадра). В конце — тестовая сборка Linux. В main — только с одобрения.
- **Каждый запуск godot (тесты, бенчи, скриншоты, dp accept) — только под systemd-run --user --scope -q -p MemoryMax=8G -p MemorySwapMax=0; не больше 4 godot на всю машину (вместе с mountain-look); исполнитель — по одному godot за раз** (2026-10-14) — зависания машины 13.10 23:47 от нехватки памяти
- **Лимит «не больше 4 godot на машину» снят: тесты и исполнители — параллельно сколько нужно; остаётся MemoryMax=8G MemorySwapMax=0 на каждый запуск godot; GPU-замеры — по одному окну за раз** (2026-10-14) — решение пользователя через главную сессию; earlyoom как страховка
- **Любой замер GPU (--gpu-profile, --bench-*, shots.sh, бенч-скрипты) — только под dp lock gpu <имя> -- <команда> (один на машину); один прогон на вариант, разница меньше шума (0,2–0,6 мс) — «в пределах шума», без перемеров** (2026-10-14) — два параллельных полноэкранных замера SL-5 и SL-10 делили видеокарту и мешали пользователю

### SL-2 Свет: небо сверху, земля снизу; дальний лес (п. 1)
`dp-engineer` (`model: opus`). Поставляет SL-К1 (include, `scene_look` → uniform), SL-К2 (uniform `sl_lat_deg`, `sl_doy` от даты полёта).
- Создать `scripts/terrain/scene_look.gdshaderinc`, секцию `configs/world.json → scene_look`, проводку в `TerrainRenderer`/`Terrain`
  (как `terrain_look`), `Terrain.set_flight_date(month, day)` из `game.gd` (там же, где солнце), широта места.
- Полусферическое окружение для рельефа, полога и импостеров: сверху — цвет неба (голубой, от `sky.*`/высоты солнца), снизу — отражённый
  от земли (цвет подстилающей зелени × альбедо); тени (Godot и дальняя тень рельефа `relief_shadow_*`) — голубоватые, не серые.
- Дальний лес: освещённая доля крон по солнцу и направлению взгляда (по солнцу — ярче, против — тени между кронами), светлые верхушки
  на солнечных склонах, альбедо полога в реалистичных пределах (хвойный лес в видимом ~0,05–0,09, лиственный ~0,08–0,12), пятна не темнее ×0,5.
- Контрактный тест `tests/contracts/test_scene_look_contracts.gd` (К1, К2-проводка).
Приёмка: тесты `terrain`, `vegetation`, контрактный; GPU full +≤ 0,12 мс (К3); `dp check gd`. Оценка — средняя.

### SL-3 Дымка с ореолом вокруг солнца (п. 7)
`dp-engineer`. Только `scripts/world/haze.gdshader` (+ ключи `haze.*`). Фаза: чистый воздух — Рэлей (3/16π)(1+cos²θ), мутный слой —
Хеньи–Гринстейн g ≈ 0,6–0,75 (нормировка ~ сохранить среднюю яркость дымки), к солнцу теплее (цвет солнца по `time.light`);
горы против солнца — слоями силуэтов (растёт in-scatter с расстоянием). Без новых проходов. Приёмка: тесты `world`/`haze`, GPU ≤ +0,03 мс,
средняя яркость дымки сбоку от солнца (90°) ± 15 % от прежней (замер шейдера на CPU-зеркале или числом в тесте). Оценка — малая.

### SL-4 Дороги вдали — тонкая нитка в цвет грунта (п. 3)
`dp-engineer`. `scripts/world_objects/osm/road.gdshader`, `osm_roads.gd`, `configs/world_objects.json → roads.look`.
Покрытие пикселя: когда ширина дороги меньше следа пикселя — непрозрачность/вклад ∝ ширина/след (нитка, а не мел), цвет вдали — к
грунту/обочине в тон рельефа (серо-бежевый, не светлее луга в 1,3 раза по яркости), specular как у рельефа, тень облаков
(`cloud_shadow.gdshaderinc`). Приёмка: тесты `osm`/`roads`, GPU ≤ +0,03 мс. Оценка — малая.

### SL-5 Склоны по сторонам света, широта, крупные пятна, берега, граница леса (п. 2, 9, 10)
`dp-engineer`. Зависит от SL-2 (include, `sl_lat_deg`). Только через include и вызовы `// SL` (К1).
- Сухость/жёлтость склона — по освещённости в полдень на широте места (`dot(n, солнце_полдень(lat, doy))` против ровного места), а не по −Z:
  в южном полушарии суше северные, у экватора почти нет разницы; северные — зеленее и темнее; то же у полога (тон, доля хвойных — как есть).
- Крупные пятна тона 0,5–3 км на лугах и в лесу (дёшево: один fbm низкой частоты).
- Прибрежная зелень: размытая маска воды (G `detail10`, грубый мип/несколько выборок) → полоса 20–60 м сочнее и зеленее (не в лесу, не на снегу/скалах).
- Граница леса: высота границы леса от широты (≈ 3500–4000 м у тропиков, ~2000 м Альпы, ~1000 м на 60°; ключ таблицей) — у верхнего края
  лес вдали редеет (просветы луга), выше — альпийский луг (ниже, охристо-зелёный), выше — камень/осыпь по существующему коду.
Приёмка: тесты `terrain`, контрактный; GPU ≤ +0,08 мс. Оценка — средняя.
- **SL-5: тон склонов по сторонам света (экспозиция, полдень на широте) не делать — убрать/выключить, если сделано; остальное (пятна тона, зелень у воды, граница леса) — как было** (2026-10-14) — решение пользователя через главную сессию

### SL-6 Цвет по сезону и дате полёта, поля по сезону (п. 4, 11)
`dp-engineer`. Зависит от SL-2. Поставляет SL-К2 (сезон: `SeasonLook` + `sl_season`). Фенология: закон Хопкинса (≈ 4 дня на 1° широты к
полюсу и на 122 м высоты; весна позже, осень раньше), южное полушарие — сдвиг на полгода, тропики — без осени.
Весной трава свежая (сочнее, светлее), к концу лета — сухость растёт (степь соломенная там, где `dryness` места высокий), осенью
лиственницы и берёзы золотые (полог, импостеры, модели деревьев — по породе), выше в горах раньше. Поля: летом зелень/рожь, к концу лета
спелость, осенью стерня и пашня (бурая), борозды вдоль поля (есть — оставить). `--date=MM-DD` для `tools/shots/menu_art.py`
(кадры сезона снимает SL-11). Приёмка: контрактный тест К2 (инварианты), тесты `terrain`, `vegetation`; GPU ≤ +0,06 мс. Оценка — средняя.
- **Поля: лёгкий разброс тона между полями и внутри поля, без пестроты — расширение SL-6 (поля по сезону, та же строка тона поля), максимум две попытки** (2026-10-14) — решение пользователя; куда — координатор: тон поля правит SL-6

### SL-7 Просвет: парус и листва (п. 6)
`dp-engineer`. `assets/shaders/sail/sail.gdshader` (+ `sail_material.gd`), `tree_model.gdshader`, `forest_impostors.gdshader` (только BACKLIGHT).
Парус: слагаемое рассеяния вперёд ∝ pow(max(dot(-вид, солнце), 0), k) × пропускание ткани, латы и швы темнее на просвет (маска `_trans` /
нормали). Листва моделей и импостеров — BACKLIGHT (лиственные больше хвойных), трава — проверить при низком солнце. 1–2 кадра паруса против
солнца исполнителю можно (3D). Приёмка: тесты `flight`/`vegetation`, GPU ≤ +0,02 мс. Оценка — малая.
