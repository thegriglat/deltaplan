## Что известно (разбор 2026-10-15)
- Пилот в прототипе и в игре — точка на цепи с **изотропным** сопротивлением `pilot_cda_m2` = 0,21 м² (Kroo 1981) по относительной скорости воздуха: сопротивление и боковая сила по скольжению уже есть, но одинаковые во всех направлениях; нет собственной инерции тела (по рысканию ≈ 15–20 кг·м² — оценка в `docs/research/pendulum/lateral-yaw.md`, п. 1) и формы кокона (боковая площадь больше лобовой).
- Расхождения с литературой («Границы модели» гайда): Clp −0,52…−0,59 против −0,93 (Cook); голландский шаг 1,7–2,1 рад/с, ζ 0,40–0,53 против 0,92 и 0,29 (Hiway Demon); Cnβ крыла 0,03–0,06 — в 1,4–2,2 раза выше; скольжение в перекладке 22–28° (цель ≤ 15–20°); лента в вираже 30° до 12° внутрь (пилот: «строго назад»). Прошлый разбор (PD-21) связывает это с обратным рысканием полос Cnp ≈ −0,15.
- Прикидка координатора (оценка, не вывод): вклад изотропного сопротивления точки на плече h в Clp — порядка −2·CdA·h²/(S·b²) ≈ −0,001; если гипотеза и работает, то не через сопротивление по крену, а через инерцию тела, боковую силу кокона или сопоставимость с моделью Cook (как там учтён пилот). Это проверяет PB-1.
- VG: паспорта — `tools/research/data/wing_passports/wings_merged.json` (поля `vmax_vg0_kmh`, `vmax_vg100_kmh`, `vmin_vg*`), прежний разбор — `docs/archive/plan/wings-lineup.md`, раздел «5. VG — не делаем» (качество +10–15 % на 55–80 км/ч, крен туже ½ хода «заметно тяжелее»). `full_pull_speed_kmh` в конфигах крыльев (63–103 км/ч у training…sport) — DHV при VG 0, а маятник даёт на полном «на себя» 45–58 км/ч: **большая часть разрыва — не VG**. PB-2 обязан разложить разрыв на причины до того, как VG «закроет» его.

## Задачи

### PB-1. Пилот как тело — прототип и проверка гипотезы
Тип `dp-researcher`, модель fable. Только прототип и документ, игру не меняет. Контракты PB-К1, PB-К2.
1. База: нынешний прототип в конфигурации игры воспроизводит числа «Границ модели» (±10 %) на training / laminar / sport; не воспроизводит — стоп и отчёт.
2. Литература: CdA пилота лёжа в коконе (лобовое), боковая площадь/сила кокона, инерция тела; как пилот входит в модель Cook / Hiway Demon (жёстко с крылом? инерция?) — сопоставимость сравнения.
3. Модель: тело пилота — анизотропное сопротивление и боковая сила кокона, собственная инерция (рыскание связано с крылом через руки), переключатель `pilot_body` (PB-К1); старое поведение — по умолчанию.
4. Опыты (как в research/pendulum.md): Clp и производные, голландский шаг (ωn, ζ), Cnβ, перекладка 45→45 (время, max |β|), ровный вираж 30° (β у ЦМ и у узла ленты), опыт Ochi, болтанка σ 1 м/с с подсчётом переворотов (66 прогонов, как PD-19/PD-21), трим/снижение/полный «на себя». До/после — сводка PB-К2.
5. Вывод: какие пункты закрывает, какие нет (с числами); для незакрытых — оценка причины абзацем, без правки модели.
Приёмка: сводка PB-К2 валидна, документ `docs/research/pendulum/pilot-body.md`, `dpcli docs check` без ошибок, источники с URL/DOI.

### PB-2. VG безмачтовых — прототип
Тип `dp-researcher`, модель fable. Только прототип и документ. Контракты PB-К1, PB-К2.
1. Разрыв полного «на себя»: маятник 45–58 км/ч против паспорта VG 0 — причины по слагаемым (ход трапеции, баланс по тангажу, поляра/Cd, Cm паруса) с числами; что из этого VG, а что нет.
2. Физика VG по литературе и паспортам: что меняет натяжение (крутка, перекос пузыря/гибкость, эффективное V, профиль, Cd0, трим) — с источниками; паспорта VG 0 / VG 100 по крыльям игры.
3. Модель: `vg` 0…1 как набор изменений параметров крыла (PB-К1), только у крыльев с VG.
4. Опыты: Vmax (полный «на себя») при VG 0 / 0,5 / 1; поляра; время перекладки 45→45 и 30→30; трим; болтанка с переворотами при VG 1. Сводка PB-К2.
5. Вывод: достижимо ли «Vmax с VG 1 = паспорт ±10 %» без подгонки; если нет — сколько даёт VG и что закрывает остальное.
Приёмка: сводка PB-К2 валидна, документ `docs/research/pendulum/vg.md`, `dpcli docs check` без ошибок.

### PB-3. Тело пилота в игре (по шлюзу)
Тип `dp-engineer`, модель opus. Перенос принятого в шлюзе в `scripts/flight/pendulum/`, `configs/pendulum.json` (PD-К2 v8, контракт стыков — до запуска). Тесты маятника проходят, включая `test_pendulum_ground*`, посадку, переворот в болтанке (`test_pendulum_robust`); числа до/после — как в прототипе ±15 %.

### PB-4. VG в игре (по шлюзу)
Тип `dp-engineer`, модель opus. `ControlInput.vg`, ввод (`scripts/game/input_controller.gd`, `configs/controls.json`), параметры VG в блоке `pendulum` крыльев (офлайн-скрипт `tools/flight/pendulum_params.py`), модель. Приёмка: Vmax с VG 1 — паспорт ±10 % (или иной порог по шлюзу), VG 0 — как сейчас (±2 %), перекладка с VG 1 дольше (число с источником). Положение VG на модели крыла — только если просто.
