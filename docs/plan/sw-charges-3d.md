# План sw-charges-3d (код задач SWD)

## Цель
Продолжение модуля sw-charges в 3D (отдельный модуль — по решению пользователя, чтобы не рос контекст координатора).
Проверить «электрическую» аналогию поля ветра над рельефом в 3D: фон + заряды на поверхности рельефа (панели) +
вихревые нити с гребней, по возможности — термики и болтанка вихревыми частицами/диполями (прототипы A/C sw-charges).
Цель модуля — **единая аналогия трёх масштабов**; порог успеха — паритет с Пикаром в его ±10–15 %, обгон не обязателен.

## Решения пользователя
См. `.dpcli/dpcli inbox sw-charges-3d`; предыстория и решения 2D — `docs/plan/sw-charges.md` (раздел «Решения пользователя»,
«Идеи на будущее») и журнал `docs/plan/sw-charges/decisions.jsonl` (база влита из `feature/sw-charges`).
- **3D sw-charges — отдельным модулем с новым координатором (чтобы не рос контекст); делать в любом случае, 2D — подготовка (список проблем «схема / 2D-артефакт»), не эталон; порог успеха — паритет с Пикаром ±10–15 %; прототипы на Python/CuPy.** (2026-11-08)
- **Параллельно с 3D-прототипами: в Rust (dp-air) вынести расчёт среднего поля ветра за общий интерфейс, чтобы Godot переключал тип расчёта ключом/настройкой, не зная деталей. Сейчас одна реализация — Пикар (поведение побитно прежнее); интерфейс проектировать так, чтобы туда встала будущая схема «панели + вихри» (поле без сетки: запрос в точке и/или выдача на сетки окон). Сама схема панелей в Rust — позже, отдельным решением.** (2026-11-08) — чтобы игра могла переключать тип расчёта ветра
- **Отмена задачи 5 (общий интерфейс поля в Rust): 3D-прототипы на Python, интерфейс в игре не нужен до решения о переносе.** (2026-11-08) — 3D тоже на Python
- **Добавить вариант без эволюции во времени: установившийся вихревой слой (лист тока) вдоль линии отрыва и границы зоны рециркуляции, сила — из критерия отрыва; цена порядка панелей. Нестационарные нити, если остаются дорогими (O(n²), рост узлов), для игры не годятся — не вкладываться в их доводку сверх уже начатого по Q1; ограничитель роста (B) — только если дёшев.** (2026-11-08) — если нити дорогие, они потом всё равно не подойдут
- **Первым проверить простейший вариант установившегося вихревого слоя: одна прямая нить вдоль подветренного склона (ось ротора вдоль хребта), концы уходят в землю подковой (∇·ω=0), отражение в земле — панелями; положение и сила — из условия равновесия вихря (аналог вихрей Фёппля за цилиндром) с точкой отрыва на гребне, без подгонки. Без эволюции во времени; болтанка — масштаб 3, не здесь. Сравнить ротор с Menke 2019 и Askervein.** (2026-11-08) — дёшево (десятки отрезков), стационарно; нити с эволюцией дороги

## Что известно из 2D (не переделывать)
- Итог 2D — `docs/research/sw_charges.md` и `docs/research/sw_charges/stage2-*.md`. Последний круг 2D (внутренний слой
  Jackson–Hunt, отрыв только с подветренной стороны) и **список проблем 2D с пометками «схема / 2D-артефакт»** доделывает
  модуль sw-charges; когда он сдаст — главная вольёт `feature/sw-charges` сюда ещё раз (сообщу в inbox). До этого — опираться
  на уже влитое и не ждать.
- 2D — не эталон: проблемы «схема» (критерий отрыва, отрыв на наветренном склоне, внутренний слой, сглаживание фона, высота
  сравнения) — чинить в 3D; «2D-артефакты» (сила и незатухание ротора, завышение σ_w) — проверить, ушли ли, не подгонять.
- Мелкая вода как среднее поле не годится (этап 1 sw-charges).
- Код: `tools/research/sw_charges/` (swpy, panels2d, proto_a, proto_c, panels_exp), интерпретатор
  `tools/research/cascade_2d/py` (numpy, scipy, matplotlib, cupy); контракты `docs/contracts/sw-charges.md` (SW1–SW7).

## Задачи (уточняет координатор)
1. **Панели 3D** (Python/CuPy): рельеф по растру места (GLO-30, 25 м; кроны/крыши DSM — сгладить или убрать, лес —
   шероховатость), панели 25–30 м у точек сравнения и крупнее вдали; плотность источников, скорость в точке; внутренний слой
   у земли (Jackson–Hunt, итог последнего круга 2D); время и память (плотная матрица 10–20 тыс. панелей / блоки).
2. **Вихревые нити 3D**: сход с гребня по физическому критерию отрыва (итог 2D), только подветренная сторона; линии
   **замкнуты** — уходят в землю по бокам хребта или петлёй (∇·ω = 0, «нет монополей»); растяжение, перезамыкание, затухание.
3. **Сравнение**: Askervein (мачты, `tools/research/data/askervein/`), Perdigão (мачты ISFS, лидары DTU, Menke 2019 —
   `tools/research/data/perdigao/`, постановка `tools/research/cases/`), Пикар ±10–15 % (крейт / `rust/dp-stand`); Bolund
   не использовать. Колонка «эксперимент» с надёжностью.
4. **Прототипы A/C в 3D** (термики-кольца, пары вихрей болтанки) над рельефом — если дёшево; уточнения из «Идей на будущее»
   sw-charges (порог рождения по Ri, экранировка).
5. **ОТМЕНЕНО пользователем 2026-11-08 (3D — на Python; интерфейс — только после решения о переносе).** ~~Общий интерфейс расчёта поля в Rust~~ (было: решение пользователя 2026-11-08; dp-engineer, параллельно с 1–4). Сейчас граница Godot ↔ крейт — `dp_air::AirModel` (`rust/dp-air/src/lib.rs:121`; реализации `Calm`, `Formula`; мост `rust/dp-gd/src/bridge.rs`), а Пикар зашит внутри `Formula` (`rust/dp-air/src/field/runtime.rs`). Задача: вынести **масштаб 1 (среднее поле)** за трейт движка поля (рабочее имя `FieldEngine`) внутри `Formula`; выбор — ключом конфига (напр. `air_model.field_engine`: `picard` | `off`) и настройкой игры, Godot передаёт только ключ. Реализация одна — Пикар; при `picard` поведение и тесты крейта/GD **побитно** прежние; `off` — поле не считается (аналитика, как сейчас без поля). Контракт трейта — до кода, с учётом будущей схемы «панели + вихри» (без сетки: опрос в точке, сборка на сетки окон, фоновый пересчёт, отмена, кеш); саму схему в Rust не писать. Приёмка: тесты rust_wind/W8 зелёные, переключение `picard`/`off` проверено тестом, без Godot-стендов для замеров.

## Ожидаемые новые для 3D проблемы
Растяжение и перезамыкание нитей; замыкание линий вихрей; обход холма сбоку меняет разгон и отрыв; цена прямой суммы панелей
и вихрей (возможны мультиполи/БПФ).

## Условия
- Прототипы — Python (NumPy, CuPy на GPU) по умолчанию; Rust/игра — только после решения пользователя. Пикар и поле игры —
  через крейт/`dp-stand`, без Godot. GPU-счёт — без замка.
- Масштабы: предел данных GLO-30 (30 м, различимо 60–90 м); мельче 25–30 м не считать.
- Данные, команды, таблицы — `tools/research/sw_charges_3d/` (README с frontmatter); выводы — `docs/research/sw_charges_3d/`.
- Не шлифовать.

## Приёмка
- Таблицы отклонений от измерений (Askervein, Perdigão) и от Пикара по высотам (10, 50, 300 м) и типам точек (гребень,
  наветренный, подветренный, долина); ротор Perdigão — есть/нет, длина против Menke 2019; время подготовки поля и запроса точки.
