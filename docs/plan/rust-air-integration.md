# Встраивание Rust-Пикара в игру (после picard-rs, 2026-10-24)

Итог `docs/plan/picard-rs.md`: крейт `tools/research/air_cascade/picard_rs/` (API — `INTEGRATION.md`), оптимизация ×2. Порог `tol_scale = 5` принят пользователем.
- Загрузка u3_heat (холодный старт): 6,2 / 7,6 / 14,4 / 18,7 с на 8 / 6 / 3 / 2 потоках (Xeon E5-2666 v3).
- Фон с тёплого старта: 0,75–1,3 с на 8 потоках, 2–3,7 с на 2 (`out/final/`).
Следующий шаг — модуль встраивания с отдельным координатором.

**Архитектура (решение пользователя 2026-10-24): поле и кэш живут в крейте, Godot опрашивает точки.**
- **Решать приходится всё поле.** Поле считается для всей области сразу: проекция давления — эллиптическая задача, давление в ячейке зависит от всей области. Решить «только в точке пилота» нельзя.
- **Пересчёт при смене условий остаётся** (`recompute_game_min`, ветер/погода), с тёплого старта.
- **Хранение — в крейте.** Поле, состояние тёплого старта обоих решений (mech, heat) и сэмплер — в одном объекте на процесс; игра всегда в одном экземпляре. Godot вызывает:
  - «посчитай место»;
  - «условия изменились» (игровое время, ветер, погода) — решение о пересчёте за крейтом;
  - `sample(pos)` / `sample_many(PackedVector3Array)`.
- **Подмена за `blend_s`** — в крейте: два поля и смешивание при опросе.
- **Фоновый пересчёт — тоже крейт (решение пользователя 2026-10-24).** Крейт сам планирует и ведёт пересчёт в своём потоке: срок `recompute_game_min`, внеочередной — при смене ветра или погоды, тёплый старт, подмена.
  - Godot только сообщает игровое время и условия (час, ветер, погода) и опрашивает точки.
  - Вход нового срока крейт собирает сам: `AirPlace.domain_case` (`air_place.gd` — нагрев, `surface_flux`, приток) переезжает в Rust, часть A1 (решение пользователя 2026-10-24).
  - Рельеф и покров места крейт получает один раз при загрузке (принцип — `docs/plan/rust-ext.md`, «Цель»); дальше Godot передаёт только время и погоду.
- **Что уходит:** копирование ~460 тыс. ячеек × 8 полей в Godot после каждого расчёта и сборка `WindField` на GDScript (`wind_field.gd:from_arrays`). Вместе с ними уходит риск рассогласования осей и единиц при сборке.
- **Что переезжает в Rust вместе с этим:**
  - приземный слой `WindField`: лог-профиль, z0, u*, колонны (`scripts/atmosphere/air_model/wind_field.gd`);
  - чтение поля целиком в `AirThermals.build` (`air_thermals.gd:189`) — перенос или пачечный опрос;
  - сброс кэша при смене места — явным вызовом. Это класс вылета CR-17: ссылки на данные старого места.
- **Потребители `sample`:** модель полёта, `field_turbulence.gd`, `atmosphere.gd`, облака, термики, сеть, кресло (`motion_source.gd`). Одиночный вызов через FFI ~1 мкс; массовые — только пачкой (A2).

**Чего в крейте нет относительно `AirPicardJob`** (`INTEGRATION.md`, «Сборка»):
- заморозка колонн (`freeze_mask`/`freeze_field`, `fixrow`);
- `z_i` по столбцам;
- `adv2`;
- грубый старт 1200 м (`warm_coarse`);
- окна 100/50 м (`air_window.glsl`, `air_clipmap.gd`).

Не проверены: сетка 200 м, Windows/macOS, rayon внутри gdext при работающем кадре.

**Оценка модуля встраивания (2026-10-24, по чтению кода; не замер) — 6–11 рабочих дней с агентами:**

| Этап | Оценка |
|---|---|
| Расширение gdext в игре: крейт-обёртка, `.gdextension`, `tools/build.sh` для Linux/Windows/macOS, упаковка itch | 1–2 дня |
| Недостающее в Rust: заморозка колонн, `z_i`, `adv2`, грубый старт; сверка с GPU на тех же случаях | 2–3 дня |
| Окна 100/50 м — перенести или решить иначе | 0,5–2 дня, неизвестно |
| Подключение к `AirRuntime`, `WindField` и приземный слой в крейте, опрос по точкам, тесты | 1,5–3 дня |
| Подготовка входа в крейте: `AirPlace.domain_case`, передача карты места при загрузке | 1–2 дня (оценка, не замер) |
| Проверка в игре: загрузка по местам, меню не висит, кадры в полёте при пересчёте, e2e | 1 день |
| Удаление GPU-Пикара: шейдеры, тесты, конфиги, документация | 0,5–1 день |

**Риски:**
- окна 100/50 м: размер и время на CPU неизвестны, а сдвиги окна идут за пилотом;
- сборка под macOS с Linux: кросс-компиляция, запуск только у друга с Mac.

**До модуля — проба на ~1 день:**
1. окно 100/50 м на CPU: размер и время;
2. проба gdext под Windows (запуск) и macOS (сборка);
3. rayon внутри gdext при работающей игре: кадр.
