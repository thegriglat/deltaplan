# A07. Центровка термика в болтанке (бот) и проверка, что термик вообще «берётся»

**Цель:** бот, как средний пилот, центрирует термики в болтанке и набирает высоту; если при правильной технике набрать нельзя — найти причину в атмосфере.

**Контекст:** итог 02 (docs/atmosphere.md → «Проходимость маршрута», tmp_xc_matrix): 0/240 маршрутов, набор в кружении −1,2…−1,8 м/с (эталон +1…+3,5), кружение 10–25 % (эталон 30–55 %), из 437 заходов в кружение чистый набор — 1. tests/atmosphere/xc/xc_pilot.gd (XcPilot), docs/research/xc_reference.md, docs/atmosphere.md (профиль термика, болтанка, радиусы), scripts/atmosphere/thermal_field.gd (только чтение).
**Папки-владения:** tests/atmosphere/xc/xc_pilot.gd (логика центровки), tests/atmosphere/test_xc_bot.gd, tools/atmosphere/ (диагностика). Атмосферу НЕ правит — если виновата атмосфера, записывает конкретные числа для карточки 03.

## Шаги
1. Диагностика «идеальным пилотом»: бот, который знает центр термика (только для диагностики, флаг), кружит вокруг ядра с креном 30–40° на скорости мин. снижения — какой набор? Если < +0,5 м/с в среднем дне — проблема в атмосфере (радиус/сила/болтанка/фоновое опускание): записать числа для 03.
2. Честная центровка (только вариометр+GPS, как ThermalAssistant): сдвиг круга к сильному сектору с учётом задержки датчика, радиус круга под ширину термика, фильтрация болтанки (среднее по полукругу), выход из «пустого» кружения по таймауту.
3. Матрица 02 заново (tools/atmosphere/xc_matrix.sh) для средний/сильный день.

## Критерий приёмки
- «Идеальный пилот» (диагностика): набор в кружении в средний день ≥ +1 м/с — иначе отчёт с числами для 03 и карточка считается выполненной как диагностика.
- Честный бот: набор в кружении ≥ 60 % от «идеального», доля кружения 25–55 %, ≥ 3 из 5 сидов на синтетике с болтанкой проходят 30 км.
- Тесты atmosphere зелёные, lint чисто.

**Модель:** opus. **Размер:** M. **Зависимости:** после 05 (общий файл xc_pilot.gd). **Перед:** 03 (калибровка).
