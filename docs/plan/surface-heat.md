# surface-heat — поток тепла с поверхности по классу покрова

Ветка `feature/surface-heat`, копия `~/deltaplan-surface-heat`, журнал `docs/plan/surface-heat/` (код задач SH).
Контракты — `docs/contracts/surface-heat.md` (SH1…SH5).

## 0. Цель
Сейчас нагрев идёт двумя несогласованными путями:
- масштаб 1 (Пикар, окна, фазы): `AirPlace.solar_flux` — H0 = 330 Вт/м² везде × косинус к склону + рассеянная доля − 40 Вт/м²
  выхолаживания, вода → 0 (маска рек `detail_water.png`, озёр из OSM в ней нет); запаздывание прогрева одно (луг, 0,3 ч);
- масштаб 2 (аналитические термики): `Terrain.thermal_source_strength_for` — ручной множитель `surface.thermal.class_strength`
  × `exposure_gain` × освещённость^`exposure_power` × сухость ложбин (`wet_k`) × граница классов.

Станет один поток H по классу покрова (одна функция `SurfaceHeat`, два разрешения — клетка решателя и точка 25 м):
(1 − α)·K↓ по склону → Rn = (1 − α)K↓ − L* → G = g_frac·Rn → H = (Rn − G)·β/(1 + β); α, β, g_frac — таблица П4
(`docs/research/surface_params.md`/`.csv`, литература). Вода — H = ρ·c_p·C_H·U·(T_воды − T_воздуха); T_воды ≤ 0 → лёд (параметры снега/льда).

## Решения пользователя (не обсуждаются)
- Классы игры — WorldCover (`SurfaceLayer.CLASS_NAMES`: none, forest, grass, crop, shrub, bare, water, built, snow).
- Влажность почвы — **не из погоды** (прогноза влажности нет и не нужно): β «норма» по классу, сдвиг к `bowen_min` в сырых
  ложбинах и к `bowen_max` на сухих гребнях по полю влажности рельефа `TerrainRelief`.
- Запаздывание прогрева по классам (`heating.lag_h`, `SurfaceHeating`) — сохранить.
- Термики: сила источника — из того же H (нормировка); `class_strength` как ручной подбор убрать; граница классов
  (`edge_boost`) остаётся — это триггер отрыва, не нагрев.
- Пикар/фазы — карта H на своей сетке по долям классов в клетке; все фазы, использующие нагрев, — с той же картой.
- **Вода (дополнение 09.10):** H = k·(T_воды − T_воздуха у поверхности), k = ρ·c_p·C_H·U, C_H ~ 1–1,5·10⁻³ (литература, не
  подбор), U — ветер у воды из модели. T_воды — чистая функция места/даты без состояния: средняя суточная температура воздуха
  из модели погоды места (typical_max_c + суточный ход), сдвинутая на запаздывание ~1 месяц (air2water / Livingstone — число
  проверить), снизу 0 °C; T_воды ≤ 0 → лёд = класс снег/лёд. Озеро/река/водохранилище по тегам OSM и размер — только если
  тривиально; горные реки холоднее (таяние) — ограничение, не делать. Та же T_воды — в Пикаре/фазах и в термиках (источник
  над водой ≤ 0 днём). Проверка до/после — на месте с крупным водоёмом (или синтетическое озеро).
- **z0 по покрову — условно:** только если данных достаточно (есть в П4) и поправка несложная (z0 — вход по клетке в решатель/
  профиль у земли без перестройки схемы). Иначе — не делать, в журнал почему.
- Не делать: θ_v, сезонный снег, влажность в меню/прогнозе, новые данные и загрузки, стиль кода/линтер, шлифовку.
- Совместимость не нужна: конфиги и форматы меняются свободно.

## 1. Физика и границы модели (зафиксировано координатором)
1. **Коротковолновая.** K↓ на горизонталь — параметризация Stull (1988, §7.3): K↓ = S₀·T_K·sin ψ, T_K = (0,6 + 0,2 sin ψ)·(1 − облачность);
   на склон — прямая доля по косинусу угла падения, рассеянная — по sin ψ (доля рассеянной — из той же литературы).
   Облачность — `sky.cover`/`sky_heat` погоды (как сейчас). Тень рельефа — как сейчас (в решателе нет; в точке — нет).
   Уточнение формы — SH-1 (литература), не подбор под старое H0.
2. **Длинноволновое.** L* — упрощённо, константа по Stull (I* ≈ 0,08 К·м/с·ρc_p ≈ 98 Вт/м², ослабление облачностью),
   на месте нынешнего H_LW = 40 Вт/м² (тот был «выхолаживанием в H», теперь это часть Rn).
3. **G и H.** G = g_frac·Rn; H = (Rn − G)·β/(1 + β). Ночью/в тени Rn < 0 → H < 0 по той же формуле (выхолаживание).
   Снег/лёд: формула даёт малое H ≥ 0 (П4 §2.4: «верхняя оценка»), принимаем как есть.
4. **β по влажности рельефа.** m = `TerrainRelief.moisture_at` (0..1; нет поля → «норма»). Кусочно-лог-линейно:
   m ≤ m_dry → bowen_max; m = m_norm → bowen; m ≥ m_wet → bowen_min; между — интерполяция ln β. m_dry, m_norm, m_wet — один
   набор на все места, по распределению поля влажности (SH-1: перцентили по 4 местам), в конфиге с обоснованием (EST).
5. **Запаздывание по классам.** Солнце для класса — на `hour − lag_h[класс]` (`SurfaceHeating`), в решателе и в точке.
   В клетке со смесью классов H = Σ f_c·H_c (каждый класс со своим α, β, g, запаздыванием).
6. **Вода.** H_w = ρ c_p C_H U (T_w − T_a). T_a — температура воздуха у поверхности (модель погоды, `diurnal_state`, с
   поправкой на высоту клетки по градиенту модели). T_w = max(0, T̄_air(дата − lag_w)) — та же поправка на высоту;
   T̄_air — средняя суточная (typical_max_c и суточная амплитуда модели). T_w ≤ 0 → лёд: клетка воды считается как snow.
   U — ветер у воды: u10 случая (меню), снизу U_min (свободная конвекция; число — SH-1). Доля воды в клетке — объединение
   маски рек и класса WATER карты поверхности (+ маска 10 м), т.е. озёра OSM теперь тоже вода.
7. **Термики масштаба 2.** s = clamp(max(H_точки, 0)/H_ref · (1 + edge_boost·близость к границе), 0, 1); H_ref — физическая
   константа (Вт/м²: H голой скалы «норма» на ровном при солнце в зените и ясном небе), не подбор под старые числа.
   Небо/облака на s не действуют (их учитывает `ThermalField._spawn` и погода, как сейчас). Вода — по H_w (днём ≤ 0 → s = 0).
8. **Чего модель не умеет (записать в документацию):** влажность почвы — только рельеф (дождей/полива нет); α не зависит от
   угла солнца; адвекция (оазис), холодные горные реки (таяние), различие озеро/река/водохранилище, суточный ход T_воды, лёд
   по толщине — вне модели; L* константа; эталон Python (`air.py solar_flux`) остаётся старым — источник истины для H в игре
   теперь GDScript (`SurfaceHeat`).
9. **Ожидаемое (оценка координатора, проверить замером):** ровный луг в полдень ≈ 200 Вт/м² (было ≈ 276), скала ≈ 300,
   лес ≈ 280 — лес по таблице П4 греет не слабее луга (низкое α, малое G). Это следствие литературы, не ошибка; в отчёт.

## 3. z0 по покрову — решение координатора
Данные есть (П4 z0_m). Сейчас z0 — один скаляр (`AirCase.Z0 = 0.1`): трение о стенку cd = (κ/ln(½dz/z0))² (скаляр в шейдере),
профиль притока, u* в замыкании, DCT-длины фаз, лог-профиль ниже первой клетки в `WindField` (z0 из meta). Поправка «по клетке
без перестройки схемы» = cd и u* — плоскость столбца (как `C_QV`), `WindField` — карта z0 в meta вместо скаляра; приток и фазы —
эффективный z0 области (лог-среднее). Это вход по клетке, схема та же → **делать** отдельной задачей SH-6 после SH-4, с условием
остановки: если нужно больше, чем плоскость столбца + чтение в шейдере + карта в meta + выборка в `WindField` (например,
смещение нуля d, перестройка нижней клетки, пересборка калибровки AM-09) — остановиться, в журнал «не делаем, почему».

  мало (они в Вт/м²), но числа проверить в SH-7.

- Инструмент «до» для термиков: `tools/research/air_thermals/probe.gd` берёт поля из Python — для до/после нужен путь через
  `AirRuntime` в игре (SH-3).
