# План cascade-2d (код задач CSD)

## Цель
Исследование, не код для игры: ясный ответ, **работает ли каскад без состояния** — мелкие уровни ветра
выводятся из родителя делением граней пополам с точным балансом массы, считаются по пути к пилоту, без
шагов по времени (идея `docs/plan/air-cascade.md`, раздел «Правило деления: баланс + рельеф + устойчивость
+ тепло»). Ответ показывает: что каскад воспроизводит из мелкого решения (разгон на бровке, w у склона,
болтанка), что не воспроизводит и почему, где ломается и сколько стоит. Механизм — простыми словами и
картинками полей «каскад против эталона». «Воздух со временем» (AMR с шагами) в модуль не входит —
следующий этап только по команде пользователя.

## Решения
Полный список с причинами — `.dpcli/dpcli inbox cascade-2d` / `decisions.jsonl`. Кратко (2026-11-04):
- Каскад без состояния; правило деления — из плана air-cascade (пользователь).
- Итог — понимание идеи; прототипы минимально достаточные, без встраивания и шлифовки (пользователь).
- Развилки координатор решает сам, без шлюзов к пользователю (пользователь).
- Геометрия: эталон — трёхмерный `picard_rs` на тонком слое (гребень вытянут по y), каскад — в разрезе
  (x, z), клетка делится 2×2.
- Эталон — `picard_rs` на вложенных сетках 400/200/100/50/25 м; базовая линия — грубое поле Пикара,
  линейно интерполированное на 25 м (как игра опрашивает поле).
- Случаи C0–C3 синтетические, C4 (разрез Аскарово) — по возможности.
- Каскад — отдельный крейт `tools/research/cascade_2d/cascade_rs`; `rust/` и код игры не меняются.
- Поля — пара json + f32 `.bin` (F1), локально в `~/data/cascade_2d`; в git — записи, метрики, картинки.
- Критерии K0–K5 — ниже, до опытов; вердикт — по одному варианту V3.

## Опыт
**Эталон P_k** — `picard_rs::api::solve` (решатель игры, без правок) на квази-2D случаях R1: гребень
постоянен по y, ветер по x, несколько клеток по y (минимум, при котором решатель работает), берётся
средний ряд. Сетки вложенные: dx = 400·2^−k, dz = 100·2^−k, k = 0…4 (25 м / 6,25 м), общая область
12,8 × 2,4 км, параметры физики — как у игры (`params` случая Онгудая 400 м). Случаи и сетки — контракт F0.

**Каскад** — от P400 (и P200 для проверки) вниз до 25 м. Поток через грань родителя делится между двумя
подгранями; потоки внутренних граней 4 детей — из баланса массы каждого ребёнка (3 уравнения, 1 свободная
степень — циркуляция). Варианты (одинаковы на всех случаях):
- **V0** — деление 0,5/0,5, циркуляция 0 (чистый механизм, без знаний о поле);
- **V1** — деление по линейной реконструкции потока вдоль грани из соседних граней родителя
  (консервативное продолжение, как в AMR, Balsara 2001 / Tóth–Roe 2002); циркуляция — из той же
  реконструкции;
- **V2** — V1 + рельеф: подграни в земле закрыты, поток родителя уходит в открытую часть, у земли
  w ≈ U·∇h;
- **V3** — V2 + устойчивость (Фруд: при Fr < ~1 избыток в обход, `docs/research/air_phase_results.md`) и
  тепло (над нагретой половиной избыток вверх, `tools/research/heat_ca/README.md`) — **вариант вердикта**;
- **V3h** — V3 + хеш грани (болтанка) ±δ_n·σ·A, δ_n ∝ 2^(−n/3): только для статистики болтанки, не для
  среднего поля.
Режимы: всё поле (для сравнения) и опрос точки «по пути» (для цены); значения совпадают.

**Базовые линии B_k** — P_k (k = 400, 200, 100, 50) линейно на 25 м по своим сеткам компонент.

## Метрики (M1, контракт)
Сравнение на сетке 25 м с P25, по клеткам воздуха. Области: ROI — 0 < z_agl ≤ 300 м, |x − x_c| ≤ 3L;
LEE — x_c < x ≤ x_c + 6L, z_agl ≤ 300 м. U_ref — скорость P25 на 100 м над землёй у входа.
- E_u, E_w — СКО (u − u_ref), (w − w_ref) в ROI / U_ref; E_u_lee — то же в LEE.
- ΔS — ошибка разгона над гребнем S(z) = U(z)/U_вход(z) − 1, среднее |ΔS| на z_agl 25/50/100 м.
- r_w — средний w над наветренным склоном (x_c − 2L ≤ x ≤ x_c, z_agl 25–75 м) каскада / эталона.
- L_rec — длина возврата (u < 0 у земли, z_agl ≤ 25 м) за гребнем.
- Термик: w_max в столбе, восходящий поток массы F_up через z = z_i/2.
- Баланс: max |∇·u|·dx/U_ref по клеткам всех уровней; поток через границы области = у родителя.
- Шум эталона E_ref — та же метрика для B50 против P25 (сходимость эталона по сетке).
- Болтанка (V3h): σ_u, σ_w по высоте против σ, которую модель игры выводит из K эталона
  (`docs/guide/air-model/turbulence.md`); справочно, не в вердикт.

## Критерии (зафиксированы 2026-11-04, до опытов)
- **K1 баланс** (обязателен): max |∇·u|·dx/U_ref ≤ 1e-5 (f32) на всех уровнях всех случаев; сумма
  подграней = грань родителя до округления.
- **K0 контроль** (C0 плоско): E_u ≤ E_u(B400) + 0,01, ложный |w| ≤ 0,02·U_ref в ROI.
- **K2 точность** (на целевом случае; случай информативен, если E(B400) ≥ 2·E_ref, иначе не в счёт):
  E_u и E_w ≤ 0,7·B400; C1 склон — ещё |ΔS| ≤ 0,5·|ΔS(B400)| и r_w ∈ [0,7; 1,3]; C2 подветренная —
  ещё E_u_lee ≤ 0,7·B400 и L_rec ±30 % (если у эталона возврат есть); C3 термик — ещё w_max и F_up ±30 %.
- **K3 цена**: спуск всего разреза до 25 м T_desc ≤ 0,1·T(P25) (время P25 на один ряд y: T/ny, те же
  потоки и машина, под замком cpu); пик памяти полного поля ≤ 0,5·P25 (на ряд); опрос точки по пути
  ≤ 20 мкс на одном ядре (бюджет ~1 мс на кадр на 50 опросов).
- **K4 Парето**: при своей цене каскад точнее любого B_k с T(P_k)/ny ≤ T_desc (иначе проще решить Пикар
  мельче).
- **K5 сходимость и устойчивость**: нет NaN/Inf, max|u| ≤ 1,5·max|u|(P25); E_u каскада против P_k
  своего уровня растёт не больше ×1,5 за уровень; побитно одно и то же на 1 и 8 потоках и в режиме точки;
  старт от P200 даёт E_u не хуже старта от P400.

Обоснование порогов: 30 % — больше разброса эталона по порядку схемы (50 м 1-й против 25 м 2-го порядка —
8–20 %, `docs/guide/air-model/limits.md`); r_w от 0,7 — у модели сейчас 0–0,5 от U·∇h
(`turbulence.md`); 10× — иначе проще окна Пикара 100/50 м, которые уже есть в rust-wind.

**Вердикт** (по V3): **имеет смысл** — K0, K1, K3, K4, K5 и K2 на ≥ 2 из 3 целевых случаев;
**при условиях** — K0, K1, K5 и K2 на 1 случае, или K3/K4 только в режиме точки — условия названы;
**не имеет** — K1 не держится, или K2 ни на одном случае, или K3 не выполнен ни в одном режиме.
Варианты V0–V2 — разбор, откуда берётся выигрыш или проигрыш (механизм).

## Случаи (F0)
C0 плоско, U10 = 5 м/с, нейтрально. C1 склон — Agnesi H = 200 м, L = 500 м, U10 = 5, нейтрально.
C2 подветренная — Agnesi H = 250 м, L = 300 м, U10 = 8, устойчиво N = 0,01 с⁻¹. C3 термик — гребень C1,
U10 = 1, нагрев солнцем, z_i = 1500 м. C4 (по возможности) — разрез Аскарово через старт `biyagoda_west`,
западный ветер 5 м/с.

## Задачи
- **CSD-0** (`dp-engineer`) — контрактная проверка F1/F2/M1 (`contract/check_contract.py` + тест на
  синтетике), обёртка venv (`py`, uv: numpy, h5py, matplotlib, scipy), README-заготовка.
- **CSD-1** (`dp-researcher`, после 0) — эталоны: сборщик квази-2D случаев R1 (через `tools/research/air3d`),
  решение `picard_rs` на 400…25 м для C0–C3 (+C4), F1 среднего ряда, F2 (время, итерации, память,
  однородность по y), сходимость эталона E_ref.
- **CSD-2** (`dp-engineer`, после 0, параллельно 1 и 3) — метрики M1 и базовые линии B_k: чтение F1,
  интерполяция на 25 м, все метрики, таблица, картинки полей (разность, профили).
- **CSD-3** (`dp-researcher`, после 0, параллельно) — крейт каскада V0–V3, V3h: всё поле и опрос точки,
  баланс на каждом уровне, время и память в F2; тесты баланса на аналитическом потоке.
- **CSD-4** (`dp-researcher`, после 1–3) — прогоны: случаи × варианты × старт 400/200, метрики, цена,
  сходимость; README с таблицами, картинками «каскад против эталона», вердиктом по K0–K5, механизмом
  простыми словами, неизвестным. Ревью — `dp-reviewer` с `model: fable`.
- Разбор болтанки (V3h) — в CSD-4, справочно. Нет вердикта «имеет смысл / при условиях» — дальше не идём.

Волны: 0 → (1, 2, 3) → 4. Исполнителей одновременно ≤ 10.
- **Итог (2026-11-04):** CSD-0…4 влиты; вердикт по K0–K5 — **не имеет смысла** (V3 хуже интерполяции B400 по E_u на C1/C2/C3: 0,236/0,230/0,312 против 0,178/0,179/0,183; спуск 0,1 с — в 10⁻³…10⁻⁴ от P25); исправление наклона у стенки вердикт не изменило. Разбор — `tools/research/cascade_2d/README.md`.

## Условия остановки
- K1 не держится на V1–V3 — вывод «не имеет», дальше не идём.
- T_desc ≥ T(P25)/ny — вывод «не имеет» по цене, точность досчитывается одним прогоном для объяснения.
- P25 не сходится или дольше 2 ч на случай — эталон P50, с пометкой (решение координатора).
- Нужна правка кода игры (`rust/`, `scripts/`) — не делать; обойти в исследовательском коде.
