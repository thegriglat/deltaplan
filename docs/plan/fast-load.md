# fast-load — Быстрая загрузка места

Ветка `feature/fast-load` от `main`, копия `~/deltaplan-fast-load`, код задач — `FL`. Слияние в `main` — главная сессия; выпуск версии — только по команде пользователя.

## Цель пользователя
Тёплая загрузка места (место уже в кеше) сейчас 28 с (Онгудай) и 43 с (точка −27.7176,−48.7799). Сократить: повторная загрузка с попаданием в кеш поля ≈ 10 с / ≈ 17 с, экран загрузки не замирает дольше 1–2 с.

## Решения пользователя (2026-10-17)
- **A. Кеш поля воздуха на диске, LRU.** Пилоты обычно летают в одной и той же погоде раз за разом. Ключ: место, слот часа, ветер (скорость, румб), небо, температура и прочие условия + хеш версии модели воздуха (тот же, что у запечённых полей учебного острова: `data/air_model_hash.txt`, `tools/build.sh`; переиспользовать, не дублировать). Размер кеша — настройка игры (по умолчанию 200 МБ), при превышении стирается самый давно использованный. Формат — бинарный, компактный (float16 + zstd, `docs/research/air_field_cache.md`, TODO T-04); запись в фоне, без замирания. Хеш не совпал или файл повреждён — поле считается заново.
- **Принцип.** Из GDScript не читать одно и то же несколько раз объёмными циклами. Общие данные места (высоты, OSM, план домов) читать один раз и делить; тяжёлые циклы — нативные функции Godot (PackedArray-операции, Image, ресурсы), рабочие потоки или кеш на диске; на главном потоке — только создание узлов и мешей.
- **B** — термики порциями сразу по готовности поля, без замирания. **C** — маска просек на общих данных с одним планом домов (с домами OSM) + починка ключа кеша; проверить и исправить ошибку вырубки (до/после: где деревья вырублены). **D** — `OsmLayer.build` и дома посёлков в рабочий поток. **E** — деревья: одна сборка сцены на породу, фоновая загрузка. **F** — пирамида высот в кеше места. **A′** — подготовка областей в двух потоках, только если поле не меняется (бит-в-бит или в пределах допуска). **G** — объекты, деревья, боты порциями во время этапа ветра.
- Попутно: выбор точки у моря — «Здесь море» проверяется по центру ячейки 0,05° (ключ места), а не по выбранной точке → отказ на суше у побережья (Ханга-Роа −27.15,−109.43). Починить.
- Исполнители: opus — потоки, кеш, модель воздуха; sonnet — простое. Тестовых сборок не делать; цену кадра на GPU не мерить — мерить время загрузки.
- Шлюзы главной сессии: после A и после всего.

## Исходное (исследование `research/load-profile`, bc718f41)
Тёплая загрузка 28 / 43 с; после рельефа 24 / 37–39 с:
- поле воздуха 14–15 с — каждый запуск заново, на диск не сохраняется; GPU 2,5 с, остальное — подготовка области в одном потоке (`air_runtime.gd:310/549`);
- объекты 3,7 / 12,4 с на главном потоке: маска просек `WorldClearings.build_for` (`world_clearings.gd:24`) 1,0 / 6,3–7,7 с — рельеф и OSM читаются повторно; план домов без домов OSM → 293 тыс. «домов» против 18 тыс. расставленных; ключ кеша `village_placer.gd:29` никогда не совпадает; 1,19 млн `stamp()`; вероятная ошибка — вырубка леса там, где домов нет;
- первая расстановка термиков 4,2 / 7,2–9,1 с на главном потоке одним кадром (`thermal_field.gd:949/965/532`; порционный `_refresh_pump` не используется);
- `OsmLayer.build` 1 / 2,7 с (`osm_pilot.gd:167/188`, цикл ЛЭП на GDScript); деревья 1,2 с (`terrain_tree_models.gd:39/229` — сцена породы собирается заново на каждый из 40 вариантов); пирамида высот `make_max_texture` 0,3–0,7 с.
Инструмент замера — `tools/research/load_profile/` в ветке `research/load-profile` (зонд `probe.gd`, разметка `instrument.py`, сводка `summarize.py`); в модуль переносится задачей FL-1.

## Задачи

### Волна 1 (параллельно)

#### FL-1. Инструмент замера и замер «до» (dp-researcher, sonnet)
Перенести `tools/research/load_profile/` из bc718f41 в ветку; сценарий `measure.sh` (без разметки кода: только зонд) — тёплая загрузка дважды + время до полёта, этапы, наибольшее замирание экрана загрузки; `compare.py` — таблица «до/после». Замер «до» на `feature/fast-load`: Онгудай и точка, по 3 тёплых запуска. Формат итога — FL-К3.
Приёмка: `measure.sh` воспроизводим, `baseline.json` по FL-К3, таблица «до».

#### FL-2. A — кеш поля воздуха на диске (dp-engineer, opus)
Писатель/читатель набора уровней по FL-К1 (переиспользует `AirBakedField`), подмена расчёта в `AirRuntime` при попадании, запись в фоне, LRU по размеру, настройка размера в настройках игры, контрактный тест.
Приёмка: поле из кеша совпадает с посчитанным (≤ 0,01 м/с по u, v, w, float16); попадание → нет этапа расчёта ветра; повреждение/чужой хеш → пересчёт; LRU стирает старое; запись без замирания главного потока > 100 мс.

#### FL-3. Проверка «море» по выбранной точке (dp-engineer, sonnet)
Отказ «Здесь море» — по выбранной точке, а не по центру ячейки 0,05°. Тест на Ханга-Роа −27.15,−109.43 (суша) и точку в открытом море.

#### FL-4. C — маска просек на общих данных, один план домов, ошибка вырубки (dp-engineer, opus)
Общие данные места по FL-К2 (высоты, OSM, план домов — один раз); `WorldClearings.build_for` и посёлки — на них; план домов с домами OSM; ключ кеша плана домов совпадает при повторе; ошибка вырубки — проверить картой маски до/после (числа: площадь вырубки, дома в плане против расставленных) и исправить.

### Волна 2 (после FL-2/FL-4 по зависимостям)
- **FL-5. B — термики порциями** (dp-engineer, opus): первая расстановка — порциями по готовности поля, без кадра > 1 с. После FL-2 (стык подачи поля из кеша).
- **FL-6. D — `OsmLayer.build` и дома посёлков в рабочем потоке** (dp-engineer, opus): после FL-4 (общие данные).
- **FL-7. E — деревья** (dp-engineer, sonnet): одна сборка сцены на породу, фоновая загрузка ресурсов.
- **FL-8. F — пирамида высот в кеше места** (dp-engineer, opus): `make_max_texture` — из кеша места при повторе.
- **FL-9. A′ — подготовка областей в двух потоках** (dp-engineer, opus): только если поле совпадает бит-в-бит или в допуске; нет — отчёт и отказ.
