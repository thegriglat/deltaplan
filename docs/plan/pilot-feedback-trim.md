# pilot-feedback-trim — триммер, клавиша X, чувствительность мыши (код задач PFT)

## 1. Цель
Разобрать отзыв опытных пилотов (2026-11-01, мышь, спортивные крылья) и ответить замерами, где причина — в физике
(регрессия балансировки/скорости трима, нейтраль штанги, демпфирование) или в конфигах (подвеска/трим крыльев
по умолчанию, ход мыши по умолчанию, поведение X). Проблемы нет — так и доложить с числами. Модуль маленький: исследование,
затем точечная правка; не раздувать.

## 2. Решения пользователя
Решение 2026-11-02 (`.dpcli/dpcli inbox pilot-feedback-trim`): три пункта отзыва — (1) кабрирует на нейтрали, двигают
подвеску на +2…+4 см почти у всех спортивных крыльев, Апогею мало и 5 см (Апогей — прикидочный, без паспорта);
(2) X (штанга в середину) даёт маятник по тангажу вместо устойчивого полёта; (3) большая чувствительность — дёргается,
не успеть на обратный ход; минимальная, ход мыши ~7–8 см — похоже на реальное. Физика прежде «нравится».

## 3. Что известно (registry/findings, контракты)
- Продольный канал «Маятника» (pendulum): 16 полос дают паспортный трим одной константой `dcm0` под `hang_from_nose_m`;
  +1 см подвески — +0,4…+0,9 км/ч (`ref.kmh_per_cm_hang`); фугоида T 5,2–5,7 с (Cook 5,4 с), затухает сама.
- После этого менялись: VM-4 (нелинейная Cm(α), PD-К2 v8 — `dcm0` пересчитан), VM-12 (отпускание рук), roll-modes,
  bar-mouse (ход мыши в отсчётах), rust-wind (ветер в крейте). «Раньше так не было» — проверить по тегам v1.5.x…v1.7.0.
- Мышь (BM-К1 v2): `mouse.bar_travel_px` 2500 отсчётов до упора, множитель 0,25…4 → 10000…625 отсчётов (31,7…2,0 см
  при 800 DPI). Минимум ×0,25 = 7–8 см у пилотов → мышь ≈ 3200 DPI; по умолчанию у них ≈ 2 см до упора.
- X: `controls.json → keyboard.center_time_s` 0,2 с — штанга в нейтраль за 0,2 с; диапазон подвески PD-К3 −4…+4 см.

## 4. Задачи
- **PFT-1** (dp-researcher) — продольный канал, пп. 1–2. Установившаяся скорость при нейтрали штанги (мышь 0, руки
  по умолчанию) и «брошенной ручке» против паспортного `trim_speed_kmh` и `pendulum.ref.trim_kmh` для спортивных крыльев,
  Апогея и учебного (контроль); переход первых 10–20 с после старта в воздухе и после разбега; то же на 3–4 тегах
  (v1.5.13 или раньше … v1.7.0) — есть ли регрессия и каким коммитом. X: из «на себя», «от себя», виража — период,
  логарифмический декремент, размах; сравнить с отпусканием штанги вручную и с литературой. Итог по каждому пункту:
  физика (где) / конфиг (ключ, значение, замер) / нет проблемы. Код игры не меняет.
  Приёмка: записка `docs/research/pilot-feedback-trim/longitudinal.md`, данные и команды — `tools/research/pilot-feedback-trim/`.
- **PFT-2** (dp-researcher) — мышь и отклик, п. 3. DPI пилотов из их чисел; ход до упора по умолчанию при 400–3200 DPI;
  отклик крыла на штангу (скорость крена на долю хода, время перекладки 30°→30° / 45°→45° при полном ходе) спортивных
  против учебного и против данных сертификации/руководств; виновата ли только чувствительность или и отклик модели.
  Предложение: `bar_travel_px`, `ui.bar_sensitivity_range` с обоснованием. Код игры не меняет.
  Приёмка: записка `docs/research/pilot-feedback-trim/mouse.md`, данные — `tools/research/pilot-feedback-trim/`.
- **PFT-3** (dp-engineer) — правка по выводам PFT-1/2, только конфиги и их тесты (PFT-К1 → v2 до запуска). Карточка —
  после итогов PFT-1/2.
- **PFT-4** (dp-writer) — `docs/guide`, `registry/findings.md`, CHANGELOG «В работе». Может войти в PFT-3.

## 5. Волны
1: PFT-1, PFT-2 параллельно. 2: PFT-3 (+ PFT-4) по итогам или шлюз.

## 6. Условия остановки (шлюз)
Причина в физике/коде модели (регрессия коммитом, нейтраль рук, демпфирование) — шлюз с вариантами до правки.
Правка, меняющая паспортные трим/поляру крыльев или PD-К2/PD-К3 (диапазон подвески), — шлюз. Конфиги в границах
PFT-К1 по замерам — без шлюза.
