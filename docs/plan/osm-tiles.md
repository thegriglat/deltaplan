# osm-tiles — тайлы OSM на всю планету

Контракты — `docs/contracts/osm-tiles.md` (O1–O9). Журнал — `dp log osm-tiles`. Основа — замер
`docs/plan/osm_vector_pack.md` §9 и эталон `tools/research/osm_pack/` (`build_tiles20.py`, `build_pilot20.py`).

## Цель
Дороги, реки, вершины и объекты для пилота OSM в любой точке мира: тайлы 20×20 км на одной мировой сетке,
статикой из Cloudflare R2 (≤ 10 ГБ на планету), игра при открытии места качает 3×3. Город узнаваем сверху
(Алматы), но не уровень 2GIS.

## Решения пользователя (не обсуждаются)
- Цель — узнаваемый ландшафт, пилоты летают в пригородах и горах; не 2GIS/Google Maps по детализации.
- Тайлы 20×20 км, одна мировая сетка без перекрытия (пояса 0,18°), один файл на тайл; игра качает ≈ 3×3.
- Состав (между B и C §9.5): дороги без `service`, `track` отдельным потоком; дома-прямоугольники ≥ 50 м²; ЛЭП с
  опорами, канатки, аэродромы, мачты/телебашни, ж/д; вершины и перевалы с именами; реки и каналы (без ручьёв).
  Без landuse, плотин, заметных зданий, path/footway.
- Бюджет: все тайлы планеты ≤ 10 ГБ (R2 free tier, раздача статикой).
- Этап 1: упаковщик на Rust, корректность — на Словении и Казахстане (сверка с Python-эталоном). Этап 2: один
  скрипт качает выгрузки Geofabrik по регионам и обрабатывает, укладываясь в свободное место (≈ 129 ГБ);
  переживает падение/остановку, докачка, тестовый запуск (Казахстан); запускает пользователь сам и видит
  прогресс; итог — каталог тайлов + манифест для R2. Заливку не делаем. Полный мировой прогон — пользователь.
- Сжатие — zstd 19. Упаковщик — максимальная параллельность (20 ядер, `rayon`, параллельный разбор PBF);
  `--threads`, по умолчанию все ядра; загрузка CPU замеряется, на стадиях кодирования ≥ ~70 % ядер.
- Параллельно — клиент в игре: **вернуть из истории git** удалённый OSM-клиент (e8fe4ba4, 4493cfec, 9c810727) и
  переключить источник на наши тайлы; Overpass, заборы, поля, landuse — не возвращать. Базовый URL — в конфиге,
  путь — в контракте; нет файла/сети — игра без слоя (пометка `missing`), ожидание загрузки ≤ 5 с.
- Приоритет клиента: **дороги, реки/каналы, вершины (и перевалы) с подписями — обязательны**; дома — бонус «как
  получится», приёмку и волну не держат. Где есть дома OSM — процедурных в этом пятне нет (Алматы сейчас —
  «огромная деревня»); высота без `height/levels` — одно правило по типу и площади (O9), без подбора.
- Подписи вершин — тот же компонент, что подпись ботов; текст — имя (+ высота, если есть `ele`); без имени — нет.
- Промежуточного шлюза со скриншотами нет.
- Пасхалки на OSM не возвращаются: `egg_place.gd` и пасхалки — как после no-osm, тайлы им не подключать.
- Финал модуля перед мировым прогоном: прогон оркестратора на Казахстане → тестовая сборка Linux, которая берёт
  эти тайлы одной командой (без R2) → пользователь летает над Алматы (город, дороги на Шымбулак). Это последний
  шлюз: отчёт с командами «тестовая сборка» и «весь мир»; мировой прогон не запускать.

- Память (после двух OOM 10.10): тяжёлые запуски (osmtiles pack/finalize, world.py, пачки godot-тестов, `dp accept` с
  тестами) — только в `systemd-run --user --scope -p MemoryMax=12G -q <команда>`; godot-тестов ≤ 4 параллельно;
  одновременно не больше одного тяжёлого запуска (`dp lock cpu`). Swap 12 ГБ, RAM 31 ГБ.

## Решения координатора (можно пересмотреть)
- **Формат тайла** (O2): 16-байтный заголовок (`DPOT`, версия, `raw_len`) + один кадр zstd 19 с protobuf `OsmTile`
  (потоки — `bytes` в эталонной кодировке zigzag-varint). Один кадр на тайл, а не на поток: у пустых тайлов
  ≈ 15 кадров × 10–20 Б заголовков — заметная доля на ~0,5 млн тайлов; клиент всё равно читает тайл целиком.
  Заголовок нужен Godot: `decompress` для zstd требует размер результата.
- **Кодировка потоков** = эталон §9 (чтобы сверять байты), отличия только в значениях: фиксированные коды
  классов вместо словаря по порядку появления, флаг «есть имя» у вершин/перевалов (связь с потоком имён),
  флаг «связь» у мачт вместо отдельного потока, `tracktype` в классе `track`, тоннель/мост у ж/д.
- **Склейка регионов** (O4): регион — независимый проход, пишет фрагменты (O2 + id объектов OSM) только для
  тайлов, пересекающих его `.poly`; тайл склеивается, когда упакованы все регионы, чьи `.poly` его
  пересекают; дубли по id (полные пути на границе) — берётся версия с большим числом точек. Без
  дополнительного диска: фрагменты — только у пограничных тайлов и только до склейки.
- **Регионы**: дерево Geofabrik, узел целиком, если `.pbf` ≤ 2 ГБ, иначе — его дети (если покрывают). Крупнее —
  больше ОЗУ на индекс узлов; мельче — больше границ. Сборные регионы (`dach`, `alps`, …) не берутся.
- **Оркестратор** — Python 3 только stdlib (`world.py`): прозрачно и правится без сборки; тяжёлое — бинарь
  `osmtiles` (Rust). Состояние — `state.json` (замена атомарно) + дописываемый `finalized.jsonl`, журнал —
  `log.jsonl`. Пока пакуется регион, качается следующий.
- **Клиент**: загрузка — новая последняя стадия сборки места `OsmTilesStage` (интерфейс OA-К3): так работают
  `missing` и догрузка «только недостающего», без отдельного механизма; кеш тайлов общий `user://osm_tiles/v1/`.
  Отрисовка — восстановленные `OsmData`/`OsmLayer`/`RoadMesher`/`PowerLinePlanner`; потребители разнесены по
  отдельным файлам (`osm_roads.gd`, `osm_pilot.gd`, `osm_buildings.gd`), каркас `OsmLayer` с пустыми вызовами
  ставит OT-8 — волна 3 идёт без конфликтов.
- Реки и каналы рисуются лентами поверх рельефа (как дороги, материал воды); в маску воды не пишут (решение
  no-osm: вода 10 м — WorldCover + реки по рельефу). Опоры ЛЭП — плановщик пролётов прежнего клиента
  (`PowerLinePlanner`), опоры OSM — не обязательны. Тропы к стартам OSM не используют (как сейчас).
- Тестовые тайлы для игры: в репозиторий — 3×3 Словении ≤ 1,5 МБ (`tests/fixtures/osm_tiles/v1/`); Алматы и
  остальное — в `/home/greg/deltaplan_data/osm_tiles/` (скриншоты — через локальный `python3 -m http.server`).
- Данные: выгрузки и результаты прогонов — `/home/greg/deltaplan_data/osm_tiles/<задача>/` (не в git).

## Допуски сверки с эталоном (этап 1)
Сравнение `osmtiles stats --zstd-per-stream` (O6) с `tools/research/osm_pack/results/` скриптом
`tools/osm_tiles/compare_ref.py` (OT-3). Словения — все потоки (80 тайлов эталона), Алматы — roads, track,
buildings на 25 тайлах эталона (`tiles20_almaty.json`).
| Метрика (сумма по тайлам эталона) | Допуск |
|---|---|
| число объектов: roads, track, river, canal, powerline, rail, aerialway | ±1 % |
| число домов ≥ 50 м² | ±0,5 % |
| точечные потоки (power_tower, vertical, peak, pass, names, aeroway) | ±1 % (поток < 200 объектов — ±max(2, 3 %)) |
| длина roads, track (км; эталон — до упрощения) | ±0,5 % |
| raw байт по потоку | ±5 % (решение пользователя: до 5 % по размеру — неважно) |
| zstd 19 байт по потоку | ±5 % |
| по тайлам: тайлы с ≥ 200 объектов в потоке, где расхождение числа ≤ 2 % | ≥ 95 % |
| набор тайлов: тайлы эталона без наших и наоборот | только не пересекающие `.poly` |
Ещё: итоговые файлы (zstd 19 целиком) — сумма ≤ суммы потоков по отдельности + 5 % (решение пользователя; замер OT-2: +0,4 %,
кадр на тайл не меняем); два прогона — побайтно равны. Набор тайлов при `--cover` — только тайлы cover в
прямоугольнике тайлов эталона (у Алматы — окно 5×5, а не весь Казахстан).

## Шлюзы (условия остановки)
- Оценка планеты по итогам этапа 1 (`estimate_planet.py`, как §9.5, по нашим ценам) > 9 ГБ → к пользователю с
  вариантами (порог домов 100 м², без track, без малых дорог — цены из §9.5).
- Набор регионов требует > 100 ГБ диска в пике или самый крупный неделимый регион не влезает в ОЗУ (пик > 24 ГБ).
- Склейка на границе Казахстан/Киргизия расходится с упаковкой объединённой выгрузки больше 0,5 % — разобрать
  причину; если Geofabrik режет пути на границе так, что правило O4 не работает — к пользователю.
- Разбор тайла в GDScript слишком медленный (окно 3×3 Алматы > 5 с на рабочих потоках) — варианты формата.

потоков, по 2–3 объекта (крайние случаи: отрицательные дельты, кириллица в имени, кольцо аэродрома), пишет Rust.

Приёмка: `cargo test --release` зелёный; python-тесты зелёные; `osmtiles cover --poly slovenia.poly` содержит все 28
тайлов «inside» эталона; `dump sample_v1.dpt` = `sample_v1.json`; `manifest` по образцу читается обратно.

### OT-3. Сверка с эталоном и оценка планеты (dp-researcher)

### OT-2. Упаковщик: pack и finalize одного региона (dp-engineer, opus)
`osmtiles pack` и `finalize` (O4, O5): разбор PBF параллельно (`osmpbf` + `rayon`; фильтр тегов и координаты
узлов — можно `osmium tags-filter` / `add-locations-to-ways`), мультиполигоны домов и аэродромов, клип, ДП, мин.
прямоугольник, кодирование и zstd по тайлам параллельно. Прогоны: Словения (`--poly slovenia.poly`) и весь
Казахстан → `/home/greg/deltaplan_data/osm_tiles/OT-2/`. Фикстура 3×3 Словении (≤ 1,5 МБ) →
`tests/fixtures/osm_tiles/v1/`.
Приёмка: `compare_ref.py` PASS для Словении и Алматы; два прогона Словении побайтно равны; время, пик RSS и
`cpu_cores_avg` по стадиям из `pack.json` в отчёте; кодирование/сжатие ≥ 14 ядер в среднем (70 % от 20);
`estimate_planet.py` — вилка в отчёте (> 9 ГБ — шлюз).

### OT-4. Склейка регионов на границе (dp-engineer)
Проверка O4 на Казахстане + Киргизии (выгрузка Geofabrik `asia/kyrgyzstan`): `cover` обоих, `pack` по
отдельности, `finalize` пограничных тайлов против `pack` объединённой выгрузки (`osmium merge`) как одного
региона. Правки `finalize` при расхождении. Приёмка: по пограничным тайлам число объектов по потокам совпадает
≤ 0,5 %, дублей ключей нет; Алматы 5×5 — юго-западные тайлы теперь с данными Киргизии. Автотест сшивки
(решение пользователя, обязателен): `tools/osm_tiles/tests/test_border_stitch.py` — объекты, пересекающие границу
выгрузок (дороги, реки, ЛЭП, дома), в итоговом тайле ровно один раз и целиком (суммарная длина частей пути в тайле
= длине в эталоне из `osmium extract` объединённой выгрузки по прямоугольнику тайла ±1 %, ключи OSM без дублей,
домов у границы не меньше и не больше эталона); запускается на готовых тайлах OT-4 и повторно — на итоге OT-6.

### OT-5. Набор регионов Geofabrik (dp-engineer)
`tools/osm_tiles/regions.py` (O8): `index-v1.json` → набор регионов (≤ `--max-region-gb`), `HEAD` размеры,

`.poly`), объединение покрывает ≥ 99 % площади континентов, крупнейший регион ≤ лимита (исключения — список),
в отчёте число регионов, сумма ГБ, число тайлов и пограничных тайлов.

### OT-6. Оркестратор world.py (dp-engineer)
`tools/osm_tiles/world.py` (O8): состояние, докачка с `Range`/`If-Range`, md5, учёт диска, конвейер

совпадают (sha) с прогоном без прерывания; время, пик диска и ОЗУ, оценка времени мирового прогона.

`OsmBuildings` (`osm_buildings.gd`): дома OSM через `BuildingPlacer`, правило высоты (O9 `height_rule`), пятна с
домами OSM без процедурных (`VillagePlacer`), препятствия. Приёмка: тесты world_objects/game зелёные; на
фикстуре: процедурных домов в пятнах с OSM — 0; время постройки домов Алматы 3×3 — в отчёте; 1 скриншот Алматы →
`build/screenshots/OT-11/`. Не держит волну: не успели — модуль закрывается без неё.

### OT-12. Тестовая сборка с тайлами Казахстана — последний шлюз (dp-engineer)
Тестовый прогон оркестратора на Казахстане (итог OT-6 или новый `world.py run --regions kazakhstan,kyrgyzstan`) →
сборка игры Linux (как в `new-release`, без версии и заливки) → `tools/osm_tiles/play_local.sh` одной командой
запускает сборку с `DELTAPLAN_OSM_TILES_URL=<каталог тайлов>` (O9, без R2 и без HTTP-сервера). Проверить, что место
у Алматы и дороги на Шымбулак выбираются в игре (любая точка или старт из каталога) и слой виден. Приёмка: сборка
запускается командой, в логе места `osm_tiles` без `missing`, 1 скриншот Алматы с воздуха →
`build/screenshots/OT-12/`. Итог — отчёт пользователю с командами «запустить тестовую сборку» и «запустить весь
мир»; мировой прогон не запускать.

## Риски
- Разбор Алматы (130 тыс. домов в тайле) на GDScript медленный — разбор на рабочих потоках, замер в OT-8/OT-11;
  шлюз выше.
- Geofabrik: скорость и вежливость (один поток скачивания, честный User-Agent); выгрузки обновляются ежедневно —
  `If-Range` по ETag, md5.
- Совпадение с эталоном: мин. прямоугольник почти квадратных домов (угол ±90°) и порядок объектов меняют байты, но
  не число — допуски по байтам шире.
- Конфликты с no-osm (`WorldObjects`, `VillagePlacer`, `WorldClearings`): no-osm закрыт; клиентские задачи
  разнесены по файлам.

## Границы модели
Проекция тайла — равнопромежуточная по широте центра пояса (ошибка масштаба по x до ±0,27 % на 60°). Дома —
прямоугольники, высота почти всегда оценочная (теги высоты у ~2,5 % домов). Морские объекты вне полигонов
Geofabrik теряются. Данные — снимок OSM на дату прогона; обновление — новый прогон.
