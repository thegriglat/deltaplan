# training-island — Учебный остров (Training Island)

Ветка `feature/training-island` от `main`, копия `~/deltaplan-training-island`, код задач — `TI`. Слияние в `main` — главная сессия.

## Цель пользователя
Место для тренировок (просьба пилота с Reddit): подъём на склоне, поиск термиков, посадка на точность, ротор за хребтом. Одно синтетическое место — остров ~10–15 км в море, рельеф и карта поверхности сгенерированы под тренировки; работает как обычное место (модель воздуха по рельефу, термики от нагрева поверхности, трава/лес/камни, вода моря, небо), без сети и без OSM.

## Решения пользователя (2026-10-16)
- Одно место, несколько стартов (имя ru/en): склон (хребет поперёк ветра, 300–600 м над морем); термики (старт над равниной с полями разного цвета, лесом и водой — термики от модели нагрева, ничего не подсвечивать); посадка (невысокий старт, поляна, круг на посадке); по желанию — чаша/седловина в подветренной стороне (ротор). Треугольник 5–10 км вокруг острова (модуль goals) должен помещаться.
- Можно несколько сгенерированных рельефов (отдельные места), если вид тренировки на одном острове не выходит хорошо — предложить с обоснованием на шлюзе 1. Начинаем с одного острова.
- Погода на острове фиксированная: на каждый старт свой набор (ветер: направление и сила, время, дата, облачность, температура — через неё сила термиков); выбора погоды для этого места нет.
- Поле ветра для каждого набора считается заранее и идёт с игрой (запечённое поле): при загрузке нет «Рассчитываем ветер» (TODO T-04, `docs/research/air_field_cache.md`). Размер в сборке — в отчёт. Если запекание упирается в формат состояния модели воздуха — шлюз до правок модели воздуха.
- Приоритет: механики (подъём на склоне, термики над полями, ротор, посадка, фиксированная погода с запечённым полем); вид — самое простое приемлемое, карта классов без генерации картинок, без визуальной полировки. Генерация на локальной NVIDIA разрешена (замок GPU, лицензии — `ASSETS.md`), но не нужна, если карта классов проще.
- Тренировки как экран и зачёт — модуль goals; здесь — только место. Общие файлы (окно выбора места, меню полёта) — согласование через главную сессию.
- Без замеров цены GPU в ходе работы (один общий замер с `main` перед сдачей), без тестовых сборок. Визуальные мелочи — не больше 2 заходов.

## Шлюз 1 — решения пользователя (Q2, 2026-10-16)
- Отдельный рельеф не нужен: склон, ротор, термики — на одном острове.
- «Тёмная пашня» = класс голого грунта (bare, источник термиков 0,70 против пашни 0,56) — без нового подкласса нагрева (TI-1b).
- Старт «Ротор»: ветер набора — набегающий поток, а не ветер у старта (TI-К2 v2 `wind_ref`, TI-8); формат состояния модели воздуха не менять.
- Термики: p90 +0,25 м/с мало. Фиксированная погода старта «Термики» должна давать набираемые потоки 1,5–3 м/с в ядре (солнечный полдень,
  неустойчивая атмосфера, база 1500–2000 м над морем) — через параметры погоды и нагрева поверхности, без особой магии для острова.
  Проверка: p90/максимум w в ядрах и набор крылом ≥ 300 м (TI-5).

## Исходное (разбор координатора, 2026-10-16)
- Место = `configs/locations/<id>.json` + папка данных формата 4 (`Locations.FORMAT_VERSION`): `meta.json`, слои `detail`/`far` (`<id>.webp`, RGB24, шаг 1/32 м), `<слой>_surface.webp` (L8, классы 0..8), `<слой>_water.webp`, `detail_detail10.webp` (LA8: L — лес, A — вода), `detail_built10.webp`, `built_patches.json`, `surface.json`, `osm_tiles.json`, `build.json` (`docs/guide/location-data.md`). Встроенные места собираются по сети в `user://locations/<id>`; источника высот из файлов игры (`res://`) нет: `DemStage` знает только `copernicus`/`terrarium`. Готовая папка с полным `build.json` в кеше грузится без сети.
- Моря в игре нет: вода — классом 6 и маской воды; рельеф ≤ 0 м — обычная сетка. `Terrain.is_sea()` отказывает в загрузке, если центр места ≤ 0,5 м и вода → центр острова — суша. Процедурный классификатор воду не даёт → карта классов острова — своя (готовый растр).
- Классов 9 (0 нет, 1 лес, 2 луг, 3 пашня/поле, 4 кустарник, 5 голый грунт/скала, 6 вода, 7 застройка, 8 снег). Нагрев — `configs/surface_heat.json → classes` по классу; «тёмная пашня» и «светлая стерня» в модели нагрева — один класс `crop` (цвет полей — только вид). Контраст нагрева даёт сочетание классов (crop, bare, grass, forest, water); нужен ли подкласс — решаем на шлюзе 1 по замеру.
- Погода — `FlightSettings` (`scripts/game/flight_settings.gd`): `temperature_c`, `wind_speed_kmh`, `wind_into_launch`, `wind_from_deg`, `sky`, `start_hour`, `month`, `day`; климата по месту нет.
- Поле ветра: GPU (`AirRuntime`, `scripts/atmosphere/air_model/`), область 38,4 км вокруг центра места + окна 6,4 и 3,2 км у старта; загрузка из файла есть (`WindField.load_file`, `--air-field`, один уровень, float32), писателя нет. Готовое поле = 5 каналов на трёх сетках, float16+zstd ≈ 6 МБ, квантование 0,01–0,02 м/с ≈ 1–1,7 МБ на вариант.
- Генератор fs1 — `tools/research/air_synth/corpus/generator.py` (Fastscape: поднятие из форм `_ridge`/`_blob` + поле Фурье, края 0 м — естественное море), 512² × 100 м; настроенные θ — `docs/research/terrain_tuning.md` §5–6.
- Проверки воздуха: F3 — стрелки ветра по w (`scripts/atmosphere/wind_field_debug.gd`), F5 — ветер у пилота, F6 — столбы термиков; выборки поля — `tools/research/wind_compare/dump_wind.gd`, `tools/research/air_start/wind_audit.gd`.

## Устройство острова (ориентир для TI-1, не догма)
- Центр места — вымышленная точка в открытом море (Чёрное море, ≈ 43,2° с. ш., 34,0° в. д., UTC+3: до берегов > 120 км), `"synthetic": true` — не попадает в выбор точки на карте.
- Остров ~14 × 10 км, центр (0, 0) — суша. Господствующий ветер в наборах — западный (270°).
- Склон: хребет С–Ю на западе острова, 350–550 м, наветренный склон к морю (ровный поток с воды), длина ≥ 3 км; старт наверху, курс на запад.
- Термики: равнина 10–80 м на юге/юго-востоке с полями (crop), пятнами голого грунта (bare), лугом, рощами леса, прудом/озером; старт на невысоком холме или южном конце хребта над равниной.
- Посадка: холм 80–150 м, поляна-посадка 1–1,5 км от старта (`landing_sites`, детали — `configs/world_objects.json → landing.sites`).
- Ротор: чаша/седловина в подветренной (восточной) стороне хребта; старт на восточном борту чаши лицом на запад (в ветер) — сразу в зоне ротора главного хребта.

## Задачи

### Волна 1 (параллельно)

#### TI-1. Рельеф и карта классов острова (dp-researcher, opus)
Генератор `tools/terrain/island/` (Python; среда fs1 — `tools/research/air_synth/corpus/setup_env.sh`): поднятие из форм под устройство выше × маска острова, fs1 с θ из `docs/research/terrain_tuning.md`, море = 0 м; детализация до 25 м; карта классов 25 м и маски 10 м (лес, вода, застройка по желанию) — процедурно, без картинок. Упаковщик пишет папку формата 4 (контракт TI-К1) в `data/locations/training_island/` (detail 40 км × 25 м, far 160 км × 100 м) и `configs/locations/training_island.json` со стартами и посадками; имена в `locale/ui.csv`; тесты, перечисляющие места (`tests/ui/test_menu_setup.gd` — число мест, страна), — под новое место. Проверка без правок движка: копия папки в `user://locations/training_island` своего профиля. Быстрая проверка воздуха на трёх наборах (склон 6 м/с с запада, ротор 9 м/с, термики в полдень): числа w. Кадры сверху и со стартов — `/home/greg/deltaplan/build/screenshots/training-island/TI-1/`.
Приёмка: детерминированная генерация (повтор даёт те же файлы), место грузится, `tests/terrain/test_locations.gd`-правила для стартов и посадок, кадры, таблица w.

#### TI-3. Фиксированная погода старта (dp-engineer, sonnet)
`start_sites[].weather` (контракт TI-К2) → значения `FlightSettings` при выборе старта и перед стартом полёта (меню, повтор полёта, сеть, командная строка); в меню полёта для такого старта погода не выбирается (элементы скрыты или заблокированы, показан набор). Тест на ongudai-подобной копии конфига (фикстура) — без зависимости от острова.

#### TI-4. Запечённое поле ветра (dp-engineer, sonnet)
Формат и ключ — контракт TI-К3. Писатель набора из трёх уровней (`AirFieldSet`) float16 + zstd; инструмент запекания `tools/terrain/bake_air.gd --id <место> --site <старт>` (условия из TI-К2); в игре `AirRuntime` при совпадении ключа берёт поле из `res://data/locations/<id>/air/<site>.*` вместо расчёта (без этапа «Рассчитываем ветер»), выставляет текущее состояние так, чтобы не было немедленного пересчёта поля старта, строит источники термиков, затем обычный фоновый пересчёт для сдвига окон; несовпадение — обычный расчёт и предупреждение в лог. Проверка свежести (`--check`). Отладка — на ongudai с фиксированными условиями. Правка формата состояния модели воздуха (`AirPicardJob`, `WindField`, `AirCase.meta`) — не делать: `blocked` → шлюз.

### Волна 2 (после TI-1)

#### TI-2. Место из файлов игры (dp-engineer, sonnet)
Загрузка встроенного места из `res://data/locations/<id>/` для конфигов с `"bundled": true` (TI-К1): без сборщика и сети, без записи в `res://`; `osm_tiles` для такого места не запрашивается; `"synthetic": true` — исключить из `Locations.builtin_at` и подбора точки на карте; файлы данных попадают в экспорт сырыми (импорт `keep` / `include_filter` в `export_presets.cfg`); каталог стартов `data/places/hg_takeoffs.json` (через `tools/places/add_builtin_places.py`, страна для синтетического места) и тесты мест (`tests/terrain/test_locations.gd`, `test_osm_any_contracts.gd`, `tests/stability/test_matrix.gd`, `tests/game/test_e2e.gd`).

#### TI-1b. Тёмная пашня = голый грунт (dp-engineer, sonnet)
Решение Q2 (1): на равнине у старта «Термики» часть полей (тёмная пашня) — класс 5 (bare) вместо 3 (crop); перегенерировать data/locations/training_island тем же генератором, детерминированно.

#### TI-8. Ветер набора как набегающий поток (dp-engineer, sonnet)
Решение Q2 (2), TI-К2 v2: weather.wind_ref = "inflow" — коэффициент притока 1 без подгонки под ветер у старта (AirRuntime, калибровка притока ~air_runtime.gd:1229); путь от StartWeather до AirRuntime.conditions_of.

#### TI-10. Источник термика поля не на воде (dp-engineer, sonnet)
Найдено TI-5: AirThermals.pick_in_column (scripts/atmosphere/air_model/air_thermals.gd) при всех кандидатах на воде берёт первый — термики поля над озером и у берега моря (0,6–0,9 м/с). Правка: лучшая точка с силой 0 → клетка не источник. Дефект общий для всех мест с водой.
