# Модуль perf — волна исправлений после PF-1

## Повод и цель

Отзыв пилота-тестировщика (2026-10-08): MacBook Pro M3 (Apple Silicon) — ~7 FPS, ноутбук сильно
греется, играть невозможно. Цель — снизить мс кадра GPU и убрать рывки главного потока, не меняя
физику и не ломая картинку; на Mac (у нас его нет) — дешёвые выигрыши, верные для любой машины
(предел пикселей рендера, автовыбор пресета). Основа — замеры PF-1 (`docs/perf/frame_profile.md`).

## Решения пользователя (не обсуждаются)

- 2026-10-08: дальше чинить производительность по отчёту PF-1; исправления — в ветке feature/perf,
  в main — только по команде пользователя.
- Ранее (`configs/game.json → graphics_autodetect.enabled=false`): «решено не оптимизировать под
  слабое железо» — автовыбор пресета выключен. Пересмотр — вопрос шлюза (PF-6).

## Почему 7 FPS на M3 (рассуждение, на Mac не проверено)

- Облака — compute-марш по лучу, цена ∝ числу пикселей буфера (`get_internal_size()` × `lowres_scale`).
- Godot на macOS по умолчанию рисует в физических пикселях Retina (`allow_hidpi` не выключен):
  MacBook Pro 14" во весь экран — 3024×1964 ≈ 5,9 Мпикс, в 3 раза больше 1920×1080 у нас.
- Пресет не выбран (автовыбор выключен) → базовые конфиги: облака medium (буфер 0,5), до 220 облаков,
  трава 100 %, MSAA 2×, масштаб 1,0.
- GPU M3 (10 ядер) по compute/растру грубо в 4–6 раз слабее RTX 4070 SUPER. Облака medium ongudai
  15–24 мс × 3 (пиксели) × 4–6 ≈ 180–430 мс; наблюдаемые ~140 мс — тот же порядок.
- Вывод: на Mac сработают те же меры, что и у нас (облака), плюс предел пикселей 3D (Retina).

## Задачи

Ожидаемый выигрыш — RTX 4070 SUPER, ongudai, по PF-1; на Mac — оценка.

### PF-2. Короткий замер для приёмки (волна 0)
- Тип: dp-engineer (Sonnet). Скоуп: `tools/bench/perf_check.sh`, `tools/bench/perf_check.py`,
  `docs/perf/data/perf_baseline_*.json`; не трогать код игры.
- Что: на основе `tools/bench/frame_profile.sh` — один короткий прогон (≤ 6 мин) на пресет×место:
  пауза на отметках 2 с (кабина) и 60 с (сзади), опыт `base`; полёт без паузы (кадр, 1 %-худших,
  максимум кадра за полёт и после первых 2 с полёта); итог — json по контракту PF-К1.
  `perf_check.py <out> --key <ключ>` печатает одно число (для проверок `num:`).
- Прогон «до» на голове feature/perf: medium и low ongudai → `docs/perf/data/perf_baseline_<пресет>.json`.
- Приёмка: прогон выполняется под `dp lock gpu`, json проходит контрактный тест PF-К1; числа «до»
  в пределах шума PF-1 (medium кабина GPU 25–35 мс).

### PF-3. Mac / Metal: что специфично (волна 0, параллельно PF-2)
- Тип: dp-researcher (Sonnet, веб). Скоуп: `docs/perf/mac_metal.md`.
- Что: Godot 4.7 на macOS — драйвер по умолчанию (Metal или MoltenVK), compute на RenderingDevice
  и локальный RD на Metal (ограничения, известные проблемы производительности, барьеры), HiDPI
  (`allow_hidpi`, `screen_get_scale`, размер окна/вьюпорта в физ. пикселях), что сообщает
  `get_video_adapter_name()/type()` на Apple Silicon, MetalFX/масштабирование в 4.7, тепло/частота
  кадров (VSync, ProMotion 120 Гц). Сравнение GPU M3/M3 Pro/M3 Max с RTX 4070 SUPER (порядок).
- Итог: короткий документ с выводами и рекомендациями для PF-6 (что настроить в project.godot /
  при старте), каждое утверждение — со ссылкой; «не проверено на Mac» явно.
- Приёмка: `dp docs check`; есть разделы «Выводы», «Рекомендации», «Источники».

### PF-4. Облака: дешевле по конфигу и предел пикселей буфера (волна 1)
- Тип: dp-engineer (Sonnet). Скоуп: `configs/atmosphere.json` (clouds, качества),
  `scripts/atmosphere/cloud_compositor_effect.gd` (размер буфера), `scripts/atmosphere/cloud_layer.gd`
  (передача параметров качества), тест контракта PF-К2.
- Что: medium `lowres_scale` 0,5 → 0,33; high 0,75 → 0,5 и `max_iterations` 200 → 128 (PF-1 п. 2);
  новый параметр качества `max_buffer_px` — предел пикселей буфера облаков (контракт PF-К2), чтобы
  на Retina/4K цена облаков не росла с разрешением.
- Ожидание: medium −7…−8 мс GPU в среднем (−34 %), high −27…−40 мс; на Retina — буфер ограничен.
- Приёмка: perf_check medium ongudai, GPU на кабине ≤ 0,8 × «до»; контрактный тест; тесты облаков;
  скриншоты до/после (вид на облака) в `/home/greg/deltaplan/build/screenshots/PF-4/` для пользователя.

### PF-5. Воздух без замираний: AirThermals.build в рабочем потоке, пересчёт мелкими порциями (волна 1)
- Тип: dp-engineer (Sonnet; ревьюер обязателен — потоки и сеть). Скоуп:
  `scripts/atmosphere/thermal_field.gd` (`_update_air`), `scripts/atmosphere/air_model/air_thermals.gd`,
  `scripts/atmosphere/air_model/air_runtime.gd` (`FLIGHT_CHUNK_MS`), тесты.
- Что: сборка источников — в WorkerThreadPool по снимку входов, подмена `air_src` на главном потоке по
  готовности (контракт PF-К4); до готовности работает прежний источник. `FLIGHT_CHUNK_MS` 25 → 5.
- Ожидание: рывки 2,1–3,7 с на старте полёта и в конце пересчёта → нет; кадр при пересчёте в полёте
  +7,3 → ≤ +3–4 мс.
- Приёмка: в полёте medium ongudai нет кадров > 250 мс после первых 2 с полёта (perf_check
  `max_hitch_ms_after2s`); тест: источники поточной сборки = синхронной (маска байт в байт);
  тесты thermal/air/net проходят.

### PF-6. Предел пикселей 3D (HiDPI/Retina/4K) и автовыбор пресета (волна 1, после PF-3)
- Тип: dp-engineer (Sonnet). Скоуп: `scripts/game/graphics_presets.gd`, `configs/game.json`
  (`render_budget_mpx`, `graphics_autodetect`), `scripts/ui/settings_panel.gd` (если нужна подпись),
  тест контракта PF-К3; по выводам PF-3 — строки `project.godot` (только свои).
- Что: масштаб 3D = min(масштаб пресета, √(бюджет / пикселей вьюпорта)), FSR 1, пересчёт при смене
  размера окна; «Масштаб рендера» пилота по-прежнему главнее. Автовыбор пресета — по решению шлюза.
- Ожидание: у нас (1920×1080) — без изменений; Retina 3024×1964 — 3D и облака в ~2,8 раза меньше
  пикселей (весь GPU-кадр примерно ×0,35–0,5).
- Приёмка: контрактный тест (1920×1080 → 1,0; 3024×1964 при 2,1 Мпикс → ≈ 0,6; 3840×2160 → ≈ 0,5);
  тесты пресетов и настроек; при окне 1920×1080 perf_check без изменений (в шуме).

### PF-7. Облака: марш 1 из 4 пикселей за кадр с перепроекцией (волна 2, после PF-4)
- Тип: dp-engineer (**Opus**, GPU/шейдер; ревьюер обязателен). Скоуп: шейдеры облаков
  (`*cloud*_cs`/raymarch, `cloud_temporal_cs`), `cloud_compositor_effect.gd`; размер буфера — по PF-К2.
- Что: каждый кадр марш только в одном пикселе из блока 2×2 (порядок обхода — 4 кадра), остальное —
  из истории с перепроекцией (уже есть temporal); при резком повороте/отсутствии истории — без шлейфа
  (сброс/расширение веса). Не больше 2 попыток по картинке.
- Ожидание: −60…−75 % цены прохода облаков после PF-4 (medium ≈ −4…−5 мс; на M3 — главное).
- Приёмка: perf_check medium ongudai, проход облаков ≤ 0,45 × после PF-4; тесты облаков; скриншоты
  кадра при развороте камеры в `/home/greg/deltaplan/build/screenshots/PF-7/` (смотрит пользователь).

### PF-8. Периодические работы главного потока порциями (волна 2, после PF-5)
- Тип: dp-engineer (Sonnet). Скоуп: `scripts/atmosphere/atmosphere.gd` (`refresh_now`),
  `scripts/atmosphere/cloud_layer.gd` (`_select`), `thermal_field.gd` (без стыка PF-К4).
- Что: `Atmosphere.refresh_now` (24–39 мс) и `CloudLayer._select` (28–43 мс) — разбить по кадрам
  (бюджет ≤ 4 мс на кадр) или в рабочий поток; развести по времени. Результат за полный цикл — тот же
  (детерминизм сети не трогать).
- Ожидание: 1 %-худших кадров 40–50 мс → ≈ средний кадр; low в полёте −1…−2 мс.
- Приёмка: perf_check low ongudai полёт `frame_ms_1pct` ≤ 25 мс (было 43–48); тесты atmosphere/
  thermal/clouds/net.

### PF-9. Трава: LOD кольцами (волна 2)
- Тип: dp-engineer (Sonnet). Скоуп: `GrassField` (скрипт и шейдер травы), `configs/vegetation.json`.
- Что: дальние кольца с реже шагом и меньше сегментов (вместо редения только в шейдере); густота у
  пилота вблизи — та же. Не больше 2 попыток по картинке.
- Ожидание: трава 2,0 → ≤ 1,0 мс (medium), примитивов −50 %.
- Приёмка: perf_check (без облаков или опыт nograss) — цена травы ≤ 0,55 × «до»; тесты травы;
  скриншоты вблизи/вдаль в `/home/greg/deltaplan/build/screenshots/PF-9/`.

### PF-10. Итоговый замер и отчёт (волна 3)
- Тип: dp-researcher (Sonnet). Скоуп: `docs/perf/frame_profile.md` (раздел «После волны
  исправлений»), `docs/perf/data/`.
- Что: полный `frame_profile.sh` low/medium/high ongudai (+ altai medium) на голове feature/perf под
  замком GPU, ни одного другого Godot-прогона параллельно; таблица до/после (мс кадра, GPU, 1 %,
  рывки), оценка для M3 и RX 5600 XT, что не проверено на Mac.
- Приёмка: `dp docs check`; данные в архиве; числа из прогона.

## Риски

- Шум замеров: облака ±0,3…3 мс (medium), до 15 мс (high); параллельные прогоны исполнителей грузят
  GPU/CPU → замеры приёмки только под `dp lock gpu`, пороги с запасом; итог — PF-10 в одиночку.
- Retina/Metal на Linux не воспроизвести (окно не больше экрана 1920×1080): предел пикселей
  проверяется контрактным тестом по размеру, итог на Mac — только отзывом тестировщика.
- PF-7 (облака по четвертям) — шлейфы при резком повороте, на краях гор; 2 попытки, иначе только PF-4.
- PF-5 — потоки: чтение `ground.height`/`WindField` из рабочего потока; детерминизм источников для
  сети (ведущий рассылает маску).
- PF-8 — порядок обновления термиков и облаков; цикл за секунду должен давать тот же итог.

## Условия остановки (шлюзы)

- После плана (сейчас) — одобрение списка и решение об автовыборе пресета.
- PF-7 после 2 попыток со шлейфами — остановка, вариант «только PF-4».
- Любая задача меняет физику полёта/воздуха (числа поля, термиков) — остановка.
