## Решения

- 30.09 — контракты v1 (`docs/easter_eggs_contracts.md`, К1–К7) до первого исполнителя.
  Контрактный тест К7 (`tests/world_objects/test_easter_eggs.gd`) пишет E0 по спецификации
  контракта — каркаса до E0 нет; координатор сверяет тест с К7 при приёмке.
- 30.09 — пользователь: E10 упрощённо — 1–3 доп. бота сразу в воздухе над дальним склоном,
  дальше существующая логика ботов; лагерь не обязателен; нужна новая логика ботов — отменить.
- 30.09 — пользователь: E4 сначала слита с E10 (парапланы в группе), затем **снята совсем**
  (парапланов не будет).
- 30.09 — порядок: E0 → (E1, E2, E5) → (E3, E9) → (E6, E7, E8) → (E10, E11), ≤ 3 исполнителя;
  освободившееся место — следующей по порядку.
- Заметка к E10 (на будущее): боты живут в шаге физики и входят в ключ мира
  (`world_key` → число ботов) и в сравнение К7 — до запуска E10 пересмотреть К7/К4
  (сравнивать ботов без добавленных, ключ мира — без них), версия контракта +1.
- 30.09 — E0 принята. Контракт v2 (по коду E0): `step(ctx)`, обязательный `lifetime_s`, порядок
  бросков, `--gpu-report`. Время GPU шумит ~1 мс между запусками — цена пасхалки теперь
  оценивается по разнице вызовов отрисовки/примитивов (координатор добавил `draws`/`prims` в
  строку `EGG_GPU_MS`, scenes/main.gd) + медиана 3 пар запусков + устройство (без теней вдали,
  без полноэкранных проходов).
- 30.09 — пользователь: появление каждой пасхалки привязано к месту и условиям («не запускать
  кукурузник на Эльбрусе»). В план — таблица «Условия появления»; контракт v3 — К8: поля даты и
  погоды в `EggContext` и общий дешёвый API места `EggPlace` (высота, над дном, крутизна,
  поверхность WorldCover, посёлки/дороги/вода OSM, старты, лагерь, `find_point`). Поставщик —
  новая задача **E0б** до волны 2 (E3, E9). E1, E2, E5 (небо) уже покрыты полями К2 — их не
  останавливаю; их условия сверю с таблицей при приёмке.
- 30.09 — пользователь по виду E2 (через главную сессию): след тонкий (ширина ~ размах), почти
  постоянной ширины, к хвосту только тает альфа, без широкого ореола; траектория горизонтальная
  на постоянной высоте; затем — «толщина и самолёт идеально», след на 20 % короче (длина и жизнь
  ×0,8), после этого принять без новых кадров на согласование.
- 30.09 — E1 принята, но в обычной игре метеор не появится: часы игры 6:00–21:00
  (`configs/world.json → time.min_hour/max_hour`, «ночи нет»), солнце в 21:00 около 0°, а порог
  −12°. Код спит до решения. Шлюз пользователю: (а) оставить спящим до появления ночи в игре;
  (б) разрешить в поздних сумерках только редкие яркие болиды (физически в гражданских сумерках

  (небо, свет, звёзды — не «лёгкий визуал»). Рекомендация — (а) или (б).
- 30.09 — E0б принята. Дописаны недостающие .uid метеора (E1 их не закоммитил).
- 30.09 — E2 принята. Исполнитель поправил `test_lifecycle` (у проверяемой пасхалки

- 30.09 — пользователь: E5 (глория) — принять как есть, правок нет (приму по отчёту
  исполнителя после проверки тестов, без новых кадров).
- 30.09 — E5 принята по решению пользователя (до такой высоты почти никто не долетит — не
  вкладываться). Отклонение от К3: кольцо рисуется экранным слоем, а не 3D-мешем — объёмные
  облака компонуются после прозрачных мешей и стирают их; честный 3D потребовал бы правки
  компоситора облаков (вне модуля). Тот же вопрос встанет у любой пасхалки «на облаке/в облаке».
- 30.09 — **решение пилота** по E3: «Опасное сближение! Так не бывает. На полёты небо
  запрашивают, там самолёты не летают». Ан-2 и шары — ≥ 6 км (конфиг) от всех стартов и от
  пилота на всём пролёте/дрейфе, Ан-2 — не над холмами (малая крутизна по трассе); не выдержать —
  на карте не появляется; запасной форс «рядом с пилотом» убран. Лайнер, метеор, глория — не
  касается; E10 — можно близко. Передано исполнителям E3 и E9 (в работе); таблица в плане
  обновлена.
- 30.09 — пожелание пилота к E11 (орлы): орёл/пара в термике подлетает и летит рядом у
  законцовки (5–15 м), подстраиваясь под крыло, поворачивает голову к пилоту, потом отваливает.
  Кинематика относительно крыла, без столкновений и влияния; при сложностях — упростить до пролёта
  рядом, не отменять без нужды. В план (строка E11) внесено.
- 30.09 — упрощение пользователя к E11 (заменяет «летит рядом, подстраиваясь»): орёл медленно
  обгоняет по диагонали мимо законцовки (5–15 м, +2–4 м/с к скорости крыла), траектория
  относительно крыла задаётся при появлении, без слежения; поворот головы — если дёшево.
- 30.09 — дополнение пользователя к E11: после обгона орёл по дуге уходит в ближайший термик и
  кружит с набором (чтение термиков через поиск из bird_flock.gd); нет термика — уходит вдаль.
- 30.09 — пользователь к E11: поворота головы нет; обгон по диагонали → ближайший термик → кружение.
