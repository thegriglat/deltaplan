## Итог SP-1 (02.10; данные — `tools/research/air_speed/`, таблица `out/breakdown.md`)
- В игре (4070 SUPER, окно 1918×1036 — игра разворачивает окно, 1280×720/320×240 задать не удалось; GPU свободен,
  под замком) пересчёт в полёте — **12–24 с** (типично 13,4–15,9 с), а не 3,7–4,1 с из окна тестов: кадр полёта —
  15–40 мс GPU отрисовки. Решатель области 7,5–9,2 с в 211–265 кадрах при GPU 2,7–3,5 с; простои GPU между порциями
  8–10 с; подготовка 1,0–1,3 с; сборка поля 0,6–1,0 с; окна 100/50 м — ещё ~3–5 с.
- Причины: одна порция на кадр, цена порции по меткам «начало–конец» включает отрисовку кадра → завышена ~×3 →
  бюджет сам урезается (~12 % GPU); шаг Пикара (~42 мс GPU) режется на 3–4 кадра; лишние ожидания окон 1,3–1,6 с.
  Гипотеза «запуски и барьеры» не подтвердилась: зависимый запуск 1,4 мкс GPU, 161 запуск — 0,23 мс из 4,2 мс
  итерации; итерацию ограничивают прогонки.
- **Рывок хуже стены:** после подачи нового поля один кадр **2,0–3,1 с** (`AirThermals.build` 1,05–1,7 с + догоняющие
  шаги физики).
- Локальный RD в рабочем потоке в 4.7.2 **работает, если создан и используется целиком в одном потоке** (между
  потоками — ошибка «only from the render thread»); `WorkerThreadPool` не годится — нужен постоянный поток. Решатель в
  потоке: холодная пара 2,13–2,23 с (блокирующий в главном 2,25 с), поле побитно то же, кадр 13,3 мс.
- Варианты для полёта: (1) термики в рабочий поток — рывок 2–3 с исчезает, 0,5 дня; (2) расписание окон — −1,3…1,6 с,
  0,5 дня; (3) явная доля GPU за кадр + исправленная цена порции — 16 мс: стена 8,3–8,6 с, кадр 44–57 мс против 32–38;
  (4) постоянный поток GPU в полёте — область 4,5–7,1 с, но кадр хуже всех (37–69 мс), 2–3 дня; (5) меньше запусков
  (решатель) — −10…20 % GPU, 2–4 дня; (6) общий RD — 3–5 дней, тот же компромисс. Рекомендация исследователя: 1 + 2
  сразу, 3 — по выбору пользователя, 4 и 6 не делать, 5 — позже отдельной задачей.
- Оценка этапа загрузки одним проходом на RX 5600 XT + Ryzen 5 4500: **≈ 7–11 с** (после SP-3 6–10 с; с вторым
  проходом air-start ≈ 11–19 с) — больше порога «не отвечает» 5 с → шлюз (б). Варианты: кусками `LOAD_BLOCK_MS` 1–2 с
  с кадром между ними, или решатель загрузки в постоянном потоке GPU (окно не замирает, стена та же).
