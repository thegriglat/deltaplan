# bar-mouse — чувствительность штанги мышью (код задач BM)

## 1. Цель
Пилот управляет штангой мышью с ходом порядка 10–20 см стола при 800 DPI, настраивает его своим слайдером
«Чувствительность штанги»; ход не зависит от размера окна и FPS; мёртвая зона без скачка. Найти настоящую причину жалобы
(пилот: cockpit, иногда chase, ПКМ не зажимает; «Чувствительность мыши» 0,5 — неуправляемо, 0,02 — нормально).

## 2. Решения пользователя
Решение 2026-10-23 (`.dpcli/dpcli inbox bar-mouse`), пп. 1–6: свой слайдер и `mouse.bar_sensitivity`; ход в px на полный
ход, без высоты окна; мёртвая зона вычитанием; старый слайдер — «Обзор мышью» (ru/en); без нелинейности; тесты (полный ход
при заданных px, независимость от FPS 30/144, обзор не меняет `control.roll/pitch`). Единицы — рекомендация главной 2026-10-23:
внутри отсчёты мыши, в меню множитель с подсказкой «≈ N см при 800 DPI».

## 3. Задачи
- **BM-1** (dp-engineer) — диагностика: куда идёт мышь в cockpit/chase/free, влияет ли `look_sensitivity_deg_per_px` на
  штангу или камеру без ПКМ, залипание ПКМ (нажали/отпустили в меню, на паузе). Тест с таблицей; поведение не чинит.
  Приёмка: тест `test_mouse_routing` зелёный на текущем поведении или красный с найденным расхождением BM-К2 (в отчёте).
- **BM-2** (dp-researcher) — сырой ввод мыши при захвате в Godot 4.7.2 по платформам (Windows «Повышенная точность»,
  X11, Wayland, macOS): ускорение ОС, `relative` vs `screen_relative`, HiDPI. Записка `docs/research/bar-mouse-raw-input.md`.
- **BM-3** (dp-engineer) — BM-К1: `MouseBar`, ключи, слайдер, locale, тесты, CHANGELOG. После BM-1 и согласования
  с trike-pilot по `input_controller.gd`/`controls.json`/`ui.json`.

## 4. Волны
1: BM-1, BM-2 параллельно. 2: BM-3 (с выводами BM-1; BM-2 — если меняет единицы, контракт v2).

## 5. Условия остановки (шлюз)
Изменение поведения камер (BM-К2); сырой ввод недоступен на платформе и нужен свой обход; правки, пересекающиеся с
trike-pilot.
