# pullin-speed — скорость полного «на себя» в «Маятнике» (код задач VM)

TODO T-86. Ветка `feature/pullin-speed` от `main`, копия `~/deltaplan-pullin-speed`.

Полный «на себя» в «Маятнике» даёт 44,6 / 56,6 / 59,9 км/ч (учебное / мачтовое / безмачтовое,
`docs/research/pendulum_pitch.md`, «После правки рук»), а «Смещение веса» по поляре паспорта —
63–103 км/ч (Vmax спортивных — DHV VG 0, то есть без VG). Причина (VM-1, PB-2) — линейная жёсткость по тангажу: Kn модели 0,14 против ≈ 0,05 нужных паспорту, плюс ход «на себя». Цель модуля (решение 2026-10-19) — правка модели: нелинейная Cm(α) и ход до «штанги у бёдер»; обычная игра летабельна.

## Решения пользователя
- VG — вариант для оценки (решение 11.10 «не делаем» пересматривается по итогу VM-1); упругость кромок не делаем. Петли и пилотаж — не цель;
  цель — честная скорость крыльев для перелётов (2026-10-19).
- Сначала разбор готовых данных в docs и tools/research; новые прогоны — только чего не хватит (2026-10-19).
- Физика прежде «нравится»: если ограничение физическое (ход рук реального пилота) — так и оставить,
  описать в «Границах»; если артефакт модели — чинить модель для всех крыльев, не подгонять числа.
- **VG и пилотаж не делаем; цель — честная Vmax для перелётов; сначала разбор готовых данных, новые прогоны — чего не хватит; проверить и точку подвески** (2026-10-19) — отзыв с Reddit про петлю; T-86
- **Ход рук недавно приведён к реалистичному — считать его данностью (физика), не кандидатом на правку; искать причину в остальном (подвеска, Cm0, CL_α, смысл паспортной Vmax); если всё же упрётся в ход — шлюз с числами** (2026-10-19) — ход рук уже правили под реальный
- **VG — в модуле: оценить, закроет ли он разницу скоростей (по паспортам VG 0 / VG full), или виновата ошибка модели; реализация VG — по решению на Q1. Отменяет «VG не делаем» в решении 19.10** (2026-10-19) — уточнение цели модуля
- **В первую очередь — правка модели: нелинейная жёсткость по тангажу Cm(α) (по PB-2, docs/research/pendulum/vg.md: малый Kn в рабочем диапазоне, сильное восстановление на малых α) и ход «на себя» до «штанга у бёдер» (0,6–0,7 м по руководству T2C) вместо 0,45. Отменяет «ход рук — данность». Условие: обычная игра не ломается — трим, разбег, посадка, управление с клавиатуры/мыши/геймпада остаются летабельными; большой ход/усилие можно обыграть по-игровому (усилие на штанге уже показывается в HUD). VG — потом, отдельно, после правки тангажа** (2026-10-19) — PB-2: разрыв Vmax — тангаж модели и ход, не VG
- **Ход «на себя» по-игровому, как ходьба/бег: обычный полный «на себя» — нынешний ход (штанга у груди), с зажатым Shift (модификатор; на геймпаде — своя кнопка) — до «штанги у бёдер». Самодельная трапеция (control-bar) — ход как есть, пропорционально** (2026-10-19) — не ломать обычную игру; большой разгон — осознанное действие
- **Добор с Shift: ход за нормальным пределом (зона «до бёдер») — индикатор усилия/хода в HUD красным; отпустил Shift — цель рук сразу возвращается в нормальный диапазон (дальше физикой рук, без задержки ввода)** (2026-10-19) — видно, что идёшь за обычный предел; выход простой
- **Самодельная трапеция (control-bar): вариант (б) — полный ход устройства = «штанга у бёдер» пропорционально, без модификатора; красный индикатор — за обычным пределом. Сложно не делать: штанги пока ни у кого нет** (2026-10-19) — ответ на вопрос координатора; KISS
- **VM-3 ограничить: найти литературу по демпфированию тангажа дельтаплана (Cmq/Mq), замерить его на прототипе и попробовать одну обоснованную поправку (по образцу cn_r_add, PD-23). Не хватило одной поправки (причина в руках пилота на перегрузке, нестационарной аэродинамике и т. п.) — шлюз с числами, дальше не копать без решения. Отдельно, в порт в игру: отпустил Shift — цель рук возвращается к обычному пределу плавно (не скачком), как пилот отдаёт штангу от бёдер; это удобство ввода, переворот им не прячем** (2026-10-19) — худший случай — одна задача; плавная отдача естественна
- **Отдельный замер отпускания обычного полного «на себя» без Shift в VM-4 не нужен — убрать из ответа на Q2** (2026-10-19) — без Shift режим остаётся как был
- **Тангаж с клавиатуры удалить из игры (W/S, стрелки вверх/вниз — pitch_push_out/pitch_pull_in, в полёте и на земле): тангаж — мышь, геймпад, самодельная трапеция; Shift — модификатор добора для мыши. Крен с клавиатуры не трогать. Плавный выход в замере VM-К5 — мышью/геймпадом (ручка возвращается с правдоподобной скоростью), не клавиатурой. Освободившиеся клавиши и подсказки — убрать из настроек, раскладки, docs и сайта** (2026-10-19) — клавиатурным тангажом никто не пользуется
- **Уточнение причины удаления тангажа с клавиатуры: это решение само по себе, не ради замера — пилоты: с клавиатуры «бред, нет контроля трапеции»** (2026-10-19) — отзыв пилотов
- **Уточнение к dceacaaa: на земле клавиатура для разбега остаётся как есть (бег, шаг, нос крыла на разбеге); тангаж с клавиатуры удаляется только в полёте. Shift в полёте — добор «до бёдер» для максимального разгона (VM-К3)** (2026-10-19) — уточнение пользователя

## Задачи


### Волна 1 — разбор (готово)
- **VM-1** (dp-researcher) — принято: `(Vmax/Vтрим)² = 1 + k/Kn`, Kn модели 0,14 (0,08–0,24) против нужных паспорту
  0,047; VG, руки, CL_α, сопротивление пилота разрыв не закрывают (`docs/research/pendulum/pullin-speed.md`).
  Совпадает с PB-2 (`docs/research/pendulum/vg.md`).

### Волна 2 — проект тангажа на прототипе (готово)
- **VM-2** (dp-researcher, Opus) — принято по Q1: нелинейная Cm(α) (σ = 0,5 на парк, luff lines) и добор «на себя»;
  медиана Vmax/паспорт VG 0 1,00 (было 0,73), трим ±0,07, Kn ≥ 0,06 (`docs/research/pendulum/pitch-nonlinear.md`).
  Открыто: переворот при отпускании с Vmax 37/48 (у игры — 17/48) → VM-3.

### Волна 3 — переворот при отпускании (Q1)
- **VM-3** (dp-researcher, Opus) — по VM-К4: что делает настоящий аппарат при резком отпускании на скорости, литература по
  Cmq/Mq, замер Cmq прототипа, одна обоснованная поправка (как `cn_r_add`, PD-23) для всех крыльев; не хватило — шлюз
  с числами (решение 2026-10-19);
  модель VM-2 с добором 0,7 м (T2C); `tuck_count` = 0, пороги VM-К2 сохраняются; ключи для порта. Код игры не правит.

### Волна 4 — порт в игру (только после VM-3, Q1)
- Координатор: PD-К2 v8 (ключи VM-2 и VM-3 «Порт в игру»), У1 v4, CB-К1 v3, PH-К1 v2 (VM-К3).
- **VM-4** (dp-engineer, Opus) — порт: `scripts/flight/pendulum/pendulum_model.gd`, `pilot_arms.gd`,
  `configs/pendulum.json`, `tools/flight/pendulum_params.py` и перегенерация `configs/wings/*.json` (если нужно),
  тесты PD-К2 v8; добор «на себя» до бёдер с модификатором (Shift / кнопка геймпада; самодельная трапеция — полным
  ходом), плавный возврат предела после отпускания модификатора и красный индикатор за обычным пределом в HUD — VM-К3; обычный ход без модификатора — как сейчас. Ревью — `dp-reviewer`.
- **VM-5** (dp-writer, Sonnet) — `docs/guide/flight/pendulum.md` («Что даёт ввод», «Границы»: σ на парк, добор 0,7 м),
  CHANGELOG «В работе», строка в `registry/findings.md`, `applied_in` у research.

### Потом
- VG — после правки тангажа, отдельным модулем (PB-2 `vg.py` переносится как есть).

### Приёмка модуля
- Тесты `pendulum`, `pilot_hud`, `control` — 0 упало.
- Vmax полного «на себя» с добором по 48 крыльям (скрипт VM-1 `tools/research/pullin_speed/`) — медиана отношения к
  паспорту VG 0 0,9–1,1; трим ±0,3 км/ч; отпускание с Vmax — без переворота.
- «Обычная игра летабельна»: тестовая сборка Linux у главной — трим, разбег, посадка, клавиатура/мышь/геймпад.

## Границы и остановка

- Пилотаж, петли — вне модуля; VG — после правки тангажа, вне модуля. Режимы `weight_shift`/`rate` (`FlightModel`) не трогать.
- Нелинейная Cm(α) — добавка к моменту крыла по решению 2026-10-19; новая модель полос (взаимная индукция и т. п.) — шлюз.
- Шлюз: VM-2 не выходит на пороги VM-К2 без подгонки по крыльям или без потери устойчивости (Kn ≤ 0, фугоида,
  «клевок» при отпускании) — итог с числами пользователю, не ослаблять пороги.
- Версию не выпускаем.
