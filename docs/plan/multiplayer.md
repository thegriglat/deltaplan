# План: мультиплеер — «зона полёта»

Статус: оценка (28.09.2026), в работу не взято. Цель — летать вместе с живыми пилотами (семья, друзья) в одном небе; для взрослых: без портов, аккаунтов и сложных экранов.

## Что уже есть
- Термики детерминированы: генерация по клеткам сетки, зерно = общий сид × клетка × время (`scripts/atmosphere/thermal_field.gd`); фокус пилота только выбирает, какие клетки считать. Одинаковые место, дата, время, погода и сид → одинаковые термики и облака у всех. Атмосферу по сети не передаём.
- Боты = почти готовые «чужие пилоты»: крыло с расцветкой, пилот, имя над головой (`bot_names`), очередь на старте, взлёт по одному.
- Трафик: ~100 байт на пилота × 10 Гц.

## Решения (предложение)
1. **Лобби** — не нужно. Два экрана: «Создать зону полёта» (место, дата, время, погода — как «Полёт…») → код вида `ОНГУДАЙ-47`; «Присоединиться» — ввод кода (+ список открытых зон). Кто в зоне — на экране загрузки и в паузе.
2. **Соединение** — маленький сервер-посредник на VPS (VPS у пользователя уже есть): все подключаются к нему сами, роутеры и порты не мешают; зона живёт на сервере (часы зоны там же), уход создателя её не закрывает. Альтернативы: прямое подключение к хозяину (порт/UPnP — у части не заработает), Steam (только если игра будет в Steam).
3. **В сетевом полёте**: время только ×1, пауза не останавливает мир, ускорения нет; в зону — только с той же версией игры. Позднее подключение: настройки зоны + текущее время → загрузка рельефа → появление в лагере у старта. Столкновений между пилотами нет.
4. **Очередь на старт** — варианты: (1) свободно, сквозь друг друга; (2) живая очередь как у ботов, простой ~60 с → уступает (рекомендую); (3) несколько стартовых мест на широких стартах; (4) «стекло» — пока не первый, полупрозрачный. Начать с (2), при заминках — (4). После посадки «Ещё раз» → в конец очереди.
5. **Боты** в сетевом полёте — выключены в первой версии (позже — ведёт сервер).

## Добавлено пользователем
- **Своё имя пилота.** Поле «Имя» в настройках (сохраняется в профиле), по умолчанию «Пилот»; уходит в зону при подключении, другие видят его над крылом — тем же выводом, что имена ботов.
- **«Быстро догнать».** Кнопка (в паузе / по клавише) — выбрать пилота из зоны и мгновенно оказаться рядом: в воздухе в ~50 м позади-сбоку на той же высоте, тем же курсом и скоростью; с земли — старт сразу в воздухе рядом с ним. «По-читерски», чтобы быстро собраться и лететь вместе; только в сетевом полёте.

## Вариант пользователя (28.09.2026): «Сетевая игра» по 4-значному коду — основной
1. **Кнопка «Сетевая игра»** в главном меню: выбирается только место; крыло, масса, время и погода — из «Полёт…». Игра выдаёт 4-значный цифровой код (например, 4721).
2. **«Присоединиться»** — ввод кода. Мир (место, дата, время, погода, сид) берётся у зоны. Если ведущий ещё на земле — встаёшь в очередь на старт; если уже летит — автоматически «догнать» (появляешься в воздухе рядом с ним).
3. **Ведущий** — первый пилот; он держит часы зоны и очередь. Вышел — ведущим становится следующий по порядку подключения. Состояние зоны (часы, очередь, параметры мира) есть у всех, поэтому смена ведущего незаметна.

Вывод: экран «Создать зону» не нужен (место + код), UI проще, минимальная версия дешевле (~7–8 дней).

### Транспорт: mesh / DHT против сервера на VPS
| | Сервер-посредник (звезда) | WebRTC-mesh + VPS для сигналинга | Чистый DHT без сервера (libp2p, mainline DHT) | OrbitDB |
|---|---|---|---|---|
| Что это | Все шлют состояние на VPS, он раздаёт остальным | Клиенты соединяются напрямую (ICE: STUN/TURN), VPS только сводит по коду | Код → ключ в распределённой таблице, пиры находят друг друга сами | CRDT-база поверх IPFS |
| Роутеры/CGNAT | Работает всегда | Пробивка NAT ~70–85 %; мобильный интернет и CGNAT (у многих провайдеров) — только через TURN на том же VPS | То же, что mesh, плюс нужны свои bootstrap-узлы и релеи | То же |
| Godot | WebSocket/ENet из коробки | официальное расширение webrtc-native (Linux/Windows) | нет готового; своя GDExtension (Rust libp2p) — большая работа | нет; JS/Go, тяжёлый стек |
| Ведущий с переключением | Логика в клиентах, сервер «тупой» | Естественно для mesh | Естественно | — |
| Задержка | +1 прыжок до VPS (для России — десятки мс, для полёта незаметно) | Минимальная | Минимальная; поиск по DHT — секунды–десятки секунд | Не для 10 Гц: eventual consistency |
| Объём | базовый | +3–4 дня (ICE, TURN, переподключения, тесты разных NAT) | +2–3 недели | не подходит |

Рекомендация: протокол «ведущий + переключение» делать в клиентах (как хочет пользователь), а транспорт на первом этапе — ретранслятор на VPS: он только регистрирует 4-значные коды и пересылает сообщения. Протокол не зависит от транспорта, поэтому позже можно заменить ретранслятор на WebRTC-mesh (VPS останется сигналингом и TURN), ничего не меняя в игре. Чистый DHT и OrbitDB для «стационарного» клиента ничего не дают: пары за CGNAT всё равно требуют релея, а сервер уже есть.

4-значный код: 10 000 вариантов — хватает, если коды выдаёт сервер (уникальны среди активных зон, освобождаются, когда зона пуста). Подбор кода чужим возможен, но ставки низкие; при желании — 5–6 цифр.

## Вариант: Telegram-бот как «лобби»
Телеграм — не транспорт для полёта (задержки и лимиты), положения пилотов всё равно идут через сервер-посредник на VPS. Бот берёт на себя всё «человеческое» вокруг:
- **Приглашения в семейный/клубный чат.** Создал зону в игре → бот пишет в чат: «Мама летит в Онгудае, 13:00, ясно, +26 — присоединиться: код ОНГУДАЙ-47» (и кто уже в воздухе). Или наоборот: в чате `/летим онгудай 13:00` → бот создаёт зону и отвечает кодом.
- **Вход без ввода кода.** Кнопка в сообщении — ссылка `deltaplan://join/ОНГУДАЙ-47`; игра при первом запуске регистрирует свою ссылку (Windows — ветка реестра пользователя, без прав администратора; Linux — .desktop в ~/.local/share/applications). Запасной путь — код вручную.
- **Имена и «друзья» без аккаунтов.** Одноразовая привязка: игра показывает код, его отправляют боту → имя пилота берётся из Телеграма, список открытых зон в игре — только зоны своих чатов.
- **Кто летает сейчас.** `/кто` — кто в воздухе, где, на какой высоте; по желанию — сообщение после посадки (время, путь, лучший термик).
Плюсы: взрослым не надо ничего настраивать — всё в привычном чате; сервер один (бот и посредник на том же VPS). Минусы: токен бота и данные чатов на своём сервере; Телеграм иногда замедляют — тогда остаётся ввод кода вручную (игра от бота не зависит).
Объём: +2–3 дня (бот, привязка, приглашения, ссылка-протокол).

## Риски
- Одинаковость термиков Windows/Linux (дробные вычисления) — проверить тестом первым делом.
- Точки с карты: разный кеш OSM → чуть разные дома/ЛЭП (на полёт почти не влияет).
- Сервер надо держать и следить за ним.
- Разные версии игры — только одинаковые.
