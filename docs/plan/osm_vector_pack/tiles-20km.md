# 9. Слой «дороги + дома + объекты для пилота» тайлами 20×20 км (замер 10.10.2026, Словения и Алматы)
Цель — понять размер слоя, который сделает дороги и дома в игре реалистичнее (сейчас дома процедурные
из WorldCover, дорог нет). Баланс по решению пользователя: город узнаваем сверху, но не уровень 2GIS.
**Все размеры — zstd 19 по потокам отдельно** (формат §1: метрические координаты тайла, сетка 1 м,
ДП 1 м, zigzag-varint дельты). Код и числа — `tools/research/osm_pack/` (`build_tiles20.py`,
`build_pilot20.py`, `almaty.py`, `summarize_tiles20.py`, `report20.py`, `taginfo_counts.py`), результаты —
`results/tiles20_*.json`, `pilot20_slovenia.json`, `report20.json`, `taginfo_counts.json`.

**Сетка.** Одна мировая, без перекрытия, один файл на тайл. Пояс `j = floor(lat/0,18°)` (0,18° = 20,0 км);
в поясе `n = floor(2π·R·cos(lat_c)/20 км)` тайлов по долготе, шаг `360/n` (ширина 20,0–20,5 км; тайл
≈ 400 км²). Координаты — метры от юго-западного угла тайла (равнопромежуточная по широте центра пояса).
Дорога клипуется по тайлу; дом принадлежит тайлу своего центроида. Тайлов на суше планеты: 134 млн км² /
400 км² ≈ **335 тыс. при целиком-суше, реально 0,4–0,5 млн с побережьем (оценка)**. Долготный индекс в
соседнем поясе другой (шаг другой), поэтому клиент берёт 3×3 функцией по координате, а не `i±1`.
Антимеридиан в замере не обрабатывался. Словения — 80 тайлов, 28 из них целиком внутри границы
(Geofabrik `.poly`). Алматы — 5×5 тайлов вокруг 43,24/76,89 из `kazakhstan-latest`; на юге тайлов
Киргизия, её данных в выгрузке нет, поэтому юго-западные тайлы почти пустые.

**Состав.** Дороги: обычные (`motorway…tertiary`, `unclassified`, `residential`, `living_street`, `road`,
`*_link`; класс, мост/тоннель, ширина, полосы; без имён) и **`track` отдельно**; `service`, `path`,
`footway`, `cycleway` и прочее не брали. Дома `building=*` кроме `no`: (1) контур (внешнее кольцо + дыры, ДП
1 м, код типа здания и крыши, высота/этажи), (2) ориентированный минимальный прямоугольник
`[x, z, w, l, угол, высота, тип]` (x, z — 1 м, w, l — 0,5 м, угол — 1°, высота — 0,5 м; дома упорядочены
по Мортону 64 м).

## 9.2 Дороги и track: замещают ли друг друга (гипотеза пользователя)
Словения, 28 тайлов внутри: корреляция байт обычных дорог и track **−0,00**, по длине −0,10 — ни
замещения, ни связи. Разброс суммы меньше, чем у каждого: CV 0,30 против 0,38 (обычные) и 0,47 (track);
максимум суммы 208 КБ против 118 КБ и 142 КБ — **частичная компенсация, не замещение**. По всем 80 тайлам
корреляция +0,63 (граничные тайлы частичные, эффект площади). Алматы, 25 тайлов: **+0,82**, но это смесь
города и пустых гор (там есть либо всё, либо ничего). Вывод: гипотеза подтверждается слабо и только внутри
однородной территории; закладывать надо сумму, а не «max(обычные, track)».

## 9.3 Алматы (5×5 тайлов, 622 109 домов; Казахстан Geofabrik 224 МБ, md5 b9a874c9…, `downloads.log`)
Центральный тайл (240,1038; 128 тыс. домов): обычные дороги 148 КБ, track 20 КБ, прямоугольники 660 КБ,
**тайл целиком (дороги + track + прямоугольники) 829 КБ — максимум**. Окно 3×3 вокруг центра: дороги
600 КБ, track 101 КБ, прямоугольники 2,64 МБ, полигоны 3,87 МБ; **«дороги + прямоугольники» 3,24 МБ, с
track 3,35 МБ, с полигонами и track 4,57 МБ**; окно 5×5: 3,93 / 4,10 / 5,61 МБ. Дома с `height` 0,1 %, с
высотой или этажами 2,5 %; IoU < 0,8 — 11,5 % (71 301), IoU < 0,9 — 22,6 %. Единичные цены близки к
словенским: прямоугольник 5,1 Б/дом, полигон 7,5 Б/дом, часть обычной дороги 14,5 Б (Словения 24), track
26. Время: разбор 265 с, пик 622 МБ. **Манхэттен не мерили** (решение пользователя): он плотнее Алматы
(мелкие прямоугольники, больше зданий на км²), худший тайл будет больше 0,83 МБ.

## 9.4 Объекты для пилота и ландшафт (отдельные подпотоки; `build_pilot20.py`)
Байт на всю Словению / на 5×5 Алматы (в скобках число объектов в Словении): ЛЭП `line|minor_line` 107 КБ
(4 775) / 12 КБ; опоры `tower` 54 КБ (13 303) / 19 КБ; канатки 3,4 КБ (258) / 0,6 КБ; аэродромы + runway
3,4 КБ (155) / 2,3 КБ; мачты, башни, трубы, ветряки с высотой 8,6 КБ (1 281) / 1,1 КБ, из них телебашни
`tower:type=communication` 6,4 КБ (915) / 0,4 КБ (31) — подмножество, в сумму не входит; ж/д 94 КБ (6 704) /
22 КБ; вершины 83 КБ (11 533) / 5,2 КБ; перевалы 4,4 КБ (456) / 2,7 КБ; **имена вершин и перевалов отдельным
потоком 69 КБ / 6,7 КБ** (имя ≈ 6–10 Б на вершину); реки `waterway=river` 123 КБ (1 022 части; с именем

(120 Б): длинные извилистые ломаные.

## 9.5 Пресеты и бюджет 10 ГБ на планету
Единичные цены (Б на объект или часть пути) × мировые числа из taginfo (`results/taginfo_counts.json`,
10.10.2026): домов 709,8 млн (building ways + relations без `no`), главных дорог (`motorway…tertiary`,
`*_link`) 25,2 млн путей, малых (`unclassified`, `residential`, `living_street`, `road`) 91,0 млн, `track`
30,1 млн, ЛЭП 2,8 млн, опор 18,6 млн, рек 2,0 млн, вершин 1,1 млн, ж/д 2,9 млн. Это **оценка**: цена пути
зависит от того, как картографирован район (Словения — длинные пути, Алматы — короче), а мы мерили части
после клипа по тайлам (на несколько процентов больше путей OSM). Вилка — минимум и максимум по двум местам.
| Пресет | Состав | Планета, ГБ (вилка) | Загрузка 9 тайлов, Словения: медиана / макс, МБ | Алматы: медиана / макс, МБ |
|---|---|---|---|---|
| A «узнаваемо» | дороги motorway…tertiary(+link); дома-прямоугольники ≥ 100 м²; вершины, перевалы, имена; реки с именем, каналы; ЛЭП, канатки, аэродромы, мачты, ж/д | **3,1–3,4** | 0,74 / 1,21 | 1,51 / 1,82 |
| B «средне» | A + unclassified/residential/living_street/road; дома ≥ 50 м²; все реки | **5,1–6,4** | 1,39 / 1,94 | 2,27 / 2,74 |
| C «детально» | B + track; все дома-прямоугольники; опоры ЛЭП | **6,5–8,0** | 1,96 / 2,91 | 2,70 / 3,28 |
Порог площади домов выбран по данным: дома < 50 м² — 20 % по числу и 19 % байт, < 100 м² — 40 % / 38 %,
< 200 м² — 80 % / 77 % (в обоих местах похоже). Отсечка 100 м² вместо «все дома» экономит 1,2–1,5 ГБ
(из 3,6–4,0), но пропадают сараи и гаражи; сверху в городе их почти не видно.
**В 10 ГБ укладываются все три пресета**, но C с контурами вместо прямоугольников (+48 % к домам) — это
≈ **8,3–9,9 ГБ**, на грани и без запаса на оверхед файлов (заголовки, индекс). Главная статья всегда дома
(прямоугольники 3,6–4,0 ГБ, полигоны 5,3–6,0 ГБ), затем малые дороги (1,3–2,2 ГБ), track (0,7–0,8 ГБ),
реки 0,1–0,25 ГБ, ЛЭП с опорами 0,2 ГБ, остальные объекты для пилота вместе < 0,15 ГБ. Если надо
уменьшить: порог дома 50 → 100 м² (−0,7…−0,8 ГБ), убрать track (−0,7…−0,8), убрать малые дороги
(−1,3…−2,2). Оценка по цене объекта — скорее верхняя (пустые районы дешевле), а число объектов по taginfo
точное.
Этап 2 (выборка по планете) отменён пользователем: `stage2.py` (выборка стартов, вырез 3×3 из planet
`osmium extract -c`, сводка) написан и проверен на Словении, не развивается.

## 9.6 Воспроизведение
```bash
D=/home/greg/deltaplan_data/osm_pack; P=$D/venv/bin/python; cd tools/research/osm_pack
uv venv $D/venv && uv pip install -p $P osmium shapely numpy zstandard pyproj
curl -sSL -o $D/slovenia-latest.osm.pbf https://download.geofabrik.de/europe/slovenia-latest.osm.pbf
curl -sSL -o $D/slovenia.poly https://download.geofabrik.de/europe/slovenia.poly
osmium tags-filter -O -o $D/slovenia-hb.osm.pbf $D/slovenia-latest.osm.pbf w/highway wr/building
$P -I build_tiles20.py $D/slovenia-hb.osm.pbf results/tiles20_slovenia.json --poly=$D/slovenia.poly   # 8 мин
$P -I build_pilot20.py $D/slovenia-latest.osm.pbf results/pilot20_slovenia.json --poly=$D/slovenia.poly
$P -I summarize_tiles20.py results/tiles20_slovenia.json results/tiles20_slovenia_summary.json
curl -sSL -o $D/kazakhstan-latest.osm.pbf https://download.geofabrik.de/asia/kazakhstan-latest.osm.pbf
$P -I almaty.py $D/kazakhstan-latest.osm.pbf $D/almaty_work results/tiles20_almaty.json
$P -I taginfo_counts.py results/taginfo_counts.json && $P -I report20.py
```
Лицензия данных — ODbL (© участники OpenStreetMap; выгрузки Geofabrik; taginfo — те же данные). Выгрузки не
коммитятся: `slovenia-latest` 299 МБ (md5 8e661b18…), `kazakhstan-latest` 224 МБ (md5
b9a874c9488f96187f218d3ca3fea87b), лежат в `/home/greg/deltaplan_data/osm_pack/`.
