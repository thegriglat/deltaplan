# no-osm — игра без Overpass

Журнал — `docs/plan/no-osm/` (`tools/dp`), контракты — `docs/contracts/no-osm.md` (N1–N4) и К8 в
`docs/contracts/easter-eggs.md`.

## Цель
В произвольной точке Overpass часто не отвечает (429/504), и тогда пропадают пасхалки и объекты.
Игра больше не обращается к Overpass. Посёлки — процедурно из пятен застройки ESA WorldCover (класс
built, 10 м): дома внутри пятна; пасхалки находят место по рельефу, покрову и рекам по рельефу.

## Решения пользователя (не обсуждаются)
- 10.10: пасхалки не зависят от OSM; «пусть появляется как-нибудь»: без OSM место находится из рельефа
  (высота, уклон, долины), покрова WorldCover, рек по рельефу. Частоту не уменьшать («живой мир»).
- 10.10: посёлки процедурно — пятна built WorldCover 10 м → дома внутри пятна (плотность по доле застройки,
  разворот по склону/краю пятна, типовые размеры дом/сарай/баня), без имени. **Один источник пятен** —
  общий для домов и пасхалок (an2, herds, balloon).
- 10.10: полностью отказаться от Overpass: удалить Overpass-клиент и сетевую часть OsmStage (рантайм и
  сборка встроенных мест), зеркала/User-Agent в configs, тесты на него; OSM — не стадия `build.json`.
- 10.10: убрать ЛЭП, здания OSM, заборы у посадок, поля, place-имена OSM.
- 10.10: **пока не трогать** потребителей дорог и озёр (RoadMesher, start_tracks, просеки world_clearings):
  читают `osm.json`, если он есть (встроенные места; позже — возможно, свой
  мировой дамп); нет файла — тихо без него.
- 10.10: проверка воды Аушкуля (WorldCover против OSM) — у отдельного исследователя главной сессии.
- Пасхалки не упоминать на сайте/devlog/страницах версий; в CHANGELOG — функционально, как уже принято.
- **Вода 10 м: SurfaceStage пишет в канал A detail_detail10 долю воды WorldCover 10 м (код 80) и реки по рельефу; OSM больше не пишет канал A и не заливает озёра; water_fraction — только WorldCover + реки по рельефу; потребитель OSM-озёр в воде 10 м удалить; встроенные места пересобрать** (2026-10-10) — исследование lakes-worldcover: вода WorldCover не теряется, озёра OSM для H не нужны

## Решения координатора (можно пересмотреть)
- Застройка 10 м — **отдельный файл** `detail_built10.png` (L8), а не канал в `detail_detail10.png`
  (LA8: L — лес, A — вода; формат маски не трогаем, у неё много читателей).
- Вода 10 м (канал A) = max(доля воды WorldCover по подвыборкам 3×3, реки по рельефу на сетке 10 м);
  OSM в маску не пишет. Основа — исследование `docs/research/lakes_worldcover.md` (ветка lakes-worldcover
  влита в модуль).
- Пятна считаются **при сборке места** (SurfaceStage, в потоке) и пишутся в `built_patches.json`: в игре
  сканировать 4001² пикселей в GDScript — секунды. Формат — JSON, как остальные метаданные папки места
  (`surface.json`, `location.json`); файл маленький.
- Дома — записи того же вида, что здания OSM `[x, z, w, l, угол, высота, крыша]`, и та же отрисовка
  (`BuildingPlacer`, MultiMesh), препятствия (`building_obstacles`) и поляны: меняется только источник.
- Встроенные места пересобираются сборщиком игры только по покрову (новые файлы N1); `osm.json`
  встроенных мест остаётся, из него убираются слои, которые больше никто не читает (здания, ЛЭП,
  посёлки, поля, заборы) — после NO-2/NO-3.
- УАЗ — только по бездорожью (нет опоры на OSM вообще), ровный открытый грунт вдоль долины.
- Посёлок для пасхалок без пятен (нет WorldCover, тайга без деревень) — опорные точки по рельефу
  (низко над дном долины, ровно, открытый грунт, ближе к воде), чтобы пасхалки всё равно появлялись.

## Задачи
Волна 1: NO-1, NO-4 параллельно. Волна 2 (после NO-1 и NO-4): NO-2, NO-3. Волна 3: NO-5, NO-6.

### NO-1. Вода и застройка 10 м, пятна (dp-engineer)
SurfaceStage: канал A `detail_detail10.png` — вода WorldCover 10 м + реки по рельефу (N1), `water_fraction`
по нему; доля built по подвыборкам 3×3 (как доля леса) → `detail_built10.png`; связные пятна
(порог доли, мин. площадь) → `built_patches.json`; запись в `surface.json`. Класс `BuiltPatches`
(чтение, ближайшее пятно, доля в точке). Пересборка покрова 4 встроенных мест (detail10, built10, пятна,
surface.json). Тесты озёр (`lake_iou_aushkul`, `river_axis_is_water`) — по новой воде.
Приёмка: контрактный тест N1/N2 зелёный; у askarovo и altai пятна есть (числа: штук, площадь, сумма
площадей против `class_fraction[7]` detail ±30 %); загрузка в игре ≤ 20 мс; тесты terrain/surface зелёные.

### NO-4. Без Overpass; убрать ЛЭП, заборы, поля, имена OSM (dp-engineer)
Удалить `overpass_client.gd` и `OsmStage` целиком (стадии OSM в сборщике и `build.json` больше нет;
`apply_water`/`water_alpha` — тоже: OSM в маску воды не пишет, воду пишет SurfaceStage в NO-1),
`tools/terrain/raw_overpass_client.gd`, `osm_live`, зеркала/UA в configs, тесты на них. Убрать ЛЭП
(планировщик, слой, модели опор, коридоры в полянах), заборы у посадок (`fence_segment`), поля, имена
посёлков OSM (имя места — из конфига встроенного места или координаты; `recent_places`, превью мира).
Не трогать: дороги, start_tracks, просеки дорог, вода OSM, здания (NO-2), `egg_place.gd` и пасхалки (NO-3),
поле `OsmData.places`/`buildings` (уберут NO-3/NO-2).
Приёмка: `grep -ri overpass scripts configs tests tools/terrain` пусто; произвольная точка собирается
без OSM (тест сборщика офлайн); тесты world_objects/terrain/ui/game зелёные.

### NO-2. Дома в пятнах застройки (dp-engineer, после NO-1, NO-4)
Процедурные дома по N3 из `BuiltPatches`: плотность по доле, разворот по склону/краю, дом/сарай/баня,
детерминированно по ключу места. Вместо зданий OSM (источник — только процедурный); препятствия и
поляны как раньше. Скриншот с воздуха над Аскарово → `/home/greg/deltaplan/build/screenshots/NO-2/`.
Приёмка: тесты world_objects/game зелёные; число домов и время постройки (≤ прежнего с OSM на altai);
1 скриншот (не больше 2 попыток).

### NO-3. Пасхалки без OSM (dp-engineer, после NO-1, NO-4)
К8 v4: `nearest_place` — из `BuiltPatches` (+ опорные точки по рельефу), `near_water_m` — вода покрова,
маска воды и реки по рельефу; УАЗ — бездорожье. an2/herds/balloon/uaz: тест по местам altai, askarovo,
ongudai, aushkul **без OSM** (objects без osm) — место находится в ≥ 80 % сидов (из 10) там, где
условия места позволяют; со встроенным `osm.json` — не хуже прежнего. Убрать `OsmData.places`.

### NO-5. Чистка osm.json и итоговый grep (dp-mechanic/engineer)
Из `data/terrain/*/osm.json` убрать слои без читателей; `OsmData` читает только дороги и воду; grep —
нет overpass в коде/конфигах, нет ссылок на удалённые слои.

### NO-6. Документация (dp-writer)
`docs/guide/location-data.md`, `docs/guide/world-objects.md`, `ASSETS.md` (атрибуция OSM — только там,
где данные OSM остались: дороги/вода встроенных мест, тайлы карты, каталог стартов), CHANGELOG «В работе».

## Риски
- WorldCover built в горах часто ловит дороги/карьеры — мелкие пятна отсекаются мин. площадью.
- Сеть при пересборке встроенных мест (COG WorldCover) — кеш блоков; без сети задача NO-1 блокируется.
- Конфликт с работой по воде Аушкуля (SurfaceStage) — разные файлы; при слиянии — `dp task sync`.

## Границы модели
Дома — типовые коробки с двускатной крышей в пятнах built; улиц, дворов, заборов нет; имени посёлка нет.

### NO-7. Счётчик загрузки данных места «этап: N/M» (dp-engineer, после NO-4)
Решение пользователя 10.10: на экране загрузки — ход скачивания счётчиком «Рельеф: 23/63», «Покров: 40/86»:
M — число запросов стадии (блоки COG/тайлы; известно заранее или после планирования окон), N — сколько готово
(из кеша — засчитываются сразу). Полоса — по тому же счётчику. Тексты — `locale/ui.csv` (ru/en). Сейчас
`LoadProgress`/`loading_screen` показывают этап и грубую долю (dem 0,4/0,7/0,9) — при холодной сборке (~60 с,
~140 запросов) кажется, что игра висит. Без шлифовки. Приёмка: тест на счётчик (N растёт до M, кеш засчитан
сразу); один скриншот экрана загрузки при холодной сборке произвольной точки.
