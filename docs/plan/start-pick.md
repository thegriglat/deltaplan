# start-pick — точный старт на рельефе

## Цель
На топокарте трудно попасть точно в начало старта. В осмотре места (3D, свободная камера над загруженным рельефом) пилот сам ставит точку старта и направление разбега; полёт начинается ровно там. Точка хранится в настройках полёта (последний полёт, избранное) и одинакова у всех в сетевой игре.

## Решения пользователя (не обсуждаются)
- 12.10: в режиме осмотра места пилот сам выставляет точную точку старта (позиция и направление разбега); UI — на усмотрение координатора; пункт меню можно переименовать/перенести; выбор из «Осмотреться» в полёте — по умолчанию нет.

## Решения координатора (UI)
- Пункт главного меню «Осмотр карты» → **«Выбрать старт на рельефе»** (en «Pick launch on terrain»), остаётся в главном меню. Почему: осмотр — это загрузка мира, как «Лететь», а не поле формы; из «Настроек полёта» пришлось бы уходить в 3D и возвращаться в форму с несохранённым состоянием (больше кода и переходов). Подпись под «Лететь» уже показывает текущее место — видно, что откроется. Слово «старт» точнее «места»: место выбирается на топокарте, здесь — точка разбега.
- В осмотре: ЛКМ по земле — поставить старт; ЛКМ с протяжкой — направление разбега к курсору; панель внизу: координаты, высота, уклон, курс с кнопками ±5°, «По склону», «Сбросить старт», «Лететь отсюда». Маркер-стрелка на земле. Недопустимая точка — маркер красный и короткая причина («вода», «слишком круто», «за краем места», «застройка»), без объяснений про опасность.
- Направление по умолчанию — вниз по склону (как сейчас для точки с карты); при «ветер в старт» ветер дует в выбранный курс; поворот к ветру `_align_start_heading` курс, выбранный пилотом, не трогает.
- В «Осмотреться» из паузы полёта точку **не** выбираем: мир там стоит посреди полёта, новый старт = новый полёт (то же, что «В меню» → «Выбрать старт на рельефе», место уже загружено — без перезагрузки); в сети старт общий и задаётся хозяином зоны. KISS.
- В «Настройках полёта» (вкладка «Место») — строка «Старт уточнён на рельефе» с кнопкой «Сбросить», если точка задана; любой другой выбор места (карта, популярные, недавние) точку сбрасывает. settings_panel.gd и graphics_presets.gd не трогаем.
- Недавние места точку не хранят (это места); избранное хранит всё FlightSettings — и точку тоже.

## Границы
- Допустимость точки — только то, чего нельзя физически: вода, застройка, круче `start_pick.max_slope_deg` (40°), за краем детального рельефа. Пологий склон, лес (вырубается поляной, как сейчас), кусты — можно: последствия — в полёте.
- Каталог «Популярные места» (`orientation`) для курса не используем.

## Задачи
### SP-1 — данные точного старта и запуск полёта из неё
dp-engineer (sonnet). Контракты SP-К1, SP-К2. Скоуп: `scripts/game/flight_settings.gd`, новый `scripts/game/start_spot.gd`, `scripts/game/game.gd` (`_choose_start`, `_align_start_heading`), `scripts/ui/place_pick_row.gd` (сброс при выборе места), `configs/game.json` (`start_pick`), тесты. Приёмка: контрактный тест SP-К1/К2, тесты старта/настроек/избранного зелёные; точка вне места/в воде → прежний автостарт.

### SP-2 — UI осмотра: маркер, панель, «Лететь отсюда», меню
dp-engineer (sonnet). Зависит от SP-1. Контракт SP-К1, SP-К2 (потребитель). Скоуп: `scripts/game/game.gd` (inspect), `scenes/main.gd`, `scripts/ui/start_menu.gd`, новый виджет панели/маркера, `scripts/ui/flight_setup_screen.gd`/`place_pick_row.gd` (строка «Старт уточнён»), `locale/ui.csv`. Приёмка: headless-тест сценария осмотр → поставить → курс → «Лететь отсюда» стартует в точке без перезагрузки места; тексты ru/en; визуал — тестовая сборка Linux.

### SP-3 — точный старт в сети
dp-engineer (sonnet). Зависит от SP-1. Контракт SP-К3. Скоуп: `server/proto/deltaplan/v1/net.proto`, `scripts/net/net_messages.gd`, `scripts/net/net_zone.gd`, `scripts/game/world_key.gd`, `scripts/game/net_flight.gd`, `docs/guide/net-protocol.md`, тесты net. Приёмка: клиент получает ту же точку и курс; WorldKey v2 круговой; тесты сообщений по документу.

### SP-4 — камни и кусты не на разбеге у любого старта
dp-engineer (sonnet). Независима. Контракт SP-К4. Скоуп: `scripts/terrain/shrub_scatter.gd`, `scripts/terrain/rock_scatter.gd`, их конфиги, тесты. Приёмка: у встроенного старта, точки с карты и добавленной поляны нет камней/кустов в радиусе разбега.

## Волны
1. SP-1 и SP-4 параллельно. 2. SP-2 и SP-3 параллельно (от ветки модуля после SP-1).

## Риски
- Повторные `add_start_clearing` при переносе точки в пределах загруженного места копятся — допустимо (поляны только лесные).
- `main._fly` из осмотра должен переиспользовать загруженное место; если нет — SP-2 чинит в своём скоупе.
