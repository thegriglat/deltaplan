# Сетевой полёт в игре

Часть описания сборки игры (вход — [game.md](../game.md)). Формат сообщений и сценарии протокола — `docs/guide/net-protocol.md`; Steam как транспорт — `docs/guide/steam.md`. Здесь — как это встроено в игру. Код зоны пилоты передают друг другу сами; ни чата, ни голосовой связи в игре нет (`docs/archive/plan/multiplayer.md`).

## Компоненты

| Где | Что |
|---|---|
| `scripts/net/net_client.gd` (автозагрузка `NetClient`) | одно соединение с сервером: адрес, `Hello`/`Welcome`, ping раз в 2 с (RTT, смещение часов сервера), повторы при обрыве (паузы 1, 2, 4 с); транспорт — пир (`ws_peer.gd` WebSocket, `loopback_peer.gd` в памяти для тестов, `steam_peer.gd`); адрес `steam:<id>` — через реестр схем |
| `scripts/net/net_zone.gd` (`NetZone`) | зона поверх клиента: создать/войти/выйти, пилоты зоны, ведущий, часы и очередь, ключ мира, источники термиков; `host_local()` — зона на встроенном сервере |
| `scripts/net/net_pilots.gd` (`NetPilots`) | отправка своего состояния и состояний ботов 10 Гц, приём чужих, буферы интерполяции (`RemotePilotState`), округление и неполные пакеты |
| `scripts/net/local_server.gd` (`LocalServer`) | встроенный сервер на GDScript: тот же контракт, что у Go-сервера (`server/`), порт 8080, свой поток |
| `scripts/net/lan_discovery.gd` (`LanDiscovery`) | объявление зоны и список «Рядом» (UDP-broadcast, порт 8081) |
| `scripts/net/net_messages.gd` (`NetMessages`) | кодек `Envelope` (proto3 JSON) |
| `scripts/steam/steam_lobby.gd`, `steam_transport.gd` | лобби «только друзья» и транспорт Steam Networking Messages |
| `scripts/ui/net_screen.gd` + `net_ui_*_backend.gd` | экран «Сетевая игра»; с сетью говорит только через backend |
| `scripts/game/net_flight.gd` (`NetFlight`) | связка `Game` ↔ `NetZone`/`NetPilots`; создаётся по «Лететь» в зоне, `Game.enable_net()` вешает её в мир; вне зоны `Game.net == null` |
| `scripts/game/remote_pilots.gd` (`RemotePilots`) | чужие пилоты и боты ведущего: тот же вид, что у ботов (`BotGlider`), физики нет |
| `scripts/game/net_queue.gd`, `net_bots.gd` | очередь на старт, боты ведущего |
| `scripts/game/catch_up_tow.gd`, `scripts/ui/catch_up_menu.gd` | «Догнать» |

Ping, повторы и таймауты — поля `NetClient` (`ping_interval_s`, `reconnect_delays_s`, `connect_timeout_s`); «Догнать» — `configs/net.json → catch_up`.

## Экран «Сетевая игра»

`NetScreen` (`menu_net_game`): адрес сервера (запоминается; **пусто — играть по домашней сети**), имя пилота (из настроек), «Создать» — зона на выбранном месте (крыло, масса, время, погода — из последнего «Полёт…»), «Присоединиться» — по коду зоны (4 цифры). Три вида: ввод, «Подключение…», зона (код крупно, кто в зоне, «Лететь»); ошибки — простым текстом по виду (`unreachable`, `zone_not_found`, `version_mismatch`, `zone_full`, `disconnected`, `bad_message`, `port_busy`, `server_failed`).

- «Создать» без адреса (NET-22): `NetZone.host_local()` поднимает `LocalServer` на этом компьютере (порт 8080, слушает все адреса), подключает свой клиент к `127.0.0.1` и создаёт зону. Остальные входят по адресу компьютера в локальной сети (`192.168.1.5:8080`) и коду. Выход создателя останавливает сервер — у остальных обрыв (3 повтора и «Связь пропала»); смены ведущего со встроенным сервером нет.
- Список «Рядом» (`LanDiscovery`): зоны компьютеров этой же сети (одна подсеть; зона пропадает через 3 с без объявлений); зона другой версии игры помечена «другая версия».
- Steam: «Друзья в игре» (раз в 5 с) и «Пригласить друзей» — `docs/guide/steam.md`.
- Версия игры должна совпадать (`Hello.gameVersion`); иначе «У вас другая версия игры».

## Мир зоны и ведущий

- Мир строится из ключа зоны (`worldKey` → `FlightSettings`; крыло и масса — свои). После постройки `NetFlight.join_world()` ждёт часы зоны, ставит время мира (`Game.set_world_time(zone_time())`) и сверяет хэш ключа (`NetZone.check_world`): не совпал — предупреждение в журнал, летим дальше.
- Время суток — только ×1 (скорость часов из настроек игнорируется, в настройках скрыта). Мир идёт по часам зоны: воздух шагает до `zone_time()` (атмосфера — функция времени), долгие кадры мир не тормозят; отстал больше `DRIFT_SNAP_S` (30 с) — время ставится заново.
- Пауза и окно итога дерево не останавливают: свой пилот летит «без рук», чужие — дальше. «Ещё раз»/«На старт» мир не сбрасывают, часы и день не трогаются.
- Каждый кадр (`NetFlight._process`): своё состояние уходит в `NetPilots.set_local_state` (фаза — имя `PilotPhase`, крыло, расцветка паруса по имени пилота, режим управления и положение пилота для маятника), чужие — в `RemotePilots` (`upsert` при появлении/смене вида, `set_pose` каждый кадр, `remove` при потере: 5 с без пакетов).
- Ведущий (живой пилот с наименьшим порядком подключения) ведёт часы и очередь, считает ботов и раз в секунду отдаёт `NetZone` источники термиков из своего поля (`sync_thermal_sources`); остальные ставят их своей атмосфере (`ThermalField.set_air_forced`): сила, потолок и снос — по своему полю.

## Очередь на старт

`NetQueue` (NET-43): места ожидания позади старта (место 0 — сам старт, дальше — места `BotPilots.find_spots`, одинаковые у всех клиентов), сначала живые пилоты, после них боты. Бежать может только первый; взлетел — следующий шагает вперёд; первый простоял `IDLE_S` (60 с) — в самый конец (за ботами); после посадки, аварии, срыва, «На старт» (и R, и «Догнать» пилота на земле) — в конец живых (перед ботами). Очередь ведёт ведущий по фазам `PilotState`: у старта (< `NEAR_LAUNCH_M` 250 м) стоит/идёт — в очереди, бежит — в очереди и его не трогают, в воздухе, на буксире, сел, разбился или ушёл далеко — из очереди; порядок рассылает `ZoneState.queue` (1 Гц и сразу при изменении). Каждый клиент сам встаёт на своё место: ходьба `Game.queue_walk_to`, пока не первый — разбег заблокирован (`InputController.run_blocked`, автопилот ждёт). `Game.restart` в сети ставит на своё место в очереди. Тест — `tests/game/test_net_queue.gd`.

## Боты ведущего

`NetBots` (NET-44): только ведущий считает ботов — тот же `BotPilots`, но «наблюдает» всех живых пилотов зоны; состояния ботов уходят `NetPilots.send_bot_state` (`isBot`) 10 Гц. Число — `Zone.botsCount` (настройки создателя), имена — из пула языка первого ведущего и дальше не меняются. У остальных боты приходят как чужие пилоты (рисует `RemotePilots`). Ведущий своих ботов из сети не рисует (рисует свой `BotPilots`). Смена ведущего: новый продолжает ботов с последних полученных состояний (положение, скорость, курс, крен, фаза, имя, расцветка; id те же), недостающих добавляет на местах ожидания; прежний ведущий считает ботов у себя без отправки до `HANDOVER_S` (2 с) и убирает. Боты стоят и бегут по очереди зоны (`BotPilots.spot_index_fn`/`spot_fn`). Описание ботов — `bots.md`.

## «Догнать»

Меню `=` (`CatchUpMenu`, геймпад — кнопка 3): список пилотов зоны (`NetFlight.catch_up_list()`; у ведущего — свои боты), ↑/↓ — выбор, Enter — догнать, Esc — закрыть. `CatchUpTow` — кинематический перелёт без физики полёта: пилот идёт к точке прибытия `arrive_offset_m` (60 м) позади-сбоку цели под углом `arrive_side_deg` (45°); разгон и торможение по `ramp_s` (2,5 с), время перелёта `t_target_s` (10 с), потолок скорости `v_max_kmh` (1000 км/ч, предел подгрузки мира), запас над рельефом `clearance_m` (50 м) со сглаженной «горкой». У точки прибытия скорость и курс сводятся к цели за `match_s` (2,5 с), затем управление и физика возвращаются пилоту. Пока буксир, фаза `TOW`, камера «сзади» вплотную (`tight`); Esc или `=` — отмена на месте; `Game.catch_up_started`/`catch_up_ended(state)` (`done`, `aborted`, `lost`). Вход в зону: если ведущий в воздухе — автоматический буксир к нему от старта (ждём его состояния до `AUTO_CATCH_UP_WAIT_S` после входа); на земле — ничего (стоим в очереди). Тесты — `tests/game/test_catch_up_tow.gd`, `test_catch_up_game.gd`.
