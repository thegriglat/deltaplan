# Погода из прогноза (FR-16)

Пилот задаёт прогноз: температуру днём `T` (дневной максимум у земли в долине), ветер на старте, откуда
ветер, облачность. `WeatherModel` (`scripts/atmosphere/weather_model.gd`, чистые функции; параметры —
`configs/weather_model.json`; план и ответы пилота — docs/archive/plan/weather-by-temperature.md) собирает из него
словарь с теми же ключами, что эталоны `configs/weather/*`:
- **Место** (`ground_context`): долина `h_v` — нижние 10 % рельефа в радиусе отсчёта кромки, средняя `h_m`;
  дата, широта, пояс. Алтай: 304 / 509 м.
- **Верх термиков и кромка**: воздух наверху — климат места (`ClimateGrid`, сетка HH2: температура и высота уровня
  700 гПа по месту и месяцу); пузырь — сухая адиабата от `T + 1 К`:
  `z_dry = h_v + (T + δ − T_u − Γ(z_u − h_v)) / (9,8 − Γ)`, где `T_u`, `z_u` — из сетки, `Γ` — `upper_air.lapse_k_per_km`
  (4 К/км, в сетку не входит); кромка `z_lcl = h_v + 0,122 (T − Td)`, `Td` — точка росы дня (раздел ниже). Верх подъёма
  `min(z_dry, z_lcl)`; запас `m = z_dry − z_lcl < −100 м` — голубой день (облаков нет). Кромка Cb — та же (разница T − Td
  и инверсия). Сетка 700 гПа — настоящая климатология ERA5 2011–2020
  (T −49,6…19,3 °C, Z 2452…3234 м); по Алтаю она в среднем на 1,2 °C холоднее прежней таблицы, `z_dry` ниже на ≈ 200 м
  (`tools/research/haze_humidity/upper_air/README.md`).
- **Сила, радиус, шаг, доля, фон, σ** — по верху над средней землёй из таблицы опор (строки = бывшие
  weak/medium/strong); × солнце сезона, × ветер рвёт термики; облака, переразвитие, Cb — по запасу `m`.
- **Облачность** (`sky`) учитывается в прогреве один раз (FBW-К2): аналитика — доля прогрева `sky.heat`
  (сила × heat^⅓, доля рождений × `duty_k`), поле — покрытие `cover` в K↓ (`SurfaceHeat`). Пелена неба
  (`sky_cover`) больше не гасит солнце источникам второй раз: `cirrus.sun_block` действует только на пелену
  сверх неба прогноза (`WeatherModel.sun_block_cover`); доля рождений поля — без `duty_k` (`sky_duty_k`).
  Мягкость, без гроз под облачностью — как было.
- **Ход дня** (`derive(…, час)`, `diurnal`): `T(t)` по Parton–Logan от максимума; утренняя инверсия держит
  термики низко, пока прогрев её не пробьёт (кромка растёт всё утро); сила × (поток/пик)^⅓, доля × поток —
  вечером термиков мало, они шире и мягче (край, σ); к закату спокойнее приземный слой. Дымка густеет не по часу, а через
  относительную влажность часа (раздел «Дымка по влажности»): `Td` дня постоянна, `T` к вечеру падает, RH растёт.
  `Game` пересчитывает день раз в `diurnal.update_s` и зовёт `set_weather(w, blend_s)`. Инерция прогрева по
  классам поверхности — `SurfaceHeating` → `Terrain.set_class_sun`.
- **После заката** (FBW-К2, `docs/contracts/feedback-1013.md`): ψ ≤ 0 → прогрев погоды 0 (запаздывание
  луга не тянет его за закат) → доля рождений и сила 0: новых термиков нет ни в аналитике, ни в поле;
  живые дожимают свой цикл. Классы поверхности без солнца (запаздывание сдвигает только дневной ход),
  суша H < 0 (выхолаживание L*). Исключения: вода — `water_flux` (тёплое озеро осенью вечером даёт H > 0);
  застройка — ночной спад `H = предел + (H_закат − предел)⁺·exp(−t/τ)`, `classes.built.night_floor_wm2`
  25 Вт/м², `night_tau_h` 1,5 ч (`SurfaceHeat.built_night_flux`, `SurfaceHeating.built_night`). Поток
  воды и города даёт среднюю конвекцию поля (w_conv), но не пузыри. Сценарий пилота (15.10 20:00,
  облачно, 7 м/с) — `tools/research/fb1013_evening/run.sh`.
- **Волна** — скрыта, `wave.enabled: false`.

Таблица «прогноз → день» по локациям и месяцам: `tools/weather/derive_table.tscn`; как часто
грозы у старта — `tools/weather/storm_rarity.tscn`. Тесты —
`test_weather_model`, `test_weather_day`, `test_storm_rarity`, `test_surface_heating`, `tests/game/test_forecast_game.gd`.

## Точка росы и воздух наверху по месту (haze-humidity)

Раньше точка росы и воздух на 700 гПа были одной таблицей под Алтай и Башкирию (50–56° с. ш.). Теперь это климат
места из ERA5 (`ClimateGrid`, `scripts/atmosphere/climate_grid.gd`; форматы и ключи — `docs/contracts/haze-humidity.md`,
HH1/HH2/HH7). `derive` зовёт `ClimateGrid.place({lat, lon, month, day, valley_msl_m})`.

**Чтение сетки.** Сетки 1° × 12 месяцев (`data/climate/*.bin`, int16, brotli) читаются один раз. Значение места —
билинейно по четырём ячейкам; месяц относится к 15-му числу, между серединами месяцев — линейно по дню. Нет файла или
битый заголовок — лог один раз и запасные значения из `configs/weather_model.json` (`climate.fallback`, `upper_air`,
`typical_max_c`, `diurnal.range_k`, `tropopause_msl_m`, `cirrus_base`, `wind.altitude_gain_per_km`) — все под Алтай.

**Td климата.** Сетка HH1 — среднее за месяц Td на 2 м (ERA5 1991–2020, срока 00 и 12 UTC) на средней высоте ячейки `Z`.
Для долины места: `Td = Td_ячейки + G·(h_долины − Z)/1000`, `G` — К/км по поясу (`climate.td_gradient_k_per_km`):
30–60° — −4,5/−3,9/−3,3/−4,2 (ДЯФ/МАМ/ИИА/СОН, сезон физический — на юге сдвиг на полгода), |φ| ≤ 20° — −4,6,
прочее — −4,0. Градиент — регрессия по подячейкам ERA5 0,25° внутри 1° (модель, не измерения); в перемешанном слое
теория даёт −1,6…−1,8, наблюдаемое в данных круче — влага убывает с высотой над источником.

**Td дня** (`WeatherModel.td_day`): `Td = Td_климат + μ·σ + β·(T_max − Tx) + r·ρ·σ`, затем `Td ≤ T` часа.
- `σ` — σ среднесуточной Td вокруг среднего месяца (сетка HH1, 0,3…12,6 К; без сетки — 4,6 К, среднее по суше).
- `μ` (в σ), `β` (К/К), `ρ` (отношение σ остатка к σ климата) — таблицы `td_day` в конфиге по поясу |φ| (0–20, 20–40,
  40–60, 60–75), физическому сезону и облачности дня прогноза (ясно / переменно / пасмурно) из ERA5 2011–2013. В
  таблице `μ` — сдвиг класса при климатической Tmax (без части, которую берёт `β`); pooled по суше: ясно −0,46 σ,
  переменно −0,13, пасмурно +0,64 (вместе с жарой дня — −0,28/+0,01/+0,13); β = 0,6 К/К, но от −0,3 (тропики летом) до 1,0 (60–75°
  зимой) — потому таблицы, а не одно число.
- `r` — N(0, 1), обрезано по ±3 σ, детерминированно от (месяц, день, место): в один день в одном месте одно и то же.
  `ρ` в 60–75° всего 0,3–0,5: там Td привязана к воздушной массе.

**Чего модель не умеет (границы).**
- Td сетки — среднее 00 и 12 UTC, а не истинное суточное среднее; σ — по ячейке 1°, сглажена против точки.
- Таблицы `μ, β, ρ` — три года (2011–2013): отдельные клетки пояс × сезон надёжны до ≈ ±0,1 σ. Облачность дня там —
  среднее `tcc` за местные 10–16 ч; 16 % дней при определении по суткам сменили бы класс.
- σ T700 (разброс воздуха наверху) посчитана в исследовании (`upper_air/t700_sd.npz`), игра её не читает: разброс воздуха наверху не моделируется.
- Высота: поправка G — по долине места (10-й перцентиль рельефа в радиусе отсчёта кромки), одна на день; суточного хода Td нет.
- Сверка (`tools/research/haze_humidity/verify/README.md`): по прогнозам Open-Meteo 22.10–06.11.2026 (38 мест, 16 дней)
  доля дней с |прогноз − климат| < σ — 67 % (ДИ95 59–75), сдвиг +0,7 К; июль 2025 — 56 %, сдвиг −0,1 К; по станциям вне ERA5
  Td ±0,2 К. Две иранские станции: сетка влажнее на 2,4–2,5 К (принято, причина не установлена). Сдвиг +0,7 К не отличим
  от разброса моделей прогноза (≈ 1 К).

## Климат места для остального (HH5, HH6)

Остальное, что раньше было одной таблицей под Алтай, берётся из сеток ERA5 1° × 12 месяцев тем же `ClimateGrid.place`
(контракт HH7); поправки на высоту долины — `climate.*_gradient_k_per_km` в `configs/weather_model.json`. Нет файла сетки —
прежняя таблица (`src.hh5/hh6 = none`).

| Что | Откуда | Где в игре |
|---|---|---|
| `Tx` — климатический максимум дня, `DTR` — суточная амплитуда | HH5 `surface_t_1deg.bin` (ERA5 2011–2020, 1,6 МБ; TX −61,1…47,8 °C, DTR 0,45…20,4 К) | умолчание дневного максимума и подсказка «обычно днём» для выбранного места; ход дня (`diurnal`, амплитуда); член `β·(T_max − Tx)` в Td дня |
| Тропопауза `trop_m` | HH6 `upper_misc_1deg.bin`, по среднему за месяц профилю T, критерий ВМО | потолок гроз: `cb_top_above_base_m = max(trop_m − z_lcl, 1000)` |
| Перистые `hcc` | HH6, высокая облачность ERA5 | `cirrus_base_cover = hcc × k_sky[облачность дня][пояс][сезон]` (`hcc_sky`, `upper_misc/hcc_sky.json`: ясно 0,12–0,35, переменно 0,48–0,93, пасмурно 1,2–2,4) |
| Рост ветра с высотой `gain_per_km` | HH6 `wr` = отношение ветра 700 гПа к ветру у земли | `(wr − 1)·1000 / (z700 − z_ячейки)`, К/км над долиной |

Поправка на высоту долины: Tx −5,5…−7,8 К/км (30–60° с. ш. по сезону: ДЯФ −5,71, МАМ −7,80, ИИА −7,40, СОН −6,59; тропики −5,5),
амплитуда ≈ −1 К/км в поясе 30–60°; для 30–60° ю. ш. данных нет — значения северного пояса, сезон сдвинут на полгода (допущение).
Региональные градиенты (Квинсленд −9,4, Загрос −7,4, Алтай, Урал) в игру не введены — зональные. Нет высоты долины
(`valley_msl_m`) — значения на средней высоте ячейки; так подсказка «обычно днём» и умолчание температуры в меню считаются на
средней высоте ячейки, а не старта.

**Границы и статус данных.**
- Рост ветра с высотой (WR) — заглушка до HH-1h: `max(0,3; 1 + 0,6·(3000 − Z_ячейки)/1000)`, `stub_mask = 1`; тропопауза и перистые — настоящие.
- Тропопауза: ±300–500 м (14 уровней, среднее профиля); Крым июль–август 15,3/14,9 км — артефакт среднего профиля у струйного течения (реально ≈ 12–13 км).
- `hcc` включает наковальни Cb и синоптическую перистость; `k_sky` — три года и выборка ≈ 24 суток в год, класс по `tcc`, который включает `hcc`, поэтому контраст классов завышен.
- Tx и DTR: ERA5 1° консервативно пересчитан на побережье — суша и вода смешаны (RMSE к суточной CDS 0,4–0,5 К); недобор суточных экстремумов поправлен по ARCO 2018–2019 по UTC-суткам, не местным.
- Опорные дни `configs/weather/*` пересчитаны под ERA5: слабый +21 °C (был +20), средний +26 °C (+24), сильный +33 и гроза +34 без изменений — те же по силе дни наступают на 1–1,5 °C теплее. Сильный день на новом воздухе даёт `cb_chance` 0,35 при эталоне 0 (температуры с `extreme` 2–6 % без Cb нет) — расхождение отмечено (отчёт HH-4d), эталон не менялся.

## Дымка по влажности

Густота мутного слоя `haze_k` — множитель к `configs/world.json → haze.visibility_km` (60 км — сухой воздух).
Контракт HH3, `WeatherModel.haze_k_rh(T, Td)`:
- `RH = e_s(Td)/e_s(T)`, `e_s(x) = 6,1094·exp(17,625·x/(x + 243,04))` (Магнус, Alduchov–Eskridge 1996);
- `RH_c = clamp(RH, 0,40; 0,95)`, `haze_k = ((1 − RH_c)/(1 − 0,40))^−0,6` (`configs/weather_model.json → haze_humidity`).
Значения: RH ≤ 40 % → 1,0; 85 % → 2,30; ≥ 95 % → 4,44. `T` — температура этого часа, `Td` — точка росы дня, так что утром и
вечером во влажном месте дымка гуще, днём сухо; результат — `w.haze_k`, `_derived.rh`. Вечерняя добавка ×1,6 и множитель
пасмурного дня ×1,3 убраны: из RH при `Td = const` первая не следует, вторая — не влажность (пасмурность теперь двигает Td
через `μ`).

Основание — Zieger и др. 2013 (ACP 13, 10609), рост рассеяния на 85 % RH для континентальной Европы ≈ 2,25–2,38; γ = 0,6
выведено из этих чисел (0,45–0,74 по станциям). Границы: один γ на все места (морской и арктический аэрозоль растёт
сильнее, пыль слабее); f(RH) измерены в Европе, для Алтая и Урала источников нет; порог 40 % — решение, не измерение;
RH > 95 % — туман, он вне модели; рост относится к рассеянию, видимость = 3,912/σ принята моделью игры. Исследование:
`tools/research/haze_humidity/haze/README.md`.
