# Фазы (масштаб 1, P10 — AirPhase, AP-19)

Поле масштаба 1 собирается по фазам: классификатор по клеткам решает, что считает Пикар
(A обтекание, B срыв, C волны — с тёплым стартом от сборки и ω по карте фаз), а что отдаётся
механизмам (H штиль, F свободная конвекция, G вечерний сток, сильное D). Контракт — P10
`docs/contracts/air-phase.md`; спецификация формул — `tools/research/air_phase/analysis/AP-18/section.md`
и `assembly/mechanisms.py` (AP-17). Все числа — `configs/atmosphere.json → air_phase` (у каждого ключа
`_doc` с источником); в коде и ядре констант модели нет, ядро получает их буфером параметров.

## Код и вызов
- `AirPhase` (`air_phase.gd`) — порядок фаз `PHASES = [A, B, C, D, F, G, H]`, раскладки буферов, слоты
  параметров ядра, чтение конфига, **подготовка по столбцам на CPU** (`prepare`): числа случая, огибающая
  срыва, амплитуды DCT и моды линейной теории, вечерний сток (Прандтль + D8 — последовательный проход по
  высоте). Общая для обоих путей.
- `AirPhaseJob` (`air_phase_job.gd` + `air_phase.glsl`) — GPU на каркасе `AirGpu`: подготовка в рабочем
  потоке, затем 15 ядер одной программой порциями (`AirGpuJob`, порция ≤ `air_phase.chunk_ms`):
  `job.case = c; job.start(gpu); poll() …; is_done(); result()` или синхронно `run(case)`; `gpu = null` →
  CPU. Общий `AirGpu` (с ядрами Пикара) можно передать — ядра фаз добавляются, `release()` освобождает
  только свои буферы.
- `AirPhaseCpu` (`air_phase_cpu.gd`) — тот же код построчно в float64 (запасной путь без GPU, рабочий поток).
- Выход (словарь): `weights` (K·ny·nx, Σ = 1), `omega` (ny·nx), `freeze` (ny·nx, 1 — колонна механизма),
  `warm = {u, v, w, th, p}` — грани MAC с ореолом как `AirPicardJob.warm`, `mech_field` (те же массивы;
  значения действительны в колоннах `freeze = 1`), `stats`, `ms`, `ms_parts`; то же для решения без нагрева
  — ключи `*_mech` (`weights_mech`, `freeze_mech`, `warm_mech`, `mech_field_mech`).

## Классификатор (P10 v3 по проверке P15 / AP-23; ключи — `air_phase.classifier`)
σ(x) = 1/(1 + e^(−x)); s(x; x_c, w) = σ((lg x − lg x_c)/w), w — в декадах. Эталон — `tools/research/air_phase/
classifier_ref.py`; ключи и значения — `recommended_config` AP-23 (имена стабильны). Fr = U_sat/(N·перепад),
N — среднее √(g/θ0·max(γ, 0)) в слое z_i … z_i + `n_layer_m`; U_sat — амплитуда профиля притока `AirCase.u_a`.
- H = 1 − s(U10; `h_c` 0,77 м/с, `h_w_dec` 0,10) — штиль по ветру (`h_axis` = u10; на SY-12 несходимость
  следует U10, а не Fr).
- Сильное D (вес заморозки) = (1 − H)(1 − s(U_sat/N; `d_strong_c` 250 м, 0,05)); D = (1 − H)(1 − s(Fr; `d_fr_c` 1,
  `d_w_dec` 0,1)) × smoothstep(0, `d_local_ramp_m`, H_c − h) — только ниже разделяющей линии тока по клеткам.
- C = (1 − H)(1 − D)·s(U_sat·|e·∇h_s|; `c_w_ms` 1 м/с, 0,1), h_s — рельеф, сглаженный на U_sat/N (волны
  w ≈ U ∂h/∂x); A = 1 − H − D − C.
- B = smoothstep(0, `b_depth_m` 50, h_eff − h), огибающая `b_env_angle_deg` 12°; нагрев 100–250 Вт/м² пузырь
  убирает (s < 0,4) или укорачивает вдвое; A, C, D, H × (1 − B).
- F = s(−z_i/L; `f_zil_c` 35, `f_w_dec` 0,2) (решение с нагревом), остальные × (1 − F); G — вес стока,
  остальные × (1 − G); затем гаусс `smooth_cells` 1 клетка и Σ = 1.
- Заморозка: H + сильное D ≥ `freeze_w` 0,5 — вся область; F ≥ 0,5 при w* ≥ `f_wstar_over_usat`·U_sat; G ≥ 0,5.
- ω = 1 − (1 − `omega_band`)·max(b_Fr, b_U10), полосы Fr 0,3–1,1 и U10 0,6–1,5 м/с (`omega_*`); ω > 0,99 → 1;
  Fr и U10 — величины случая, карта однородна. Фазы её считают, но игра не использует (`air_phase.omega.use_map = false`):
  Пикар идёт с ω = 1, запасное правило — по сходимости.

## Механизмы
- **A** — линейная теория [JH75, Sm80] через DCT-II на эффективном рельефе T = max(h_eff, H_c) (огибающая
  срыва и срез блокирования — один синтез вместо трёх в AP-17), 13 высот `agl_levels_m` над T, в клетки —
  интерполяцией; фон — профиль притока решателя U(z) (в AP-17 — столб K-замыкания с разгоном; упрощение).
- **B** — пузырь u/U_top = −r + (1 + r)(z/d)², r = 0,2, d = h_eff − h, над ним — A.
- **D** — H_c = base + (h_max − base)(1 − Fr), base — 5-й процентиль; ниже H_c — потенциальное обтекание
  стенок в слоях (до 12, шаг 100 м; красно-чёрная верхняя релаксация `sor_iters`), w = 0.
- **H** — среднее = поле D (предел Fr → 0), разброс `stats.h_spread` = 0,45·U_sat·доля H.
- **F** — θ′ слоя перемешивания из баланса тепла вдоль ветра (τ = `AirCase.p.tau_cool`), анабатика
  u_a = (B_s·L·sin α)^(1/3), волновая часть θ′ = −γ·η выше z_i; статистика `stats.convection` по z/z_i:
  σ_w/w* [LWP80], ⟨w′³⟩/w*³, асимметрия S, доля восходящих a_up = ½(1 − S/√(S² + 4)) и w_up
  (модель потока массы).
- **G** — включается, когда средний поток тепла игры ≤ 0 (вечер, ночь); выхолаживание — `AirCase.heat`
  (Rn < 0: длинноволновое −98,5·(1 − 0,3·cover) Вт/м² плюс G, `SurfaceHeat`; см. [surface-heat.md](surface-heat.md)). Склон — модель Прандтля с
  замыканием по потоку (`AirPhase.prandtl`), долины — гидравлический слой по расходу D8; вес — сток против
  фона на высоте струи. Параметры (K 0,3 м²/с, C_D 0,01, Δθ ≤ 6 К, u ≤ 3,5 м/с) — оценки, уточнить облётом.

## Чего не умеет
- Фон — профиль притока, без торможения массивом и роста слоя от края (в AP-17 был столб с разгоном) —
  его даёт Пикар в A/B/C-клетках; в замороженных — нет.
- Линейная теория одна на эффективном рельефе: в клетках с малой долей срыва поле A считается над огибающей.
- Карта ω однородна (Fr, U10 по случаю); местного Fr нет.
- G стационарен (нет хода ночи), Q завышен на больших водосборах; на крутых склонах при сильной инверсии
  (N 0,02, sin α 0,3) модель Прандтля даёт < 1 м/с; струя 10–40 м тоньше клетки 105 м — в клетке видно
  среднее с верхней частью профиля (θ′ может быть > 0 у склона).
- Проекции ∇·u = 0 внутри P10 нет: тёплый старт проецирует Пикар (`AirPicardJob`), без GPU поле
  остаётся без проекции (в центрах C3 бездивергентности не требует).
- CPU-путь медленный на 96 × 96 (синтез A O(n³) и сборка по клеткам в GDScript) — запасной путь.
