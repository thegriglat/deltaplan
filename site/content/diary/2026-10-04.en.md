Summary of the day on the wind neural network: all P3 probes and the new "2.5D operator" architecture (ann2) hit the same relative error of ≈ 22 % of wind speed, only 6–10 % better than P2. The direction is postponed, and the game keeps the P2 network — it shipped in [1.0.5](/releases/1.0.5/) together with the Map inspection mode.

<!--more-->

## P3: closed without a gain

Overnight the last variants of the third pilot finished (postponed mountain systems, wind at 60 m, median m/s; control P3E0 — 0.683):
- P3E6 — background stratification θ̄(z) in FiLM: 0.689, no help ({{< commit 03a8790 >}});
- P3E7 — U-FNO (spectral convolutions from neuraloperator, with a DFT-matrix twin for ONNX): 0.732, 7 % worse ({{< commit 9283dd4 >}});
- P3E8 — training only on "confidently converged" cases: 0.692, and the non-converged ones got worse (0.59 versus 0.48) ({{< commit 9c5dffa >}}).

P2 remained the best (300 places, 0.62 / 1.84 m/s): triple the data volume gave more than any encoding tweak. The user's decision: close P3, put P2 into the game ({{< commit c705c6c >}}). The final table is in [docs/archive/plan/air-nn-p3.md](/docs/archive/plan/air-nn-p3.md).

In passing, the user noted three ideas of a different formulation to "keep in mind": marching along the wind in vertical slices, wind-following threads with a "piston in a tube" and Monte Carlo, and a streamline grid whose cells are stream tubes.

## WindNinja as a second reference

We checked whether WindNinja (a mass-conserving model of the USDA Forest Service, public domain) can serve as an independent reference or a fallback for the wind ({{< commit 607e591 >}}). We built 3.13 and 4.0.0 for CPU only and compared them with the solver at 60 m:
- on ridges the speed-up agrees (1.19 versus 1.13 of the inflow), and the direction differs by a median of 10°;
- in valleys and on lee slopes the solver holds 0.3 of the inflow, WindNinja 0.84–0.97: a diagnostic model without momentum equations has no braking by the mountain massif.

The user's decision: braking by the massif is a real phenomenon, the solver stays the reference, and mass-conserving heuristics do not replace it. Details — [tools/research/windninja/README.md](/tools/research/windninja/README.md).

## ann2: the architecture from scratch

The user decided to start the wind network anew — module ann2, plan [docs/plan/ann2.md](/docs/plan/ann2.md). The criterion changed too: not "ρ within tolerance", but **wind error ≤ 10–15 % of speed** (10 % is the goal, 15 % acceptable); P2 is currently at 17–30 %.

- **AN-1, data limit** ({{< commit 96abd5c >}}): maybe the network hits the noise of the target? No: the target drift for converged cases is 0.003 m/s against a P2 error of 0.59, and for non-converged ones the mean of 11 snapshots differs from the mean of 51 by 0.009 at an error of 0.355. There is no point in fixing the target — [docs/research/ann2_data_limit.md](/docs/research/ann2_data_limit.md).
- **AN-2/AN-3, "2.5D operator"** ({{< commit a26c333 >}}, {{< commit f5271b1 >}}): a ConvNeXt convolutional encoder + an atmosphere-profile encoder + attention + a head over continuous height with a σ estimate, 3.0 M parameters, 40,000 steps. 7–9 % better than P2 (0.567 versus 0.624 on converged cases), the same as P2 on weak wind and non-converged cases; overfitting after ~26,000 steps. The head turned out 12 times slower than P2.
- **AN-4** ({{< commit 7ff8800 >}}): a data check on 140 cases — no discrepancies; the case Froude number is within the seed-to-seed spread; excluding convective cases (w*/U > 0.5) from training is worse by ~4 %; a decomposed DeepONet-style head — 34 ms on CPU instead of 167 ms with no loss of accuracy.

Conclusion: the relative error is ≈ 0.22 for all networks (P2, P3, AN-3, AN-4) — the architecture is not the bottleneck, the problem is in the formulation or the data volume. After AN-3 we discussed what next: a test of memorizing 5–10 terrains, a different loss function, splitting the tasks; for weak wind, a separate model (slope winds and convergence as thermal sources, switching by w*/U, no LES) ({{< commit c3a45d5 >}}). The user's decision: **postpone** the direction, keep the results and tables in the plan and the findings registry, delete the run data — it is reproducible with the commands from the README ({{< commit 59368a8 >}}).
