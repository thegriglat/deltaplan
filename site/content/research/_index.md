## Прототипы модели воздуха

Два физических прототипа проверяют идею «одно поле воздуха вместо набора формул» (подробное описание физики и выводов — на странице [«Модель воздуха в трёх масштабах»](/mechanics/air-model/)):

- **[`tools/research/heat_ca/`](/research/heat_ca/)** — 2D-разрез хребта, клеточный автомат тепла и массы на GPU; пять сценариев (склон на солнце, оба склона, ветер, инверсия) и шесть сравнительных опытов (линейность, метод Пикара, матрицы перехода, ADI, ядро струи) — какой способ считать установившееся поле быстрее и без потери физики. Итог — [`out/summary.md`](/tools/research/heat_ca/out/summary.md).
- **[`tools/research/air3d/`](/research/air3d/)** — перенос выбранного метода (Пикар) на реальный рельеф Онгудая в 3D: время решения, память, сходимость по клетке, размер полей для игровой библиотеки. Итог — [`summary.md`](/tools/research/air3d/summary.md).
- **[Данные Askervein](/research/askervein/)** — полевые измерения обтекания холма (Zenodo 4095052, CC BY 4.0) для калибровки разгона ветра на бровке.

## Отвергнутые варианты и почему

- **Поле ветра по массе (уравнение Пуассона, без тепла)** → заменено моделью воздуха с тепловой связью: без нагрева земли и инерции воздуха нет притока к прогретому склону, столба над гребнем и потолка термиков на инверсии.
- **CUDA** → не выбрана: видеокарты у пилотов ожидаются AMD, а не NVIDIA. Выбран переносимый Vulkan compute (RenderingDevice в Godot); CuPy/CUDA использовались только в прототипах-исследованиях на GPU разработчика.
- **Rust + rayon / GDExtension** → рассмотрены и отклонены в пользу расчёта прямо на GPU через compute-шейдеры — офлайн-счёт на CPU не даёт нужной скорости для регулярного пересчёта поля в игре.
- **Линейные ядра и суперпозиция** (опыты 1 и 3 прототипа) → отклонены: линейны только при малом подъёме воздуха (единицы см/с), при обычном для склона нагреве ошибка суперпозиции — десятки процентов.
- **Шаги по времени как основной способ счёта в игре** → отклонены как слишком дорогие на мелкой сетке (минуты на кадр); используются как эталон в исследовании и как способ перехода между часами, если понадобится.
- **Матрицы перехода слой за слоем** → не выбраны как основной метод (сложнее реализовать в шейдере, растёт память), оставлены как запасной решатель для мелких окон.

## Как воспроизвести опыты

Оба прототипа — отдельные Python-скрипты вне игры (свой venv, GPU через CuPy), команды запуска — в README каждого:

```bash
cd tools/research/heat_ca
uv venv .venv && uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python run.py all              # все сценарии 2D
.venv/bin/python study.py cells          # сходимость по клетке
```

```bash
cd tools/research/air3d
PY=../heat_ca/.venv/bin/python
$PY study.py conv && $PY study.py matrix && $PY study.py cells   # 3D на рельефе Онгудая
$PY report.py figs && $PY report.py tables
```

Подробности, флаги и что означают выходные файлы — [`tools/research/heat_ca/README.md`](/tools/research/heat_ca/README.md) и [`tools/research/air3d/README.md`](/tools/research/air3d/README.md).
