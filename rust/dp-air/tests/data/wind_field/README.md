# Дамп поля воздуха (RW-6i)

Эталон GDScript (`WindField`, `AirFieldSet`) для `rust/dp-air/tests/wind_field.rs`. Снимает и проверяет `tools/research/rust_wind/dump_wind_field.sh` (`--verify` — пересъёмка и побитное сравнение); Godot — под замком `.dpcli/dpcli lock cpu`.

Файлы: `field.json` (сетка, ограничители, сценарий подмены `ops`, карта массивов `arrays: имя → [смещение, длина]` в f32) и `field.bin` (f32 LE подряд, ≈ 1,7 МБ).

## Откуда данные (вне git)
- Случай R1 Онгудая 400 м, U10 = 3 м/с, 12:00, ветер с 150°: `~/data/air_cascade/ongudai/ongudai_d400_u3_heat.{json,bin}` (рельеф `hc`, типы клеток `cell`, фон `gam`, `z_i`).
- Решения Пикара (R4): `~/data/air_cascade/rw6i/u3_heat.*` и `u3_mech.*` — `picard solve ongudai_d400_u3_{heat,mech}.json --threads 4 --tol-scale 5 --save-state …` готовым `rust/picard_rs` (release). Нет файлов — `dump_wind_field.sh` пересчитывает их сам (2 × ≈ 1 мин при 4 потоках). Каталог данных — `$DP_AIR_DATA` (по умолчанию `~/data/air_cascade`).
- Вырез 24 × 24 клетки (с ореолом) из 96 × 96, начало `(48, 32)`; уровень B — вырез 12 × 12 из A со сдвигом 6 клеток (для проверки порядка уровней и подмены).
- Поток тепла, карта z0 и `z_i` по столбцам — детерминированная синтетика дампера (в игре их даёт `AirPlace`); числа лежат в дампе, Rust читает те же.

## Что сравнивается
Сырые массивы после `from_mac` (u, v, w_mech, w_conv, θ′, `k1`, столбцы `u*`, `U_out`, `A_out`, desc, `w*`, `hmix`), 2000 точек опроса A (у земли 1/5/20/50 м, склоны, долина, полоса края, над `z_i`, вне области; `ground_h` — рельеф сетки + добавка либо NaN), 48 точек для уровня B и «простого» поля C (без метаданных: z0 числом, нет `gam` и нагрева), сценарий подмены `AirFieldSet` (одиночные подмены, подмена во время подмены, цепочка снимков).
