# PR-7: пачка 1b (build_mom, project)

Замер: Онгудай 400 м, release, 8 потоков, под замком cpu (18 слотов), `run.sh before|after`.
Арифметика не менялась; тождественность: `compare_r2.py` → identical=4/4.

## Правки (одна пачка, по отдельности не мерились)

- `kernels.rs`: `build_all_mom` — один проход по блокам клеток (512) для u, v, w; `mom_cell::<COMP>`
  (inline) — те же формулы, что `build_mom_chunk`; nu, nuh, th, p, скорости читаются в L1 один раз на блок.
- `solver.rs::project`: `div -= mean*fluid`, `phi -= pm*fluid` — построчно (`par_chunks_mut(nx)` zip
  с внутренней маской `fluid_int`), без `halo_index` (деление/остаток на элемент); перенос phi → pfull —
  построчный `copy_from_slice` в пуле, `pfull.fill(0)` убран (ореол pfull нулевой с выделения и не пишется).
- `solver.rs::apply_phi`: u, v, w, p — один проход по строкам x (вместо четырёх по элементам с `i % nx`).
- `solver.rs::divergence`: построчно, срезы со сдвигом вместо `q % nx`, `q / (nx·ny)`.
- `mg.rs`: `set_rhs` и обнуление phi (`zero_phi`) — в пуле (были последовательными).

Убранные копии: `pfull.fill(0)` — 499 408 · 4 Б ≈ 2,0 МБ записи за вызов `project` (сетка 98×98×52); последовательный
перенос phi → pfull (1,84 МБ чтения/записи, деление и остаток на элемент) стал построчным копированием в пуле;
три прохода `apply_phi` по u/v/w/p слиты в один. Новых временных массивов нет, добавлен постоянный `fluid_int`
(1,84 МБ, один раз). L1-промахи не изменились — их дают прогонки (lines.rs), не эта пачка. Бисекция не понадобилась.
Профиль `perf record` до/после не снимался: доли фаз — по `phase_ms` выше (project 26,8 % → 19,2 % итерации,
mom 32,6 % → 35,6 %: доля mom выросла лишь потому, что весь итерационный цикл стал короче).
