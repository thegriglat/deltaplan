# Профиль до оптимизации (PR-4)

Объект: ветка `x86_64+avx2+fma` (`picard isa`), `ongudai_d400_u3_heat`, 191 итерация до критерия, Xeon E5-2666 v3 (10 ядер, 20 логических, Haswell),
`perf` 6.12 под замком cpu 18 слотов. Сборка с символами: `CARGO_PROFILE_RELEASE_DEBUG=line-tables-only cargo build --release` (кодоген тот же; после профиля
собран обычный release). Файлы — `out/prof/`, `perf.data` и сырые R2 — `~/data/air_cascade/picard_rs/prof/` (вне git, ≈ 20 МБ). Воспроизведение — `out/prof/prof.sh`
(комментарий в конце — остальные шаги), сводка — `out/prof/summary.json`. Решение пользователя: оптимизация и замеры — на 8 потоках; 1 и 18 потоков есть
только как база (stat, record 18), 1 поток — без record и без точных групп.

Нормировка: «клетко-прогонка» = 21 657 600 на итерацию (47 × 460 800, README «Где запас») × 191 итерация. События Haswell: все 11 из карточки поддержаны;
в общем наборе они мультиплексируются (36–45 % времени), поэтому на 8 потоках сняты и точные группы по ≤ 4 события (`_A/_B/_C`): совпадают в пределах 2–3 %.

## Фазы (R2 v2, 8 потоков, мс/итерацию; доли %)
без perf 101,3: mom 32,6 / heat 37,4 / proj 26,9 / kupd 3,0 / other 0,1; под `perf stat` 101,9: 32,7 / 37,4 / 26,8 / 3,1 / 0,1; под `perf record -F 499` 102,9: 32,6 / 37,4 / 26,9 / 3,0 / 0,1.
Накладные perf ≤ 1,6 %. Против PR-1 (105,05 мс) −3,6 % — на 0,6 п.п. вне ±3 %: разброс серий, коды идентичны.

## Горячие функции (доля циклов, self; mangled-имена perf)
`solve_line_avx2_fma_version` 74,5 % (8) / 67,6 % (18) — всё остальное по отдельности < 6 %: `build_mom_chunk` 5,8 / 6,7, `build_heat_chunk` 3,5 / 4,0, `kloc_chunk` 3,05 / 2,8,
`resid_chunk` 1,2, `prolong_chunk` 1,1 / 0,9, `Picard::project` 0,88 / 0,48, `det_sum` 0,65 / 0,58; rayon и crossbeam ≈ 6,5 / 8,5 %, ядро Linux 2,1 / 6,0 %.
Горячая ветка — avx2_fma (базовой в отчёте нет). 92 % всех L1-промахов — в `solve_line` (`report_l1miss_*`).

## Внутри `solve_line` (perf annotate, 8 потоков)
Загрузки x-соседей 25 %, строки (`row[RHS]`) 18 %, записи cps/dps/x 17 %, ветвления (`o==lo||hi`, `c!=0`, границы) 20 %, остальное 20 %.
Деление: два деления слиты в один `vdivps`; на и сразу после него ≈ 8 % выборок; цепочка зависимостей ≈ 18–20 тактов на клетку против 63–149 измеренных —
арифметика не упор (решение пользователя: деления и кэш cp/den исключить). Направление x без кэш-промахов всё равно 63 такта при 169 инструкциях — упор в число инструкций.

## Находки «Где запас» (по убыванию выигрыша; доли от времени итерации, 8 потоков)
| # | статус | выигрыш |
|---|---|---|
| 3 | подтверждена: y 7,8 и z 3,0 L1-промаха против 1,1 в x | 12–25 % (потолок 30) |
| 5 | подтверждена: 169–186 инструкций, 56 ветвлений на клетко-прогонку | 10–20 % |
| 8 | подтверждена, больше оценки: `Picard::project` последовательно 7,0 мс/итерацию = 6,6 % стены | 4–7 % |

| 4 | отдельно не измерена | ≤ 3 % |
| 6 | ветка выбрана, код скалярный; SIMD — после 3 | 1,3–2× после 3 и 5 |
| 1 | опровергнута как упор (один vdivps) | ≤ 3 % — исключить |
| 2 | опровергнута как упор | ≤ 5 % — исключить |
| 9 | пренебрежимо | < 1 % |

Приоритеты пользователя: 1) L1-промахи — `solve_line` (92 %), y и z; 2) последовательные циклы вне пула — `Picard::project` (pfull.fill, `halo_index`, `apply_phi`), 6,6 % стены; 3) копии — те же циклы.

Ограничения: perf-выборки с «проскальзыванием» (стоимость относится к следующей инструкции); счётчики с мультиплексированием — оценки с масштабированием; harness-значения
получены разностью серий на не сошедшемся поле; ложное разделение кэш-линий в y — гипотеза. Лицензии: данные Онгудая — `~/data/air_cascade/ongudai/` (описание в `docs`), perf — GPL, не поставляется.
